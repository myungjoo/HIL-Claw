## Why

> `n_max` is the one value an instance may set: it is the cost of a measurement (C-4), and the owner lists it among the initial run caps next to N and the round budget, which are instance parameters. ## Acceptance Criteria
What is **fixed** and taken as input, not re-decided:
- **Owner (#5 B-4)**: for the initial runs, "measurement repeats adaptive per OD-13 with an initial upper bound of 10", listed among the "Initial run caps". Nothing else of the owner's speaks of this value.
- **ADR-0007** (accepted under §9; its own choices, not the owner's): the measurement stops at n = `n_max`; `n_max` is the one value of the policy an instance may set, "default 10, never below `n_min`"; `n_min` = 5 is a constant of the policy; all values are initial values; the constants live in the harness source and are traced through the source commit of the instance. **ADR-0009**: the caller passes `n_max` to the timing run of `cpu_standin`.
- ADR-0004: `runs/<run_id>/instance.json`, one per run, "What the instance was started with", written once, immutable; nothing enforces it. ADR-0018: the frame of the file (decision 2), the open top level of version 1 and **the rule of what raises `schema_version`**. ADR-0020 and ADR-0022: the members `tolerance` and `source_commit`. Nothing is kept between calls (ADR-0010 decision 7).

What the ADR **decides**. The content of each decision is the executor's to work out and justify from the fixed inputs; the reviewer's Approve confirms it. For every point give the choice, the alternatives considered and one or two lines of reason; mark each value as **cited** or as **this record's own**:
1. **Scope**: of `runs/<run_id>/instance.json`, the one member in which a run states its upper bound of timing repeats; nothing else of the file and nothing of any other file. State that the file is still not a complete instance record (ADR-0018 decision 1).
2. **What the member states.** The upper bound of repeats of one measurement in the sense of ADR-0007 decisions 1 and 4, for the run. Say exactly what a reader may conclude and what it may not: it is a bound on the samples of **one** measurement, not on the number of measurements, attempts, candidates or rounds, and not a budget of time, of hardware quota or of tokens (OD-2, OD-19); it says nothing about `n_min`, `cv_max` or any other constant of the policy. Whether one value holds for every execution point and backend of the run is to be weighed against ADR-0007 decision 10 and its Boundaries (values for a simulator and a board are initial values only; "whether a deterministic simulator needs repeats at all" is open): say what the fixed inputs carry and leave the rest open by name - do not invent a per-point or per-backend form.
3. **The member: its name, place and form.** Weigh at least: (a) one top-level *integer* member (for example `n_max`, the name ADR-0007 uses - note that ADR-0007 says its names "are names of this record, not fields of any file", so the name is this record's choice); (b) a member inside an object that groups measurement parameters or run caps - weigh it against the fact that no other parameter of that kind has a fixed form (every other value of the policy is a constant, and N and the round budget wait for other decisions), so such an object would be shaped by members that do not exist. The value form: a JSON integer, the lower bound `n_min` (cited: "never below `n_min`"), and an upper limit only as far as a fixed input carries one (ADR-0001's *integer* range 0 to 2^53 - 1 is the only range the records have; the C driver allocates `n_max` samples and has its own limits - say what follows and do not invent a smaller cap). Say what is no value: another JSON type, a boolean, a number with a fraction or an exponent (decide and state how `10.0` and `1e1` are read, in line with how ADR-0012 and ADR-0018 read an *integer* and with what `hilclaw/run_state.py` accepts), a string of digits, a negative number, a value below the lower bound.
   - **The lower bound is a constant of the source, not of the file.** `n_min` = 5 is an initial value that a later source may change, and the file is written once. Decide whether the validity of the member is stated with the number 5 (the rule of version 1 of the schema) or by reference to the policy's constant, and say what follows for a file whose value a later policy would refuse. Note that `hilclaw/instance.py` imports nothing of the harness today.
4. **A file without the member; the version; the default.** By ADR-0018 decision 2's own rule, which leaves this choice to the record of the member. The inputs pull two ways and the record must settle it: ADR-0007 decision 8 gives a **default 10** and says the value "is recorded with" what the instance was started with. Weigh at least: (a) the member may be absent from a valid file, the version stays 1, and absent **means** the default of ADR-0007 decision 8 - then say where the number 10 lives (a constant of the source, `N_MAX_DEFAULT` today), that a reader of this record that applies it is not reading it from the run, and what a later change of that constant does to a run whose file is silent (the file is never rewritten; ADR-0007 decision 8 traces constants through the source commit, and ADR-0022 decision 6 says the member `source_commit` states the start only - everything further is OD-11 and not decided); (b) the member may be absent from a valid file, the version stays 1, absent means "not stated", and no reader substitutes a value - then the default of ADR-0007 is a matter of whatever writes the file (it writes 10 when the instance sets nothing), which is not decided here, and say what "default 10" means until a writer exists; (c) the member becomes required and the version becomes 2 - then every file and reader of today is of another version before a first run exists, and reading another version is OD-11. If the member is present it must be valid; say whether a present and invalid member makes the file invalid as a whole (ADR-0020 decision 3 and ADR-0022 decision 5 are the precedents; confirm or correct). **Whichever is chosen, no sentence may make the bound of a run depend silently on something the run did not record.**
5. **How the member is read**, only as far as it follows from the fixed inputs: from this member of the file of the run, at each use, nothing kept between calls; no request carries it (weigh this sentence against ADR-0009's "the caller's `n_max`" and state the reading: ADR-0009 speaks of the caller of the timing run, not of the request of a tool). Observation to state truthfully: no tool, hook or module reads the member today; the harness functions take `n_max` as an argument with a default of their own. Do not say which tool or component reads it or at which moment.
