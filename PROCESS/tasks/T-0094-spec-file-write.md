### The write - recommended `write(data_root, content)`, returning `None`
- **The content first (decision 4).** `content` is the whole file as `bytes`. Before the file system is touched: (a) it is valid by decision 2 - `parse(content)`; `TypeError`, `InvalidSpecFileError` and `UnsupportedVersionError` pass through unchanged, so **a content of another version is not written and keeps its own class** (call `parse` before `final_name`: T-0093 `## Result`); (b) it has a path by decision 3 - the final name is `final_name(data_root, document)` and nothing else; a valid content whose `id.run_id` is no run directory name raises `hilclaw.layout.InvalidPathValueError` unchanged and is not written; (c) it is in the written form of decision 2 - it ends with a line feed and holds no carriage return byte, the check `hilclaw.instance_file.write` makes; no member order, indentation or number of lines is checked. Recommended: a class `WrittenFormError(ValueError)` of this module, no subclass of `InvalidSpecFileError` (a content `parse` accepts stays a valid one). A carriage return **escaped** in a string (`\r` as two characters of the text) is no carriage return byte and is accepted.
- **The function takes no tuple, no `run_id` and no path** (decision 3: "A write is given no other final name"). Comparing a tuple given as arguments with the content is left out: the record leaves it to the code task and no caller exists.
- **`data_root`** is a `str` or a path, is not resolved, **must be an existing directory and is never created** (`FileNotFoundError` or `NotADirectoryError` otherwise - the convention of `hilclaw.instance_file.write`, named by ADR-0029 Consequences). A value that is no path is the `TypeError` `final_name` already gives.
- **The directories (decision 5).** Every missing directory between the data root and the final name is created (`runs/`, the run directory, `rounds/`, `<RRRR>/`, `coder/`, `candidates/`, `<CC>/`, `attempts/`, `<AA>/`). **The write requires neither the presence nor the absence of any of them nor of any other file** - not `instance.json`, `STATE.json`, `decision/decision.md`, the directory of an earlier attempt, or `output/` - and reads, opens and lists none of them. Whether a failed write removes the directories it created is your choice (recommended: they stay, as in `hilclaw.instance_file`); say which in the docstring.
- **The temporary file (decision 6)**: `spec.json.<token>.tmp` in the attempt directory of the final name, `<token>` matching `[a-z0-9-]{1,64}` and different for every write (recommended: the process id, a hyphen and 16 random hexadecimal characters), created as a new file (mode `"xb"`), holding the whole content. **Nothing named `output` is created, entered, read or listed.**
- **Stable storage (decision 7)**: the content of the temporary file is flushed and `os.fsync` is called before the last step. The directory entry is not flushed.
- **The last step cannot replace (decision 4).** Recommended: `os.link(temporary, final)` followed by the removal of the temporary name. **No fallback to `os.replace` or `os.rename`**: where the link is not possible, the write fails with that `OSError` and has put nothing under the final name. The final name is never opened.
- **A taken name (decision 4).** When the last step finds the name taken - by a file with other bytes, with equal bytes, an invalid or empty file, a directory, a symbolic link - the write removes its temporary file and raises a class that is **no `OSError`** (recommended: `NameTakenError(Exception)` of this module; the message names the file relative to the data root and says the content was not written). What is under the name is not opened, read or compared; equal bytes are reported as any other; nothing is retried. **The docstrings decide no more about that report** (sub-question 26 (i)).
- **A failure of a step while the writer lives**: the `OSError` passes through unchanged; the temporary file this call created is removed after any exception raised before the name is given, an interrupt (`BaseException`) included; a removal that fails does not hide the failure it follows. Once the name is given, a removal that fails is no failure of the write: the temporary name stays as a second name of the file. Only the file this call created is removed: a leftover of another write is not listed, read, removed or given the final name.
- **The bytes under the final name are exactly those given**: nothing is added, removed, defaulted or normalised (white space, member order, the three free places as written).
- Recommended order of the checks: the validity of the content (`parse`), the path (`final_name`), the written form, `data_root`, the file system. Nothing is created before the last of them. State the order in the module docstring and pin it with one test.
- Whether the new classes are the module's own (recommended: the docstring of `hilclaw.instance_file.WrittenFormError` names ADR-0018, so it is not this file's class) or imported is your choice; importing must not edit `hilclaw/instance_file.py`.
