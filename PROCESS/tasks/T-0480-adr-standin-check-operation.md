## Why

PLAN P1-1 is open. Its completion criterion (D18) needs `sim.run`, `board.run` and `correctness.check` to work on `cpu_standin` as well as on the mock; PLAN P2-5 (the first run, `cpu_standin` x GEMM) needs the same operations. This is checklist work, not a D18 deferral.

T-0479 landed ADR-0168 (main `bc54bd01`) and `hilclaw/standin_answer.py`. ADR-0168 Consequences now name ADR-0144 slice (4) as free of ADR-0144 decision 7: the `cpu_standin` operation of `correctness.check`, then those of `sim.run`/`board.run` with the waiter's build and process, then the `cpu_standin` entry of the default table. The building blocks are on `main`: `hilclaw/standin_container.py` (slice 1), `hilclaw/standin_copies.py` (slice 2), `hilclaw/standin_image.py` (slice 3), `hilclaw/standin_answer.py` (ADR-0168), `hilclaw/standin_settings.py` (ADR-0116 flags, ADR-0117 limits), `hilclaw/harness/verification_program.c` (ADR-0017), `hilclaw/build_log.py` (ADR-0078 keeper).

Two design points the operation needs are still open in the records, so they cannot be settled in code alone (CLAUDE.md "미결은 발명하지 않는다"):

1. **The compiler's log out of a build container.** ADR-0078 decision 5 and ADR-0108 decision 4 say a log inside a container "holds the paths of that environment" and that its route out is the container's (OD-14 ①; ⑱ (다)). ADR-0144 decision 3 ("Standard error") says the client writes its own text to the same standard error as the compiler, and "Whether the compiler's log of ADR-0078 must exclude it is not decided here". ADR-0168 answered the situations of ⑱ (다) but not this. Through the client the operation gets the container's standard output and standard error as two byte strings (`ContainerResult.stdout`, `.stderr`), not the one joined pipe `clang_build` gives; and for a build container that ended with 125 to 127 (ADR-0168 C5) the compiler may never have started, while ADR-0078 decision 2 keeps the log of "every build whose compiler process was started and has ended". The waiter's build of ADR-0145 is a second build of a timing call, while the keeper takes at most one log (ADR-0078 decision 6; ADR-0108 decision 5).
2. **The time limit of a forced removal.** `run_in_container` needs `removal_timeout_s` with no default; no record gives it a value (ADR-0117 gives the build and process limits only). `hilclaw/coder_runtime.py` has `REMOVAL_TIMEOUT_S = 60` for the coder's container (ADR-0137's code choice) — for the record to weigh, not to copy.

By D20 ② these are one ADR; by D20 ① the ADR goes with its first code slice, the check's operation, in one task (code mode; the ADR file is part of the PR). The run tools' operation is **not** in this task: its waiter-build log depends on this ADR, which has not landed (D20 ④). The planner plans it after this lands.

This is a design part of OD-18 (and of OD-14 ①) that the driver may close (DRIVER §9, D6). No owner-only part is known (#5 A/B items, C-6, OD-3, OD-25 are not touched; HQ-0034 OpenMP stays out). HQ-0073 (runtime acceptance of ADR-0168, items (lxxv)-(lxxvii)) is unresolved but blocks nothing here: tests use stubs. **Stop conditions the executor checks, not assumes away:**
- If a choice needs a new value of `error.kind` or `condition`, a new file, file name or member in the data plane (for example a second log file per identity for the waiter's build), or a change to the bytes rule of ADR-0078 decision 4 / ADR-0108 decision 4 that the record cannot read as within it, that is a data-plane change (CLAUDE.md A-13; ADR-0101 Consequences). **For the check's own build**, stop and return BLOCKED with a Korean question for the owner (DRIVER §8: the issue, options (a)/(b)/..., what stays blocked and what does not). **For the waiter's build only**, do not stop: leave that piece open in Boundaries with the reason, named for the run-tools task, since the check's operation does not depend on it.
- If writing the record shows an owner-only decision (for example a reading of #5 A-2 "에러 로그" beyond what ADR-0078 decision 2 and 5 already read), stop and return BLOCKED with the question.
