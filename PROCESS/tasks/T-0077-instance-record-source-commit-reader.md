### Validity of the member (ADR-0022 decisions 3 and 5)
- `source_commit` becomes a defined top-level member of version 1: it is checked by `parse` and `validate` and is **no longer in `Instance.others`**.
- **Absent**: the content is valid and states no source commit. `schema_version` stays 1; `SCHEMA_VERSION` is unchanged.
- **Present**: a JSON string of **exactly 40 or exactly 64 characters, each one of `0`-`9` and `a`-`f`**. Anything else makes the content invalid as a whole: `InvalidInstanceError`, nothing returned - not the hw_profile or the tolerance either. In particular no value: another JSON type (`null`, `true`, `false`, a number - a 40-digit integer literal included -, an array, an object such as `{"commit": "..."}`), the empty string, any other length (7, 12, 39, 41, 63, 65, 80 characters), an upper-case hexadecimal digit anywhere, a character outside the sixteen (`g`, a space, `-`), white space or a prefix around a full name (a trailing line feed, a leading space, `sha1:` in front), the name of a branch or a tag (`main`, `v1.0`), `git describe` output.
- **Pitfalls to avoid, each pinned by a test**: the check is on the sixteen ASCII characters themselves, so a digit of another script (a full-width `０`, an Arabic-Indic digit) is no value though `str.isdigit` and an unanchored `\d` accept it, and `int(value, 16)` or `bytes.fromhex` must not be the rule (they accept upper case, and `int` accepts white space, `_` and a sign); a pattern ending in `$` accepts a trailing line feed - use a full match that does not.
- **The value handed out** is the string as the file states it. Nothing is normalised, shortened or resolved.
- **Order**: the rules for the whole text, then `schema_version` (another version is still `UnsupportedVersionError` before any other member is looked at, a broken `source_commit` included), then the members of version 1. Where `source_commit` comes among `hw_profile` and `tolerance` is yours (recommended: last, the order of the records); state it in the module docstring. The first rule found broken is reported and names its place (`source_commit`), by the module's `_fail` conventions.
- Every other top-level member stays open and uninterpreted (`source-commit`, `sourceCommit`, `source_commits`, `commit` included): passed over, returned in `others`, and the content then states no source commit (decision 8, "A misspelt name").
- `validate(document)` applies the same rule to a parsed document. State in its docstring what it accepts for a value built in memory (recommended, as the module does for `hw_profile.key`: exactly a `str`, so a subclass of `str` and `bytes` are none).
- The validator does not check that the commit exists anywhere, that it was pushed, or that the statement is true, and it does not tell which of the two lengths the source repository uses (decisions 3, 4 and 8).
