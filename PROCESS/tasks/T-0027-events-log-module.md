Constraints:
- **Standard library only**, plus `hilclaw.layout` and the public names of `hilclaw.keys`. Adding any package is the BLOCKED reason "new external dependency". `pyproject.toml` stays unchanged. No JSON Schema file.
- Runs on CPython 3.11 and 3.14 (both CI matrix entries) and behaves the same on POSIX and Windows hosts. All file access is in **binary mode**; the bytes written are the same on every host (no `\r`, no platform default encoding, no byte order mark).
- `data_root` is always given by the caller and must be an existing directory (as in `hilclaw.artifacts`). The module reads no configuration and no environment variable, runs no `git`, commits nothing, and writes nowhere but `runs/<run_id>/events.ndjson` and the directories above it.
- The path comes from `layout.run_file(data_root, run_id, "events.ndjson")`. The module joins no path segment itself and edits no other module. Do not import a private name of `keys.py` and do not edit it: restate the *name* pattern of ADR-0001 decision 1 in the module and use `keys.MAX_INTEGER`.
- **No temporary or scratch file** anywhere in the data tree (ADR-0004 decision 7).
- **No event kind**: no value of `kind` and no payload member is defined, listed, special-cased or presented as valid, in the module or in the tests (ADR-0006 decisions 1 and 3, Boundaries). Tests use placeholders such as `example_kind` and `example_member`.
- **The caller cannot state the time**: `time` is the writer's clock reading (decision 3: "not a statement of an agent"). The append function takes no time argument and no clock argument; tests replace the module's clock through `monkeypatch`.
- The module never edits, removes or reorders a complete line (decision 5). The only bytes it ever removes are a torn tail (decision 6).
- The writer reads no earlier line and does not look for damage (decision 6): an append looks at the end of the file only, in bounded chunks from the end, and must not read or parse the whole file.
- No command line entry point, no `main` (OD-18 is open). No locking (OD-17). No value of a real run is written as a fact.

Module (new, `hilclaw/events.py`; provisional name, flat next to the sibling modules. Python because the package is Python and JSON and file handling are in the stdlib — one line in the commit body and `## Result`):
- Module docstring that names ADR-0006 as the rule it implements, lists the conventions of this module and says what it does not do; docstrings on the public names (external API, CLAUDE.md "코멘트 최소화" exception); no other comments unless the code cannot say it. Keep the docstrings short enough for the cap (T-0025 ended at 298 of 300 lines because of them).
- Public API (provisional names and shapes; the executor may rename or regroup them, but every public function must be tested and each capability must exist):
  - **Check an event**: `validate(event)` — checks a parsed line against decision 3, in the order decision 6 gives (version first, then the rest):
    - the value is an object (exactly `dict`);
    - `schema_version` is present and an *integer* of ADR-0001 (exactly `int`, 0 to 2^53 − 1; `bool`, `float` and a negative number are not) — otherwise **damage**; an *integer* other than 1 is **unsupported version**, a distinct error, raised before any other member is looked at (a version 1 reader does not interpret such a line);
    - exactly the members of the table: `schema_version`, `time`, `kind`, `data` required; `round`, `candidate`, `attempt` optional; any other member is an error;
    - `time`: a `str` of exactly 20 characters `YYYY-MM-DDThh:mm:ssZ` with ASCII digits (`[0-9]`, not `\d`), a date that exists in the Gregorian calendar, year `0001`-`9999`, `hh` 00-23, `mm` 00-59, `ss` 00-59 (`…:60Z`, `2026-02-30`, `0000-…`, lower case `t` / `z`, fractions and offsets are rejected);
    - `kind`: a *name* (`[a-z][a-z0-9_]{0,31}`), checked against **no** vocabulary;
    - `round`: *integer*; `candidate` and `attempt`: *integer* ≥ 1; `candidate` only together with `round`, `attempt` only together with `candidate`;
    - `data`: an object (exactly `dict`), possibly empty. Its content is outside the envelope and is **not** checked by `validate` (planner's reading of decision 3: "No member holds `null`" speaks of the envelope members; a `null` inside `data` is the kind's business — ask the reviewer to confirm this reading);
    - no envelope member is `null`.
    The error message names the member and the rule, with values shown through `reprlib.repr`.
  - **Append**: `append(data_root, run_id, kind, data, *, round=None, candidate=None, attempt=None)` — builds the line with `schema_version` 1 and `time` read from the clock in UTC, checks it with the same rules as `validate`, and additionally requires that `data` can be written as strict JSON (string member names, no `NaN` / `Infinity`, no value outside JSON, not nested beyond what the interpreter serialises): otherwise it raises and writes nothing. `None` for one of the three numbers means "absent" and the member is left out. Then: create `runs/<run_id>/` when missing (ADR-0004 decision 1), remove a torn tail if there is one (decision 6), and append the JSON text followed by one LF, with the members in the order of the table of decision 3 and the LF as the last byte written. Returns the event as written (a `dict`). The argument values are not modified.
  - **Read**: `read(data_root, run_id)` — returns the events of the complete lines in file order (plain `dict` values as parsed) and whether a torn tail exists (for example a `NamedTuple` `Log(events, torn_tail)` with the number of tail bytes, 0 for none). A missing file and an empty file both give no event (decision 2). The file is split at the byte `0x0A` only — not with `splitlines()`, which also splits at `\r`, `\x0b`, `\x0c`, `\x1c`-`\x1e`, `\x85` and U+2028 / U+2029. A torn tail is never returned as an event, also when its bytes parse (decision 6). A damaged complete line — not valid UTF-8, not exactly one JSON text that is an object (a blank or white-space-only line included), a member name repeated in any object of the line (`object_pairs_hook`; `json.loads` accepts repeats silently), `NaN` / `Infinity` (`parse_constant`), or anything `validate` calls damage — raises an error that names the path relative to `data_root` and the **line number** (from 1). A complete line of another *integer* version raises the distinct unsupported-version error with its line number. `read` never writes: it does not remove the torn tail and repairs nothing. It accepts any member order and JSON white space, a `\r` before the LF included.
  - **Remove a torn tail**: `remove_torn_tail(data_root, run_id)` — the removal `append` performs, exposed because the step that commits the data repository must perform "the same removal" (decision 6). Returns the number of bytes removed (0 when the file is missing, empty or ends with LF). It removes exactly the bytes after the last LF (the whole content when there is no LF) and reads no earlier line.
  - Error types (provisional): one `ValueError` subclass for an event or an argument that breaks decision 3; one for a stored file that is damaged or not usable; one for an unsupported version (say whether it is a subclass of one of the others and why). Errors of `hilclaw.layout` for `run_id`, and `FileNotFoundError` / `NotADirectoryError` for `data_root`, pass through unchanged. Argument checks come before any file access.
- Written form (decision 2): `json.dumps` of the envelope in table order (`schema_version`, `time`, `kind`, `round`, `candidate`, `attempt`, `data`; absent members left out) plus `\n`, encoded as UTF-8, nothing else. The separators and whether non-ASCII characters are escaped are this module's choice (both are valid JSON); the lines of the Example of ADR-0006 are the model. The members of `data` are written in the order the caller gave them.
- Rules for the cases the ADR leaves unsaid (provisional; one line of reason each in `## Result`):
  - Whether the append also flushes to the operating system (`flush` + `os.fsync`): decision 10 leaves it to this task. Follow `hilclaw/artifacts.py` unless you find a reason not to, and claim nothing beyond process death in the docstring.
  - A path that is not a regular file (a directory, a symbolic link — not followed): every function raises the "not usable" error and writes nothing, as `hilclaw/artifacts.py` does.
  - A file in the place of `runs/` or `runs/<run_id>`: follow `hilclaw/artifacts.py` (`read` gives no event, `append` passes the `OSError` through) and list it.
  - A failed append (the write or `fsync` raises): the error passes through; what is left is at most a torn tail, which the next append or `remove_torn_tail` removes. State exactly this in the docstring and nothing more. Whether a file or directory the failed call created is removed: choose, say which.
  - How the unsupported version is reported by `read`: raising (as above) is the suggestion; it must not be skipped silently and must not be interpreted. Whether a file may hold lines of two versions is OD-11 and is **not** decided by this choice — say so in the docstring.
  - Anything else you meet (a byte order mark at the start of a line, JSON nested too deeply, a very long line): treat it as damage where decision 6 says so, otherwise follow `hilclaw/artifacts.py`, and list it.
