## Why
PLAN P1-1 (the FR-10 tool contracts, the mock backend, the conformance tests) is open. For `correctness.check` the code on `main` is a row of pure modules bound to no tool: the request side (`hilclaw.check_identity`), the answer side (`check_parameters`, `check_result`, `check_judging`, `check_answer`, `check_operation`, `check_failure`, `check_ending`, `mock_check`), the reading of "covered" (`hilclaw.gemm_contract.covers`) and the reader of the file of a run (`hilclaw.instance.read`, whose `Instance` holds `op_signature`, `draws` and `tolerance` since T-0143).

**Nothing in the package renders what lies between them**: the part of moment 4 that follows the selection of the backend. Three landed records fix it, and the last of them puts it together (ADR-0046 decision 8, the row of moment 4):

> a situation of the file: one of the four kinds; then `no_backend`; then `not_offered`; then `op_signature_not_stated`; then `op_signature_not_covered`; then, for a file that states no number of draws, `draws_not_stated`; then, for a file that states no tolerance, `tolerance_not_stated`. No line, nothing consumed, no seed drawn; the same request can be repeated

### The module
Recommended public names, and no other: `KIND_OP_SIGNATURE_NOT_STATED`, `KIND_OP_SIGNATURE_NOT_COVERED`, `KIND_DRAWS_NOT_STATED`, `KIND_TOLERANCE_NOT_STATED`, `KINDS`, `Admitted`, `admit`.

- **The four kind constants** - the strings `"op_signature_not_stated"`, `"op_signature_not_covered"` (ADR-0041 decisions 4 and 5), `"draws_not_stated"` (ADR-0046 decision 5) and `"tolerance_not_stated"` (ADR-0021 decision 4), each spelt once in the code of the package. **`KINDS`** - the `tuple` of the four **in the order of the answers** (ADR-0046 decision 8); here the order means something, and the docstring says so.
- **`Admitted`** - what a check that is admitted takes from the content of the file, as one immutable value (recommended: a `typing.NamedTuple` with the fields `m`, `k`, `n`, `draws`, `rtol`, `atol`, no field default): the three dimensions are `shape.m`, `shape.k` and `shape.n` of the stated op_signature record (ADR-0041 decision 2), `draws` is the stated number (ADR-0046 decision 2), `rtol` and `atol` are those of the stated tolerance (ADR-0021 decision 4). **Each is handed out as the content states it, unchanged; nothing is derived, rounded, bounded or defaulted. It holds no seed** (the seed is drawn later and elsewhere, ADR-0021 decision 3), no hw_profile, no key, no `ext`, no `label`.
- **`admit(instance, *, covers)`** - recommended signature; no parameter has a default.
  - `instance`: what one `hilclaw.instance.read` returned for the run of the call, the read of moment 4 (ADR-0046 decision 4). `covers`: the predicate of ADR-0041 decision 5, a callable that is handed an op_signature record and answers whether the contract covers it.
  - The answers, **the first whose condition holds and no other** (ADR-0046 decision 5):
    1. `instance.op_signature` is `None`: `hilclaw.tools.ToolFailure` (exact type) of kind `op_signature_not_stated`. **`covers` is not called.**
    2. `covers(record)` answers that the stated record is not covered: `ToolFailure` of kind `op_signature_not_covered`. `covers` is called **exactly once**, with the record object the instance holds, and that object is not modified.
    3. `instance.draws` is `None`: `ToolFailure` of kind `draws_not_stated`.
    4. `instance.tolerance` is `None`: `ToolFailure` of kind `tolerance_not_stated`.
    5. Otherwise an `Admitted` is returned.
  - So a content that states no op_signature is answered `op_signature_not_stated` whatever else it lacks; one that states a covered op_signature and neither a number of draws nor a tolerance is answered `draws_not_stated`; and `tolerance_not_stated` is answered only for a content that states a covered op_signature and a number of draws (ADR-0046 decision 5: the kind keeps saying "that the tolerance is the one thing missing").
  - **Nothing else of the instance is looked at**: not `hw_profile`, `hw_profile_key`, `others`, the key of the op_signature, an `ext` or a `label` (ADR-0041 decision 5: "An `ext` is not looked at"), and no member is compared with another or with any limit.
  - What `covers` raises passes through as the same object (for a record out of `read` the real predicate raises nothing).
  - This task's choices, to be stated in the docstring as the module's own and no rule of a record (recommended): an `instance` that is no `hilclaw.instance.Instance` and a `covers` that is not callable are `TypeError`, raised before anything else is done; an answer of `covers` that is not exactly a `bool` is `TypeError` and **is never taken as "covered"**; the values of an `Instance` are taken as `read` returns them and are not validated again (an `Instance` built by hand with other values is the caller's).
