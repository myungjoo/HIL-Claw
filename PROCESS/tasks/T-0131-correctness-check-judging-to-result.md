## Why

- `hilclaw.harness.verification.judge_report` returns a `Judgement(broken, verdict, counts)` for one report (ADR-0017 decision 7; ADR-0021 decision 2 gives "**all of the judging**" to the tool function's side, "the same code for every backend").
- `hilclaw.check_result` (T-0130, landed as `8778332`) builds the result object of ADR-0042 decision 7 from plain values. By design it "maps nothing from a type of the harness" and refuses a member of the harness's `Broken`.

### The module
Three public functions and no other public name (recommended names and parameters; another shape of the interface is the task's choice as long as every rule below holds - check `hilclaw/` and `tests/` for a collision and say so):

- **`condition_of(broken)`** - the value of `condition` for a member of `hilclaw.harness.verification.Broken`: `Broken.TIMEOUT` -> `"time_limit"`, `Broken.EXIT_STATUS` -> `"exit_status"`, `Broken.REPORT_FORM` -> `"report_form"`, `Broken.CHECK_VALUE` -> `"check_value"` (ADR-0042 decision 3, row by row). The returned strings are the members of `check_result.CONDITIONS` (not spelt a second time where the code can avoid it). Anything that is not a member of `Broken` - `None`, a `str` such as `"time_limit"` or `"TIMEOUT"`, an `int`, a member of another enumeration - is refused.
- **`from_judgement(judgement, *, m, k, n, draws, rtol, atol)`** - the result of a check from a `Judgement`:
  - `judgement.broken` is `None`: returns `check_result.completed(...)` with `counts` taken from `judgement.counts` as it is. `outcome` is the one `completed` derives; **a `verdict` that disagrees with it is refused** (a `Verdict.PASS` beside a count with `failed` of 1 or more, a `Verdict.FAIL` beside all-zero counts), as is a `verdict` that is no member of `Verdict` and a `counts` of `None`.
  - `judgement.broken` is a member of `Broken`: returns `check_result.broken(condition_of(...), ...)`. A judgement that also holds a `verdict` or `counts` is refused ("A run has no partial verdict" - ADR-0017 decision 7, as ADR-0042 decision 4 cites it). Recommended: all four members are mapped, also the two `judge_report` never returns, so that the function is total over the type; say so in the docstring without saying who finds which condition in a call.
  - `judgement` itself: recommended exactly a `Judgement` (a plain tuple of three, a `VerificationResult`, `None`, a `dict` are refused); if the executor accepts more, the docstring says exactly what.
  - Whatever `check_result` refuses of `m`, `k`, `n`, `draws`, `rtol`, `atol` and of the counts is refused here with what it raises, unchanged.
- **`from_report(report, *, m, k, n, draws, seed, rtol, atol)`** - `from_judgement(judge_report(report, m=..., ..., seed=..., rtol=..., atol=...), ...)` with the same dimensions, number of draws and tolerance on both sides, so that no call can judge with one set and report another. What `judge_report` raises (`VerificationArgumentError`, `TypeError` for a `report` that is not exactly `bytes`, what NumPy raises) passes through unchanged and is documented by reference to that function. **`seed` is used for the judging only and is no member of the result.**
- **No parameter has a default**, and the module holds no number of draws, tolerance, dimension, seed or source of a seed.
- **What a refused argument raises** (the task's choice). Recommended: `TypeError` for a wrong type and `ValueError` for a wrong value or an inconsistent judgement, the message naming the parameter or the field (`broken: `, `judgement: `, `judgement.verdict: `), in the manner of `hilclaw/check_result.py`; no own exception class. Whatever is chosen is determinate for every argument (no `AttributeError`, `KeyError`, `IndexError` or unpacking error leaking from an unchecked access), documented, and tested. The order in which the checks are made is the module's and is stated in the docstring.
- The functions are pure apart from what `judge_report` computes: no argument is modified or kept, no file is read or written, no process is started, no clock or random source is read, nothing is kept between calls; equal arguments give equal results.
- Docstrings: the module docstring says what the module joins (by record and decision number), each function's purpose, the choices that are the module's own, and what the module does not do (it is no tool and is bound to none; it calls no operation and says nothing of what an operation returns or of how a report reaches a caller; it draws no seed; it reads no file of a run; it gives no default of any value; it stores nothing). Each public function gets a Doxygen-style docstring in the manner of `hilclaw/check_result.py`. **No docstring states a rule the records do not hold**: nothing on who calls the functions, where `draws` or a seed comes from, what a caller does with a result, or which role reads one.
