### Bytes to a document (decision 2) - recommended name `parse(content)`
- Takes the whole content as `bytes` (`TypeError` for anything else, as `hilclaw.instance.parse`) and returns the parsed document, values as `json.loads` returns them. Nothing is added, defaulted, normalised or repaired.
- **Invalid** (one class of the new module, or `hilclaw.spec.InvalidSpecError` passed through for the rules of ADR-0002 - your choice; a caller must be able to tell "invalid" from "another version" by the class): the content starts with a byte order mark; is not UTF-8; is not exactly one JSON text (empty content, two texts, trailing garbage, the tokens `NaN`, `Infinity`, `-Infinity`); is nested too deeply to parse; is a JSON text that is no object; holds a member name twice in **any** object - the embedded records and the values of `task.objective`, `profile` and `ext` included; parses to a document `hilclaw.spec.validate` refuses; or writes `-0` at an *integer* place.
- **The spelling rule.** `1.0` and `1e0` at an *integer* place are refused by `validate` already (a `float` is no `int`); pin that with tests and add no second check. **`-0` is the one case the parsed document does not show**: the content must be refused although `validate` accepts its document. Establish from ADR-0002 and `hilclaw/spec.py` which places are *integer* places and which are the three free places (`task.objective`, the `profile` object of an entry of `feedback.attempts`, a value of the top-level `ext`); the `ext` of an embedded record is **not** free (its values are strings or integers). Recommended technique (the one of `hilclaw.run_state.parse`): a second pass over the text that keeps integer literals as text, walked everywhere but below the three free places. **Inside the three free places `-0`, `-0.0`, a fraction, an exponent and an integer above 2^53 - 1 are accepted**: the record adds no rule for a number there beyond the grammar of JSON. What Python makes of such a literal (`1e999` becomes `inf`; a literal longer than the interpreter's digit limit cannot be converted) is this module's convention: choose, state it in the docstring as a convention and not as a rule of the record, and test it.
- **Another version, set apart.** A content that is one JSON object without a repeated name and whose `schema_version` is an *integer* (exactly `int`, 0 to 2^53 - 1, not spelt `-0`) other than 1 raises a class that is **not** the invalid one (recommended: `UnsupportedVersionError(Exception)` of the new module, as `hilclaw.instance` and `hilclaw.run_state` each have one), before any other member is looked at. Its docstring does not call such a file damaged and does not say how it is read (OD-11). A `schema_version` that is no *integer* (`"1"`, `1.0`, `true`, `null`, `-1`, `-0`, 2^53, absent) is invalid.
- The written form (LF line ends, a final line feed) is **not** checked by this function: it binds the writer, and "a reader accepts any JSON text of this shape". Any white space of JSON, any member order, CR LF line ends and a missing final line feed are accepted.
- Recommended order of the checks: type, byte order mark, decoding and parsing (with the repeated-name hook), the top level is an object, the version case, `validate`, the `-0` walk. State the order in the module docstring and pin it with one test.

### The final name of a content (decision 3) - recommended name `final_name(data_root, document)`
- Returns the `pathlib.Path` that `hilclaw.layout.attempt_artefact(data_root, id.run_id, id.round, id.candidate, id.attempt, "spec.json")` builds for the `id` of `document`. Pure: nothing is read, created, resolved or checked on disk; `data_root` is used as given.
- **A valid document whose `id.run_id` is no run directory name has no path**: the function raises (recommended: `hilclaw.layout.InvalidPathValueError` passed through, or a class of the module that says "no path" - your choice, one line of reason) and returns nothing. Such a document stays valid for `parse` and for `validate`: **`parse` does not refuse it.**
- Whether the function validates the document itself or requires one that `parse` returned is your choice; say which in the docstring. A document that is no valid spec must not yield a path by an unchecked member (for example `id.round` as `True` or as `"3"`): either it is validated first or `layout` refuses it - pin the behaviour with tests.
- **No function takes a path and a content and reports whether they agree, and none opens a file** (Out of Scope). The comparison of decision 3 is `final_name(...) == path` for whoever holds both.
