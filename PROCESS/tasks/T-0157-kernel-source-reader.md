### Fixed by the records (not re-decided; implement exactly)
1. **Admitted name** (N1, N2): a name is admitted when it matches **in full** `[a-z0-9][a-z0-9_-]{0,61}\.[ch]` and the part before the dot is none of `con`, `prn`, `aux`, `nul`, `com1` to `com9`, `lpt1` to `lpt9` (22 stems). "In full" excludes a trailing newline (`"a.c\n"` is not admitted). `com0.c`, `lpt0.h`, `cons.c` are admitted.
2. **R1**: the reader starts from the path of the `output/` of an attempt. It lists the attempt directory (the parent of that path) and looks for the entry whose name **exactly as listed** is `output` (no case folding, no normalisation) and that is itself a directory (a symbolic link is not, whatever it points to). No attempt directory, an attempt path that is not a directory, no such entry, or an entry `output` that is not itself a directory: **no kernel source**. An entry listed as `Output` is not the `output/` on any file system - the reader must not find the directory by a path lookup alone.
3. **R2, R5, R6**: the kernel files are the entries directly below `output/` that are themselves regular files (a symbolic link is not) and whose listed name is admitted. Nothing below a sub-directory is looked at. No file is opened, read, executed or stat-ed for its size.
4. **R3, R4**: the compiled set is the kernel files whose name ends in `.c`, in ascending order of their names compared byte by byte (`a-b.c` < `a.c` < `a0.c` < `a_b.c`). "This attempt has a kernel source" means exactly: the compiled set is not empty. Headers (`.h`) are never in it.
5. **R7**: no bound on number or size: 17 or 1,000 admitted files, or a file above 262,144 bytes, are read like any other.
6. **R8**: a directory that exists and cannot be listed (the attempt directory or `output/`), or an entry of either whose kind cannot be determined, is **a failure of the reader**: a third outcome, never "no kernel source" and never passed over. Read it as T-0155 note (2) does: the reader determines the kind of every entry it lists in both directories.
7. **The same answer on every machine of C-7**: nothing depends on the order of a directory listing, on the case sensitivity of the file system or on a normalisation.

### Left to this task (Python form only; decide, say it in the module docstring as a convention of the module, test it, and list each choice in `## Result`)

Suggested, not required: a `NamedTuple` answer with the tuple of paths and a member that is `None` or one of three strings, and for (iii) an exception class of the module (a subclass of `OSError` or of `Exception`, your choice) with such a member and the original error as `__cause__`. The paths of the compiled set are `pathlib.Path` values formed as the given path joined with the listed name; the given path is used as it is (not resolved, not made absolute), as `hilclaw/layout.py` does.

- **Conventions chosen under "Left to this task".**
  1. The three outcomes: a returned `KernelSource` for (i) and (ii), an exception for (iii), as the planner suggested. The exception is a subclass of `Exception` and not of `OSError`, so that a caller's `except OSError` does not take it for something else; its text holds no path, entry name or system text, so a later operation cannot leak one by printing it (ADR-0056 decision 6, "The message").
  2. The argument: a `str` or an `os.PathLike` whose `os.fspath` is exactly a `str`, held as `pathlib.Path` holds it (not resolved, not made absolute; a trailing separator and `.` components dropped). Another type, a NUL character, or a last component that is not exactly `output` raises `InvalidOutputPathError` before anything is looked at - the planner's reading, confirmed by the reviewer in both rounds.
  3. An attempt directory that is a symbolic link to a directory counts as a directory: the reader cannot tell it from a link in any component above it (a data root below a linked home or temporary directory), and R1 denies a link only for the entry `output`, R2 for a kernel file.
  4. `is_admitted_name` answers `False` for a value that is not exactly a `str` (a `str` subclass included) and raises nothing.
  5. Also a convention: at the listing of the attempt path only `FileNotFoundError` and `NotADirectoryError` are "no kernel source" (`no_attempt_directory`); every other `OSError` there, every `OSError` of the listing of `output/` (also "gone since the first listing") and every `OSError` of `os.lstat` on a listed entry is a failure. The kind of every listed entry of both directories is determined before any name is filtered. The module uses `os.listdir` and `os.lstat` only; `os.scandir` was not used because `DirEntry.is_dir` swallows a `FileNotFoundError`, which R8 does not allow to be passed over.
- **Situations R1 to R8 do not cover** (registered, not decided):
  - On native Windows a directory junction named `output` is reported by `os.lstat` as a directory and is taken for the `output/` (reviewer, round 1; seen on the development machine). Native Windows is not a machine of C-7 (Windows is used with WSL), so nothing was changed.
  - The two listings and the questions for kinds are separate system calls: an `output` replaced between its `lstat` and its listing is followed. The docstring says so.
  - A path with a lone surrogate is answered `no_attempt_directory` on Windows and is expected to leave `os.listdir` as a `UnicodeEncodeError` on POSIX (reviewer, round 2; not run). It cannot be reached through `hilclaw.layout.attempt_artefact` with a data root that came from the system.
  - An error that leaves open whether the attempt directory exists (a parent that cannot be traversed) is answered as `attempt_directory_unlistable`.
