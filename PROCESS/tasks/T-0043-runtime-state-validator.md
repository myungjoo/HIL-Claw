### Capabilities (provisional names and shapes; each must exist and every public name must be tested)
1. **Validity of a file content** — from the `bytes` of a file, the list of decision 6, in this order of concern:
   - not UTF-8, or a byte order mark → invalid; not exactly one JSON text that is an object (empty content, white space only, an array, a scalar, two texts, trailing bytes that are not white space, `NaN` / `Infinity` tokens) → invalid; a member name twice **in any object of the file**, also inside a member this record does not define → invalid;
   - `schema_version` missing or not an *integer* (exactly `int`, 0 to `keys.MAX_INTEGER`; `true`, `1.0`, `"1"`, `-1`, 2^53 refused) → invalid; an *integer* other than `1` → **unsupported version**, a distinct error that is not invalidity, raised **before any other member is looked at** (the text rules above still come first);
   - at version 1: `round` and `budget_spent` required; `round` an *integer*; `budget_spent` an object with **exactly** `totals`, `position`, `open_steps`;
   - `totals`: an object, possibly empty, from an axis *name* to a non-negative integer **of any size** (exactly `int`; a value above `keys.MAX_INTEGER` is valid; `true`, a float, a negative number, a string, `null` refused);
   - `position`: an *integer* — a value above `keys.MAX_INTEGER` is an **error in the stored form**, although `journal.SpendView` accepts it in memory (T-0042 reviewer note);
   - `open_steps`: an array, possibly empty, of identity objects: `step` (a *name*) and `execution` (an *integer* ≥ 1) required; `round` (≥ 0), `candidate` (≥ 1, only with `round`), `attempt` (≥ 1, only with `candidate`) optional; no other member; no member holds `null`; **no identity twice** (two objects with the same members and values, whatever their member order);
   - any order of members, of axes and of open steps is accepted, and so are CR LF line ends, a missing final line feed and any white space JSON allows: the written form binds the writer only;
   - a top-level member this record does not define is **not interpreted and not an error**, whatever its value.
   The error names the place and the rule (for example `budget_spent.open_steps[2].candidate`). Recommended: one error type for invalidity (a `ValueError`) and a distinct one for the unsupported version; whether the latter is `events.UnsupportedVersionError` or the module's own — choose and say.
   Also offer the same check for an **already parsed document** (a `dict`, as `artifacts.validate` and `events.validate` do), for a caller that built the value in memory; say what the text-level rules (encoding, repeated names) mean for it — they cannot be checked there.
2. **What the reader gets** — for a valid content: `round`, the spend view as a `hilclaw.journal.SpendView` (`totals` a mapping, `position` unchanged, `open_steps` a set of `journal.Identity` with an absent number as `None`), and the top-level members this record does not define, uninterpreted. Recommended: one named tuple. For an invalid content nothing is returned: "the reader … uses no member of the file and repairs nothing".
3. **Conversion both ways** between the stored `budget_spent` object and `journal.SpendView`, usable without a whole file. From a view to the stored object: a malformed view is an argument error (the checks of `journal` — `journal.fold((), view)` is a public way to run them); a view whose `position` is above `keys.MAX_INTEGER` is refused, not capped; a total of any size is carried exactly.
4. **The written form** — from `round`, a view and (recommended) the further top-level members the caller gives, the `bytes` of the file by decisions 2 and 4: UTF-8, LF line ends, a final line feed; `schema_version`, `round`, `budget_spent`, then the others; inside `budget_spent` `totals`, `position`, `open_steps`; the axes in ascending order of their names; the open steps in ascending order of `round`, `candidate`, `attempt`, `step` (by code point), `execution`, **an absent number before every present one**; inside an identity object `round`, `candidate`, `attempt`, `step`, `execution`, absent numbers left out. The exact white space and the order of the other members are the writer's: choose one, the same on every call, and say why (decision 2 names line-wise diffs, NFR-2). The defining properties, which the tests must show: the bytes are a function of the values (two equal views built in different orders give the same bytes); the output is accepted by capability 1 and reads back to the same `round`, view and other members; both files of the Example of ADR-0012 read to the values this function is given to write them.
   Further members given by the caller must be a strict JSON object (`tools.check_json_object` can check it) and must not hold one of the three names of this record; they are written and never interpreted.

### Cases ADR-0012 leaves unsaid — choose, implement, test and list each with one line of reason
- **An integer too long for the interpreter** (CPython refuses a decimal text above 4300 digits by default): decision 4 says "a reader that cannot represent it reports an error and does not round". Recommended: reported as an error of the module, never truncated, the limit left as the interpreter has it; the same on the way out (a total too long to print).
- **`-0`, `1.0`, `1e0` where an integer is required**: a float is not an integer (as in `hilclaw.events`). For a total, decision 4 says "written in decimal digits without sign, fraction or exponent": say whether `-0` is refused as a total (the JSON parser of the standard library returns `0` for it; `parse_int` sees the text) and what holds for `round`, `position` and the numbers of an identity, for which the record states no written form. If you read this as needing a record, BLOCKED with the question.
- A number beyond the float range, or a value nested too deeply to parse, **inside a member this record does not define**: recommended as `hilclaw.events` has it (an infinity as the parser gives it; nesting the interpreter cannot parse is reported as invalid). Say which.
- White space and line ends before and after the JSON text; a content of white space only.
- `schema_version` that is an *integer* other than `1` in a file whose other members are broken → unsupported version (nothing else is interpreted). `schema_version` `0`.
- The type accepted for the content (`bytes` only, or also `bytearray` / `memoryview`; a `str` is refused, since the encoding is part of validity) and the argument errors of the written form (`round` not an *integer*, a view of another type, other members that are not a strict JSON object or that repeat one of the three names).
- An axis with total `0` (kept: decision 4), an empty `totals` and an empty `open_steps` (always written).
- Which error a broken identity object raises: `journal.step_identity` raises `JournalError` or `events.InvalidEventError`; recommended to turn both into the module's error with the place in front.
- Anything else you meet. If you read one as a rule about another member of the file, about a missing file, about what a writer keeps, or as a change of what ADR-0012 accepts, return BLOCKED with the exact question.
