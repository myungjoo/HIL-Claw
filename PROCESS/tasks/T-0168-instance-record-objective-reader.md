## Why
ADR-0053 (T-0152, landed as `3cc7284`) fixed the member of `runs/<run_id>/instance.json` in which a run states its objectives and its constraints: the top-level member `objective`. Its Consequences name one code slice:

> in `hilclaw/instance.py`, the validity of the member by decision 4 and a reader of the target of a run beside `draws_of`, with tests in `tests/test_instance.py`. The names, the return form and how "not stated" is told from a value are the code task's. Whether the checks are shared with `hilclaw/spec.py` or repeated is the code task's too

**This task is that slice.** Today `hilclaw/instance.py` defines twelve members; a top-level `objective` of any value - `null`, `""`, `"latency_minimisation"` included - is handed back uninterpreted in `Instance.others`, the file counts as valid, and nothing in the package can answer "which target does this run state". By ADR-0053 such files are invalid, and two existing test cases assert the opposite (see "Existing cases that change").

It serves PLAN P1-8 (the instance record) and is a precondition of what PLAN P2-2 needs (a spec's `task.objective` is "copied from the instance record"). It ticks **no PLAN checkbox**: P1-8 stays open.

### The validity of the member (ADR-0053 decision 4; ADR-0050 checks 1 to 3)
- `objective` joins the members the module defines (`_DEFINED`), so it is no longer handed back in `others`.
- **A present member is valid exactly when** it is an object with exactly the members `objectives` and `constraints`; `objectives` is an array of exactly one entry; that entry is an object with exactly the member `type`; `type` is the name `latency_minimisation`; `constraints` is an array and it is empty. **So one value is valid today**: `{"objectives": [{"type": "latency_minimisation"}], "constraints": []}` (any order of the two members, any white space of JSON).
- **Nothing else is a value**: `null`, `true`, `false`, a number, a string (`"latency_minimisation"` included), an array, `{}`, an object that lacks `objectives` or `constraints` or holds a third member, an `objectives` or a `constraints` that is no array, an `objectives` that is empty or holds two or more entries, an entry that is no object or holds `weight`, `priority`, `direction` or any member besides `type`, a `type` that is no string or is any other name (`throughput_maximisation`, `memory_ceiling`, `Latency_Minimisation`, `""`), and **a `constraints` that holds any entry - `{"type": "memory_ceiling", "bound": 123456789}` included** (decision 4: not admitted here because not admitted there). Check 4 of ADR-0050 (the form of a constraint entry) is **not** made: every entry is refused whatever its form, as `hilclaw/spec.py` does.
- A present and invalid member raises `InvalidInstanceError` naming the place (recommended places: `objective`, `objective.objectives`, `objective.objectives[0]`, `objective.objectives[0].type`, `objective.constraints`, in the manner of the module's other messages; the first rule found broken is reported); nothing is returned, so no member of that content is used, and nothing is repaired.
- The member is checked after `draws` (the order in which the records defined the members). Another `schema_version` is still `UnsupportedVersionError` before the member is looked at. The text rules (a member name twice **in any object, the inner ones included**, an integer too long for the interpreter) stay text rules.
- **A content without the member is valid and states no objective and no set of constraints**: the field is `None`. **No value stands in - not `latency_minimisation`, not the one valid value, not an empty set of constraints, nothing taken from a spec, from another member or from another run** (decision 5). No function of the module has a default argument and no named tuple of the module has a field default.
- The admitted type name is held by the module as what makes a member valid, never as a value handed out for an absent member. The module does not import `hilclaw.spec` or `hilclaw.spec_file` and uses no private name of another module.
- **The written form of a `bound`** (decision 4, last bullet) binds nothing today and is **not implemented**: no valid file holds a `bound`.
