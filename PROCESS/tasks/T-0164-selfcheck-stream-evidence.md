## Acceptance Criteria
### Fixed by the record and by the code on `main` (not re-decided; implement exactly)
1. **Pure.** The module reads values handed in: the bytes of the session's standard output, the two tokens, and (for the second function) how the process ended. It opens no file, starts no process, reads no environment variable, clock or configuration, keeps no state and prints nothing. The same input gives the same value.
2. **The stream is "newline-delimited JSON"** (K8). Each line is read on its own; a line that is not one JSON object establishes nothing and is not an error. The function never raises for the content of the output: truncated output (the time limit cuts it), an empty output, binary noise and a line of any length give a value.
3. **The session side is read from the `system/init` event and from nowhere else** (line 113): the server `hilclaw` among `mcp_servers` ("each with `name` and `status`") with its `status` word, `mcp_server_errors` ("The key is omitted when there are no errors"), and the tool names.
4. **The two session-side tool names** are `mcp__hilclaw__selfcheck_token` and `mcp__hilclaw__selfcheck_fail` (line 100), built from the server name `hilclaw` and the public `selfcheck_wire.TOKEN_TOOL_NAME` / `FAIL_TOOL_NAME`, not spelt a second time. The server name is a public constant of this module (the session slice writes the configuration file under it). A tool is "listed" only when its exact name is there.
5. **The model side is the final response text of the `result` message and nothing else** (lines 106, 129): "The tokens are looked for in the model's own text only ... **never in an event that carries a tool result, and never in the session's output as a whole**". A token that stands anywhere else in the output - another event, another member of the `result` message, a line that is not the `result` message - is not found. "The last line of the stream is a `result` message" (K8).
6. **The status word never widens**: only the exact `selfcheck_outcome.CONNECTED` reads as connected and only a word of `selfcheck_outcome.REFUSED_STATUS_WORDS` as refusing; both are taken from that module, not spelt again.
7. **The built `SessionEvidence` is one `selfcheck_outcome.decide` accepts**: every yes-or-no member exactly `True` or `False`, `exit_status` an `int` or `None`. With a stream written as K8 and K9 describe a passing session (and the passing wire facts), `decide` gives `passed`; nothing else of this module's making gives it.
8. **Nothing existing changes**: no existing module is edited and no private name (a leading `_`) of another module is imported.

### The names of Claude Code's output (the core of this task)
Every name of a member, and every discriminating value, that the module reads from the session's output is **one named module constant**, used through that constant only. The module docstring holds a short table of them with the standing of each, in the record's own three words:
- **verified** (on a page, K8; never tried): `mcp_servers`, its `name` and `status`, `mcp_server_errors` and that the key is omitted when there are no errors, that the last line is a `result` message, that the stream is one JSON value per line;
- **observed once** (K9, T-0106; one session that never reached the model): that the init event has a member `tools` listing the session-side names, that the server reads `connected`;
- **not verified** (on no page read, K8): how an event says that it is the `system/init` event and how a line says that it is the `result` message; the form of an entry of `mcp_server_errors`; the form of `tools` (taken as an array of strings); **which member of the `result` message holds the final response text**; whether `status` ever takes the word `failed`.

For each "not verified" name the executor takes a provisional value (planner's suggestion, not required and not asserted: the pair `type`/`subtype` with `system`/`init`, `type` with `result`, and the member `result` for the text) and the docstring says, once, that these are provisional, that they are runtime acceptance item (v) of ADR-0054, and what a wrong one costs. **The cost must be the safe one, and the tests show it**: a stream that uses another name for any of them yields no `init_read`, no `result_read`, no listed tool or no token - so `session_failed` or `no_call`, **never `passed` and never `front_refused` (b)**. Do not write, in code, docstring, test name, commit or PR text, that any of these is how Claude Code behaves; do not consult a live `claude` for them (D16) and do not cite memory of its output as a source.

### Left to this task (decide, say each in the module docstring as a convention, test it, list each choice in `## Result`)
- **The public names.** Planner's suggestion, not required: `read(output, *, token, fail_token) -> StreamFacts`; `evidence(facts, *, timed_out, exit_status) -> SessionEvidence` (a started session; "no session was started" stays `SessionEvidence()`, which the caller makes); `SERVER_NAME = "hilclaw"`; `TOKEN_TOOL_SESSION_NAME`, `FAIL_TOOL_SESSION_NAME`; `OTHER_STATUS`.
- **What `StreamFacts` carries**: the nine members of `SessionEvidence` that come from the output (`init_read`, `server_status`, `server_in_errors`, `any_config_error`, the two `..._tool_listed`, `result_read`, the two `..._in_reply`) and, for the report slice (decision 7, "the tool names of the `system/init` event that begin with `mcp__hilclaw__`"), those names **bounded** as line 138 says: a name leaves the module only when it is short and of letters, digits, `.`, `_` and `-`, else the word `selfcheck_wire.OTHER`; at most `selfcheck_wire.MAX_LISTED` of them with a flag that more were seen; the length is `selfcheck_wire.MAX_STRING`. Nothing else: no line, no fragment, no reply text, no token, no model name, no path.
- **How a line is read as one JSON object.** Planner's reading: as `selfcheck_login` reads the status output - strict UTF-8, strict JSON, no `NaN`/`Infinity`, a member name given twice has no single answer, nesting too deep is no object; `\n` ends a line and a `\r` before it and white space around the object are allowed; a blank line is nothing.
- **Which event is "the" `system/init` event** when the stream holds more than one. Planner's reading: the first. Weigh the other reading (more than one is an output the check cannot read) and say which was taken and why. No reading may make `passed` easier than a stream with one event does.
- **Which line is "the" `result` message.** Planner's reading: the last line of the output that is not blank, when it is a `result` message; a `result` message that is followed by another line is not it, and an output cut before its last line has none. The text is read only when that member is a string.
- **The status word that is carried.** Planner's reading: `CONNECTED`, a word of the refusing list, `None` when no entry of `mcp_servers` names the server, and **one fixed stand-in for every other value** - a word outside both, a non-string, `"Connected"`, `" connected"` - so that no string the `claude` program chose leaves the module (L6). `mcp_servers` that is no array, or an entry that is no object or has no string `name`, names nothing.
- **The server named more than once in `mcp_servers`.** The record does not say. Planner's constraint, to the safe side: such a stream is neither connected nor a ground for `front_refused` (b) - the stand-in above.
- **`mcp_server_errors`, whose entry form is on no page.** Planner's reading, to the safe side: the key present with any value other than an empty array sets `any_config_error`; and, since the configuration file of the check names one server only (decision 4) and nothing says how an entry names its server, the same sets `server_in_errors`. The executor may instead look for the server name in an entry if it says what form it assumes and marks it "not verified". **Constraint either way: no stream that holds a non-empty `mcp_server_errors` reads as `passed`, and none in which an entry may concern `hilclaw` reads as `front_refused` (b).** Say in `## Result` that with the first reading the two members always agree, so the corner T-0163 left for the record (an entry for another server) cannot arise from this reader.
- **How a token is looked for.** Planner's reading: as an exact substring of the reply text; no case folding, no trimming, no decoding of escapes beyond what JSON did. A token is of the form `selfcheck_server` accepts (32 lowercase hexadecimal characters, the two different); another form is refused before anything is read.
- **What the functions raise.** `TypeError` / `ValueError` with a fixed text that holds nothing of the argument: an `output` that is not `bytes`, a token of another type or form, two equal tokens; for the second function a `facts` of another type, a `timed_out` that is not exactly a `bool`, an `exit_status` that is neither `None` nor an `int` (`True` is none). **No default and no exception yields a listed tool, a token in the reply or a connected server.**
- **A time limit together with an exit status** (contradicting arguments of the second function). Planner's reading: handed on as given; `decide` does not cross-check either.
- Nothing else.
