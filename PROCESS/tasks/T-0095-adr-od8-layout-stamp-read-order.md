## Why
PLAN P1-8 ("런타임 STATE/instance/events 스키마 - OD-8 종결 필요(§9 ADR 경로)") is open, and so is PLAN P1-1 (the tool contracts). One registered question stands between the two and waits on nobody: **OD-8 sub-question 22, part (i)**.

- ADR-0004 decision 9: "The path `runs/<run_id>/instance.json` is the same in every layout version: a reader finds the version there before it uses any other path of the run."
- ADR-0024 fixed how the file states the layout version (the stamp follows from `schema_version`; a valid version 1 file states layout version 1) and observed (decision 5): "The code of today does not read the file first: `hilclaw/layout.py` builds the paths of a run without reading any file, and a call of a journaled HW tool does its lookup before the selection reads `instance.json` ..., a lookup that reads `STATE.json` and `events.ndjson` ...; a call answered in the lookup does not read `instance.json` for the hw_profile at all ... **This record changes no order of any call and decides nothing for a tool.** Whether the sentence of ADR-0004 binds the order in which a reader uses the files of a run is not decided (sub-question 22, first part)." Its Alternatives row for point 5 set the binding rule aside as "a rule for the order of a call, which is the contract of a tool (ADR-0016 decision 2); registered as sub-question 22".
- ADR-0018 decision 4: "A call answered in the lookup ... does not read it for the hw_profile ... Whether a call reads the file for another member, such as the layout version stamp (ADR-0004 decision 9, OD-11), is the record of that member."
- So an accepted record holds a sentence about every reader, the landed code does something else, and two later records each say that the answer belongs to a further record. `hilclaw.instance.layout_version_of` (T-0081) exists and "is bound to no tool". Nothing says whether the frame of a tool call has to change, so every later slice that reads a run (the rest of P1-1, the start of an instance, P2-1) would be written against an open order.

DRIVER §6: a task that needs a design-level decision carries the record that closes it. **This task writes that record.** It ticks **no PLAN checkbox** (P1-8 and P1-1 stay open). What it enables: either the statement that the frame of a call stands as it is, or one small code slice (Follow-ups).
