## Why

**PLAN P3-17** (D31 ③) asks to show that the C kernel path of `cpu_standin` (build, correctness, measurement) runs on the owner's LAN aarch64 machine (a Raspberry Pi 5), and to check the per-key separation of its records (ADR-0001), since the same target on another machine gives another hw_profile. T-0567 (PR #381, ADR-0204) landed the means of reaching the machine: `hilclaw/remote_run.py` (ssh, destination in `HILCLAW_AARCH64_SSH`, per-task remote directory `hilclaw-driver/T-NNNN/`, `put`/`get`) and `hilclaw.toolchain_check.remote_check`. ADR-0204 decision 9 put the compiler question to the owner as HQ-0101. **The owner answered (b)** ([#5 comment 6858780049](https://github.com/myungjoo/HIL-Claw/issues/5#issuecomment-6858780049), recorded in `PROCESS/STATE.json` HQ-0101 `decision`; PLAN P3-17; DRIVER §6 D31 ③): pulling and building on that machine the container images this demonstration needs is allowed, including the base image a build pulls and the packages put into the image. (a) and (c) were not taken: nothing is installed on the host, the host's gcc does not stand in for clang, and #5 A-7, ADR-0035 decision 3 and ADR-0144 decisions 4 and 5 stay as they are. Host packages and any other download stay on the D29 request path (an HQ).

This task is that next step, as one feature (D20 ①, ③): the §9 ADR that records the answer and decides how the demonstration is carried out, the arm64 image built on the machine, the small driver-side code that runs the evaluation there and brings its records back, and the real demonstration. It is one task, not split, because the demonstration's form depends on the ADR's choices (D20 ④ forbids pre-creating a task whose content depends on an unlanded decision). Expected size about 560 lines including the ADR, near the D30 recommendation.

**The path to show is the existing given-code evaluation**, `python -m hilclaw.given_eval <request> <c-file>` (ADR-0200 decision 5, ADR-0202 decision 2): one fresh run with round 0 only — instance start, `key.store`, placement, `correctness.check` at `sim` and `board`, `board.run`, `round.end`, `run.commit` — starting no `claude`. Each build and process runs in a container of the image `HILCLAW_STANDIN_IMAGE` names (ADR-0144, ADR-0186, ADR-0188).

**Two facts the ADR must settle first** (expected from the records; the executor confirms them read-only before writing code):

1. **Where the package runs.** #5 B-2 (owner; ADR-0204 Boundaries) keeps "a `board.run` or `sim.run` over the network" for the owner. The reading this task proposes is that the package itself runs **on that machine** — a snapshot of the checkout's `HEAD` copied into the remote task directory, run there with the machine's Python 3.11.2 against a data root in the same directory — so every tool call stays local to that machine, as on any C-7 machine, and no tool reaches across the network. The package needs `numpy` (`pyproject.toml`; `hilclaw.standin_check` imports it). Whether the machine's Python has a usable `numpy` is not known. Installing it on the host, or downloading it into a user directory, is not covered by HQ-0101 (b). If it is absent, the ADR weighs the forms below and does not download anything outside an image. It may choose a form that HQ-0101 (b) covers. Otherwise it writes an HQ.
2. **The `host.cpu` value of that machine.** ADR-0035 decision 2's rule for Linux reads the first `model name` line of `/proc/cpuinfo`. Its line 96 says a machine without one yields **no record and nothing substituted**, and its line 99 notes that some ARM systems have no such line. An arm64 Raspberry Pi 5 kernel is expected to have none. Then no hw_profile can be written for the request by ADR-0035's rules. The ADR judges whether a reading rule for Linux without a `model name` line is the driver's to add under §9 (a source rule for a case ADR-0035 left without a value, keeping the member and its meaning, "the model name the operating system reports for the processor") or an owner question under D23 (a changed meaning of a value). If it is the owner's, it writes an HQ with the concrete forms (criterion 2).

**Brake (D31 ②).** This is the PLAN item's own work. Do not harden existing paths beyond what the demonstration needs.

**Open HQs (D27 ⑦).** Do not ask again or anticipate HQ-0096 (P3-16) or HQ-0100 (nightly environment). If an owner-only part appears (numpy on the host, the `host.cpu` rule under D23, committing a concrete image recipe for the runtime, #5 B-2), write it in `## Result` as an HQ in the DRIVER §8 structure (Korean; issue, options (a)/(b)… with the recommendation, what it blocks and what it does not). Land the rest and return `DONE` (D27 ⑥).
