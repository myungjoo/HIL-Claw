## Why
PLAN P1-1 (the FR-10 tool contracts, the mock backend, the conformance tests) is open. For `correctness.check` the code on `main` is a row of pure modules bound to no tool. Two of them stand on either side of a gap:

- `hilclaw.check_admission.admit` (T-0144) gives the four answers between the selection of the backend and the start line and hands out an `Admitted` (`m`, `k`, `n`, `draws`, `rtol`, `atol`). It draws no seed.
- `hilclaw.check_ending.carry_out(operation, request, hw_profile, parameters, *, rtol, atol)` (T-0141) calls an operation once and returns the result or raises `EndedWithoutOutcome`. It is handed a finished `hilclaw.check_parameters.CheckParameters(seed, draws, m, k, n)`.

**Nothing in the package renders what lies between them**: the draw of the seed and the building of the check parameters. Until 2026-10-13 that could not be cut, because no record said where the draw lies relative to the start line or what a call answers when no seed can be had. ADR-0048 (T-0145, `main` `7e27ac6`) now fixes both:

- the tool function draws the seed **before it appends the start line**, after the last answer of moment 4 (decision 3);
- a call that reaches the draw asks the source once, and no value stands in for a seed (decision 3);
- a draw that yields no seed - the source raises an error, or returns something that is no seed - is a tool failure of the tool's own kind **`seed_not_drawn`**, answered alike for both cases (decisions 4 and 5);
- its message says that the draw yielded no seed and which of the two cases it was, may say of which kind the returned value or the raised error was, and carries nothing a source returned and nothing of what a source raised; the tool function does not hand the error of a source or its traceback on as its answer (decision 6);
- a raised request to end out of a source is not answered with this kind and passes through (decision 5).

Checked on 2026-10-13 at `main` `0873ca1`: the string `seed_not_drawn` occurs in no file of `hilclaw/` or `tests/`; no file under `hilclaw/` but `hilclaw/harness/__init__.py` (a docstring) names `seed_source`; no module builds a `CheckParameters` from an `Admitted`.

T-0145 `## Result`, Follow-ups, cut this slice: "The pure part of the step from a `check_admission.Admitted`, a seed source and an operation to a result or an ending: it can now stand ahead of the tool function. The draw belongs to the place before the start line, so the module is cut in two callables or the caller keeps the order: the draw (rendering `seed_not_drawn` from `SeedSourceError` without chaining what `draw` raised into the answer, and letting a `BaseException` that is no `Exception` pass) for `before_start`, and the step from a drawn seed through `check_parameters.CheckParameters` and `check_ending.carry_out`."

### Interface as landed (the tool function and the builder of T-0126 are written against this)
- Public names, and no other: `KIND_SEED_NOT_DRAWN`, `draw`, `check`.
- `KIND_SEED_NOT_DRAWN == "seed_not_drawn"` (ADR-0048 decision 5); the tool's own, not in `tools.RESERVED_KINDS`.
- `draw(source)` - one positional-or-keyword parameter, no default. For the place before the start line.
  - a seed (exactly an `int`, 0 <= seed < 2**64): the same object is returned; the source was asked exactly once, with no argument, through `seed_source.draw`.
  - the source raised an `Exception` (any class, a `ToolFailure` and a `SeedSourceError` included; a callable that needs an argument): exactly a `tools.ToolFailure` of kind `seed_not_drawn`, first-case message.
  - the source returned what is no seed (not exactly an `int`, or out of range): exactly a `tools.ToolFailure` of kind `seed_not_drawn`, second-case message.
  - a request to end (`BaseException` that is no `Exception`): not caught, the same object passes through.
  - a `source` that is not callable (`None` included): the module's own `TypeError("source: must be callable")`, raised before anything is asked; never `seed_not_drawn`. This is the line ADR-0048 Limits leaves to the code, stated in the docstring as the module's own choice.

Neither the wording of `SeedSourceError` nor its chaining is read.

No type name, no value, no digit. Nothing may depend on the wording.
  - What the answer holds: `args == (kind, message)`, `error_object()` those two; `__cause__` is `None`; `__context__` is `None` outside a handler of the caller; the frame of `draw` holds `source`, the callable, a `bool` and the message - not the error of the source, not the `SeedSourceError`, not a returned value. Nothing is written, printed or kept.
