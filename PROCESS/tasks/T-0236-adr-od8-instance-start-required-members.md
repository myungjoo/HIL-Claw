## Why

PLAN P1-8 ("런타임 STATE/instance/events 스키마(#4 §4) - **OD-8 종결 필요(§9 ADR 경로)**") is open, and the OD-8 register row names as residue "무엇이 언제 run의 파일을 쓰고 instance의 시작이 무엇을 확인하는지". Every `instance.json` member record since ADR-0020 has left the same question open in the same words: the file stays valid without its member ("A valid file is 'not thereby enough to start a run'", cited by ADR-0031 from ADR-0018 decision 2), and **whether the start of the instance refuses to begin without the member** is a registered sub-question of OD-8: ⑲ (tolerance, ADR-0020), ㉑ (`n_max` and the default 10 of ADR-0007 decision 8, ADR-0023), ㉕ (가) (N, ADR-0028), ㉘ (가) (op_signature, ADR-0031), ㉜ (`draws`, ADR-0046), ㉞ (가) (objective, ADR-0053). **Planner's judgements (the reviewer is asked to re-check each):**
- **Authority (DRIVER §9).** OD-8 is design-level and not owner-only; P1-8 carries "OD-8 종결 필요(§9 ADR 경로)". The members this record may require at start each rest on a source that already says the instance has them: **tolerance** - owner, HQ-0004 answer (3): "none - an instance must state both" (https://github.com/myungjoo/HIL-Claw/issues/5#issuecomment-6052377983); **objective** - FR-2 has the user state the target of each Loop instance (ADR-0053 decision 5 reads it so); **N** - owner, #5 A-9: "a Loop-instance parameter chosen by the user at instance start" (ADR-0028 Context); **op_signature** - UC-1 step 1 (the model / kernel is given at start) and FR-13's key; **draws** - ADR-0046 decision 2 (i): "Whoever starts the instance states the number, once for the run"; **`n_max`** - ADR-0007 decision 8: per instance, "default 10", the value "is then part of what the instance was started with and is recorded with it". Requiring them at the start therefore invents no requirement; it decides *where* the check sits and *what a refusal is*.
- **Not the writer component.** Who performs "the start of the instance" (ADR-0004's role) is OD-23 (`논의중`). The record speaks of the role, as ADR-0072 decision 1 spoke of "the promotion step" and left the agent to OD-23. If the record cannot stand without naming a component, return BLOCKED (`requirement-unclear`).
- **Owner-only items stay out**: the N range and the initial-run cap (#5 A-9 "1 ≤ N ≤ 5" of the initial UI, #5 B-4 N = 1-2; ADR-0028 decisions 2-3 say neither is a validity rule) - not applied, named in Boundaries; the objective menu and combination rule (#5 A-4, OD-1 residue) - not touched; gates (OD-3).
- **`n_max` is the one member where "refuse" and "fill in the default" both have grounds**: ADR-0007 decision 8 gives a default that becomes "part of what the instance was started with"; ADR-0023 rejected reading an *absent* member as the default (its alternatives row 4) and ADR-0025 decision 2 says the *write* fills in nothing (not the 10). Neither forbids the *start* from putting 10 into the content before the write. Decide it with both alternatives weighed; whichever is chosen, the value 10 is cited from ADR-0007, never restated as a new constant.
- **`draws` has no default in any record** (ADR-0046 decision 3 gives none; ADR-0017 decision 9 gives "≥ 1" only). Do not invent one: if a source for a default is not found, refusing is the only choice that invents nothing.
