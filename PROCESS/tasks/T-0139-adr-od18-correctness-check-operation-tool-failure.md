## Why
PLAN P1-1 (the FR-10 tool contracts, the mock backend, the conformance tests) is open. For `correctness.check` the landed records are ADR-0021 (the split, the seed, the tolerance), ADR-0038 (the execution points), ADR-0040 (the identity of a call), ADR-0041 (the dimensions), ADR-0042 (the members of a result), ADR-0043 (the form between the tool function and an operation), ADR-0044 (the mock's side), ADR-0045 (an answer of neither form) and ADR-0046 (where the number of draws comes from).

One path of a call that reaches the operation has no rule: **the operation raises a tool failure**. Every record since ADR-0021 passes it on:

- ADR-0021 decision 5 (line 84): "Which tool failure a backend may raise when it cannot carry out the experiment at all — a target that cannot be reached, a fault of a board — is not listed (OD-10, #5 B-2)."
- ADR-0040 decision 7 (line 104): "Which tool failures can stand as the `failure` of an end line of this tool — those a backend may raise — is a later slice's."
- ADR-0043 decision 6 (line 110): "What the tool function does with a tool failure an operation raises belongs to the slice that names those kinds."
- ADR-0045 Status limit (2), decision 4 (line 70: "What the tool function does with a tool failure an operation raises, this one included, is not decided") and decision 8 (line 103: "whether its step is ended with it, under which kind, with which message").
- ADR-0046 Consequences (line 204) still lists "the tool-failure kinds a backend may raise" among what the next slices must add.
- The code says the same of itself: `hilclaw/check_operation.py` lines 42-45 ("A `ToolFailure` an operation raises is handed on as the same object. That is no rule of a record"), and `hilclaw/journaled_step.py` lines 19-22 (a plain `ToolFailure` out of a step passes through and no end line is appended: the step stays open).

The tool function of `correctness.check` cannot be written without this rule, and ADR-0016 decision 5 (d) makes the mock's scripts express "each tool-failure kind the contract lets a backend raise", so the conformance tests of P1-1 wait on it too. **This task is the record for that one item** - the follow-up "(planner - document mode, later) the tool-failure kinds of a backend (OD-18 sub-question 10, third clause)" of T-0136, T-0137 and T-0138.

The task ticks **no PLAN checkbox**: P1-1 stays open, and the tool still cannot be registered after this record.
