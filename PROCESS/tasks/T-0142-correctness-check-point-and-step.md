### The module
Recommended public names, and no other: `MEMBER`, `SIM`, `BOARD`, `STEP_SIM`, `STEP_BOARD`, `STEPS`, `NUMBERS`, `check`, `step_of`.

- **`MEMBER`** - the string `"point"` (ADR-0040 decision 4). **`SIM`** and **`BOARD`** - the strings `"sim"` and `"board"`, the two values of that member.
- **`STEP_SIM`** and **`STEP_BOARD`** - the strings `"correctness_check_sim"` and `"correctness_check_board"` (ADR-0040 decision 3), each spelt or formed once in the package. **`STEPS`** - the `tuple` `(STEP_SIM, STEP_BOARD)`: the `step` values of this tool, stated once, for the builder that takes them when the tool function is built.
- **`NUMBERS`** - the `tuple` `("round", "candidate", "attempt")`: the numbers a request of this tool requires (ADR-0040 decision 5), in the form the two existing builders take as `numbers`.
- **`check(request)`** - the check of the member `point`, in the convention of the `check` parameter of `hilclaw.journaled_tool.tool_function`: it returns `None` or raises `hilclaw.tools.ToolFailure` of kind `tools.KIND_INVALID_REQUEST` with a message that starts with the name of the member.
  1. A request that has no member `point` is refused (ADR-0040 decision 4; Walk-through line 118).
  2. A request whose `point` is not exactly one of the two values is refused: **compared as it is, case-sensitive, nothing normalised** - `"Sim"`, `"BOARD"`, `" sim"`, `"sim "`, `"sim.run"`, `""`, `true`, `false`, `0`, `1`, `null`, a list and an object are each "another value".
  3. **No other member is looked at**: a request that carries, beside a valid `point`, the five frame members, a member no record names, or nothing else at all is not refused by this function. The docstring says that the member list of a request is open (ADR-0040 decision 5), that this is one part of the tool's own check and not the whole of it, and that the frame members are checked by the builder before it is called.
  4. This task's choices, to be stated in the docstring as the module's own and no rule of a record (recommended): a `request` whose type is not exactly `dict` is refused with the same kind (the frame check refuses it first in a tool function; this keeps the function total); a value whose type is not exactly `str` (an instance of a `str` subclass included) is "another value", and it is refused **without calling any code of the value** (no `==`, no `hash`, no `str()` / `repr()` of it), so an unhashable or hostile value gives the refusal and no other exception.
  5. The message: exactly a `str`, of bounded length, composed from constants of the module; it names the member and may name the two values the contract accepts; of the value given it shows at most the name of its type, never the value (a request may hold anything). Nothing may depend on its wording beyond the member name at its start; the docstring says so.
  - The request is not modified; nothing is kept between calls; no file, clock or random source is read.
- **`step_of(request)`** - the `step` of a call: `STEP_SIM` for a request whose `point` is `"sim"`, `STEP_BOARD` for `"board"`. For every request that `check` refuses it raises the same refusal (recommended: it carries out the same check first), so that **no value outside `STEPS` is ever returned** and no `KeyError` or `TypeError` comes out of it. It reads no member but `point`: two requests that differ in anything else have the same `step` (the identity is formed by the builder, not here).
