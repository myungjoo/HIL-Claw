## Why
ADR-0030 (landed as `1465b31`, T-0095) answered part (i) of sub-question 22 of OD-8 for the calls of its decision 1: a call of a tool whose tool function carries out the lookup of a journaled tool or the selection of a HW tool about a run **has the layout version stamp of that run before it uses any other path of it**. Its Consequences cut one code slice:

> **A code slice follows** (code mode; PLAN P1-1 and P1-8 stay open): the read of ⓢ in the path of a journaled tool and of a journaled HW tool, before the lookup, answered with the four kinds as the read of ④ is today (`hilclaw/run_files.py`). Where it is placed - `hilclaw/journaled_step.py`, the builders, or the part they share - and whether the reader of the stamp is a parameter like the reader of the hw_profile or `hilclaw.instance.layout_version_of` is the code task's. A journaled tool that selects no backend appends its two step lines in a run that has no `instance.json` at all, and both builders answer an ended or an open identity from the log whatever the state of that file. ### The rule (cited from ADR-0030; not this task's choice)
- **Which functions.** The function `hilclaw.journaled_tool.tool_function` returns and the function `hilclaw.hw_tool.tool_function` returns - the two builders of a tool function that exist.
- **The moment ⓢ**: after the data root was obtained (②, `hilclaw.data_root_source.obtain`, whose `no_data_root` passes through as today) and **before `STATE.json` or the log is opened** (③). A refused request (①) and `no_data_root` (②) are answered as today and read no file.
- **The read**: `runs/<run_id>/instance.json` of the data root of the call, as a whole, once in ⓢ, **at every call** (nothing is kept between calls). The call has the stamp exactly when the file is valid and its `schema_version` is `1` - what `hilclaw.instance.layout_version_of` returns without raising.
- **The answer when the stamp cannot be had**: a `hilclaw.tools.ToolFailure` of one of the four existing kinds, by the same rows and borders as the read of the selection today (`hilclaw.run_files.reading` with the mapping `hilclaw/hw_tool.py` holds in `_KINDS`): `run_file_missing` for `hilclaw.instance.MissingInstanceError` and for a `FileNotFoundError` or `NotADirectoryError` (a data root that is no existing directory at the read included); `run_file_invalid` for `InvalidInstanceError` (an empty file, a partial content, a member that breaks its rule, a path that is no regular file); `run_file_unsupported` for `UnsupportedVersionError`; `run_file_unreadable` for every other `OSError`. The failure is chained to the error it answers for; its message starts with `runs/<run_id>/instance.json` and does not hold the data root. **No kind is added and none changes its meaning.**
- **What such a call has done**: appended no line, opened neither `STATE.json` nor the log, not asked the reader of the hw_profile, selected and called no backend, not run the step. The same request again is answered as if the failed call had not been made.
- **For every identity**: a kind of ⓢ is answered whether the identity has no line, is ended or is open - the lookup is not carried out. An ended or an open identity of a run without a valid version 1 file is **no longer** answered from the log.
- **The order of the kinds one call can meet**: `invalid_request`; `no_data_root`; a situation of `instance.json` in ⓢ; a situation of ③; else the stored `result` or `failure`, or `step_open`; else, for an identity with no line, a situation of ④; then `no_backend`; then `not_offered`.
- **④ is unchanged**: the selection of `hilclaw.hw_tool` still asks its parameter `hw_profile_of`, once, for an identity with no line only, and answers what it raises as today. One read does not serve both moments.
- **The stamp is compared with nothing**: not with `hilclaw.layout.LAYOUT_VERSION`, which the changed modules do not read.
