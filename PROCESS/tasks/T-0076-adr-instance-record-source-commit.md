## Acceptance Criteria
What is **fixed** and taken as input, not re-decided:
- **Owner (#5 A-1 detail 3, A-12 point 4)**: `instance.json` records the commit hash of the source repository, as "도구 버전"; in P1 the version of the harness is that hash; it is the P1 implementation of the measurement-contract pin of OD-11 (confirmed part). Nothing else of OD-11 is confirmed.
- NFR-2 and NFR-7 ③: a result can be traced back to the tool version that produced it, and the record of the source commit in `instance.json` is the link between the two histories.
- ADR-0004: `runs/<run_id>/instance.json`, one per run, "What the instance was started with", written once, immutable; nothing enforces it. ADR-0018: the frame of the file (decision 2), the open top level of version 1 and **the rule of what raises `schema_version`**. ADR-0020: the member `tolerance`. Nothing is kept between calls (ADR-0010 decision 7).
- NFR-7 ①: components can be replaced at a round boundary; FR-6: a run can be resumed after the system version changed. Both are requirements as they stand; how they meet the pin is OD-11.

What the ADR **decides**. The content of each decision is the executor's to work out and justify from the fixed inputs; the reviewer's Approve confirms it. For every point give the choice, the alternatives considered and one or two lines of reason; mark each value as **cited** or as **this record's own**:
1. **Scope**: of `runs/<run_id>/instance.json`, the one member in which a run states the commit of the source repository it was started with; nothing else of the file and nothing of any other file. State that the file is still not a complete instance record.
2. **What the member states.** Which repository: the source repository in the sense of #5 A-1 ("소스 repo", the repository that holds the layer-2 package and the layer-1 definitions; not `HIL-Claw-data`, whose own commits are #5 A-3). Which commit: the one the instance was started with. Say exactly what a reader may conclude from the member and what it may not - in particular whether it is a statement about the tree the tools were loaded from at the start, and that it says nothing about the coder's model, the compiler or the machine (those are hw_profile values and other members).
3. **The member: its name, place and form.** Weigh at least: (a) one top-level *string* (for example `source_commit`) holding the full object name of the commit; (b) an object that can also hold what (a) cannot say (point 4), closed or open, said explicitly as ADR-0018 decision 3 says it for `hw_profile`; (c) a member that also identifies the repository (a URL or a name) - weigh it against #5 A-1 ("소스 repo는 설정 파일로 참조한다" is about the data repository; no input names a form for identifying the source repository) and leave it out or open unless a fixed input carries it. The form of the hash: lowercase hexadecimal, full length; whether both lengths of git's object formats (40 and 64) are valid; that an abbreviation, a branch, a tag or a `git describe` string is none. Do not add a rule no input carries.
4. **A source that is not exactly a commit** - the question ADR-0018 handed over ("what a tree with local changes means"). Cases to weigh: tracked files changed or untracked files present under the package; the package running from a place that is no checkout of the repository at all. What must hold: **the member never states a commit that does not identify the source the instance was started with** - NFR-2's link must not be made false by form. Weigh at least: (a) the member can only state a commit, so an instance started from such a source cannot state one and the member is absent (with point 5 (a): "not stated"); (b) the member carries a second value saying that the tree differed from the commit; (c) the member holds something other than a commit for that case. Decide what the **member** can express. **Do not decide what the start of an instance does** when it meets such a source (refuse, warn, record) - that is the writer's (OD-8 sub-question 17, OD-23); if the choice of form cannot be made without it, register the exact question as a sub-question and say which forms stay possible, or return BLOCKED (see Process).
5. **Whether a valid version 1 file may lack the member, and whether adding it raises `schema_version`** - by ADR-0018 decision 2's own rule, which leaves exactly this choice to the record of the member. Weigh: (a) the member may be absent from a valid file and the version stays 1 - then say what "`instance.json` records the source commit" (owner) means for such a file: a valid file is not thereby a complete instance record (ADR-0018 decision 2), and a reader that asks for the source commit of a run whose file lacks it reports that it is not stated and **never substitutes a value - in particular never the commit of the source the reader itself runs from**; (b) the member becomes required and the version becomes 2 - then every file and reader of today is of another version before a first run exists, and reading another version is OD-11. If the member is present it must be valid; say whether a present and invalid member makes the file invalid as a whole (ADR-0020 decision 3 is the precedent; confirm or correct).
6. **What the member is the pin of, and what it is not** - only as far as the fixed inputs carry it. It states the source at the start of the instance. NFR-7 ① and FR-6 allow the source to change during the life of a run, and the file is written once: say plainly that the member then no longer names the source of every later result, and that whether a later result records its own stamp, whether a call compares the source it runs from with this member, and what follows from a difference are **OD-11 and not decided** (cite the proposal lines as proposals). Say how the sentences of FR-9 and of ADR-0003, ADR-0007, ADR-0009, ADR-0010 and ADR-0017 that lean on "the source commit of the instance" read against this, as a reading, without editing any of them.
7. **How the member is read**, only as far as it follows from the fixed inputs: from this member of the file of the run, at each use, nothing kept; no request carries it. Observation to state truthfully: no tool, hook or module reads or writes it today. Do not say which tool or component reads it or at which moment.
8. **Limits**, in the manner of ADR-0018 decision 6 and ADR-0020 decision 7: whoever can write the file changes what the run claims to have been produced by; nothing checks that the stated commit exists in the source repository or was ever pushed (#5 A-3 is about the other repository; say what the inputs carry for this one and no more); a misspelt top-level name reads as "not stated" under 5 (a); two processes with two sources (ADR-0010 decision 7); the commit names the source and not the installed dependencies or the interpreter.
