### The module
- **Two public functions**, one for each kind of ended judging, each returning a new plain `dict` that is a result of ADR-0042 decision 7. Recommended names and parameters (another shape of the interface is the task's choice, as long as every rule below holds; check `hilclaw/` and `tests/` for a name collision and say so):
  - `completed(*, m, k, n, draws, rtol, atol, counts)` - a completed run. The keyword names are those of `hilclaw.harness.verification.judge_report`, which the later caller holds at that point.
  - `broken(condition, *, m, k, n, draws, rtol, atol)` - a broken run.
  - No parameter has a default: **no value of `draws`, of a tolerance or of a dimension is given by this module.**
- **Public constants** for the values the record fixes, so that no caller spells them again: the three values of `outcome` (`"pass"`, `"fail"`, `"broken"`) and the four values of `condition` **in the order of ADR-0042 decision 3** (`"time_limit"`, `"exit_status"`, `"report_form"`, `"check_value"`), for example `PASS`, `FAIL`, `BROKEN` and a tuple `CONDITIONS`. Their names are the task's choice.
- **What `completed` returns**: exactly the five members `outcome`, `shape`, `draws`, `tolerance`, `counts` - no `condition`.
  - `counts` is a `list` with one `dict` for each draw, in the order given, each with exactly `failed` and `non_finite`.
  - `outcome` is `"pass"` when every `failed` is 0 and `"fail"` when at least one is 1 or more (ADR-0042 decision 4, line 67; ADR-0017 decision 7 as cited there). **Recommended: the function derives `outcome` from `counts` and takes no verdict argument**, so that no call can state a verdict its counts contradict. If the executor takes a verdict argument instead, a verdict that disagrees with the counts is refused.
  - The argument `counts` is a sequence with one entry per draw, each entry a pair `(failed, non_finite)`; a tuple of `hilclaw.harness.verification_arrays.Counts` is such a sequence, and the tests use plain tuples and may use `Counts`. Say in the docstring exactly which sequence and entry types are accepted.
- **What `broken` returns**: exactly the five members `outcome` (`"broken"`), `condition`, `shape`, `draws`, `tolerance` - no `counts`, whatever the caller knows of the draws that were reported (ADR-0042 decision 4: "A broken result has no `counts`").
- **Common to both**: `shape` is a `dict` with exactly `m`, `k`, `n`; `draws` the integer; `tolerance` a `dict` with exactly `rtol` and `atol`. No member holds `None`. No other member is ever returned: nothing of the request (`run_id`, `round`, `candidate`, `attempt`, `execution`, `point`), no seed, no exit status, signal or time, no index or deviation, no version member, no text member (ADR-0042 decisions 5 to 7).
- **The spelling of the two tolerance numbers** (the task's choice). Recommended: each is returned as the `float` of the argument, so that the JSON literal `hilclaw.tools.encode` writes is that of the binary64 value the comparison is evaluated with (ADR-0042 decision 5: "a JSON number whose binary64 value is the one the comparison is evaluated with"); an `int` argument is accepted as `check_tolerance` of the harness accepts it and is returned as its `float`.
- **The member order of the returned `dict`** is visible in the line `hilclaw.tools.encode` writes. Recommended: the order of the table and of the three examples (`outcome`, `condition`, `shape`, `draws`, `tolerance`, `counts`). The docstring says that the order is this module's and no rule of the record.
- **What is refused** - nothing is returned for an argument the table does not admit. Recommended: `TypeError` for a wrong type and `ValueError` for a wrong value, each naming the parameter, in the manner of `hilclaw/backends.py`; one own exception class is the task's choice. Whatever is chosen is determinate for every argument (no `KeyError`, `IndexError`, `AttributeError`, `OverflowError` or unpacking error leaking from an unchecked access), documented and tested. Refused are at least:
  - `m`, `k`, `n`, `draws`: anything that is not exactly an `int` (a `bool`, a `float`, a `str`, `None`), and an `int` below 1. **No upper bound is added** (the table states none; `keys.MAX_INTEGER` and the harness's bound of `draws` are other sources' and are not repeated here).
  - `rtol`, `atol`: anything that is not exactly an `int` or a `float` (a `bool` included), a negative value, a NaN, an infinity, and an `int` too large for a `float`.
  - `condition`: anything that is not exactly a `str`, and a `str` that is none of the four values (among them `"pass"`, `"TIMEOUT"`, `"timeout"`, `""`). A member of the harness's `Broken` is refused like any other non-`str`: the mapping from it is not this module's.
  - `counts`: not a sequence of the accepted type (a `str`, a mapping, `None`); a number of entries other than `draws`; an entry that is no pair; a `failed` or `non_finite` that is not exactly an `int` or is negative; `non_finite` greater than `failed`; `failed` greater than `m * n` (the relations of ADR-0042 decision 4, line 67 - a count the definitions cannot produce is no count).
- If the executor finds an argument the table admits but `hilclaw.tools.check_json_object` refuses in the returned object (for example an `int` beyond the interpreter's limit for decimal conversion), it is refused by the module too; say in `## Result` which arguments these are.
- The functions are pure: they do not modify or keep an argument (the returned object shares no mutable object with `counts`), read and write no file, start no process, keep no state; equal arguments give equal results.
- Docstrings: the module docstring says what the module renders (ADR-0042 decision 7, by decision number), what each function is for, the choices above that are the module's own, and what the module does not do (no judging, no mapping from the harness or from an operation, no tool, no check of a stored result, no default of any value). Each public function gets a Doxygen-style docstring in the manner of `hilclaw/gemm_contract.py`. ### The interface as landed (the tool function and the mock's script are written against this)

- Public names of `hilclaw.check_result`, exactly six: `PASS` (`"pass"`), `FAIL` (`"fail"`), `BROKEN` (`"broken"`), `CONDITIONS` (the tuple `("time_limit", "exit_status", "report_form", "check_value")`, in the order of ADR-0042 decision 3), `completed`, `broken`. None of the names occurred in `hilclaw/` or `tests/` as a module-level name before; `broken` is also a field name of the harness's tuples, with the same meaning.
- `completed(*, m, k, n, draws, rtol, atol, counts)` - all keyword-only, no default. Returns a new `dict` with exactly `outcome`, `shape`, `draws`, `tolerance`, `counts`; no `condition`.
- `broken(condition, *, m, k, n, draws, rtol, atol)` - `condition` positional or by keyword, the rest keyword-only, no default. Returns a new `dict` with exactly `outcome` (`"broken"`), `condition`, `shape`, `draws`, `tolerance`; no `counts`, and the function takes none.
- **How `outcome` is determined**: `completed` derives it from `counts` and takes no verdict argument - `"pass"` when every `failed` is 0, `"fail"` when at least one is 1 or more.
- **Accepted argument types**:
  - `m`, `k`, `n`, `draws`: exactly an `int` (`bool` and other subclasses refused) of at least 1. No upper bound is added, except the one named under "Arguments the table admits but the module refuses".
  - `rtol`, `atol`: exactly an `int` or a `float`, finite, not negative, and for an `int` within what a `float` holds (what the harness's `check_tolerance` accepts).
  - `condition`: exactly a `str` (a subclass of `str` is refused) that is one of `CONDITIONS`. A member of an enumeration, the harness's `Broken` among them, is refused like any other non-`str`.
  - `counts`: exactly a `list` or a `tuple` with `draws` entries. Each entry is a `tuple` of two items `(failed, non_finite)`; an instance of a `tuple` subclass (the harness's `Counts`) is read as the tuple it is (through `tuple.__iter__`, so a subclass that overrides its own iteration or length cannot change the outcome). **A `list` as an entry is refused.** Each item is exactly an `int` of at least 0 with `non_finite <= failed <= m * n`.
- **What a refused argument raises**: `TypeError` for a type that is not accepted, `ValueError` for a value of an accepted type that the table does not admit. The message starts with the name of the parameter and `: ` (`m: `, `rtol: `, `condition: `, `counts: `, `counts[1]: `, `counts[1].failed: `). An entry that is a tuple of another length than 2, and a `counts` of another length than `draws`, are `ValueError`. A missing, surplus or positional argument is Python's own `TypeError`. No own exception class.
- **Member order** of the returned `dict` (the module's choice, said so in the docstring): `outcome`, `condition`, `shape`, `draws`, `tolerance`, `counts`; within `shape` `m`, `k`, `n`; within `tolerance` `rtol`, `atol`; within an entry `failed`, `non_finite`.

A negative zero is accepted (it is not negative, and `check_tolerance` accepts it) and returned as it is, so `encode` writes `-0.0`.
