## Why
ADR-0046 (T-0138, landed as `ec5fed4`) fixed where the number of draws of a check of `correctness.check` comes from: the top-level member `draws` of `runs/<run_id>/instance.json`. Its Consequences name one code slice:

> A code slice can now give `hilclaw/instance.py` the validity of the member and a reader of it beside `tolerance_of` and `n_max_of`; the tests that pin the fields of `Instance` and compare a whole `Instance` (`tests/test_instance.py`) change if that slice adds a field.

**This task is that slice.** Today `hilclaw/instance.py` defines eleven members; a top-level `draws` of any value - `0`, `"2"`, `true` included - is handed back uninterpreted in `Instance.others`, the file counts as valid, and nothing in the package can answer "which number of draws does this run state". The tool function of `correctness.check` (a later task, after HQ-0012) takes the number from the one read of moment 4 that also gives the hw_profile, the op_signature and the tolerance (ADR-0046 decision 4); that read is `hilclaw.instance.read`, so the number must be a field of what it returns.

It serves PLAN P1-1 (the second record of `correctness.check`) and P1-8 (the instance record). It ticks **no PLAN checkbox**: both stay open.
