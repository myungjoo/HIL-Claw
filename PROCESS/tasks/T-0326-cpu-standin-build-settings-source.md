## Why

PLAN P1-1 is open. Its completion criterion (D18) needs `sim.run`, `board.run` and `correctness.check` to work on `cpu_standin`. P2-5, the near goal, is a run on `cpu_standin` × GEMM. No `cpu_standin` operation exists yet for any of the three tools.

ADR-0116 (landed in T-0325, main 2ca335c) decides two things for the first case:
- **The source.** The backend's own flags, trailing flags and environment rule are one fixed set in the package source. The `cpu_standin` operations of `correctness.check` and of the run tools both read that one set (ADR-0107 decision 4).
- **The values.** Flags `-std=gnu11 -O2 -ffp-contract=off`. Trailing flags `-lm`. The environment is inherited unchanged. No thread setting.

Its Consequences name the code slice: "the one source of settings that the `cpu_standin` operations of `correctness.check` and of the run tools read … as constants of the package, with tests". Its Limit 1 and its runtime acceptance paragraph leave one check to that slice's tests: that the two harness programs and a `gemm` kernel build and run under this set with the clang of the development machine and of CI.

This slice is the first piece of the `cpu_standin` operations, so it lies on the path to P1-1's criterion and to P2-5. The D18 priority rule therefore does not set it aside.

None of the open HQs is needed:
- HQ-0034 (OpenMP) would only add to the set. ADR-0116 decision 6 says the set stands as recorded until it is answered.
- HQ-0033 is a runtime acceptance notice for the C-7 systems that this machine and CI do not have.
- HQ-0021 and HQ-0026 block the operations, not this source.

It exposes:
   - `FLAGS`, a `tuple` of `str` equal to `("-std=gnu11", "-O2", "-ffp-contract=off")`, in that order;
   - `TRAILING_FLAGS`, a `tuple` of `str` equal to `("-lm",)`;
   - `ENV`, equal to `None`. This is the inherited environment of ADR-0116 decision 5, in the meaning `env=None` has for `hilclaw.clang_build.build` and `hilclaw.local_run.run`.

   You may add at most one public helper that returns these three as the keyword arguments `flags`, `trailing_flags` and `env` of the two harness build functions. If you add one, test it under criterion 4. Add no other setting:
   - no compiler (OD-14 ①);
   - no time limit (OD-14);
   - no OpenMP flag or runtime;
   - no `-march`/`-mcpu`/`-m<feature>` flag;
   - no warning flag;
   - no define;
   - no thread variable.
3. **Nothing else reads or changes.** Do not wire the module into any existing module: not `check_definition`, the run tools, `clang_build`, `local_run`, `harness/`, `mcp_front` or `tools`. The operations that will read the module are out of scope. The module reads no file, no environment variable, no configuration and no hw_profile (ADR-0116 decision 2), and it starts no process.
4. **Tests** in a new `tests/test_standin_settings.py`, following DRIVER §5 test rules ①-④:
   - **Values.** The three values equal those of criterion 2, with exact types: `tuple`, every element `str`, `ENV is None`.
   - **No forbidden setting.** No element of `FLAGS` starts with `-o`, `--output`, `-march`, `-mcpu`, `-fopenmp`, `-W` or `-D`. No element of `TRAILING_FLAGS` names an OpenMP runtime (`-lomp`, `-lgomp`).
   - **Happy path: the harness builds and runs.** On POSIX with clang on `PATH`, build each harness program with a calibration kernel under the set (`flags=FLAGS`, `trailing_flags=TRAILING_FLAGS`, `env=ENV`):
     - The verification program with `gemm_conforming.c`. The build gives `ok`. `run_verification` on a small shape gives no `broken` and verdict `PASS`.
     - The verification program with `gemm_failing.c`. The build gives `ok`, and the verdict is `FAIL`. This shows the set does not change the harness verdicts.
     - The timing driver with `gemm_conforming.c`. The build gives `ok`. One `run_timing` call gives no `broken`.
     Use the skip/fail rule of `tests/harness/test_calibration.py`: skip off POSIX or without clang, but fail when `GITHUB_ACTIONS` is `"true"` and clang is missing.
   - **Branch: the trailing `-lm` is used.** A temporary kernel source that conforms to the `gemm` contract and calls a `<math.h>` function the compiler cannot fold away (for example `expf` of an input value, multiplied by zero or otherwise kept harmless to correctness) builds `ok` under the set.
   - **Negative: what the set leaves out.** Each of these temporary kernel sources builds with `ok` false under the set:
     - a source that declares `int omp_get_max_threads(void);` itself (no `<omp.h>`, so the outcome does not depend on an installed header) and calls it. The link fails: the set links no OpenMP runtime (ADR-0116 decision 6).
     - a source with a syntax error. A broken kernel is a result, not an exception.
   - **Negative: no warnings as errors.** A kernel source that draws a warning under `-Wall` (for example an unused local variable) builds `ok`. The set carries no `-Werror` (ADR-0116 decision 3).
