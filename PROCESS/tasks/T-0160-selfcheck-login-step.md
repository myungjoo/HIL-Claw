## Acceptance Criteria
### Fixed by the record (not re-decided; implement exactly)
1. **The call.** Exactly `claude auth status`: the program named `claude`, found on the `PATH` as `hilclaw.local_run.run` finds a program, with the two arguments `auth` and `status` and **no further option**; started once as a child process, without a shell, with no standard input, under a time limit; the environment is the one of the calling process, unchanged. One call of the function starts the program at most once; nothing is retried.
2. **Logged in**: exit status 0 **and** an output that is one JSON object whose `authMethod` is a string other than `none`. The member `loggedIn` and every other member are not read.
3. **Nothing is logged in** (`not_logged_in`): exit status 1, whatever the output is and whatever caused that status.
4. **`login_unreadable`**: everything else that ran - exit status 0 with any other output (not JSON, JSON that is not an object, no `authMethod`, an `authMethod` that is not a string, `authMethod` equal to `none`), any other exit status (a process ended by a signal included), the time limit.
5. **`no_claude`**: no `claude` program could be started - `ProgramNotFoundError` of `local_run.run`, and an `OSError` of the start itself (hint (b) of T-0153: `no_claude` is an outcome of step one).
6. **Neither `login_unreadable` nor `no_claude` nor `not_logged_in` is ever read as logged in.** The module offers its caller exactly one way to tell "logged in" from the three outcomes, and no default, fallback or exception path yields "logged in".
7. **What leaves the module of the status output**: the value of `authMethod`, and that only when it is exactly one of `none`, `claude.ai`, `oauth_token`, `api_key`, `api_key_helper`, `third_party`; any other string is carried as the word `other`. No other byte of the standard output and no byte of the standard error is in the value the function returns, in its `repr`, in an exception it raises or in anything it writes. The child's standard error is not passed on.
8. **The module never runs `claude auth login`** and starts no other program. It writes no file, reads no configuration and no environment variable of its own, prints nothing.
9. For `login_unreadable` the caller can learn "the exit status, or that the time limit ended the call" (decision 6, third row); for `not_logged_in` the fixed instruction to run `claude auth login` exists as a text of the package (decision 3) that holds nothing of the output.

A byte order mark, invalid UTF-8 (UTF-16 too), a second value or trailing text, `NaN` / `Infinity` anywhere, and nesting too deep to parse (`RecursionError`) are `login_unreadable`; none raises. Integers are not converted (`parse_int` returns a constant), so the interpreter's limit on integer digits does not decide what is one JSON object (round-1 finding F3). **A duplicate `authMethod` key is read as no `authMethod`** (so `login_unreadable` at exit status 0, and no `auth_method` carried): two answers are not one answer, and neither "first wins" nor "last wins" can then make an ambiguous output read as logged in.
- *`auth_method` for the other outcomes*: carried, bounded by rule 7, whenever the output is one JSON object with a single string `authMethod`, whatever the outcome (after the time limit: the output captured until then); otherwise `None`. Nothing is concluded from it for the outcome.
- *Instruction text*: as above; it names the command and holds nothing of the output.
- *Bad arguments*: `timeout_s` as `local_run.run`. **`cwd` goes one step beyond "follow `local_run.run`"**: because fixed point 5 reads every `OSError` of the start as `no_claude`, a `cwd` that is not a directory when the call begins is refused before the start with `FileNotFoundError("cwd is not a directory")` (no path in the message) and a `cwd` that is not a path with `TypeError`, so that a caller's bad argument is not reported as a missing `claude`. Differences from `local_run.run`, both before anything is started: a file given as `cwd` raises `FileNotFoundError`, not `NotADirectoryError`; with both arguments bad, the `cwd` error comes first. `OverflowError` for a `timeout_s` longer than the platform can wait for is passed on from `local_run.run` (after the child was started and killed).
- *`no_claude`*: the lookup that finds nothing and every `OSError` of the call - a file the system cannot execute, and also a start that failed for another reason (a `cwd` that cannot be entered or vanished after the check). That last case has no test of its own (round-3 Nit; the `OSError` branch is covered by the POSIX test of a file the system cannot execute).
