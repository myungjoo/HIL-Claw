## Why
ADR-0021 (landed as `691870d`, T-0073) fixed who draws the seed of a call of `correctness.check` for the first case and what the source of that seed must be (decision 3):

> **The source, as a property and not an algorithm**: the seed comes from a source whose output nobody can predict or influence before the draw - not derived from the request, the identity, any file of the data plane or of the source, a clock, a counter or anything an earlier call left - and it is drawn over the whole range of seeds the harness accepts. In a registry that `default_registry` builds, no request, option or variable of the front process sets it. How the source is bound, and whether a test binds one of its own, is the code task's.

Its Consequences name two code slices that need no further record: the judging half of `run_verification` as a public function (done: T-0074, `judge_report`, `7f5feea`) "and a source of seeds with the property of decision 3. A conformance test that compares the outcomes of two calls binds the source (decision 6)."

**This task is that second slice.** Today nothing in `hilclaw/` draws a seed: every caller of the harness passes one (`run_verification`, `judge_report`, `draw_inputs` all take `seed` as a required parameter, and the module docstring of `verification.py` says the module holds "no ... seed, source of a seed"). The tool function of `correctness.check`, which cannot be written yet, will need exactly one place to ask, and its tests and the conformance tests of P1-1 will need to put a source of their own in that place. The package already has this shape once: `hilclaw/data_root_source.py` (ADR-0015 decision 3) - a source is a callable without arguments, `configured` is the source of the fronts, `obtain(source)` asks a source once and checks the answer, and a tool function is built with a source in reach. ### The module
Recommended shape (names yours), the counterpart of `hilclaw/data_root_source.py`:
- **A seed source** is a callable without arguments that returns a seed or fails. It is asked at each draw and its answer is not kept.
- **`system()`** - the one source of the package: returns an `int` drawn from the operating system's random generator, uniformly over **the whole range of seeds the harness accepts**, `0 <= seed < 2**64` (`SEED_LIMIT`), for example `secrets.randbits(64)`. It takes no argument and has no parameter with a default; it reads no environment variable, option, configuration, file of the data plane or of the source, clock or counter; it is not seeded, cannot be re-seeded and holds no generator object or state of its own; it does not use the module `random`'s default generator or NumPy's. What the platform raises when it has no random source is passed on.
- **`draw(source)`** - asks `source` **exactly once** and returns the seed it named. It refuses, by raising and never by repairing, everything that is not a seed by the rule the harness already has: anything that is not exactly an `int` (a `bool`, a `float`, a `str`, `None`, a NumPy integer), a negative, a value of `2**64` or more. **No value is ever clamped, reduced modulo the limit, replaced by a draw of another source, or retried.** A `source` that is not callable is a `TypeError`. What is raised for a refused value and for a source that raises (your own exception class of the module, chained; or the source's exception passed on) is yours to choose and document. It is **not** a `hilclaw.tools.ToolFailure`, and the module does not import `hilclaw.tools`.
- **Nothing is kept and nothing is written**: no module-level variable changes, no cache, no file, no standard stream, no log. Two calls are independent.
- **No message, exception argument or `repr` of what the module raises holds a value a source returned** (name the type and the rule instead): a refused value is not the seed of a check, but a module whose errors never show a drawn value cannot leak one (ADR-0021 decisions 3 and 5, "until it is answered"). If you choose otherwise, give the reason.
- The range comes from one place. Either the module takes `SEED_LIMIT` from `hilclaw.harness.verification_arrays` (it then imports a module that imports `numpy`; keep the sentence of `hilclaw/harness/__init__.py` true), or it writes the limit itself and a test pins the agreement with `SEED_LIMIT` and with what `program_arguments` and `draw_inputs` accept (the precedent of `hilclaw.instance`). Choose, and say why.

### Tests (`tests/harness/test_seed_source.py`, excluded from the size cap)
Helpers live in the test file and get no tests of their own (test rule 5). The tests pass on Linux (CI) and on Windows (the driver's clone) and need no clang and no process.
- happy: `system()` returns exactly an `int` inside the range on each of many calls; `draw(system)` returns a value `program_arguments` and `draw_inputs` accept; `draw` over a test's own source returns exactly what the source named, for `0`, `1`, a middle value and `2**64 - 1`; the source is asked exactly once per `draw` (a counting source).
- the whole range: with the standard-library call that `system` uses replaced by a stand-in, the smallest and the largest value it can give come out as `0` and `2**64 - 1` (no bit is dropped, no offset added), and `system` asks it for exactly the width of the range.
- the property, as far as a test can hold it: `system` takes no parameter (`inspect.signature`); with `os.environ` emptied or filled with likely-looking variables, `random.seed` called with a fixed value before each call, and the clock functions of `time` replaced by constants, successive results of `system()` are not all equal (state the probability of a false failure in a test comment of one line, for example 2**-64 per pair); the module has no attribute that changes between two calls; `system` reaches the operating system's generator (the stand-in above is called) and not `random.random` / `random.getrandbits` of the default generator (replaced by functions that fail the test).
- branch / negative (parametrised): a source returning `-1`, `2**64`, `2**64 + 1`, `True`, `False`, `1.0`, `"1"`, `None`, a `bytes`, a list, a NumPy `uint64` - each refused with what you documented, never returned, never repaired; a source that raises an `Exception` - what you documented, with the cause reachable; a source that raises `KeyboardInterrupt` - as you documented; `draw` of what is not callable (`None`, an `int`, a `str`) - `TypeError`, and nothing is asked; `draw()` without an argument and `system(1)` - `TypeError`.
- no leak: for each refused value above, `str`, `repr` and `args` of what was raised do not contain the decimal or the hexadecimal digits of that value (use values long enough not to match by chance); nothing is written to `stdout` / `stderr` (`capsys`) and no file appears in a temporary working directory.
- independence: two `draw` calls over one counting source ask it twice and return its two answers in order; nothing of the first call changes the second.
- agreement: the range the module accepts is exactly the range of `verification_arrays.SEED_LIMIT` and of `program_arguments` (the first refused value above the range and the last accepted one are the same for all three).
