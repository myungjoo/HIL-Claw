## Acceptance Criteria

### `hilclaw/hypotheses_file.py` (new; Python, as the rest of the package)

Public names are the executor's; the suggested ones mirror `hilclaw.spec_file` so that a reader of both finds the same shape. The reasons for any departure go into the commit body.

- **Exceptions**: `InvalidHypothesisFileError(ValueError)` (a content breaks the text form or a rule of decisions 2 to 5; message "field path: rule" as in `hilclaw.spec_file`; what `hilclaw.hypotheses.validate` raises is wrapped with its message unchanged), `UnsupportedVersionError(Exception)` (no `ValueError`), `WrittenFormError(ValueError)` (no `InvalidHypothesisFileError`), `NameTakenError(Exception)` (no `OSError`). The executor may import nothing private from `hilclaw.spec_file` or `hilclaw.hypotheses`: small private helpers of its own (the duplicates of `_object`, `_nan`, `_literal`, `_unsigned` are a few lines each). A shared helper module is **out of scope** here (it would touch `spec_file.py` and its tests); if the executor judges the duplication worth removing, it is a follow-up.
- **`parse(content)`** returns the document of `content`, the bytes of a hypothesis record file, as `json.loads` gives it (a new `dict`, nothing added, defaulted or repaired; `content` not kept or modified). In this order, as `spec_file.parse`:
  - `TypeError` for a `content` that is not exactly `bytes`;
  - `InvalidHypothesisFileError` for a UTF-8 byte order mark; for a content that is not UTF-8 or not exactly one JSON text (`NaN`, `Infinity`, `-Infinity` refused; an empty content is invalid, ADR-0059 decision 2); for a member name twice **in any object, unknown top-level members included** (a rule for the whole text, ADR-0018 decision 2); for nesting too deep or an integer literal this interpreter cannot read (a limit of the reader, said so in the docstring); for a text that is no object;
  - `UnsupportedVersionError`, before any other member is looked at, when `schema_version` is an `int` from 0 to `hilclaw.keys.MAX_INTEGER` other than 1 and is not written `-0` (ADR-0059 decision 2; OD-11). Nothing else of such a content is interpreted;
  - `InvalidHypothesisFileError` for a document `hilclaw.hypotheses.validate` refuses;
  - `InvalidHypothesisFileError` for `-0` at an *integer* place. Every number of a valid document stands at an *integer* place **except below a top-level member that ADR-0059 does not define**: the top level is open, and ADR-0059 sets no rule for a number there, so a sign, a fraction, an exponent or a large integer below an unknown top-level member is accepted and returned as parsed (state this in the docstring, as `spec_file` does for its two free places). Note that `-0` matters: a `ref.round` written `-0` would otherwise parse to a valid 0.
- **`final_name(data_root, document)`** validates the document with `hilclaw.hypotheses.validate` (its `InvalidHypothesisRecordError` passes through, a document of another `schema_version` included) and returns `hilclaw.layout.hypothesis_record(data_root, document["run_id"], document["round"])`. A valid document whose `run_id` is no run directory name has no path: `hilclaw.layout.InvalidPathValueError` passes through. This is the rule "`run_id` and `round` against the path" of ADR-0059 decision 2 for whoever holds both: `final_name(data_root, parse(content)) == path`; no function takes a path. Nothing is read, created or resolved; the document is not modified.
- **`write(data_root, content)`** puts `content` under `final_name(data_root, parse(content))` if that name is free and returns `None` - the steps of ADR-0029 decisions 4 to 7 with this final name (ADR-0059 decision 1). In this order, nothing created before the last: what `parse` raises; what `final_name` raises (`InvalidPathValueError`; `TypeError` for a `data_root` that is no path); `WrittenFormError` when the content does not end with a line feed or holds a carriage return byte (no member order, indentation or line count checked); `FileNotFoundError` / `NotADirectoryError` for a `data_root` that is no existing directory (never created). Then every missing directory between `data_root` and the final name is created, and `hilclaw.once_write.write_once(path, content)` gives the name - temporary file `hypotheses.json.<token>.tmp` in `decision/`, stable storage, hard link with no fallback to a replacing rename, temporary file removed. A taken name raises `NameTakenError` (equal bytes reported as any other; the entry under the name is never opened, read or compared; nothing retried). Any other failing step raises its `OSError` unchanged; the directories created stay.
- **Module docstring** in the style of `hilclaw/spec_file.py`, but no longer than it needs to be for this record: which record and decisions it implements (ADR-0059 decisions 1 and 2, by ADR-0029 decisions 2 to 7); the rules `parse` holds and their order; the open top level and the number rule below it; the steps `write` holds; the conventions the record does not fix (copy those of `spec_file` that apply, adapted); the limits of `write` (ADR-0029 decision 7: POSIX systems with hard links; nothing stated for a network file system, WSL on a Windows drive or native Windows; two writers not prevented); and what it does **not** do: no file read, no directory listed, no "same content", no content composed, no lock, no commit; it does not check what one content does not show (`candidates` against the round's specs, a `ref` naming an attempt that exists, the `metric` against `instance.json`), it reads no other version (OD-11), it is no tool, and which agent writes the file, when, and what follows a taken name are open (ADR-0059 Boundaries; OD-23, OD-18, OD-17). No comment beyond the docstrings (CLAUDE.md "코멘트 최소화").
- **No change** to `hilclaw/hypotheses.py`, `hilclaw/layout.py`, `hilclaw/spec_file.py` or `hilclaw/once_write.py`. If the executor finds one of them must change, it stops and reports why in `## Result` (BLOCKED "requirement-unclear" if the slice cannot stand without it).

### Tests (CLAUDE.md test rule; DRIVER §5 line 113)

- `tests/test_hypotheses_file.py` (new), on the model of `tests/test_spec_file.py`, covering every public function and exception class of the module.
- **Happy**: the ADR-0059 Example, **copied from the record** as bytes with a final line feed, parses to the expected document, gives the expected `final_name` (`<data_root>/runs/20261009t012331z-9f3a6c1e0b7d4a52/rounds/0001/decision/hypotheses.json`) and is written there byte for byte; missing directories are created; any member order, white space, CRLF line ends and a missing final line feed are accepted by `parse`; an unknown top-level member of any JSON type, including a number written `-0`, `1.5`, `1e400`, `-3` or above 2**53 - 1, is accepted and returned as parsed.
- **Negative and branch**, one case at least for each rule above: non-`bytes` content (`str`, `bytearray`); BOM; invalid UTF-8; empty content; two JSON texts; `NaN`/`Infinity`; a non-object text (array, number, string); duplicate member names at the top level, inside an unknown top-level member, in a hypothesis, a basis entry and a `ref`; nesting too deep; `schema_version` 0, 2 and `MAX_INTEGER` set apart (`UnsupportedVersionError`, also when the rest is invalid), `schema_version` `-0`, `-1`, `MAX_INTEGER + 1`, `1.0`, `"1"`, `true` invalid; a document `validate` refuses (message unchanged, field path present); `-0` at `round`, `candidates`, `tested_by`, `ref.round`, `ref.candidate`, `ref.attempt`; `final_name` with an invalid document, another version, and a valid document whose `run_id` is no run directory name (`InvalidPathValueError`), and with `data_root` of a wrong type; `write` with every class above, in the order stated (for instance an invalid content with a bad `data_root` raises the content's error), the written-form errors, a missing and a non-directory `data_root`, nothing created in each of these cases; a taken name (with equal bytes and with other bytes; the existing file unchanged; no temporary file left); an `OSError` injected at the creation of a directory, of the temporary file, at the write or flush and at the link (monkeypatch, as `tests/test_spec_file.py` does), the temporary file removed and nothing under the final name; a leftover `hypotheses.json.<token>.tmp` of another write is not touched.
- The hard-link tests run where `tests/test_spec_file.py`'s do; follow its skip conditions, if any, rather than adding new ones.
