## Why
PLAN P1-9 is the runtime self-check the owner ordered in the answer to HQ-0006 (b-2): a check of the `hilclaw` package that the bring-up of an instance runs **on the runtime machine**. Its design record is ADR-0054 (T-0153). Six slices have landed, each bound to nothing: step one (`hilclaw/selfcheck_login.py`, T-0160), the server side with the wire copy (`selfcheck_server.py`, T-0161), the reading of the wire copy (`selfcheck_wire.py`, T-0162), the outcome table (`selfcheck_outcome.py`, T-0163), the reading of the session's output (`selfcheck_stream.py`, T-0164) and the session itself (`selfcheck_session.py`, T-0165, `749e710`).

What is left of P1-9 is decision 7 and the composition. The planner splits it in two, because one task would pass the cap (every sibling module stands at 280 to 300 lines):

1. **this task** - the report as a pure module: which members a report has, from which landed value each is taken, the one line, and the exit status for each outcome. It starts nothing;
2. the next task - the composition and the command of the package: step one, then `selfcheck_session.run` only when logged in (with the data root in `keep_out`), then this module; the values of the two time limits; writing the line to standard output and returning the exit status. **That task ticks PLAN P1-9.**

This task ticks **no PLAN checkbox** and changes no OD and no `ARCHITECTURE/` file.

Planner's judgements (the reviewer is asked to re-check each):

## Acceptance Criteria
### Fixed by the record and by the code on `main` (not re-decided; implement exactly)
1. **One public function builds the report of one check** from the `LoginStatus` of step one and the `SessionRun` of step two, or no `SessionRun` when no session step was run. It is pure in those arguments: it starts no process, reads no file, no environment variable and no clock, keeps no state and prints nothing.
2. **The outcome in the report is the one `selfcheck_outcome.decide` gives** for those values - `decide(login.outcome, run.session, run.wire, torn=run.torn)`, or `decide(login.outcome, SessionEvidence(), None)` when there is no `SessionRun` - so a report can never name an outcome its evidence does not have. No outcome is computed in another way and no outcome word is written in this module as a literal: they are the constants of `selfcheck_login` and `selfcheck_outcome`.
3. **The members** (line 137; the names are this task's), each taken from the named value and from nowhere else:
   - the outcome; for `front_refused`, which of conditions (a) and (b) held (`Verdict.refused_a`, `refused_b`; line 124, last column);
   - the fixed instruction text `selfcheck_login.LOGIN_INSTRUCTION`, **when and only when** the outcome is `not_logged_in` (lines 72, 122);
   - the `authMethod` value under the rule of decision 3 (`LoginStatus.auth_method`: one of the six values, or `other`);
   - for step one, its exit status and whether the time limit ended the call (`LoginStatus.returncode`, `timed_out`; line 123, last column);
   - the Claude Code version as the client stated it (`WireFacts.client_version`) - **absent when no wire copy exists** (line 137);
   - the name and the release of the operating system and the Python version as the interpreter states them, **without the host name**;
   - the revision asked for and the one answered (`revision_asked`, `revision_answered`) and what was seen of `server/discover` (`probe_seen`, `probe_before_initialize`, `probe_revision`, `probe_error`);
   - the tool names of the `system/init` event that begin with `mcp__hilclaw__` (`StreamFacts.session_tools`, with `session_tools_dropped`);
   - for each of the two tools: whether its name was in that event, whether its call was requested and answered as the record says, and whether its token was in the reply (`SessionEvidence.token_tool_listed` / `fail_tool_listed`; `WireFacts.token_call_requested`, `token_call_answered`, `fail_call_requested`, `fail_call_answered`; `SessionEvidence.token_in_reply`, `fail_token_in_reply`) - what the row `no_call` asks ("which names, calls and tokens were seen");
   - every unforeseen method name (`WireFacts.unforeseen`, with `unforeseen_dropped`);
   - how far the session got: started (`session.started`), `system/init` read (`session.init_read`), the server started (a wire copy exists - `run.wire is not None` - and the client's `initialize` arrived - `run.wire.reached`; two facts, as T-0165's follow-up says), the `result` message read (`session.result_read`); its exit status and whether the time limit ended it (`session.exit_status`, `session.timed_out`);
   - whether the directory of the check was removed (`SessionRun.removed`) - the one member beyond line 137 (see Why).
4. **Strings are bounded at this gate** (line 138), whatever the caller hands in: the client version, the three revisions and a tool name are put in only when they are 1 to `selfcheck_wire.MAX_STRING` characters of ASCII letters, digits, `.`, `_` and `-`; a method name also `/`; anything else is `selfcheck_wire.OTHER`. The `authMethod` is put in only when it is one of `selfcheck_login.AUTH_METHODS`; anything else that is a string is `AUTH_METHOD_OTHER`. A list is cut at `selfcheck_wire.MAX_LISTED` items, and that it was cut is said by its `..._dropped` member. A tool name that does not begin with `selfcheck_stream.TOOL_PREFIX` is not put in.
5. **Built from named members, never copied text** (line 139). The report holds booleans, integers, `null`, the bounded strings above, the fixed instruction text, outcome words, and lists and objects of those. It holds no line or fragment of the status output, of the session's output, of the standard error or of the wire copy, no reply text, no token, no path, no command line, no environment variable, no host name, no user name, and no text of an exception. The function takes no argument through which such a text could arrive other than the values of criterion 1.
6. **The line** (line 136): one public function turns a report into the bytes of **one JSON object on one line ended by one LF** - compact, ASCII, as `hilclaw.tools.encode` writes a result. The same report gives the same bytes; the member order is fixed.
7. **The exit status** (line 140): one public function from an outcome word to an integer: **0 for `passed` and for nothing else**; a non-zero value for each of the other six; **never 1 and never 2**. A word that is no outcome is refused (never 0).
8. **Nothing existing changes**: no existing module is edited and no private name (a leading `_`) of another module is imported.

### Left to this task (decide, say each in the module docstring as a convention, test it, list each choice in `## Result`)
- **The public names and the form of the report value.** Planner's suggestion, not required: `build(login, run, *, system) -> dict` (a plain JSON object), `line(report) -> bytes`, `exit_status(outcome) -> int`, `system_facts() -> SystemFacts`, the exit status constants, and one constant per member name (or one tuple of them, in the order written).
- **The member names and the shape** (flat, or grouped as `login` / `session` / `wire` / `tools` objects). They are names of a process output, not of a schema; say so. Planner's constraint: lowercase words joined by `_`; none of them `schema_version` or a name of `STATE.json`, `instance.json` or `events.ndjson`, so that nobody reads the line as a data-plane record.
- **Absent or `null`.** Line 137 says the client version is "absent when no wire copy exists". Decide one rule for a value that does not exist (the member is left out, or it is `null`) and apply it to every member; the planner's reading is that the whole group of wire-side members is left out when `run.wire is None`, the session-side group when no session step was run, and that a member inside a group that exists is `null` when its value is `None`. The instruction text is left out, not `null`, for every outcome but `not_logged_in`.
- **The values of the operating system and of Python.** The record names three things "as the interpreter states them". Planner's reading: `platform.system()`, `platform.release()` and `platform.python_version()` and nothing else - **never `platform.node()`, `platform.uname()` as a whole, `platform.platform()`, `platform.version()`, `sys.version`, `socket.gethostname()` or an environment variable**. To keep the builder pure, the planner suggests that a small public function reads those three and the builder takes its value as an argument (so the tests give fixed values). The record sets no bound for them (L6 distrusts the `claude` program, not the interpreter); whether a length cap or the bounding of criterion 4 is applied to them (a Python version can end in `+`, a kernel release can be long) is the executor's - say which and why, and the line must stay one line whatever they hold.
- **The exit status values.** Planner's suggestion, not required: one distinct value per outcome, so that a caller can tell the two outcomes the owner fixed a consequence for (`not_logged_in`, `front_refused`; line 131) without parsing; none of 3 and 4 (which `hilclaw/__main__.py` already gives a meaning), none of 120, none of 126 or above (the shell's own). The status of "the check itself faulted" (an exception of the composition) is **not** chosen here: it is the next task's.
- **Values that contradict each other.** Planner's reading: a `login.outcome` that is not `None` together with a `SessionRun` (a session after a step one that did not say logged in - decision 3 forbids it), and a `login.outcome` of `None` with no `SessionRun`, are refused with a fixed text (`ValueError`) rather than reported; the errors `decide` raises for values of another form pass through. A `login` that is no `LoginStatus`, a `run` that is neither `None` nor a `SessionRun`, a `stream` or a `removed` of another form: `TypeError` with a fixed text that holds nothing of the argument.
- **`stream` is `None`** although a `SessionRun` exists (no session was started: no `claude` found): the tool names are then an empty list or left out, under the rule above.
- **The module docstring's known limits**: L2 (a pass is one observation); the function believes the yes-or-no values and the integers it is given (L6); a `session_failed` report says how far the session got and not why (line 139, the cost); the record lists no member for the error codes of condition (a), for the status word of the server, for `torn` or for an unplaceable line, so the report does not say them (a question for the record, see Follow-ups); nothing calls the module yet; where the report is kept and what the instance's log is are not this module's (O7, ⑯ (나)).
- Nothing else.

### Tests (`tests/test_selfcheck_report.py`; CLAUDE.md test rules, D12)
No test starts a process. Values are built by hand from the public NamedTuples of the landed modules; the system facts are given, not read (one test may call the reader of the platform and check only the form of what it returns).
