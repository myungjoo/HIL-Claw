### The module
One public function and one public exception class, and no other public name (recommended names; another shape is the task's choice as long as every rule below holds - check `hilclaw/` and `tests/` for a collision and say so):

- **`from_answer(answer, *, m, k, n, draws, seed, rtol, atol)`** - the result of a check for what an operation returned, as a new `dict` of the form of ADR-0042 decision 7:
  - **(A) a byte string**: returns `check_judging.from_report(answer, m=..., k=..., n=..., draws=..., seed=..., rtol=..., atol=...)`. Every byte string is a report whatever its bytes are: an empty, a short, a long or a malformed one is judged and gives the broken result the judging finds, and the bytes `b"time_limit"` are a report of the wrong form (ADR-0043 decision 4). What `from_report` raises passes through unchanged.
  - **(B) one of the two strings**: returns `check_result.broken(answer, m=..., k=..., n=..., draws=..., rtol=..., atol=...)` - the string goes into `condition` as it is. Nothing is judged. The two strings are taken from `check_result.CONDITIONS` (its first two items), not spelt a second time where the code can avoid it; the tests pin each as a literal. What `check_result.broken` raises for the other arguments passes through unchanged.
  - **Neither form**: raises the module's exception and returns nothing. In particular `"report_form"` and `"check_value"` - values of `condition` that an operation never returns - are neither form and **must not** yield a broken result, although `check_result.broken` would accept them; likewise `"pass"`, `"fail"`, `"broken"`, `""`, `"TIME_LIMIT"`, `" time_limit"` (nothing is normalised), `None`, a number, a `bool`, a tuple or a list, a `dict` (a result object included), a member of the harness's `Broken`.
  - **Which Python types count** (the code task's by ADR-0043 decision 4; recommended): a byte string is exactly `bytes` - what `judge_report` takes - and a string exactly `str`, as `check_result.broken` takes its condition; a `bytearray`, a `memoryview`, an instance of a subclass of `bytes` or of `str` are neither form. If the executor accepts more, the docstring says exactly what, no accepted value may reach `from_report` or `check_result.broken` and be refused there as a wrong type, and the tests cover it.
  - **The form is established first**, before any other argument is looked at or used (ADR-0043 decision 5: "before it uses it"): an answer of neither form raises the module's exception also when another argument is bad. The order of the remaining checks is that of the function called and is stated in the docstring.
  - **`seed` beside a condition**: it is not used (no result holds it, nothing is judged). Recommended: it is then not checked either, and the docstring says so in one sentence; checking it is the executor's choice only if it needs no new import beyond the documented set.
  - No parameter has a default. The seven after `answer` are keyword-only, as in `from_report`.
- **The exception class** (recommended name `NeitherFormError`; a direct subclass of `Exception`, so that a caller can tell it from the `TypeError` / `ValueError` of a refused argument): **not** a `ToolFailure`, **not** a `StepFailed`, no subclass of either, no attribute named `kind` or `spend`, no failure kind in its message. Its docstring says what it means (the answer has neither form of ADR-0043 decision 4, so no result was made) and **does not say what a call then answers** (sub-question 15).
