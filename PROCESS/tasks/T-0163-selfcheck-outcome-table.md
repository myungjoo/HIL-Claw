## Acceptance Criteria
### Fixed by the record and by the code on `main` (not re-decided; implement exactly)
1. **A pure function.** The module decides one outcome from values handed in. It opens no file, starts no process, reads no environment variable, clock or configuration, keeps no state and prints nothing. The same input gives the same value.
2. **A closed list of seven; exactly one.** The outcomes are `no_claude`, `not_logged_in`, `login_unreadable`, `front_refused`, `passed`, `no_call`, `session_failed`, in that order of rows, and "the first row whose condition holds, read from the top, is the outcome" (line 117). The three words of step one are the constants of `hilclaw.selfcheck_login` (`NO_CLAUDE`, `NOT_LOGGED_IN`, `LOGIN_UNREADABLE`), not spelt a second time; the four of step two are new public constants of this module. `session_failed` is "**every other case**": no input of the stated form ends in an exception or in no outcome.
3. **Rows 1 to 3** are the outcome of step one, taken as it is: when step one did not end in "logged in", that word is the outcome whatever the other arguments hold ("after either no session is started", line 71).
4. **`front_refused`** (line 124), all of: step one logged in; a session was started; the wire copy shows that the server was reached (`WireFacts.reached`); and one of
   - **(a)** an error that condition (a) names is in the wire copy - `bool(WireFacts.errors)`, **as the record is written**: a -32602 answered to `tools/call` or `tools/list` is among them, whoever caused it;
   - **(b)** all of: `initialize` answered and no `tools/list` request after it (`initialize_answered and not list_after_initialize`); "the session ended by itself"; "the `system/init` event was read"; and that event "either names `hilclaw` neither in `mcp_servers` nor in `mcp_server_errors`, or gives it a `status` word of the list of words taken to mean a failed or dropped connection". **"That list holds one word today, `failed`"**: a public constant of this module, a tuple of exactly that word. "Every other `status` word - `pending` and any word outside the list included - a server that was never started, and an entry in `mcp_server_errors` ... are **not** this outcome."
   Condition (a) asks nothing of how the session ended: it holds for a session ended by the time limit or with a non-zero exit status as well.
5. **`passed`** (line 125), all of: step one logged in; "the session ended by itself within the time limit with exit status 0"; "the `system/init` event shows `hilclaw` as `connected`, no `mcp_server_errors` entry and both tool names"; "the wire copy shows `initialize` and `tools/list` answered with results, at least one `tools/call` of each tool answered as the table above says, and no JSON-RPC error that condition (a) of `front_refused` names" (the expression of T-0162 Result line 188); "the text the model wrote holds both tokens". **"No path reads as passed without the model"** (line 129): without both token facts there is no `passed`, whatever else holds.
6. **`no_call`** (line 126), all of: "the session ended by itself with exit status 0"; "its `result` message and a wire copy holding the `initialize` request were read"; "the `system/init` event shows `hilclaw` as `connected`"; and "something `passed` needs of the tool names, the calls or the tokens is missing". A session to which `passed` fails for another reason only (`tools/list` not answered with both tools, `initialize` not answered, an `mcp_server_errors` entry) is not `no_call`.
7. **`session_failed`** (line 127): every other case - among them a session that could not be started, a non-zero exit status, the time limit, no `system/init` event, "no readable wire copy or one without an `initialize` request", a `status` word that is neither `connected` nor of the list (`pending` included), `hilclaw` named in `mcp_server_errors`.
8. **The module sees evidence, not sources**: no line of the session's output, no reply text, **no token**, no path, no name of a member of a `system/init` event or of a `result` message, and no session-side tool name (`mcp__hilclaw__...`) is an argument, a constant or a returned value. Where the evidence comes from is the session slice's.
9. **Nothing existing changes**: no existing module is edited and no private name (a leading `_`) of another module is imported.

### Left to this task (Python form and the corners the rows do not spell; decide, say each in the module docstring as a convention of the module, test it, and list each choice in `## Result`)
- **The public names**: the function, the type of the session evidence, the type returned, the constants. Planner's suggestion, not required: `decide(login_outcome, session, wire, *, torn=False) -> Verdict`; `SessionEvidence` a `NamedTuple` with a default for every member so that `SessionEvidence()` is "no session was started"; `OUTCOMES`, the tuple of the seven in table order; `CONNECTED = "connected"`; `REFUSED_STATUS_WORDS = ("failed",)`.
- **What the session evidence carries.** It must let every session-side and model-side condition of rows 4 to 7 be answered and nothing more. Planner's reading of the least set: whether a session was started; whether the time limit ended it; its exit status (`None` when it has none); whether a `system/init` event was read; the `status` word that event gives `hilclaw` in `mcp_servers` (`None` when it does not name it there); whether `mcp_server_errors` names `hilclaw`; whether `mcp_server_errors` holds any entry; whether each of the two tool names was in that event (two booleans); whether a `result` message was read; whether each token was in the text the model wrote (two booleans). The status word is compared and never returned.
- **What the function returns.** The outcome and what the report must say of it that the caller cannot see from its own arguments: for `front_refused`, "which of (a) and (b)" (both can hold; planner's suggestion: two booleans, both false for every other outcome). Nothing else.
- **"The session ended by itself."** Planner's reading: started, not ended by the time limit, and an exit status that is an integer of zero or more (a negative status is a signal on POSIX: something else ended it). Say what is taken for Windows, where a kill has no sign.
- **How the wire copy is handed in when there is none.** Planner's reading: `wire` is a `WireFacts` or `None`; `None` stands for "no readable wire copy" - no file, the reader's `WireCopyError` or `OSError` - and with it neither `front_refused`, `passed` nor `no_call` can hold. The caller maps the reader's exceptions to `None`; this module catches nothing.
- **A copy that is `torn` or holds an `unplaceable` line.** The record does not name either. **Planner's constraint, to the safe side (T-0162 Result line 196: "never let an `unplaceable` copy pass"): neither is ever `passed`.** Planner's reading for the rest: the facts the copy does establish stand - an error of condition (a) in such a copy is still `front_refused`, and `no_call` can still hold - and a session that would have passed but for `torn` or `unplaceable` is `session_failed` ("left no readable wire copy"), not `no_call` (nothing of the names, calls or tokens is missing). Weigh the other reading (such a copy establishes nothing at all) and say which was taken and why.
- **`hilclaw` with a word of the list in `mcp_servers` and also named in `mcp_server_errors`.** The row says both "gives it a `status` word of the list" (this outcome) and "an entry in `mcp_server_errors` ... [is] not this outcome". Planner's reading: the entry in `mcp_server_errors` wins, so not (b).
- **"No `mcp_server_errors` entry" of `passed`.** Planner's reading: no entry at all, for any server (the literal words; the safe side). With `hilclaw` connected and an entry for another name, `passed` cannot hold; `no_call` can, when its own condition holds.
- **Inputs that contradict each other** (a login outcome of step one together with evidence of a started session; evidence of a session not started together with an exit status). Planner's reading: the table is applied as it stands and the first row that holds wins; nothing is cross-checked.
- **What the function raises.** `TypeError` (or `ValueError` for a value of the right type and a wrong content) with a fixed text for an argument of another form: a login outcome that is neither `None` nor one of the three constants, a `wire` that is neither `None` nor a `WireFacts`, a session evidence of another type. **A member that must be a boolean counts as true only when it is exactly `True`** - `1`, `"true"`, a non-empty list never satisfy a condition of `passed`; whether such a value is refused or read as false is the executor's, and no reading of it may reach `passed`. **No default and no exception yields `passed`.**
- **The status word is compared exactly**: `"Connected"`, `" connected"`, `"connected\n"`, `b"connected"` and a non-string are not `connected` and not of the list.
- Nothing else.
