### The refusals
A tool call whose `tool_input.command` holds, as a simple command (outside quotes, in any position a `gh pr merge` is recognised today - after `;`, `&&`, `|`, inside `$( )`, after `env X=1`, after `then`), one of the following is refused with exit status 2 and a one-line reason that names the forbidden command; `gh` is not called for it:
- **`git push` with a force flag**: at least `--force`, `--force-with-lease` (with or without `=<value>`), `--force-if-includes`, and a short-flag word that holds `f` (`-f`, `-fu`, `-uf`), in any position among the arguments of `push`; a `git` word is recognised the way a `gh` word is (`git`, `git.exe`, a path ending in either, any case), and options between `git` and `push` (`-C <dir>`, `-c <name>=<value>`) do not hide it.
- **`rm` with both a recursive and a force flag**: `-rf`, `-fr`, `-Rf`, `-r -f`, `-rvf`, `--recursive --force` and mixed forms, whatever the operands are (DRIVER §1-5 forbids the command, not a target).
- **`gh repo delete`**, with or without an operand or flags.
- A command line that cannot be tokenised (an unclosed quote) and that looks like one of the three - by a pattern in the manner of `_LOOKS_LIKE_MERGE` - is refused; one that cannot be tokenised and looks like none of the three and not like a merge proceeds, as today.
- **Text inside a quoted argument is never a forbidden command**: `git commit -m "never use rm -rf or git push --force"`, `gh pr create --body "... gh repo delete ..."`, `echo 'rm -rf x'` proceed. This is the reason the tokeniser is reused; a check of the raw string is not acceptable.
- Not refused: `git push`, `git push origin HEAD:main`, `git push --delete origin <branch>`, `git push -u origin <branch>`, `rm <file>`, `rm -f <file>`, `rm -r <dir>`, `rmdir <dir>`, `gh repo view`, `gh repo clone`, `git fetch --force`, `git checkout -f`, `git clean -fd`, `git reset --hard` (DRIVER §3-0 uses the last two).
- The forbidden commands are checked before any `gh pr checks` is run; a command line that holds both a forbidden command and a merge is refused for the forbidden command without a call of `gh`.
- A payload without a string `tool_input.command` proceeds, as today; no filter on `tool_name`.

A git word is `git`, a path ending in `git`, or any word ending in `git.exe` / `.cmd` / `.bat`, any case; options between `git` and `push` (`-C`, `-c`, `--git-dir`, `--work-tree`, `--namespace`, `--super-prefix`, `--config-env`, `--attr-source` with their values, any other dash word) do not hide it.
  - `rm` with a recursive and a force flag in any spelling (`-rf`, `-fr`, `-Rf`, `-r -f`, `-rvf`, `--recursive --force`, abbreviations, mixed), anywhere after `rm` up to `--`, whatever the operands are; the PowerShell `Remove-Item` and its aliases (`rm`, `ri`, `rd`, `del`, `erase`, `rmdir`) with `-Recurse` and `-Force` (abbreviations such as `-rec -fo` included).
  - `gh repo delete`, with or without operand or flags (a gh word as for merges).
  - In every position a merge is recognised: after `;`, `&&`, `|`, a newline, inside `$( )` and backticks, after `env X=1`, `sudo`, `xargs`, `find -exec`, `then`, on a continued line, for any `tool_name`.
  - The line is read in several ways and one refusal is enough: cut at every separator; with each `$( )`, backtick substitution or parenthesis counted as one word of the command around it (so `git push origin $(...) --force`, `git -C $(pwd)/repo push -f`, `Remove-Item (Join-Path $a b) -Recurse -Force` are refused); with braces ignored at the ends of a word and as limits of a PowerShell script block (`%{Remove-Item $_ -Recurse -Force}`); with a backslash before white space or `;` `|` `&` `)` as an escape and as the end of a Windows path (`Remove-Item .\build\ -Recurse -Force`).
  - An untokenisable line (unclosed quote, multi-digit number glued to a redirection) that holds, in order, the name, the sub-command and a flag of one of the three.
- Not refused (rows of `NOT_FORBIDDEN`): the whole "Not refused" list of this file, `git push --no-force`, `git stash push -f`, `rm -r -- -f`, `Remove-Item <file> -Force -ErrorAction SilentlyContinue`, and every mention inside a quoted argument or a comment.
- Provisional choices (conventions of this task, not requirements; nothing of DRIVER 1-5 was changed, no OD closed):
  - One public function with private helpers; `forbidden_command` and `merge_invocations` tokenise separately, so that the merge path is untouched.
  - A command is looked for at any word of a simple command, as a merge is; the price is the false refusals below.
  - `git` and the removal names need a path boundary or an `.exe` / `.cmd` / `.bat` ending (unlike `gh`), because "any word ending in `rm`" would refuse `confirm` or `terraform`.
  - A `+<refspec>` is refused: it is a force push without a flag. `--no-force` / `--no-force-with-lease` alone are not force flags; next to a force flag the line is refused whatever the order.
  - PowerShell `Remove-Item -Recurse -Force` and its aliases are refused as the same command (PowerShell is the other shell of the development machine and `rm` is its alias there); the `cmd` forms are not recognised.
  - Flags or commands from a variable, `xargs` input, an alias or a shell function are not recognised (a refusal of every `rm $x` would be useless).
  - A here-document body or an unquoted mention that holds one of the three is refused, as for merges.
- **Known limits - not recognised** (rows of `KNOWN_MISSES`; the guard is a second line behind the discipline of DRIVER 1-5, not a sandbox):
  - Flags or commands that only exist at run time: a variable (`rm $FLAGS x`, `git push $FLAGS`), the output of a substitution (`git push $(echo -f)`), a brace expansion that builds a flag (`rm -r{f,} x`), `$'...'`, the standard input of `xargs`.
  - `eval`, `bash -c "..."`, `cmd /c "..."`, `iex`, `Start-Process`, a module-qualified `Remove-Item`; aliases and shell functions (`git -c alias.p='push -f' p`).
  - A command inside a substitution in double quotes (`out="$(git push --force 2>&1)"`) or inside backticks in double quotes: quoted text is never a forbidden command (acceptance criterion), and the tokeniser does not tell an escaped `$(` from a live one.
  - An unquoted backslash path without `.exe` (`C:\tools\git push -f`).
  - A force push by configuration (`git -c remote.origin.push=+... push`, `git push --mirror`), `git send-pack`; the `cmd` forms `rd /s /q` and `del /s`; deletions through `gh api`; other ways of deleting (`find -delete`, `git clean`).
  - A `case` pattern inside a substitution (its unpaired `)` ends the substitution early); flags after a substitution directly followed by `#`; a process substitution as the value of an option before the sub-command (`git -C <(x) push -f`); a flag glued to a group (`rm -r(x) -f`); two PowerShell backtick escapes that pair up as a substitution and take a flag with them.
  - The known limits of the tokeniser listed in T-0007 `## Result` apply as they are (wrongly paired quotes of a here-document body or a PowerShell backtick-escaped quote hide what stands between them).
- **Known false refusals** (the command holds none of the three; rows of `FORBIDDEN` pin them): an unquoted mention (`echo rm -rf x`) or a here-document body; `git rm -r -f <path>`, `git rm -rf --cached .`; an operand spelled like a removal command followed by both flags (`cp src/rm dst -r -f`, `python -m pytest -k rm -rf`); `git push -o +x origin main`; a PowerShell block read as one command (`if (...) { git push } else { echo +1 }`); `high repo delete`; a PowerShell path ending in a backslash at the end of a line, joined with the next line (`rm -r .\a\` then `ls -Force`); an untokenisable line that holds name, sub-command and flag in order anywhere (so also `git ... push ... --follow-tags` in a body with an odd number of apostrophes).
