### The refusal
A tool call whose `tool_input.command` starts the program `claude` as a simple command, outside quotes, is refused with exit status 2 and a one-line reason that names it and PROCESS/DRIVER.md 1-5 (in the manner of the existing reasons); `gh` is not called for it, and it is checked before any `gh pr checks`, like the three forbidden commands.
- **Any subcommand, any flag, or none** (D16: "하위 명령·플래그 불문"): `claude`, `claude -p "x"`, `claude --print x`, `claude auth status`, `claude --version`, `claude mcp list`, `claude -p x --mcp-config f --strict-mcp-config`. The guard does not tell a harmless subcommand from another.
- **The program word**: `claude`, `claude.exe`, `claude.cmd`, `claude.bat` (`claude.ps1` is the executor's choice), a path ending in one of them (`/usr/local/bin/claude`, `~/.local/bin/claude`, `C:/tools/claude.exe`), any case - in the manner of `_GIT`, with a path boundary so that a word that only ends in or contains the name is not the program.
- **In every position a command is recognised today at the head of a simple command**: after `;`, `&&`, `||`, `|`, a newline, inside `$( )` and backticks, on a continued line, after variable assignments (`X=1 claude -p x`), and for any `tool_name` (PowerShell included).
- An untokenisable line (an unclosed quote) that looks like a start of `claude` - by a pattern in the manner of `_LOOKS_FORBIDDEN` - is refused; one that looks like nothing the guard knows proceeds, as today.
- **Text inside a quoted argument or a comment is never a start of `claude`**: `git commit -m "never start claude -p"`, `gh pr create --body "... claude auth status ..."`, `echo 'claude -p x'`, `git status # claude -p` proceed.
