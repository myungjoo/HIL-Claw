## Acceptance Criteria
### Fixed by the records (not re-decided; implement exactly)
1. **The list.** `hilclaw.check_failure.BACKEND_KINDS` holds exactly the two names `no_kernel_source` and `kernel_source_unreadable`, spelt so, and stays an immutable set. `KIND_OPERATION_FAILURE_INVALID`, every reserved kind of `hilclaw.tools.RESERVED_KINDS` and every other kind of this tool's contract (`operation_answer_invalid`, `seed_not_drawn`, the four of `hilclaw.check_admission.KINDS`) are not members.
2. **A raised backend kind is answered as raised.** For a tool failure an operation raised whose kind is one of the two, `ended_with` returns the raised kind and the raised message as they are (ADR-0047 decision 4), and through `hilclaw.check_ending.carry_out` and the tool function the end line's `failure` holds exactly that kind and that message, with the empty `spend` (ADR-0040 decision 6); the caller gets a tool failure of that kind and message; the identity is ended, and the same request afterwards is answered from the log with the same tool failure, with no backend selected and no script asked (ADR-0056 decision 7).
3. **Every other kind is answered as before.** A tool failure of any kind outside the two - a reserved kind, `operation_failure_invalid` itself, `seed_not_drawn`, a stand-in name - is `operation_failure_invalid` with a message of the module, exactly as today. The rows of `ended_with` for a kind or a message that cannot be read as exactly a `str` are unchanged, now reachable for the two real kinds without patching.
4. **Who raises.** Any backend may raise the two, a script of the mock included. The tool function raises neither itself and answers neither before the start line; `hilclaw/check_tool.py`, `hilclaw/check_seed.py`, `hilclaw/check_operation.py` and `hilclaw/mock_check.py` are not edited. `default_script` still raises no tool failure.
5. **The message is not checked.** `ended_with` checks nothing of a backend kind's message beyond its type (ADR-0047 decision 4; ADR-0056 decision 6: "A message that breaks this is not detected"). What the message may show is a rule for the code of an operation that raises, which this task does not write.
6. **A backend kind raised for a situation it does not mean "is taken as it is"** (ADR-0047 Limits): nothing in the chain looks at the output path, at a file or at the hw_profile to decide whether the kind fits.
