## Why
ADR-0033 (landed as `dfa1ef7`, T-0102) fixed the member of `runs/<run_id>/instance.json` in which a run states its budget of wall-clock time, the third axis of FR-3: the top-level member `wall_clock_budget_s`, an integer number of seconds. Its Consequences cut one code slice:

> **The code slice that can now be cut** (within the size cap, code mode): in `hilclaw/instance.py`, the validity of the member by decision 3 and a reader of the wall-clock budget of a run beside `round_budget_of`, with tests in `tests/test_instance.py`. The name and the return form of that reader and how "not stated" is told from a value are the code task's. **Binding the reader to a clock, to `STATE.json`, to the log, to a tool or to anything that ends a run is not part of that slice**, and neither is measuring the time of a run or writing the file. `hilclaw/instance_file.py` takes the validity of a content from `hilclaw.instance.parse`, so it refuses a content with an invalid member once the slice lands, without a change of its own.

**This task is that slice.** Today `hilclaw/instance.py` defines eight members (`schema_version`, `hw_profile`, `tolerance`, `source_commit`, `n_max`, `candidates_per_round`, `op_signature`, `round_budget`); a `wall_clock_budget_s` of any value - `0`, `"8h"`, `true` included - is handed back uninterpreted in `Instance.others`, the file counts as valid, and nothing in the package can answer "which wall-clock budget does this run state".

It serves PLAN P1-8 ("런타임 STATE/instance/events 스키마"). It ticks **no PLAN checkbox**: P1-8 stays open (further members, the writer and the start of an instance, the result files, the rest of `STATE.json`, the event kinds).
