## Why
PLAN P1-8 ("런타임 STATE/instance/events 스키마 - OD-8 종결 필요(§9 ADR 경로)") is open. `instance.json` has its frame and four members - `hw_profile` (ADR-0018), `tolerance` (ADR-0020), `source_commit` (ADR-0022) and `n_max` (ADR-0023) - all implemented in `hilclaw/instance.py`. Of the three facts ADR-0004 put into the purpose of the file ("What the instance was started with; source commit (#5 A-1); layout version"), the layout version is the last one without a place:

> This tree is **layout version 1**. The version is raised when a path, file name or number form fixed here changes; it is not raised when a file is added in a place this record leaves open. The version is recorded **per run, in `instance.json`** [...]. The path `runs/<run_id>/instance.json` is the same in every layout version: a reader finds the version there before it uses any other path of the run. The name of that stamp, and whether it is a field of its own or follows from a `schema_version`, belongs to the instance schema and to OD-11. - ADR-0004 decision 9

- ADR-0018 decision 2 kept both shapes open on purpose: `schema_version` "is not, by this record, the layout version stamp [...] neither answer is chosen or excluded - a later record may add a member, or add 'a change of the layout' to what raises this version." Its Alternatives table rejects deciding it there ("It would decide what ADR-0004 decision 9 left to the instance schema and OD-11; the frame can be stated without it").
- ADR-0012, ADR-0018, ADR-0020, ADR-0022 and ADR-0023 each name "the layout version stamp" in their Boundaries (ADR-0020 through the list of ADR-0018) as a matter of a later record; ADR-0005 and ADR-0006 say their `schema_version` is independent of the layout version.
- The code holds the number and nothing reads or writes a stamp: `hilclaw/layout.py` has `LAYOUT_VERSION = 1` (used by no other module; `tests/test_layout.py` pins the value), and `hilclaw/instance.py` defines `schema_version`, `hw_profile`, `tolerance`, `source_commit` and `n_max` and hands every other top-level member back uninterpreted in `Instance.others`.

DRIVER §6: a task that needs a design-level decision carries the record that closes it; the route used so far is two tasks (record, then code). **This task writes the record**, ADR-0024. It ticks **no PLAN checkbox** (P1-8 stays open: further members, the writer and the result files remain).

Planner's judgements (2026-10-09, from the files; the reviewer is asked to re-check each):
- **Design-level, not owner-only.** That the layout has a version, that it is 1, what raises it and that it is recorded per run in `instance.json` is ADR-0004's (accepted under §9 on 2026-10-07, objection window until 2026-10-14). - **How far it hangs on OD-11** (the judgement the T-0079 planner note asked for). OD-11 is `제안됨`; its confirmed part is only "P1 harness version = source commit hash" (#5 A-12). Its two proposals - the pin of the measurement contract with forced re-measurement, and "P1 = `schema_version` stamp recorded; reading older versions and migration tools are P2; a resume of a run of another version detects and reports" - are **unconfirmed**, and the second may not be written into NFR-7 ② without the owner (OpenDecisionProposals OD-11, second bullet). The planner reads the stamp as separable from them: **that a stamp is recorded** is ADR-0004's and needs no OD-11 proposal; **what a reader does with a run whose layout version it does not know** (read it, refuse it, migrate it, resume it) is OD-11 and is excluded here. ADR-0004 says "a reader finds the version there before it uses any other path of the run": a shape under which a valid file can be silent about the layout leaves that reader with nothing, and a shape that makes a new member required raises `schema_version` before a first run exists (ADR-0018 decision 2, "What raises the version"). ## Acceptance Criteria
What is **fixed** and taken as input, not re-decided:
- **ADR-0004 decision 9** (accepted under §9; its own choices, not the owner's): the tree is layout version 1; the version is raised when a path, file name or number form fixed there changes and not when a file is added in a place it leaves open; the version is recorded per run, in `instance.json`; a finished run is not rewritten into a newer layout; `runs/<run_id>/instance.json` is at the same path in every layout version; `db/` needs no stamp of its own in version 1.
- **ADR-0018 decision 2**: the frame of the file, `schema_version` = 1 as the version of the schema of this file, the open top level, the rule of what raises `schema_version`, what a version 1 reader does with another `schema_version`, and that both shapes of the stamp are open. ADR-0020, ADR-0022 and ADR-0023: the members that exist.
- **OD-11**: status `제안됨`; confirmed is only the P1 harness version = source commit hash (#5 A-12). Its two proposals are **not** inputs.
- Nothing is kept between calls (ADR-0010 decision 7). The file is written once and nothing enforces it (ADR-0004).

What the ADR **decides**. The content of each decision is the executor's to work out and justify from the fixed inputs; the reviewer's Approve confirms it. For every point give the choice, the alternatives considered and one or two lines of reason; mark each statement as **cited** (with the record and the decision) or as **this record's own**:
1. **Scope**: of `runs/<run_id>/instance.json`, how the file states the layout version of its run; nothing else of the file and nothing of any other file. State that the file is still not a complete instance record (ADR-0018 decision 1).
2. **What the stamp states.** The layout version, in the sense of ADR-0004 decision 9, of the tree under `runs/<run_id>/` of this run. Say exactly what a reader of this record may conclude and what it may not: it speaks of paths, file names and number forms of ADR-0004, not of the content of any file (cited: ADR-0005, ADR-0006, ADR-0012 on the independence of their `schema_version`), not of `db/` or `blobs/` (weigh ADR-0004's "`db/` needs no stamp of its own in version 1" and say what the fixed inputs carry for the top level - leave the rest open by name), not of the source that wrote the run (that is `source_commit`), and nothing checks that the tree of the run in fact has the stated layout.
3. **The shape of the stamp.** Weigh at least: (a) **a top-level member of its own** (a name of this record's choice - for example `layout_version` - and an *integer* form; say what is no value, in line with how ADR-0023 decision 3 and `hilclaw/instance.py` read an *integer*: no boolean, no fraction, no exponent, no string of digits; and whether a version 1 validator accepts only the value 1 or any *integer*, with what follows for a file that states another one - see the last boundary of this list); (b) **the stamp follows from `schema_version`** - "a change of the layout" is added to what raises `schema_version`, so every valid version 1 file states layout version 1 and no member is added; weigh the coupling (every layout change makes every reader of the file meet another `schema_version`, and a later `schema_version` raised for another reason needs a stated mapping to a layout version) against ADR-0005 / ADR-0006 / ADR-0012, which keep the two kinds of version apart for their files; (c) both (a member of its own that a version 1 file must hold) - then see point 4 on the version. Say for the chosen shape how "a reader finds the version there before it uses any other path of the run" (cited) is met by a reader of this record.
4. **A file that states no layout version; the `schema_version`.** By ADR-0018 decision 2's own rule, which leaves the choice between "a member that may be absent from a valid file" and "a new version" to the record of the member. For shape (a) weigh at least: the member may be absent, `schema_version` stays 1 and absent means "not stated" (then say what a reader of this record has for such a run - nothing, not `LAYOUT_VERSION` of its own source: a constant of whichever source reads the file is not what the run recorded, ADR-0023 decision 4 is the precedent - and say honestly that ADR-0004's "a reader finds the version there" then fails for that file); the member is required and `schema_version` becomes 2 (then every file and reader of today is of another version before a first run exists, and reading another version is OD-11); absent **means** layout version 1 as a rule of schema version 1 (a number written in the record, not a constant of a source - weigh whether that is shape (b) under another name). For shape (b) there is no absent case; say so and say what the Limits then are. If a member is present it must be valid; say whether a present and invalid member makes the file invalid as a whole (ADR-0020 decision 3, ADR-0022 decision 5 and ADR-0023 decision 4 are the precedents; confirm or correct). **Whichever is chosen, no sentence may make the layout version of a run depend silently on something the run did not record.**
5. **How it is read**, only as far as it follows from the fixed inputs: from the file of the run, the file read as a whole, at each use, nothing kept between calls. Observations to state truthfully: nothing reads or writes a stamp today; `hilclaw.layout.LAYOUT_VERSION` is used by no other module; the paths of a run are built by `hilclaw/layout.py` without reading `instance.json`, and a journaled call looks into `events.ndjson` before the selection reads `instance.json`.
