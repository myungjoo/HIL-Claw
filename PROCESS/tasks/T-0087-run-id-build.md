### The functions (recommended shape; names yours)
1. **The form (decision 2)**, a pure function, for example `compose(time, random)`, returning a `str` of exactly 33 characters: the 16 characters `YYYYMMDDthhmmssz`, one hyphen, 16 characters of `0-9a-f`.
   - The time part is the given time in UTC to the second: the year in four digits with leading zeros (`0001` to `9999`), month, day, `hh` 00-23, `mm` and `ss` 00-59 in two digits each, `t` and `z` in lower case. **Do not rely on `strftime("%Y")`**: on Linux it does not pad a year below 1000; format the fields yourself.
   - The random part is the given 64 bits as lower-case hexadecimal, padded with leading zeros to 16 characters (0 gives `0000000000000000`, 2**64 - 1 gives `ffffffffffffffff`).
   - What the function takes as "the time" and as "the bits" is yours (planner: a `datetime.datetime` and exactly an `int` with 0 <= value < 2**64, by the rule of `hilclaw/harness/seed_source.py`). Decide and state, each with a reason and a test: a fraction of a second (the form is "to the second"; planner: dropped, not rounded); a time without a time zone; a time with a zone that is not UTC (refused, or converted to UTC - choose one and say why); a value that is no time; bits that are a `bool`, a `float`, negative, 2**64 or more, or not an `int`. **A value that cannot be written in the form is reported, not written** (ADR-0027 decision 7; T-0086 first Follow-up): nothing is clamped, wrapped or replaced. With `datetime` a year outside `0001`-`9999` and a second of 60 cannot be given at all; if you choose another type for the time, those two are cases the function must refuse. Which exception reports each is yours (a `TypeError` for a wrong type and a `ValueError` or a class of the module for a wrong value is the package's habit).
2. **An id for a run (decisions 2 and 6)**, a function without arguments, for example `new()`: it takes the UTC reading of the clock of this machine at the call and 64 bits from the operating system's source of random bits (`secrets.randbits(64)` or an equal standard-library call - **never the module `random`, never a seed, never anything derived from the time, the process id or a caller**) and returns the id of rule 1. It accepts no argument through which a caller could hand in a time, bits, a seed or a generator. How a test fixes the two (replacing a module-level name with `monkeypatch`, as `hilclaw/events.py` does for its clock) is yours. What the platform raises when it has no random source is passed on.
3. **Nothing else (decisions 1, 3 and 5).** No function of the module checks, parses, recognises or compares an id: no "is of the form", no reading of a time out of an id, no ordering helper. Nothing reads, lists or creates a path; no `data_root` is taken; nothing is kept between calls (no counter, no last id, no cache); no retry and no second draw. `hilclaw.layout.check_run_id` is not replaced, wrapped or tightened. Whether the module calls `check_run_id` on its result is yours (every id of the form matches the pattern, so it can only be an assertion); the tests check it either way.
4. Whether the shape `[0-9]{8}t[0-9]{6}z-[0-9a-f]{16}` or the length 33 is exposed as a public constant is yours; if it is, the docstring says that it is the shape of what the module builds and **no rule of validity** for a `run_id`.
