## Why
PLAN P1-9 is the runtime self-check the owner ordered in the answer to HQ-0006 (b-2): a check of the `hilclaw` package that the bring-up of an instance runs **on the runtime machine**. Its design record is ADR-0054 (T-0153). Seven slices have landed, each bound to nothing: step one (`hilclaw/selfcheck_login.py`, T-0160), the server side with the wire copy (`selfcheck_server.py`, T-0161), the reading of the wire copy (`selfcheck_wire.py`, T-0162), the outcome table (`selfcheck_outcome.py`, T-0163), the reading of the session's output (`selfcheck_stream.py`, T-0164), the session (`selfcheck_session.py`, T-0165) and the report (`selfcheck_report.py`, T-0166, `d489a43`).

**This task is the last slice: it binds them.** One new module calls step one, calls step two only when step one says logged in, builds the report, writes its one line to standard output and returns the exit status; and it is the "one command of the package" of decision 1. After it, a bring-up (PLAN P2-1, not this task) has one thing to start.

**This task completes PLAN P1-9: when it is DONE the driver ticks the P1-9 checkbox at wrap-up** (the executor does not edit PLAN). It changes no OD and no `ARCHITECTURE/` file.

## Acceptance Criteria
### Fixed by the record and by the code on `main` (not re-decided; implement exactly)
1. **One new module, `hilclaw/selfcheck.py`, is the whole check.** Its `main` runs one check and returns the exit status; `python -m hilclaw.selfcheck` runs it and exits with that status. `hilclaw/__main__.py` is **not** edited: its only argument is a tool name of the registry, and the check is "not an FR-10 tool and not in the registry" (line 55).
2. **The order** (decision 3; T-0166's follow-up), exactly:
   - `login = selfcheck_login.read(timeout_s=<the limit of step one>)`, with no `cwd` (the record names none: it is inherited);
   - **only when `login.outcome is None`**: `run = selfcheck_session.run(timeout_s=<the limit of the session>, keep_out=<criterion 4>)`; otherwise `run = None` and **no session is started** (lines 71-72);
   - `report = selfcheck_report.build(login, run, system=selfcheck_report.system_facts())`;
   - `selfcheck_report.line(report)` is written to standard output, which is flushed; nothing else is ever written to standard output;
   - the status returned is `selfcheck_report.exit_status(report["outcome"])`.
3. **Exactly one call of each step, no retry** (line 91): `read` is called once; `run` at most once; whatever the outcome, nothing is tried again and `claude auth login` is never run (line 73).
4. **The data root is named to step two** (line 87, "outside both checkouts"; T-0165: "the composing slice must pass the data root"): `keep_out` holds the data root the configuration names (`data_root_source.configured()`), asked once, when one is configured. The check reads nothing in the data root and writes nothing there, and does not ask that it exists (decision 5: the check needs no data root).
5. **The environment is untouched** (line 95, L6): the module sets, removes and reads no environment variable of its own (what `hilclaw.config` reads for the data root is that module's), and passes no `env`.
6. **Nothing but the report leaves on standard output, and the child's standard error is not passed on** (line 139). The module prints no progress, no path, no token, no command line.
7. **No data-plane file** (O7, line 135): the module writes no file at all; the only files of a check are those `selfcheck_session.run` makes and removes.
8. **Exit status**: 0 only when the report was written and its outcome is `passed`. Never 1 and never 2 (line 140).
9. **Nothing existing changes**: no existing module is edited and no private name (a leading `_`) of another module is imported.
