## Why
PLAN P1-1 (the FR-10 tool contracts, the mock backend, the conformance tests) is open. For `correctness.check` the code on `main` is a row of pure modules bound to no tool: `hilclaw.check_result`, `hilclaw.check_judging`, `hilclaw.check_answer`, `hilclaw.check_parameters`, `hilclaw.mock_check` and `hilclaw.check_operation` (T-0137: one call of an operation; a returned value of neither form and a raised error become `OperationAnswerInvalid`; **a `ToolFailure` an operation raises is handed on as the same object, "no rule of a record"**).

Since T-0139 a record has that rule: **ADR-0047**. After an operation raised a tool failure the step is ended with a `failure`, whatever kind was raised (decision 3). Where the raised kind is a *backend kind* the `failure` holds the raised kind and message; where it is a *kind outside the contract* the `failure` holds the tool's own kind `operation_failure_invalid` with a message that carries nothing of the raised message (decision 4). The contract names no backend kind, so **today every tool failure an operation raises is answered with `operation_failure_invalid`** (decision 5).

Nothing in the package renders that record: the string `operation_failure_invalid` occurs nowhere under `hilclaw/` or `tests/`. T-0139 `## Result` lists the code as a follow-up ("the pure part of the rule: from the kind of a tool failure an operation raised to the kind and message the step ends with", only "if it can be a new module with its own test file that edits no existing assertion") and says what the tool function needs ("For the code task, concretely").

**This task carries that pure part into the package as one small module, ahead of the tool function** - the same kind of slice as T-0130, T-0131, T-0133, T-0135 and T-0137. The tool function (after HQ-0012 and the remaining slices of the second record) then has the kind spelt once, and the message rule and the reading of a raised object tested once. **This task builds no tool function, no step, no registration and no end line, and it does not call an operation.**

The task ticks **no PLAN checkbox**: P1-1 stays open.

### The module
Recommended public names, and no other: `KIND_OPERATION_FAILURE_INVALID`, `BACKEND_KINDS`, `ended_with`.

- **`KIND_OPERATION_FAILURE_INVALID`** - the string `"operation_failure_invalid"` (ADR-0047 decision 4), spelt once in the package. It is a name of ADR-0001 and **not** a member of `hilclaw.tools.RESERVED_KINDS`, which is not edited.
- **`BACKEND_KINDS`** - the list of the backend kinds of this source: an empty `frozenset` (ADR-0047 decision 5: "The contract as it stands has no backend kind"; "the tool function of a source commit has the list of that commit"). Its docstring comment says that a kind is added only when a record of this tool's contract names it. It does not hold `KIND_OPERATION_FAILURE_INVALID` ("It is no backend kind").
- **`ended_with(raised)`** - from a tool failure an operation raised to what the `failure` of the end line holds: it returns the pair `(kind, message)`, each exactly a `str`, `kind` a name, so that `hilclaw.tools.ToolFailure(kind, message)` and `hilclaw.journaled_step.StepFailed(spend, kind, message)` can be built from every pair it returns.
  1. **Before anything else**: a `raised` that is no instance of `hilclaw.tools.ToolFailure` raises `TypeError` (the caller's own defect; an error that is no tool failure is `hilclaw.check_operation`'s part, ADR-0045).
  2. **A kind outside the contract** (ADR-0047 decision 4, third bullet) - with `BACKEND_KINDS` empty, every tool failure: the pair is `(KIND_OPERATION_FAILURE_INVALID, <a message of this module>)`, whichever kind was raised: a reserved kind (each of the thirteen), `operation_failure_invalid` itself, another kind of this contract, a kind another tool's record names (`blob_unreadable`), any other name.
  3. **A backend kind** (decision 4, second bullet; the sixth row of the table of decision 8) - a kind that is a member of `BACKEND_KINDS`: the pair is the raised kind and the raised message, as they are. No call takes this path today; the tests reach it by replacing the constant (`monkeypatch.setattr`). The docstring says, by citation, that a record that names a backend kind says what its message may hold and "may decide otherwise for its kind". **If the executor or the reviewer finds that rendering this row says more than the record does, leave it out** (then no `BACKEND_KINDS` either, and the docstring says in one sentence that the row for a backend kind is not rendered because no such kind exists); say which in `## Result`.
  4. **How the raised object is read** (this task's choice; the record's Limits call a backend that does not answer the contract "not detected"): `kind` and `message` are attributes a backend's code can replace after construction. Recommended: each is read once; a `kind` whose type is not exactly `str`, or a failed read, is answered as a kind outside the contract (never an error of the backend's code out of this function, never a `TypeError` for an unhashable value); on the backend-kind path a `message` whose type is not exactly `str` is answered as a kind outside the contract as well. State the choice in the docstring as the module's own and no rule of a record.
  - No parameter has a default. Nothing is kept between calls; `raised` is not modified; no file is read or written; no clock or random source is read.
- **The message of `operation_failure_invalid`** (ADR-0047 decision 4, "The message of ..."):
  - Composed by this module from constants built when the module is imported, as `hilclaw.check_operation` does it. It says that the operation raised a tool failure of a kind the contract does not let a backend raise.
  - It carries **nothing of the message that was raised**, and it does **not show a raised kind that is neither a reserved kind nor a kind of this contract**.
  - Optional by the record, recommended here: it says whether the raised kind was a reserved kind or not, and for a reserved kind it names it (the name is then one of `hilclaw.tools.RESERVED_KINDS`, a list the records fix; membership is tested with a value that is exactly a `str`). The module does not tell a kind of this contract from any other name (see the planner's judgement on the kept-out strings); the docstring says that the record allows more and why the module says less.
  - Composing it never raises and never calls code of the raised object beyond the reads of point 4. It is exactly a `str` of bounded length. Nothing may depend on its wording; the docstring says so, and the tests pin no wording beyond these bullets.
- Docstrings: the module docstring says what the module renders (ADR-0047 decisions 4 and 5, by number), the choices that are the module's own (the pair instead of an exception; how the raised object is read; what the message says of the classes), and what the module does not do: it is no tool and no step and is bound to none; it calls no operation and catches nothing; it does not say which tool failure was raised by an operation (its caller does); it appends no line and states no spend; it names no backend kind; it says nothing of what anybody does after the answer. Each public name gets a Doxygen-style docstring in the manner of `hilclaw/check_operation.py`. **No docstring states a rule the records do not hold.** Comments follow CLAUDE.md "코멘트 최소화".
