### The function
- One new public function in `hilclaw/gemm_contract.py`, taking one op_signature record. Recommended name and signature: `covers(record)`; another name is the task's choice (check `hilclaw/` and `tests/` for a collision and say so).
- **For a record that `hilclaw.keys.op_signature_key` accepts**, it returns exactly `True` or `False` (`bool`): `True` when `record["kind"]` is `KIND`, `record["dtype"]` is `DTYPE`, `record["layout"]` is `LAYOUT` and each of `record["shape"]["m"]`, `["k"]`, `["n"]` is at least 1; `False` otherwise. The upper bound of a dimension is that of a valid record (`keys.MAX_INTEGER`); no other bound is added.
- **All four conditions are written out in the code**, the `kind` condition included, although today's `hilclaw.keys` refuses every kind but `gemm` (ADR-0041 decision 9, "Two sources, two answers": a source that knows another kind must answer "not covered" for it, not treat it as `gemm`).
- **`ext` and `label` are not looked at for the answer**: a record that is covered stays covered with any valid `ext` and any valid `label`; one that is not covered is not made covered by either.
- **An argument that `hilclaw.keys.op_signature_key` refuses** (not a mapping, a missing or unknown field, a wrong `schema_version`, a `dtype` that is no name, a `bool` or negative dimension, an empty `ext`, ...). Recommended, and the planner's expectation: the function validates with `keys.op_signature_key(record)` first and lets its `keys.InvalidRecordError` pass through unchanged, so that `False` always means "a valid record this contract does not cover" and never "not a record". If the executor chooses otherwise, the choice must still be determinate for every argument (no `KeyError` / `TypeError` / `AttributeError` leaking from an unchecked lookup, and no `True` for anything `op_signature_key` refuses), documented in the docstring and tested.
- The function is pure: it does not modify `record`, reads and writes no file, starts no process, keeps no state; two calls with equal records give equal answers.
- It returns nothing but the `bool`: no key, no dimensions, no reason, no failure kind. The string `op_signature_not_covered` does not enter `hilclaw/` in this task (it is a value of `error.kind` of one tool, and this module is bound to no tool).
- **No new import** in `hilclaw/gemm_contract.py`: the module's imports stay `reprlib` and `hilclaw.keys` (the existing test `test_module_is_bound_nowhere_and_imports_keys_only` asserts this and is **not** edited). No other file under `hilclaw/` comes to mention `gemm_contract`.
