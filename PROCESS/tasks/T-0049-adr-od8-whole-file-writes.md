## Why
ADR-0013 fixed how the runtime `STATE.json` is replaced on disk and registered **sub-question ⑮ of OD-8**: "Whether the other files that are rewritten as a whole — `artifacts.json`, the key record files — are written by the same technique (ADR-0005 Boundaries; with OD-17)". Its Consequences say: "`artifacts.json` is written in place today (`hilclaw/artifacts.py`), and a death inside that write can leave a file that its reader reports as corrupt. ADR-0005 left atomic writes open for that file."

The facts today, none of them a recorded decision:
- `hilclaw/artifacts.py` `_write` opens `runs/<run_id>/artifacts.json` with `"wb"` (truncating) on **every** added record and every class change. A process killed inside that write leaves a partial file; every later `load`, `add_record` and `set_retention_class` of the run then raises `CorruptArtifactsError` until someone restores the file from the history — and the records added since the last commit are lost with it, although their blobs are stored (ADR-0005 decision 8, "blob first, then record"). T-0025 `## Result` follow-up (f) asks whether this needs a rule.
- `hilclaw/key_records.py` `_store` creates `db/<hw_profile_key>/hw_profile.json` and `db/<hw_profile_key>/<op_signature>/op_signature.json` with `"xb"`. A process killed inside that write leaves a partial record file, reported as `CorruptKeyRecordError` "until it is removed by hand" (module docstring; T-0023 `## Result` follow-up (a)). **A key record file is not rewritten**: the module never modifies, replaces or deletes a stored record, and whether an attribute may be updated is OD-26. So the wording of ⑮ ("rewritten as a whole") fits `artifacts.json` and not, by the letter, the key record files; what the technique means for a file that is created once (the move of ADR-0013 step 4 *replaces* an existing file, and ADR-0001 decision 3 says that a tool that finds a differing stored form "writes nothing") is a point the record must work out.
- Both module docstrings give the reason "no path of `runs/` (`db/`) is a scratch location (ADR-0004 decision 7)" for writing without a temporary file. ADR-0013 decision 3 has since read that decision as one about scratch *directories*, for `STATE.json` only.

A code task cannot change either write as a "provisional convention": a temporary file beside `artifacts.json` or inside a key directory is a statement about what may exist in the data plane, what a commit takes and what a reader makes of a leftover — the reason T-0046 gave for a record before T-0047. DRIVER §6: a task that needs a design-level decision carries the record that closes it; the route used so far is two tasks (record, then code). **This task writes the record**, ADR-0014. It ticks **no PLAN checkbox** (P1-6 is ticked and stays so; P1-8 stays open).

### Decisions of ADR-0014 (`ARCHITECTURE/decisions/ADR-0014-od8-whole-file-writes.md`, 128 lines; the change is 139 insertions, 9 deletions, 4 files — inside the 300 LOC / 5 files cap)
1. **Scope**: how the bytes of `runs/<run_id>/artifacts.json`, `db/<hw_profile_key>/hw_profile.json` and `db/<hw_profile_key>/<op_signature>/op_signature.json` come under their final names. No member, value list or validity rule of ADR-0005 or ADR-0001 changes; nothing `artifacts.validate` or `hilclaw.keys` accepts changes; nothing of who writes, of the lock or of any other file.
2. **`artifacts.json`** (the record's own; the steps are ADR-0013's): every write, the first included, is a replacement by the five steps of ADR-0013 decision 2, the content valid by ADR-0005 decisions 2, 3 and 6. What the new content is stays ADR-0005's (previous records plus one addition or one allowed edit); no rule is added for an invalid previous file. The missing file is the "previous content" and the replacement may create the run directory. **Gained beyond `STATE.json`**: the file accumulates between commits, so the death of the writer of the k-th record no longer destroys the k − 1 records before it. Rejected: the in-place write plus the last commit (today); a recovery rule that rebuilds a partial file (the store has no `type`, `round` or class and is shared between runs; the files that name a blob by hash are undefined — ADR-0005 decisions 8 and 10); an append-only form (a change of ADR-0005 decision 2).
3. **Key record files** (the record's own): created once. Requirement: a death leaves no record file or the whole one. Steps 1 to 3 and 5 as ADR-0013 (temporary file in the key directory). **The last step gives the final name only if it does not exist, in one step, and otherwise changes nothing; a replacing rename is not this step and there is no fallback to one** (on a file system without hard links or a non-replacing rename the write fails). Reason: a replacing move could put a record over one that appeared after the writer's check — with an equal canonical form and other attributes an update OD-26 has not allowed, with another canonical form a write where ADR-0001 decision 3 says "writes nothing". Today's exclusive creation already has the property; the requirement keeps it and is not a lock. Means: POSIX `link()` then removal of the temporary name, or a rename that does not replace — the code task chooses. When the name is found taken, nothing was written under it and ADR-0001 decision 3 applies to the record there; only the form of the report is the code task's. The write may create `db/` and the key directories; a death can leave a key directory without a record file in the working tree (as today); ADR-0004 decision 1 and "written when the directory is created" of decision 5 are read as statements about the committed tree. "A key is stored iff its record file exists" is cited as a convention of `hilclaw/key_records.py`.
4. **Temporary files**: `<final name>.<token>.tmp` in the directory of the final file, `<token>` = `[a-z0-9-]{1,64}`, different per write (the form of ADR-0013 decision 3). Not in `layout.RUN_FILES`; in a key directory the dot keeps it from being a key directory name (ADR-0004 decision 5). No name is reserved for later files. **Readings of ADR-0004**: for `runs/` those of ADR-0013 decision 3; **for `db/` the same reading** (decision 5 is about files with a meaning; decision 7 about directories in which an actor works); nothing of OD-20 / OD-7 and nothing of where scratch directories are is decided or narrowed. Layout version 1. Never committed; the `*.tmp` line of the data repository is a second guard, cited as a fact; no change there is made or required.
5. **A leftover** is not a record: never read in the place of the final file, never given the final name, never committed; a reader lists nothing; removal allowed, not required. With `link()`, a death between the link and the removal leaves the temporary name as a second name of the stored record — a leftover like any other.
6. **Promised**: the death of the writing process; a reader during a write sees one of the two states. **Not promised**: machine loss (#5 A-3). The flush stays required (both modules flush on every write today, so the rule adds a creation and a rename, or link and removal). Cost for `artifacts.json` named, not measured. Environments as ADR-0013 decision 5, plus the non-replacing step for key records. **Two writers stay a limit**: the lost update of `artifacts.json` exists today and remains; only a mixture of two writes is excluded. No atomicity is added between the store and the file, between files, or with a commit.
7. **Other files**: three files only; nothing is decided for `instance.json`, `spec.json`, the result files, `best.json`, `technique_stats.json`.
