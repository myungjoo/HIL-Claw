### `hilclaw/mock_check.py` - the mock's operation of this tool and the default script's answer
Recommended public names: `operation`, `default_script`. No other public name beyond imported modules.

- **`operation(script)`** - returns the mock's operation of `correctness.check` bound to `script` (ADR-0044 decision 2):
  - It is called as `operation(request, hw_profile, parameters)` with **exactly these three positional arguments**; any other number of arguments and any keyword argument is Python's `TypeError`, and the script is then not asked.
  - It asks the script **exactly once**, as `script("correctness.check", request, hw_profile, parameters)`, with the three objects **as they are** (the same objects; none copied, derived, replaced, checked or left out), and at no other moment: building asks the script nothing.
  - **It does not look at the answer**: it returns the very object the script returned, whatever it is (`bytes`, one of the two strings, `None`, a `dict`, `"pass"`), and catches nothing - a `ToolFailure` of any kind, any other `Exception`, `SystemExit` and `KeyboardInterrupt` pass through as the same object with no `__cause__` added. It does not look at `parameters` either: a third thing that is no `CheckParameters` reaches the script unchanged.
  - It keeps nothing between calls and adds no clock, random source, counter or file.
  - `script` that is not callable is refused with `TypeError` when the operation is built (as `mock_backend.backend` does).
  - The object returned is callable and accepted by `hilclaw.backends.Backend(hilclaw.mock_backend.NAME, {"correctness.check": ...})`; a `repr` in the manner of `mock_backend._Operation` is recommended.
  - Whether `mock_check` imports `hilclaw.mock_backend` or `hilclaw.backends` is the executor's choice (neither is needed); it builds **no** backend and no table.
- **`default_script(tool, request, hw_profile, parameters)`** - the default script's answer for this tool (ADR-0044 decisions 3 and 4):
  - For check parameters it can compute a report for it returns exactly `bytes`: **a complete report for `m`, `n` and `draws`** in the form `hilclaw.harness.verification.judge_report` takes as complete (`draws * (4 + 4*m*n) + 4` bytes). For each draw `d` from 0, in order: the check value of the inputs the generator gives for the seed, `d` and the dimensions, in the harness's spelling (4 bytes, `=I`); then the `m*n` fp32 elements in row-major order, as the bytes they have on the host, **each element the fp32 value nearest to the corresponding element of the float64 product of the inputs widened to float64**, ties to the value whose last significand bit is 0. After the last draw the end mark (`verification.END_MARK`, not spelt a second time), and nothing else.
  - **The answer depends on `parameters` alone.** `tool`, `request` and `hw_profile` are not read, not checked and not modified: any objects there (`None` included) give the same bytes. It reads no clock, random source, counter, file or environment variable, starts no process, keeps nothing between calls and modifies no argument.
  - **Which code computes it** is the executor's choice and is stated in the docstring and in `## Result`. Recommended: `verification_arrays.draw_inputs`, `check_value` and `reference`, then `.astype(numpy.float32)` (NumPy rounds to nearest, ties to even, under the default rounding mode - ADR-0044 decision 4, observation), `struct.pack("=I", ...)` and `verification.END_MARK`, so that the framing is the harness's of the same source commit. **The docstring then states the shared-defect limit of ADR-0044 decision 7 in one or two sentences**: a defect of the generator, the check function or the float64 product that both sides share is not seen by a check at this script.
  - **Never (B), no tool failure**: for no argument does it return one of the strings `"time_limit"` / `"exit_status"` or anything that is not `bytes`, and it never raises a `hilclaw.tools.ToolFailure` or a `hilclaw.journaled_step.StepFailed` (neither is imported).
  - **Check parameters it cannot compute a report for**: it raises and returns nothing. Recommended: a `parameters` that is not exactly a `CheckParameters` raises `TypeError`; the five values are checked with `verification.program_arguments(m=..., k=..., n=..., draws=..., seed=...)` **before anything is computed**, and its `VerificationArgumentError` passes through unchanged; what Python or NumPy raises for a size it cannot hold (`MemoryError`, `OverflowError`, a plain `ValueError`) passes through unchanged. **No cap of its own** on `draws`, a dimension or the size of a report is invented. No exception carries a `kind` or a `spend`, and no docstring says what a call then answers (sub-question 15).
  - How much is held at once is the executor's choice (one draw's arrays at a time is recommended; the report itself is returned whole).
- Docstrings: the module docstring says what the module renders (ADR-0044 decisions 2 to 4 and ADR-0043 decision 2, by number), the choices that are the module's own (the four positional things a script of this tool is asked with; that `default_script` ignores its first three parameters; which code computes the report; what is raised), and what the module does not do: it builds no backend and no table and is bound to no registry; it is not the whole default script of the default registry (it says nothing of `sim.run`, `board.run` or `profiler.collect`); no fault injection (OD-18 sub-question 8, open); it is handed no tolerance and judges nothing; it gives no value or default of `draws`, a seed or a dimension; it says nothing of what a call answers when a script's answer has neither form or when the default script raises.
