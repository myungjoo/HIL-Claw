## Why
PLAN P1-5 ("GEMM spec 예시 ... 와 `spec.json` 스키마") and P1-3 (harness) are the items this belongs to; it ticks **no PLAN checkbox**.

The repository owner's answer to HQ-0009 (2026-10-13, https://github.com/myungjoo/HIL-Claw/issues/5#issuecomment-6136238336), part 2, quoted in ADR-0050 as **O2**: "The first type is the memory ceiling: an upper bound, in bytes, on the memory the kernel's execution uses at the execution point that measures it, operands included. Which measurement of the first case stands for that memory on `cpu_standin`, how it is taken, and at which of the two execution points (HQ-0005) it is judged, is the record's design. A candidate over its ceiling is infeasible and is not compared on the objectives; what the round loop then does with it is what FR-1 does with a failed correctness check at the same execution point."

ADR-0050 (T-0117, `fd337bd`) defined the form of a memory-ceiling entry (`{"type": "memory_ceiling", "bound": <integer bytes>}`) and **did not design the measurement**. Its decision 5 registered the rest as **sub-question 9 of OD-13** and left three things to the record that answers it:
- which measurement stands for that memory on `cpu_standin`, how it is taken, at which of the two execution points it is judged;
- "**When `memory_ceiling` is admitted is for the record of sub-question ⑨ to say** - that record, not this one, knows from when something can judge a ceiling (a record alone judges nothing; the harness code that follows it does)";
- the principle that binds it: "No part of the runtime may treat a ceiling that was not judged as met."

State of `main` at `a7fdb6a` (planner, 2026-10-13): `hilclaw/spec.py` is at version 2 and implements checks 1 to 3 of ADR-0050; its private `_constraint` refuses every entry of `constraints` (T-0148, PR #100). `hilclaw/spec_file.py` reads and writes version 2 only, and ADR-0051 already fixed the spelling of `bound` in a file, so this record needs no spelling rule. No module of `hilclaw/` measures memory: `hilclaw/local_run.py` returns exit status, timeout flag, output bytes, command and wall-clock time and says of itself that it sets "no resource limit"; the timing driver (`hilclaw/harness/timing_driver.c`) and the verification program (`hilclaw/harness/verification_program.c`) report nothing about memory. The run tools `sim.run` and `board.run` have no contract; `correctness.check` has several records and no registered tool.

**This task is the record that answers sub-question 9.** The code that follows it (the harness slice that takes the measurement, then check 4 of ADR-0050 in `hilclaw/spec.py`) is later tasks.

- The Decision section answers the parts of sub-question 9, and only these:
  1. **The quantity.** Which one figure, in bytes, stands for "the memory the kernel's execution uses at the execution point that measures it, operands included" (owner, O2) on `cpu_standin`. Say exactly what the figure contains and what it does not: the three operand arrays; what the kernel allocates itself; the stacks of its threads and a run-time library it brings; and the parts that are the harness's and not the kernel's (the program of the harness, the C library, the input generation, in a verification run the drawn inputs and whatever else that program holds). If the figure contains something that is not the kernel's, say so as a limit and say in which direction it errs (a ceiling is then stricter or looser than the owner's words). Weigh at least these candidates in "Alternatives considered", with the reason each is or is not taken: the peak resident set of the process of a run as the operating system reports it for an ended child; a figure the harness's own C program reads about itself and reports; an account of allocations only; a figure computed from the operand sizes alone (which measures nothing of the kernel).
  2. **How it is taken.** In which run of the harness - the timing run of ADR-0009, the verification run of ADR-0017, or a run of its own - and why; which side reads it (the C program or the Python side) and through which interface, **cited** with its unit on each platform of C-7 (a unit that differs between platforms is converted to bytes by a stated rule); when in the run it is read; whether it is one reading or more than one, and whether anything of ADR-0007 (repeats, the stopping rule, the summary statistic, keeping raw samples) applies to it - a memory figure is not a timing sample, so say so either way. What a run that did not complete (broken, timed out) yields: **no figure and therefore no verdict**. The interface must be in the C library, POSIX, or the Python standard library of the supported version: **no new external dependency** (see "Do not invent").
  3. **The verdict.** A candidate is over its ceiling when the figure is greater than `bound` (state what holds at equality; "upper bound" is the owner's word, the reading of equality is the record's). The verdict has three outcomes and the record keeps them apart: within, over, and **not judged** (no figure). By the principle of ADR-0050 decision 5, cited, "not judged" is never "within". The record adds **no margin, tolerance or repetition rule** that would let a candidate over its ceiling count as within.
  4. **The execution point.** At which of the two points of ADR-0038 the ceiling is judged in the local configuration - the sim point, the board point, or both - and why, read against O2 ("at the execution point that measures it") and against ADR-0038's limit that both points are the same local run on one machine. Then, **by citation only**, which case of FR-1 the owner's sentence thereby selects for a candidate over its ceiling (the return to code generation after a failed check at the sim point, or the drop after a failed check at the board point). The record writes **no procedure of the round loop** (PLAN P2-1), no repair bound (OD-19) and no promotion rule (OD-15, OD-29).
  5. **What carries the figure and the verdict.** Sub-question 9 also names "그 값을 싣는 도구·결과의 멤버". Say as much as the landed records allow: which call at the point is the one whose execution is measured (a run tool, `correctness.check`, or neither yet), given that the run tools have no contract and ADR-0038 names no member. **Name no member of a data-plane file** (`instance.json`, `STATE.json`, an event, a result file below an attempt); if the answer cannot be completed without one, register what is left as a new numbered sub-question of OD-13 (next free number in that section) and say what closes it (the contracts of the run tools, PLAN P1-8). A report line between the harness's C program and its Python side is an internal interface in the sense of ADR-0009 decision 8 and may be described as that record describes its own.
  6. **From when `memory_ceiling` is admitted** (ADR-0050 decision 5 hands this to this record). State the condition as a condition on what exists, not as a date: which code must have landed before check 4 of ADR-0050 may admit the value in `hilclaw/spec.py`, so that no valid spec can state a ceiling that nothing judges. Read it against the fact that no round loop exists yet (PLAN P2-1): say whether the harness slice alone is enough, or whether the admission waits for the tool path that hands a verdict to a caller, and why; state the cost of the choice either way (ADR-0050 L6). Cite ADR-0050 decision 6 (a): the admission raises no version. The record itself admits nothing: `hilclaw/spec.py` is not edited by this task.
- **Limits** - write each before the statement it limits (the notes of T-0117 and T-0121): at least - the kernel shares the process with the harness and can falsify or evade whatever the process reports about itself (rest of OD-16; ADR-0009 decision 10); what the chosen figure over- and under-counts against the owner's words; the dependence of the figure on the machine, the allocator, the thread count and the build flags, none of which the record fixes; one measurement is one run and says nothing of another; the two points on one machine (ADR-0038 decision 8); the platforms (POSIX premise of ADR-0009; nothing for native Windows); other backends, kinds, dtypes and kernel languages; **it is a record, not code, and nothing was run** - every statement about an operating-system interface is cited from its documentation and none was observed on a machine of C-7.
