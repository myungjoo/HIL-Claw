## Why

PLAN P1-8 (runtime STATE / instance / events schemas, "OD-8 종결 필요(§9 ADR 경로)") is still open. ADR-0100 (T-0296, touched up by T-0297) decided that a changed **result definition** of a `step` value takes a new, never-used `step` value, and explicitly left the failure kinds outside "what counts as a change" (ADR-0100 decision 4). It registered OD-8 sub-question ㊱:

> (가) 도구 계약이 기록 단계에 대해 정한 실패 종류 — 끝 줄의 `failure`에 담기고 반복 호출이 다시 내는 것(ADR-0011 결정 3) — 가 바뀌었을 때 그것을 ADR-0100 결정 3의 규칙으로 구분하는지, 다른 방법으로 구분하는지. (나) 지금까지 쓰인 `step` 값을 어디에 나열하는지(나열한다면) — 기록이 새 값이 쓰인 적 없음을 확인할 수 있도록(ADR-0100 결정 3).

An end line holds either `result` or `failure` (`kind`, `message`; ADR-0011 decision 3), and a repeated call raises the stored failure again. Failure kinds come from two sources: kinds reserved by the frame for every tool (ADR-0015 decision 2, ADR-0019 decision 2, ADR-0026 decision 3) and kinds a contract names for its own tool (for example the backend kinds of `correctness.check`, ADR-0047 decision 5, ADR-0056, ADR-0060, code in `hilclaw/check_failure.py`). A change of a frame-reserved kind touches every tool at once, so the answer to (가) cannot simply copy ADR-0100 decision 3. Part (나) is the practical side of ADR-0100 decision 3 ("a new `step` value that no accepted record and no tool has used"): without a list, a later record cannot check that. ADR-0098 answered the same need for event kinds with one index file (`ARCHITECTURE/EventKinds.md`), which is a model to weigh. This task writes one design record (DRIVER §9) that answers ㊱ and, if the record so decides, the index it names. It writes no code.
