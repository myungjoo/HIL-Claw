### The tool definition (`hilclaw/tools.py`; ADR-0015 decision 2)
- `Registry.register` takes the name, the tool function, a `description` and an `input_schema`. **Both are required; there is no default** (a default would be a text or a schema that is not "stated … with the tool"). Recommended signature: `register(self, name, function, description, input_schema)`.
- `description`: exactly a `str`, non-empty ("a non-empty string written for the caller"). Otherwise `TypeError` (not a `str`) or `ValueError` (empty), in the manner of the existing checks. Whether a text of whitespace only is refused is this task's choice (the record says "non-empty").
- `input_schema`: one JSON object in the strict sense (`check_json_object`) whose member `type` is exactly the string `"object"`. Otherwise `TypeError` (not a `dict`) or `ValueError` (not a JSON object in the strict sense; `type` absent or another value). **Nothing else of the schema is checked**: "which keywords a schema may use is not fixed (F14)". No request is ever compared with it, in `call` or anywhere else.
- A refused registration adds nothing: the name stays free and `names()` is as before. The existing checks of `name` and `function` and their order relative to each other are unchanged; where the two new checks stand in that order is this task's choice.
- **Reading a definition.** The registry gives a reader the name, the tool function, the description and the schema of a tool. Recommended: a small immutable type `ToolDefinition` (for example a `typing.NamedTuple` with `name`, `function`, `description`, `input_schema`) and `Registry.definition(name)` that returns it or raises `UnknownToolError` exactly as `get` does; **`get(name)` keeps returning the tool function** (`call` and `hilclaw/__main__.py` use it) and `names()` is unchanged.
- **The schema a caller passed and later changes.** Choose, document in the docstring and test: recommended that the registry keeps its own copy made at registration and that what a reader gets is not the object the registry holds (a reader that changes it does not change the next list). What must hold either way: two lists of one unchanged registry are equal, and the module docstring sentence "Nothing here keeps state between calls" stays true.
- `default_registry()` returns an empty registry, as today.

### The reserved kinds (`hilclaw/tools.py`; ADR-0015 decision 2, the table)
- Constants for the five values, each of exactly the spelling of the record: `invalid_request`, `no_data_root`, `step_open`, `tool_crashed`, `bad_result`. `KIND_TOOL_CRASHED` and `KIND_BAD_RESULT` keep their names. Recommended names for the others: `KIND_INVALID_REQUEST`, `KIND_NO_DATA_ROOT`, `KIND_STEP_OPEN`; and one immutable collection of the five (recommended `RESERVED_KINDS`, a `frozenset`).
- `hilclaw.journaled_step.KIND_STEP_OPEN` stays a public name with the value `"step_open"` and takes it from `hilclaw.tools` (the module imports `tools` already), so that the value is written once.

- Nothing raises `invalid_request` or `no_data_root` in this task (no tool exists; the data-root source is slice ②).
- The kinds of the command-line front (`bad_usage`, `unknown_tool`, `bad_request`, `no_input`) are not reserved kinds of the frame and are not touched.
