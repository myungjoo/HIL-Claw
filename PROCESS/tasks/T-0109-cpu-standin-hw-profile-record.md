### The function (ADR-0035 decisions 2 to 6 and 8)
- One public function (recommended name `local_record`; recommended call form `local_record(hw_source, *, timeout_s, compiler=None)`) that returns the hw_profile record of the machine it runs on: a new plain `dict` with exactly the members `schema_version` (`hilclaw.keys.SCHEMA_VERSION`), `accelerator` (`"cpu_standin"`), `revision` (`"host"`), `toolchain` (`{"clang": <line>}`), `host` (`{"cpu": ..., "os": ...}`) and `hw_source` (the caller's value). No `label`, no `ext`, no further member of `toolchain` or `host`. The record is one `hilclaw.keys.hw_profile_key` accepts; whether the function also returns the `Key` is the task's choice.
- **`hw_source` has no default and is never derived**: a value that is not one of `hilclaw.keys.HW_SOURCES` is an error (recommended: what `hw_profile_key` raises, `InvalidRecordError`), raised whatever the machine holds. Whether it is checked before or after the machine is read is the task's choice; say which.
- `timeout_s` is required, has no default and bounds each command the function starts; `compiler` is as in `clang_build.build` (`None` for `clang_build.DEFAULT_COMPILER` on `PATH`, one name or path, or a command prefix).
- **`toolchain.clang`**: the first line that `<compiler> --version` writes to standard output, in the spelling of decision 6 (see the planner's judgement above on how the command is run).
- **`host.cpu`** and **`host.os`**: exactly the two tables of decision 4, selected by the kernel name: `Darwin` (macOS), `Linux` with a kernel release that contains `microsoft` in any case (WSL), `Linux` otherwise. The kernel name is compared as it is (`linux`, `Windows`, `FreeBSD`, an empty name: no rule). Files: `/proc/cpuinfo` and `/etc/os-release` and no other path (not `/usr/lib/os-release`). Which interface gives the kernel name and release (`os.uname`, `platform.uname` or the command `uname`) is the task's choice, as long as it is the fact `uname -s` / `uname -r` names and the tests can replace it; note that `os.uname` does not exist on Windows.
- **A line** is the text up to the first line feed, without one carriage return directly before it; **nothing else ends a line** (not a lone carriage return, a form feed or a vertical tab - these are characters of the line and make the fact unreadable). **The spelling**: each run of space and tab characters becomes one space; spaces at both ends are removed; nothing else changes. The result must be 1 to 255 characters, each from 0x20 to 0x7E.
- `/proc/cpuinfo`: of the first line that holds a colon and whose text before its **first** colon, with spaces and tabs removed at both ends, is exactly `model name`: the text after that colon, then the spelling. Later `model name` lines are not looked at (decision 7: the first processor).
- `/etc/os-release`: the text after `ID=` (and after `VERSION_ID=`) on the first line that **starts** so (`ID_LIKE=` and a line with a leading space do not), without one pair of double or single quotes around it. No `ID` line: unreadable (the default of `os-release(5)` is not used). An `ID` or `VERSION_ID` that, after the quotes are removed and before the spelling, is empty or holds a space or a tab: unreadable. No `VERSION_ID` line: the two-word form. `host.os` is the environment word (`linux`, `wsl`, `macos`), then the values, joined by single spaces.
- **A fact that cannot be read is an error, and then no record is returned**: one public exception class of the module (recommended name `UnreadableFactError`) whose message names the fact (`toolchain.clang`, `host.cpu`, `host.os`, the kernel name) and the reason. Every case of decision 6: the command or the file is missing or gives nothing; the command ends with a status other than 0; no `model name` line; the `os-release` cases above; a kernel name without a rule; a result that is empty, longer than 255 characters or holds a character outside 0x20 to 0x7E. **Nothing is substituted**: no `unknown`, no placeholder, no cut or transliterated text, no value from another source (`platform.processor`, `PRETTY_NAME`, `NAME`, `lscpu`, an environment variable, another file, a later line).
- The facts are read at each call; nothing is kept between calls. The module writes, creates and removes no file, stores nothing (`hilclaw.key_records` is not imported), registers nothing, is imported by no other module of the package and has no command-line entry.
- **The seam**: the tests must be able to give the function the kernel name and release, the content (or absence) of the two files and the outcome of each command, so that every case runs on Linux (CI) and on Windows (the driver's clone) without depending on the host. Arguments, replaceable module-level private functions or a small reader object are all acceptable; no public default argument may carry a machine fact.

### Provisional choices (each with its reason; all reviewed)
- Names `standin_profile`, `local_record`, `UnreadableFactError`: the task's recommendations.
- Return form: the record only - the key is one call of `hw_profile_key` away.
- `hw_source` checked first - a wrong statement of the caller is reported whatever the machine holds and costs no command.
- `timeout_s` checked by `local_run.run` at the first command - one check, no copy of it.
- Kernel name and release from `os.uname()` at each call (`platform.uname()` caches). A platform without `os.uname` (native Windows) is an `UnreadableFactError` for the kernel name.
- The kernel name is read before the compiler is started (changed in review round 1), so that nothing is started on a platform without a rule.
- Seam: three private module-level functions the tests replace - `_kernel()`, `_read(path)`, `_run(command, timeout_s)`; no public argument carries a machine fact.
- Bytes throughout: a byte outside ASCII outside the fact does not matter; one inside makes the fact unreadable; nothing is decoded with replacement.
- A line ends at a line feed only; one carriage return directly before it is dropped; a carriage return at the end of data without a line feed is a character of the line (unreadable).
- A timeout, a command that cannot be started (an `OSError`) and a file that exists but cannot be read: the fact cannot be read. The docstring tells these apart from the cases decision 6 lists.
- An empty file is "no model name line" / "no ID line".
- os-release quotes, literally: one pair is removed only when the same quote character is the first and the last character of a value of at least two characters. `ID="x` gives `linux "x`; `ID=""x""` gives `linux "x"`; `ID="` gives `linux "`; a trailing space after the value is unreadable.
- `host.os` is spelt and length-checked as a whole (255 characters apply to the string of the record).
- `microsoft` is matched with ASCII case folding only.
- The character range is checked before the length (round 2), so the reason given for a long value outside ASCII is its character.
