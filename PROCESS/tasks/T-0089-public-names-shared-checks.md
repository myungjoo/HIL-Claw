## Why
`hilclaw/hw_tool.py` (T-0064, PR #57) calls two private names of sibling modules:

- line 151: `backends._hw_tool(tool)` - the check that a name is one of `backends.HW_TOOLS` (`hilclaw/backends.py` lines 42-47; also used inside `Backend.__init__` and `select`);
- line 172: `journaled_tool._built(step, numbers, carry_out, source=..., check=..., hw_profile_of=..., perform=...)` - the check when a tool function is built and the first two moments of a call (`hilclaw/journaled_tool.py` lines 105-121), which `journaled_tool.tool_function` and `hw_tool.tool_function` share.

T-0064 recorded this as a provisional choice ("one implementation of the request check and of the refusal of a tool name, while an existing test fixes the public names and the signature of `journaled_tool` and `backends.py` must stay unchanged. Accepted for this slice by both reviewers") and left the follow-up: "Public names for the shared check of `journaled_tool` (`_built`) and for the HW tool name check of `backends` (`_hw_tool`), so that `hw_tool` uses no private name of a sibling module; it needs a change of `backends.py` and of the test that fixes the public names of `journaled_tool`." The follow-up was carried through every task file since and was never done. **This task does it.** The next HW tool builders (the rest of PLAN P1-1) will build on `hw_tool` and should find the shared parts under public names with docstrings and tests of their own.

It serves PLAN P1-1 ("FR-10 도구 계약 ... 인터페이스 + mock 백엔드 + 백엔드 적합성 테스트"). It ticks **no PLAN checkbox**: P1-1 stays open.

Planner's judgements (2026-10-09 UTC, from the files; the reviewer is asked to re-check each):
- **The previous planner's note holds.** A search of `hilclaw/` for `<module>._<name>` across modules finds exactly these two calls and no other. No test calls either private name.
- **Independent of HQ-0005** (OD-18 sub-question 7, task T-0088): the change adds no tool, backend, operation, table entry or contract and decides nothing about which HW tools a backend offers or about the execution points.
- **No record is needed, as far as the planner can see.** The names of functions of a module were each code task's provisional choice so far (T-0064, T-0083, T-0087). One point must be checked by the executor and the reviewer before the first commit, not assumed: a public builder that takes a caller's `carry_out` is a way to build a function that checks a request as a journaled tool does and then does **not** go through `hilclaw.journaled_step`. ADR-0015 decision 5 places the two step lines and the lookup "inside the tool function the registry holds for a journaled tool", and the module docstring of `journaled_tool` says its step "is reached only through `hilclaw.journaled_step.run`". The private name carries that possibility today for `hw_tool` only. The docstrings must therefore say exactly what the public name gives and what it does not guarantee, and must not weaken a sentence of ADR-0015 or ADR-0016. **If the executor or the reviewer reads the exposure as a design choice that needs a record or the owner, do not decide it: return BLOCKED ("requirement unclear") with the exact question.** Another shape that avoids the point (for example exposing the check when built and the check of a request as two functions, without a `carry_out` parameter) is allowed and is the task's choice.
- **The stale docstring sentence of `check_run_id` in `hilclaw/layout.py` is left out** ("the form of a ``run_id`` is open"). ADR-0027 Consequences list it among the sentences "not edited and now less exact (follow-ups for the integrator)", together with sentences of nine records; it belongs to that sweep, is no part of this refactoring and would add a file and a second subject to the PR.
- **A-13 reading**: code mode; no new external dependency (`pyproject.toml` unchanged), no data-plane schema change, no security concern. Behaviour of every existing public function is unchanged.

### The change
1. **`hilclaw/backends.py`**: the check of a HW tool name gets a public name (planner: `check_hw_tool(tool)`, by the model of `hilclaw.layout.check_run_id`; the name is yours). It returns `tool` when it is exactly a `str` and one of `HW_TOOLS`, raises `TypeError` when it is no `str` and `ValueError` when it is no HW tool - **the classes and the messages of today, unchanged**. `Backend.__init__` and `select` use it as they use `_hw_tool` today. No private alias of the old name stays.
2. **`hilclaw/journaled_tool.py`**: what `_built` does gets a public form that `hw_tool` can use (planner: one public function with the signature of `_built`; a split into two functions without a `carry_out` parameter is allowed - see the planner's judgement in `## Why`). `tool_function` keeps its signature, its behaviour, the order of its checks and its messages. No private alias of the old name stays.
3. **`hilclaw/hw_tool.py`**: the two calls use the public names. **No attribute of the form `<module>._<name>` of another `hilclaw` module is left in `hilclaw/`.** `hw_tool.tool_function` keeps its signature, its behaviour, the order of its refusals when built (`tool`, `table`, `step`, `numbers`, then the callables) and its messages.
4. **No behaviour changes.** Every existing test passes **unmodified**, with one exception: the assertion of `tests/test_journaled_tool.py::test_the_public_names_and_the_signature` that lists the public names of the module is extended by the new name or names; the rest of that test stays.
