## Acceptance Criteria

### `hilclaw/layout.py`: the path of a case (ADR-0072 decision 1)

- **`case_record(data_root, hw_profile_key, op_signature, run_id, round)`** (suggested name, beside `hypothesis_record` / `verdict_record`) returns `op_signature_dir(data_root, hw_profile_key, op_signature) / f"case-{run_id}-{RRRR}.json"`, where `run_id` passes `check_run_id` and `<RRRR>` is the round directory name of ADR-0004 decision 2 (decimal, zero-padded to at least four digits, as `round_dir` and `hypothesis_record` write it). `round` is an integer from 1 to `keys.MAX_INTEGER`: round 0 has no case (ADR-0072 decision 3, line 60). Every other rule is that of `op_signature_dir`. Errors are `InvalidPathValueError` as in the rest of the module, argument order of checks as the executor finds natural (state it in the docstring only if it matters).
- `OP_SIGNATURE_FILES` and `op_signature_file` stay as they are (they are the three names of ADR-0004 decision 5). No other change to `layout.py`.

### `hilclaw/cases.py` (new; Python, as the rest of the package)

Public names are the executor's (the module name too, if a better one fits; avoid `check_*`, which the package uses for `correctness.check`). The reasons for any departure from the suggestions go into the commit body.

- **`SCHEMA_VERSION = 1`** and an exception **`InvalidCaseError(ValueError)`** (suggested name). Message "field path: rule" with the offending value shortened by `reprlib`, as the other validators do. **An error of a copy** is raised as this exception with the copy's field path prefixed by its member name - for instance `hypothesis_record.hypotheses[0].id: ...`, `verdict_record.verdicts[1].verdict: ...` - and chained (`raise ... from err`) to the original `InvalidHypothesisRecordError`, `InvalidVerdictRecordError` or `MismatchError`, so a caller catches one class. (If the executor judges plain pass-through clearly better, it may choose it; then say why in the commit body and `## Result`, and keep the order below.)
- **`validate(document)`** returns `None` when `document`, an already-parsed JSON document, is a valid version-1 case by ADR-0072 decisions 2 and 3, and raises for the first rule found broken. `document` is not modified; nothing is read, written or logged. In this order:
  1. `document` is a mapping; the required members `schema_version`, `run_id`, `round`, `hypothesis_record` are present; `schema_version` is exactly the integer 1 (any other value, another integer among them, refused as any wrong value); `run_id` is a *string* of ADR-0001 (as `hilclaw.verdicts` checks it); `round` an *integer* from 1 to `keys.MAX_INTEGER` (round 0 refused: ADR-0072 decision 3 line 60).
  2. `hypothesis_record` passes `hilclaw.hypotheses.validate`; then its `run_id` and `round` equal the case's (decision 2 line 47).
  3. If the member `verdict_record` is present: it passes `hilclaw.verdicts.validate`; its `run_id` and `round` equal the case's; then `hilclaw.verdicts_hypotheses.check(verdict_record, hypothesis_record)` holds (decision 3 line 58). A present `verdict_record` whose value is `null` or any non-object is invalid (absence is the only form of "no verdicts", decision 2 table). An absent `verdict_record` is valid and is **never** read as `inconclusive` or any other value (decision 3 line 59; say so in the docstring).
  4. Any other top-level member is passed over, neither interpreted nor checked (open top level, decision 2 line 48).
- **`build(hypotheses, verdicts=None)`** (suggested name) returns a new case document: `schema_version` 1, `run_id` and `round` taken from `hypotheses`, `hypothesis_record` a deep copy of `hypotheses`, and - only when `verdicts` is not `None` - `verdict_record` a deep copy of `verdicts` (no member at all when it is `None`; never `null`). Every member of the inputs, unknown top-level members included, is kept; nothing is added, removed or altered inside the copies (decision 3 line 53). The result passes `validate` before it is returned; for any invalid input (a non-mapping, a missing `run_id`, an invalid copy, a broken rule between the two) `build` raises `InvalidCaseError`, never `KeyError` / `TypeError`. The inputs are not modified, and a later change to them does not change the returned document. `build` reads no file and chooses nothing about promotion: whether a round without verdicts is promoted stays open (ADR-0072 Boundaries line 132) - `build(h)` only gives the form decision 3 admits.
- **Module docstring** (short; it may refer to `hilclaw/hypotheses.py` and `hilclaw/verdicts.py` for conventions): cite ADR-0072 decisions 2 and 3, the file path via `hilclaw.layout.case_record`, and **what it does not do**: the rule that the file name is formed from the case's `run_id` and `round` (decision 2 line 47; it needs the path - the file module's); that the case lies in the key directory of the run's instance (decision 1 line 24, a rule between files); that the copies equal the source files in `runs/` (audit, NFR-2); that a *ref* names an attempt that exists; reading a case or a copy of another `schema_version` (only version 1 of each is read; setting apart is the caller's, OD-11); the text form, final name and write of the file (ADR-0029 decisions 2, 4, 6, 7 - the next task); and anything of the lookup, the `basis` kind `case`, promotion (when, by whom, OD-29 / OD-23 / OD-25), `best.json` / `technique_stats.json`, or injection. It is no tool, no hook and no CLI entry. No comment beyond the docstrings (CLAUDE.md "코멘트 최소화").
- **No change** to `hilclaw/hypotheses.py`, `hilclaw/verdicts.py`, `hilclaw/verdicts_hypotheses.py`, `hilclaw/hypotheses_file.py`, `hilclaw/verdicts_file.py` or any other module beyond `layout.py`. If the slice cannot stand without such a change, stop and report why in `## Result` (BLOCKED "requirement-unclear" if needed).
