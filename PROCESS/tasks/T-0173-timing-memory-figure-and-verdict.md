## Why
ADR-0052 (the measurement that stands for the memory of a `memory_ceiling` at `cpu_standin`, OD-13 sub-question ⑨) orders its code slices (Consequences, line 111): "**(1) The harness slice**: `hilclaw/local_run.py` hands on the usage of the process it waited for; the Python side of the timing run (`hilclaw/harness/timing.py`) yields the figure for a completed run; the verdict of decision 5. `hilclaw/harness/timing_driver.c` is not touched." T-0172 (PR #120, merged as 3549094) landed the first part: `local_run.RunResult.max_rss`, the raw `ru_maxrss` from `os.wait4`, `None` without `wait4`. This task lands the rest of slice (1): the unit rule that turns that raw value into the figure in bytes (decision 4), the rule that only a completed timing run yields a figure (decision 4), and the three-outcome verdict (decision 5). With it, conditions (a) and (b) of decision 7 are on `main`; condition (c) (the run-tool contract, PLAN P1-1/P1-8) is not, so `memory_ceiling` stays **not admitted** and `hilclaw/spec.py` is not touched. It ticks **no PLAN checkbox** and changes no OD.

Planner's judgements (the reviewer is asked to re-check each):
- **No undecided design is needed.** ADR-0052 fixes the quantity (decision 3: the maximum resident set size of the timing-run process, in bytes, one number, no baseline subtracted), the unit rule (decision 4, line 56: Linux - and WSL, which presents itself as Linux - value times 1024; macOS the value as is; any other platform no figure; the platform is read from `sys.platform`, "how is the code task's"), the positive-integer rule (line 57), the completed-run rule (line 60: *completed* is ADR-0009 decision 8; `converged` and `not_converged` both yield a figure; a broken run never does), and the verdict (decision 5, lines 67-70: *within* iff figure <= `bound`, *over* iff figure > `bound`, *not judged* iff no figure; equality is within; no margin, no rounding, no statistic; "not judged" is never "within" and the three outcomes may not be folded into two). Function, member and module names are the code task's ("no function, member name or module layout is decided here", line 111).
- **Why a module of its own for the rule and the verdict.** `timing.py` says of itself that it does not "judge a broken run or one that is not converged" and "summarises nothing"; the verdict is a judgement against a `bound` that no timing run carries (decision 7 (c) forbids a caller-chosen bound to become the admission path, and nothing records a bound yet). Keeping the unit rule and the verdict as pure functions in `hilclaw/harness/memory_ceiling.py` lets them be tested on every platform with stated values (Consequences line 111) and keeps `timing.py` to one new member and one call. The module name is the planner's suggestion; the executor may choose another name, and then updates `touchesFiles` in the Result.
- **The figure is an in-package interface, not a data-plane member.** Decision 7 line 82: "for a completed timing run the Python side has the figure beside the intervals; for any other run it has none. This is an interface between parts of the package of one source commit ... and is not a file or a field of the data plane." No record, result file, event, `instance.json` or `STATE.json` member is named or written.
- **The `bound` domain.** A `bound` is an *integer* of ADR-0001 (ADR-0050 decision 4 line 72 and check 4 line 108; ADR-0001 line 34: 0 to 2^53 - 1), and 0 is a valid bound meaning zero bytes. The verdict function therefore accepts exactly an `int` (not a `bool`) in that range and raises a `ValueError` subclass otherwise - it never returns *within* for a value outside the domain. It does not validate a spec or an instance (that is `hilclaw/spec.py`, check 4, slice (3), later).
- **A-13**: code mode. Standard library only, no new dependency. No data-plane schema, member, path or layout version touched.
- **D16**: nothing here needs the `claude` program, a board, an accelerator or an API key. Tests use the existing Python stand-in of `tests/harness/test_timing.py` and stated values. On the native-Windows development machine `max_rss` is `None`, so the figure is `None`; the Linux path is exercised on CI. Runtime acceptance items (i)-(iv) of ADR-0052 (Consequences line 114: the documented unit actually reported on each machine kind of C-7, the harness share, the Linux floor, descendants) are **not** closed here; CI observes (i) for its own machine kind only.

## Acceptance Criteria
1. **New module `hilclaw/harness/memory_ceiling.py`** (name per Why) with a module docstring that names ADR-0052 decisions 3-5 as the rule and states what it does not do (no measurement of its own, no admission of `memory_ceiling`, no margin, no caller of the verdict, no data-plane member). Public API (names are the executor's; these are suggestions):
   - a function `figure(max_rss, platform)` returning the figure in bytes as an `int`, or `None`: for `platform == "linux"` the value times 1024; for `platform == "darwin"` the value as is; for every other `platform` string `None`. A `max_rss` that is not exactly an `int` (so `None`, a `bool`, a `float`, a `str`) or is not positive yields `None`. It never raises for any `max_rss` value. `platform` is required (no default), so the caller states which platform it read.
   - an enum `Verdict` with exactly three members, *within*, *over* and *not judged* (spelling the executor's).
   - a function `verdict(figure, bound)` returning *not judged* when `figure` is `None`, *within* when `figure <= bound`, *over* when `figure > bound`. `bound` must be exactly an `int` (not a `bool`) with 0 <= `bound` <= 2**53 - 1, and `figure` must be `None` or exactly an `int` >= 1; anything else raises a `ValueError` subclass of this module (no result is returned). No margin, rounding or tolerance.
2. **`hilclaw/harness/timing.py`**: `TimingResult` gains one member appended after `run` with the default `None` (suggested name `memory_bytes`), so that any five-value positional construction stays valid. For a completed run (`broken is None`, whether `converged` or `not_converged`) it is `memory_ceiling.figure(run.max_rss, sys.platform)` - so `None` where the runner obtained no usage, the platform has no rule, or the value is not a positive integer; for every broken run it is `None` even where `run.max_rss` is an `int`. `sys.platform` is read at call time. The `TimingResult` and `run_timing` docstrings and the module docstring's "What this module does not do" paragraph are updated: the result now carries the figure of a completed run (ADR-0052 decision 4, as Consequences line 112 foresees), and the module still judges nothing - the verdict lives in the new module. Every other behaviour of `run_timing`, `parse_report` and `driver_arguments` is unchanged; the driver program's arguments and report are unchanged; `timing_driver.c` is not touched.
3. **`hilclaw/harness/__init__.py`**: the docstring names the new module in its list, in one short clause.
4. **Tests** (D12 ②-④):
   - `tests/harness/test_memory_ceiling.py` (new, runs on every platform; pure stated values):
     - happy: `figure(5, "linux") == 5120`; `figure(5, "darwin") == 5`; `figure(1, "linux") == 1024`;
     - branch: every platform other than `"linux"` and `"darwin"` gives `None` (at least `"win32"`, `"cygwin"`, `"freebsd13"`, `"linux2"`, `""`); verdict *within* for `figure < bound` and for `figure == bound` (equality is within), *over* for `figure == bound + 1`, *not judged* for `figure is None` with any valid bound including 0; a `bound` of 0 with a figure of 1 is *over*; a `bound` of 2**53 - 1 is accepted;
     - negative: `figure` gives `None` (and does not raise) for `max_rss` of `None`, `0`, `-1`, `True`, `False`, `1.0`, `"5"`; `verdict` raises the module's error for a `bound` of `-1`, `2**53`, `True`, `1.0`, `None`, `"1"` and for a `figure` of `0`, `-1`, `True`, `1.0`, `"1"`; the enum has exactly three members; no path from *not judged* yields *within* (e.g. `verdict(None, 2**53 - 1)` is not *within*).
