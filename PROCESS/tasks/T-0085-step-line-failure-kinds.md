### The answer at the two appends (`hilclaw.journaled_step.run_prepared`, reached by `run`)
| Where | What `events.append` raises | Answer |
|---|---|---|
| the append of the start line (line 209 today) | an `OSError` (`FileNotFoundError`, `NotADirectoryError`, `PermissionError` and every other subclass included) or an `events.CorruptEventsError` | `ToolFailure` of kind `start_line_failed`, chained to the error (`raise ... from error`); **the step is not called**, no end line is appended |
| the append of the end line (line 216 today) | the same classes | `ToolFailure` of kind `end_line_failed`, chained to the error; **no outcome is returned**, whether the step returned a pair or raised `StepFailed`, and also when the line turned out complete |
| either append | `events.InvalidEventError`, and every other exception that is none of the classes above | unchanged: it passes through as the same object (so `tool_crashed` at `tools.call`); a class that is no situation is not caught |

- **Only the two appends are mapped, each `try` enclosing its `events.append` call alone.** Unchanged and unmapped, whatever their class: the argument refusals before any file is read; the four kinds of the lookup (`_state`); `step_open` and the answer of an ended identity; what `before_start` raises; what the step raises (an `OSError` out of the step leaves the step open and passes through); `InvalidOutcomeError` out of `_outcome` and `_checked_end` (no end line is appended); a `BaseException` that is no `Exception`.
- **Message** (decision 6): it names `runs/<run_id>/events.ndjson` by its path relative to the data root and says what was found there or what the file system reported; it carries **neither the outcome nor an amount** (nothing of `spend`, `result` or `failure`), and not the absolute path the system or `events._root` gave. The message of `events.CorruptEventsError` already starts with the relative path and may be used as it is; for an `OSError` this task composes it (the class and `strerror`, as `run_files.read_failure` does for a read, but not with the words "could not be read"). The wording is yours; tests may check that the message starts with the relative path and holds none of the outcome; nothing else in the package may depend on the wording.
- **No second read and no second try.** The failing call does not read the log again, does not try the append again, removes nothing and marks nothing (decision 2, Alternatives, Boundaries).
- A first call whose two appends succeed, a repeated call and every lookup answer behave exactly as before.
