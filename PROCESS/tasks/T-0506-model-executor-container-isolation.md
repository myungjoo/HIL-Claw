## Why

**State.** PLAN P2-14 (Llama 3.2 1B end-to-end, the D18 goal) is: "P2-11의 각 연산에 대해 instance가 커널을 내고, P2-13의 실행기가 그 커널로 토큰을 생성해 reference와 맞는다". Since T-0497 the executor can take its kernels from attempt directories (`hilclaw/attempt_kernel.py`), that is, kernels written by the coder. But the executor builds those kernels into shared libraries and runs the forward program **as host processes** (`hilclaw/model_forward_execute.py` docstring: "it chooses no flag of a kernel or of the program, no container and no environment"; `model_build` calls `clang_build.build` on the host, `model_forward_run` calls `local_run.run` on the host). The isolation of the model program's build and process is open: ADR-0153 Boundaries ("whether ADR-0144's container is used for it, and then whether its image gains the two loading needs of decision 2; time and memory limits (OD-14, NFR-4)"), ADR-0166 Boundaries and ADR-0176 Boundaries repeat it, and the OD-31 row's 잔여 lists "④의 … 실행기 프로세스의 격리(OD-14)".

**Why P2-14 needs it (D18).** NFR-4 and the owner decision of 2026-10-15 (items 1 and 2) require that the builds and runs of generated kernel code use an isolated environment, a container; ADR-0153 (Consequences, "Readings for the owner to check") reads NFR-4's sandbox as covering a model run, and ADR-0144 decision 4 forbids a host build or process for the first case's runs. A P2-14 generation runs instance-written kernels; without this record and slice it would run them unprotected on the host. This is not input hardening or wording, so D18 does not set it aside.

**Why now, and why not the bf16 timing run.** Every other remaining P2-14 piece is blocked: the bf16 `timed` flags and so the instance start of bf16 contracts wait on HQ-0078 (T-0505, BLOCKED), and P2-10 waits on HQ-0076 (T-0493). This record touches neither `sim.run` / `board.run` nor any run result: nothing here depends on HQ-0078's answer. Deriving a binding from a key's best (OD-20, OD-7) needs `best.json` content, a data-plane schema matter, and is not part of this task.

**Task unit (D20 ①).** The ADR and its first code slice in one code-mode task. One ADR covers the executor's build and process isolation as a whole (D20 ②); the code slice is the bf16 forward path, which is P2-14's. Later slices (for example the fp32 `model_program.c` path of ADR-0153, if the ADR extends to it) are listed in the ADR for the planner.

**ADR number.** Use **ADR-0182**, not ADR-0181: ADR-0181 is the number of T-0505's unlanded draft on branch `claude/T-0505-bf16-timing-run` (CLAUDE.md "세션 진입 점검", the #8 M23 lesson). If `ARCHITECTURE/decisions/` on `origin/main` already holds ADR-0182 at start, take the next free number above it and say so in Result.

**RuntimeAcceptance.** `PROCESS/RuntimeAcceptance.md` has no `실패` item as of `main` `a577a9ec`; RA items about the model program's isolated environment already exist (ADR-0153 (lxvii), (lxviii), in the migrated items) and this task narrows them, it does not close them.

**D16.** Tests use a stub `docker` (as `tests/first_run_stubs.py` and `tests/test_standin_check.py` do) that runs the real `clang` and the program in the build directory where `clang` is available; no real Docker daemon, no `claude`, no real weights.
