### The module - each item is a requirement
The recommended names are provisional; the behaviour is not.

7. **Docstring**: what the module is (the array side of a verification run of ADR-0017: no process, no build, no report bytes), the generator and the check value in the words of the C header (or by pointing at it and stating that both must give the same bit patterns), "Conventions of this module", "What this module does not do". Otherwise comments only where the code cannot say it.
8. **`draw_inputs(m, k, n, *, seed, draw)` → `(a, b)`** (decision 3; decision 4 "regenerates them from the seed"): `a` of shape `(m, k)` and `b` of shape `(k, n)`, dtype `float32`, C-contiguous, **bit for bit the values of the C program** for draw `draw` counted from 0: `word(d, e) = mix(base(d) + (e + 1) * G)` with `e` counting the m·k elements of `a` in storage order and then the k·n elements of `b`; `bits = (word & 1) << 31 | 126 << 23 | word >> 41` viewed as `float32` in the byte order of the host. **Array operations only**: no interpreter loop over elements (a loop over a bounded number of chunks is allowed if you choose to bound memory; say which you chose and the peak memory per element in `## Result`). `base(d)` may be computed with Python integers masked to 64 bits; element words with `uint64` arrays, whose arithmetic wraps. No NumPy overflow warning may be raised for any valid argument (seed `2**64 - 1` included): the tests run with warnings turned into errors for this module's calls.
9. **Arguments of `draw_inputs`**: `m`, `k`, `n` integers ≥ 1; `seed` an integer in 0 .. 2^64 - 1; `draw` an integer in 0 .. 2^64 - 2 (the C program accepts `draws` < 2^64). `bool` is not an integer here. Anything else raises one argument-error class of the module (a `ValueError` subclass, as `TimingArgumentError`) naming the argument. **No argument has a default** (decision 6). What happens when the arrays do not fit in memory is NumPy's `MemoryError` and is not caught.
10. **`check_value(a, b)` → `int`** (decision 4): `zlib.crc32` of the bytes of `a` followed by the bytes of `b` as they are in memory, without a loop over elements and without copying when the arrays are contiguous - the value the C program reports as a `uint32_t`. It is no protection against anything (decision 10); say nothing more of it.
11. **`reference(a, b)` → `float64` array of shape `(m, n)`** (decision 4, **owner**): the float64 product of the inputs widened to float64 (`a.astype(float64) @ b.astype(float64)` or the same by another NumPy call). Its rounding error is not accounted for (decision 5): no compensation, no extended precision.
12. **`check_tolerance(rtol, atol)`** (decision 5, validity rule): each must be a finite number that is not negative; anything else raises the argument-error class naming the parameter. It is a public function so that slice ③ can refuse a tolerance before a process is started. Provisional: `int` and `float` are numbers, `bool` and every other type are not. **No default value anywhere** (decision 6, **owner**).
13. **`count_failures(output, expected, *, rtol, atol)` → a small named result with `failed` and `non_finite`** (decisions 5 and 7): `output` is the kernel's output as a `float32` array of the shape of `expected` (the float64 reference); it is widened to float64 (exact) and the predicate `|out - ref| <= atol + rtol * |ref|` is evaluated in float64 per element. `failed` is the number of elements for which the predicate does not hold; `non_finite` is the number of elements of `output` that are NaN or an infinity. **Every non-finite element fails** (owner), for every valid tolerance - write the count so that this holds by construction and not by the accident of a NaN comparison, and so that no NumPy warning is raised for NaN or infinite outputs. The tolerance is checked by `check_tolerance` first. The result holds **counts only**: no index, no deviation, no element of the inputs, the output or the reference (decision 7).
14. **Arguments of `check_value`, `reference`, `count_failures`**: provisional - arrays of the dtype and shapes named above are required; a wrong dtype, a wrong number of dimensions or shapes that do not fit (`a` `(m, k)` against `b` `(k, n)`; `output` against `expected`) raise the argument-error class. Keep these checks short; they guard the harness's own callers, not a kernel.
15. **What the module does not hold**: no process, no build, no path, no report parsing (the split of the report by lengths is slice ③), no verdict over draws, no time limit, no tolerance value, no seed value, no dimension of any instance.
16. **Import of `numpy`**: imported by this module only. `hilclaw/__init__.py`, `hilclaw/harness/__init__.py`, `hilclaw/__main__.py`, `hilclaw/mcp_front.py` and every other existing module stay as they are, so the two fronts still start without `numpy` being imported. ADR-0017 Consequences leaves "where it is imported, and whether a front can start without it" to the code task: record this as **the state after this task, not a promise**, and add no test that pins it.

### Tests (`tests/harness/test_verification_arrays.py`; excluded from the size cap)

The test file holds its **own implementation of the generator and of the check value, written from the C header with the standard library only** (`struct`, `zlib`, integers masked to 64 bits), as `tests/harness/test_verification_program.py` does; do not import from that file and do not edit it.   - `check_value` equals `zlib.crc32` over the test's own packed bytes, for the drawn arrays and for one hand-written pair;
  - `reference`: dtype `float64`, shape `(m, n)`; equal within a margin the test chooses to the product the test computes from its own generator with `math.fsum`; for a hand-written pair with exactly representable results, exactly equal; a case that shows the widening (a product that float32 arithmetic would round but float64 holds);
  - `count_failures`: an output equal to the reference rounded to `float32` passes under a tolerance the test chooses (`atol` > 0, mind the cancellation observation of decision 5) with counts `(0, 0)`; hand-written cases at the edge of the predicate with exactly representable numbers (on the bound passes; the next `float32` beyond it fails), for `rtol` only, `atol` only and both.
