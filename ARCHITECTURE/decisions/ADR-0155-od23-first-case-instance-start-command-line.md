## Context

- **The start function** (cited: ADR-0115 decision 2; code on `main`): `hilclaw.start_instance.start(document, *, data_root)` takes a parsed `instance.json` document, exactly a `dict`, and a data root; applies ADR-0076 decisions 2 and 3, the refusal of a given id (ADR-0111 decision 2) and ADR-0109; writes `runs/<run_id>/instance.json` by ADR-0025; and returns the id it built. It reads no configuration. Its reports are exceptions told apart: what `hilclaw.instance_start.prepare` raises for type, validity (`hilclaw.instance.InvalidInstanceError`, `UnsupportedVersionError`) and scope (`OutOfScopeError`, which "is no refusal of the start: what the start does with such a document stays open"); `GivenRunIdError`; `MissingMembersError` with every missing member in the order of `REPORT_ORDER`; the `ValueError` of `json.dumps` for NaN or an infinity in a member `hilclaw.instance` does not define; `RunIdInUseError` with the built id, which is no `OSError`; and the `OSError` of the file system. Its docstring: "it binds no caller (OD-23, UC-1) … has no command-line or MCP entry (ADR-0115 decision 3)".
- **The caller is open** (cited): ADR-0115 decision 1, "The caller may be a command-line front, a UI, the Round-Manager of PLAN P2-1, a CI, or a CI through a `claude -p` session as S2 step 1 has it"; its Walk-through, first row: "A person or a CI script starts it through a command line of the package (an entry a code task would add, of the form `python -m hilclaw.<module>`, not a tool of the registry's command-line front)"; its decision 2: gathering the values — "asking a person, reading a command line, receiving them from an agent" — "is not in the function"; its decision 3: the start is no FR-10 tool. ADR-0118 decision 3: "Whether the loop also calls the start function of ADR-0115 for a new instance is not decided; the caller of the start stays open."
- **The fronts of the package** (cited: ADR-0010 decision 3): "The **command-line front** is for people, scripts and tests, and for whatever runs outside a Claude Code session"; agents call tools through the MCP front. Decision 5: a front obtains the data root as `hilclaw.config.load_data_repo()` gives it; "The modules below keep taking `data_root` from their caller and reading no configuration … the front is that caller." `hilclaw.data_root_source.configured` is that source, and `obtain` asks it once and fails with `no_data_root`.
- **The turn loop's entry** (cited: ADR-0122 decisions 1 and 5; code): `python -m hilclaw.turn_start <run_id>` takes the id of a run that exists, has no option, reads nothing from standard input, and tells its starter "through the process only": one line of compact JSON with an `outcome` member, and exit statuses where only "run over" is 0. It runs the self-check before the first turn (ADR-0125 decision 2). A run directory that holds `instance.json` and no other file is a run whose round 0 has not started, and the loop takes it up (cited: ADR-0120 decisions 2 and 4).
- **History** (cited): `instance.json` enters the data repository's history through the turn loop's turns — the entry step 0 of the first turn commits it on a fresh run directory (ADR-0143 decision 5, revising the "no commit of its own" of ADR-0127 decision 3), and the end of round 0 commits it with the rest of round 0 (ADR-0127 decision 3).
- **UC-1**: actor "배포 엔지니어 / CI"; step 1, the user names "*(HW + 모델 + 최적화 target type + (선택) budget + (선택) gate 구성 + autonomy 모드 + 라운드당 후보 수 N + (선택) 참고 사례·자료 + (선택) 주입할 가설)*" and "instance를 시작한다"; step 2, "시스템이 instance용 작업공간 … 을 만들고 STATE를 초기화한다". S1 step 2 is a person's start; S2 step 1 is "CI가 `claude -p`로 … instance를 기동한다".
- **What nothing can do today**: no module calls `start`. Outside a test nothing writes the `instance.json` of a run, so no first run (PLAN P2-5) and no nightly run (PLAN P2-10) can be started.

## Decision

### 1. Scope

- **The start of an instance of ADR-0076 decision 1** (the scope of ADR-0115 decision 1), **by a person or by a script**: a shell line typed by a person, or a program that runs a command — a CI job without a Claude Code session, a test, and a script that the nightly routine of DRIVER D17 runs if PLAN P2-10 has that routine start its run by a command (how the nightly run is started is the P2-10 task's — PLAN P2-10; D17).
- **Outside**: a start by a UI, by an agent of a Claude Code session, or by a CI through a `claude -p` session (S2 step 1); every instance outside ADR-0076 decision 1; a branch, a continuation or a resume (OD-8 ①). Nothing here is required or excluded of them. In particular this record does not say that a `claude -p` session may or may not run this entry through its shell; that is the matter of the record that makes an agent a caller (ADR-0115 decision 3).

### 2. (a) The caller: the command-line entry `python -m hilclaw.new_run`

**A person or a script starts a first-case instance by running `python -m hilclaw.new_run <file>`. The entry calls `hilclaw.start_instance.start` once and is the only caller of `start` this record names.**

- **A new module `hilclaw/new_run.py`**, not a `main` in `hilclaw/start_instance.py`. **Why**: the entry reads the configuration, a file, its arguments and its standard output; the start function does none of these, and its tests need none (ADR-0010 decision 5 keeps configuration in the front). The split is the one of `hilclaw.turn_loop` and `hilclaw.turn_start`. The name says what the command makes, a new run, and is not a third "start" beside `start_instance` and `turn_start`.
- **It is not a tool of the registry's command-line front** `python -m hilclaw <tool name>` (ADR-0115 decision 3 and its Walk-through): it is not entered in the registry, has no tool name and no MCP name, and its error kinds are no tool-failure kinds.

### 3. (b) The input: one argument, the path of one file holding the JSON document

- **Command line**: exactly one argument, the path of a file whose content is the `instance.json` document as JSON. **No option exists**, and nothing is read from standard input.
- **Why a file and not standard input**:
  - A start run without input waits on nothing: with no argument the entry fails at once, while a reader of standard input would wait on a terminal.
  - The path names the input in a shell history or a CI log, and the file stays where the starter put it, as a record of what was given.
  - It is the form of `hilclaw.turn_start`: one argument, nothing from standard input.
- **The document is passed to `start` unchanged.** The entry parses the file into one JSON object and hands that `dict` to `start`. It adds no member, fills in no default (the defaults of `n_max` and `coder_model` are the start's, ADR-0076 decision 2 and ADR-0136 decision 4), removes nothing, and asks nobody. **Gathering the values stays with the person or the script that writes the file** (ADR-0115 decision 2).
- **Input that gives no JSON object starts nothing.** The entry calls `start` only with a `dict`. It reports, as told apart in decision 5:
  - **bad usage**: not exactly one argument;
  - **unreadable input**: the file cannot be opened or read;
  - **bad input**: its bytes are not UTF-8, not one JSON text, or one JSON text whose value is not an object.
  The decoding rules are the code task's within that answer: a byte order mark, duplicate member names, and the tokens `NaN` and `Infinity` that `json.loads` accepts and JSON does not. Whatever those rules are, a value that reaches `start` and makes `json.dumps` raise is told apart as its own kind (decision 5).

### 4. (c) The data root, and what the entry does not take

- **The data root** comes from `hilclaw.data_root_source.obtain(hilclaw.data_root_source.configured)`, asked once per start, as `hilclaw.turn_start` does (cited: ADR-0010 decision 5). When it fails, the entry starts nothing and reports **no data root**. The entry creates no data root and checks nothing of it beyond what `obtain` checks.
- **The order** of the arguments, the input and the data root before `start` is the code task's. Nothing is written by the entry before `start`, and every failure before `start` starts nothing.
- **What the entry takes is what the document holds.** UC-1 step 1 also names an autonomy mode, a gate configuration, references and injected hypotheses. The entry takes none of them beyond the members the document of ADR-0076 holds — `injections` (ADR-0075 decision 2) included, which the document carries or not as given and `start` writes as given. **This record decides nothing about them**: not their form, not whether the start takes them, not whether a run without them may start (OD-3 / #5 A-5; OD-30 and HQ-0031; OD-9).

### 5. (d) What the starter is told

- **The form** (this record's, after the precedent of ADR-0122 decision 5): through the process only. Standard output gets exactly one line, a compact JSON object in ASCII ended by one line feed, with a member `outcome` that names the kind; the data of a kind are further members. **Exit status 0 means that a run was started, and no other kind has status 0.** No status is 1 or 2, which the interpreter uses. Standard error gets nothing for a kind, except as below. No traceback reaches the starter.
- **The kinds, each told apart from every other**:

| Kind | When | Data on the line |
|---|---|---|
| **started** | `start` returned | the run id it built |
| **given run id** | `GivenRunIdError` (ADR-0111 decision 2) | none |
| **missing members** | `MissingMembersError` (ADR-0076 decision 3) | every missing member, in the order of `REPORT_ORDER` |
| **invalid** | what `prepare` raises for validity: `InvalidInstanceError` or `UnsupportedVersionError` | a text |
| **out of scope** | `OutOfScopeError` — nothing was started because the document is outside ADR-0076 decision 1; this tells what happened and does not make it a refusal of the start, which stays open (ADR-0076 decision 1 and Boundaries) | a text |
| **run id in use** | `RunIdInUseError` (ADR-0109 decision 3) | the id the start built |
| **file system** | an `OSError` of the write | a text |
| **unwritable value** | the `ValueError` of `json.dumps` for NaN or an infinity | a text |
| **bad usage**, **unreadable input**, **bad input** | decision 3 | a text |
| **no data root** | decision 4 | a text |
| **fault** | any other `Exception` | the class name |

  The entry tells `InvalidInstanceError`, which is a `ValueError`, apart from the plain `ValueError` of `json.dumps` by class, and `RunIdInUseError` from an `OSError` as `start` keeps them apart.
- **When the line cannot be written.** The entry checks that it has a standard output before it calls `start`; a process without one gets the **fault** kind, said on standard error, and nothing is started. If writing the line fails after a run was started, the entry writes one line to standard error that names the run id, and ends with a status other than 0. **Why**: the id exists only in the entry's process once `start` returns (cited: the limit of ADR-0111 decision 5), and the run directory alone does not tell the starter which run is the one just made.
- **Fixed here**: the kinds and that each is told apart; status 0 for **started** only, and no 1 or 2; one line of JSON with `outcome`; the run id on **started** and on **run id in use**; the missing members on **missing members**. **Left to the code task**: the words of `outcome`, the names of the other members, the numbers of the other statuses and whether kinds share one, the texts, and the order of the checks of decision 4.

### 6. (e) What the entry does not do, and how the starter goes on

- **It does not**: start a turn or a turn loop, or any `claude` process; run the self-check; write `STATE.json` or any line of `events.ndjson`; make a commit (`instance.json` enters history through the turns, ADR-0143 decision 5 and ADR-0127 decision 3); take a lock (rest of OD-17); look at a run directory before `start`; register a tool or get an MCP name; keep anything between calls; write anything on the starter's behalf beyond what `start` writes (no notification, no file). It asks no question and shows no menu.
- **The starter goes on with a second command**: `python -m hilclaw.turn_start <run_id>` with the id reported on the **started** line. The two commands are not joined (Alternatives (b)):
  - `hilclaw.turn_start` has one argument and no option (its module docstring), and its outcomes say what a start of the loop found (ADR-0122 decision 5); a joined command would merge two report vocabularies in one status.
  - Starting a run then needs no `claude` and spends no plan usage. A person can read the written `instance.json`, and a script can choose when and on which machine the loop starts. A loop that died or stopped is started again by its run id alone (`hilclaw.turn_start`), by whatever started it (ADR-0118 decision 3; ADR-0122 decisions 1 and 2).
  - A run directory that holds only `instance.json` is a run whose round 0 has not started, and the loop takes it up (cited: ADR-0120 decision 4). So a death between the two commands leaves a state that the loop already reads.
- **The turn loop does not call the start function** (an answer to ADR-0118 decision 3's open sentence, for the scope of decision 1).

### 7. How the entry stands to the owner's sentences

- **K1, "the initial UI offers 1 ≤ N ≤ 5".** Two readings were weighed.
  - **(i) The entry is not that UI.** It offers no choice and shows no range. It takes the document as given, and `candidates_per_round` is whatever the document states. A document that states 6 starts if `start` accepts it, as a valid file may state a value "the initial UI would not offer" (cited: ADR-0028 decision 3). The UI and its offering stay open with UC-1's menu, and so does whether anything at the start checks the chosen value against a range (OD-8 sub-question ㉕ (가), unchanged).
  - **(ii) The entry is the initial UI and refuses N outside 1 to 5.** It would add a refusal that no record has: ADR-0028 decision 3 reads the range as "not a rule of validity" and leaves to "whatever offers the user the choice" whether anything checks it. It would also read "UI" as the entry, which the owner has not said, and it fixes in code a policy the owner said "may change later".
  - **Chosen: (i).** It contradicts no owner sentence: K1 speaks of what a UI offers, and the entry offers nothing. It needs no value from the owner. Reading (ii) needs the owner's word that a command line is "the initial UI", which this record does not supply.
- **K2, the initial run caps** (N = 1–2, budget 5–10 rounds, an initial bound of 10 on measurement repeats). **Left with whatever applies them; the entry does not.** ADR-0028 decision 2 reads the N cap as a cap "for the initial runs" and "what applies that cap is not decided (sub-question ㉕)". ADR-0032 decision 4 lets a run state no round budget. The bound of 10 is the `n_max` default the start fills in (ADR-0076 decision 2), not an action of the entry. Applying the N cap in the entry would refuse N = 3 to 5, which K1's UI offers, and so choose between K1 and K2; that choice is the owner's.
- **The P2-5 run** (PLAN: `cpu_standin` × GEMM, N=1, 5 rounds) lies inside both: its document states those values; the entry neither supplies nor checks them.

### Walk-through

| A start of decision 1 | What follows |
|---|---|
| A person writes `inst.json` with every required member and runs `python -m hilclaw.new_run inst.json` | The entry reads it, obtains the data root, calls `start` once. `start` checks, builds the id, writes `runs/<run_id>/instance.json` and returns the id. The entry writes the **started** line with the id and ends with status 0 |
| The person then runs `python -m hilclaw.turn_start <run_id>` | The loop finds a fresh run directory, runs the self-check and starts the round-0 turn (ADR-0120, ADR-0125). Its first entry step commits `instance.json` (ADR-0143 decision 5) |
| The file lacks `tolerance` and `draws` | `start` raises `MissingMembersError`. The **missing members** line names `draws`, `tolerance` in that order. Nothing is written |
| The file states `"candidates_per_round": 6` | The entry passes it on. Whatever `start` answers is reported; the entry adds no range check (decision 7) |
| The file states `"run_id": "abc"` | **given run id**; nothing is written (ADR-0111 decision 2) |
| No argument, or two | **bad usage**; nothing is read or written |
| The file holds `[1, 2]` or is not UTF-8 | **bad input**; `start` is not called |
| `hilclaw.config.json` names no existing directory | **no data root**; `start` is not called |
| The final name is found taken | **run id in use**, naming the built id; nothing was written under that name (ADR-0109) |
| If the nightly routine of DRIVER D17 starts its run by a script that runs the two commands (PLAN P2-10 decides) | The same entry and the same reports. The script reads the id from the **started** line |

## Consequences

- **The code slice for the planner** (code mode, one task within the D4 cap, PLAN P2-5):
  - a new module `hilclaw/new_run.py` with decisions 2 to 6, whose `main` takes its arguments, its data-root source and its standard output from its caller for tests, as `hilclaw.turn_start.main` does;
  - its test file `tests/test_new_run.py`: fixtures written by the tests and temporary data roots only; every kind of decision 5 (each refusal and stop of `start`, the input and data-root failures, a fault, a standard output that fails before and after a start), negative cases, and the run id of a **started** line naming the written file. No `claude`, no stub `claude`, no container and no board is needed (D16);
  - the docstring fix of `hilclaw/start_instance.py` (below).
