## Decision

A sentence is **cited** when a source is named with it. Every other sentence is **this record's own**.

### 1. Scope and terms

- **The sessions**: every `claude -p` turn session the turn loop starts for a run of ADR-0120 decision 1 (ADR-0146 decision 1), the main session and its sub-agents; nothing outside them.
- **A call**: one call of a `mcp__hilclaw__` tool in such a session, through the MCP front.
- **A hook after a call**: a hook on `PostToolUse`, `PostToolUseFailure` or `PostToolBatch` (H23, H24, H28).
- **What a call leaves**: what is in the data checkout after the call because of it — a line of `events.ndjson`, or a file a tool wrote (and later its commit).

### 2. (a) What there is to journal after a call, and who writes it today

| Group | Tools (holder) | What a call leaves | Who writes it | A model action? |
|---|---|---|---|---|
| **Journaled step** | `correctness.check` (evaluator) | The start line and the end line of its identity (ADR-0011 decision 2), or nothing for an ended or an open identity, which is answered from the log | The tool function, through `journaled_step` (ADR-0015 decision 5) | No |
| **Writes a file of its own, no line** | `state.write`, `key.store`, `case.write`, `round.end`, `run.commit` (Round-Manager); `verdicts.write` (evaluator); `spec.write`, `coder.run` (coder-driver) | The file it writes (`STATE.json`, the key record files, the case, the round-end `STATE.json`, `eval/verdicts.json`, the spec, what `coder.run` brings into `output/`), or for `run.commit` the commit; no line in `events.ndjson` (`run.commit` removes a torn tail before the commit). `coder.run`: "a call leaves no record in the data plane besides what it brings into `output/`" (ADR-0126 decision 7), and today fails with `no_container_runtime` | The tool function | No |
| **Reads only** | `state.read`, `instance.read`, `run.fresh` (both); `hypotheses.read`, `checks.read`, `timings.compare` (evaluator) | Nothing | — | — |
| **On no list** | `blob.push`, `blob.fetch` | Nothing: refused by the caller check (ADR-0146 decision 6) and not pre-approved; and "A call writes nothing" (`blob_tools`) | — | — |

- **No group has a model action in what it leaves.** The decision to call is the model's; what a call leaves is written by the tool function, and no agent of these sessions holds a tool that writes a file (ADR-0139 decision 4; Context). **This record's reading**: the proposal's concern, "결과 저널링은 모델 행동이면 안 됨", is met in these sessions today without a hook.
- **What no call leaves in the data plane**: a read; a call stopped by the caller check or the budget check (ADR-0146 decision 6: "nothing is journaled"; ADR-0147 decision 5); a failed call of a tool that writes no line; and the order of calls across tools. These are the events a further journal would add (option (i)).
- **The journaled call and the two hook events.** A call of `correctness.check` that returns a result has had its end line appended "before the result is encoded or leaves that process" (ADR-0015 decision 5), so `PostToolUse` (H23) fires only after the line is in the log. A call that the tool function answers with a failure — `start_line_failed`, `end_line_failed`, `step_open`, a request the tool function refuses, a `run_file_*` kind — reaches Claude Code as `isError` true (Context), so it fires `PostToolUseFailure` (H24), whose `error` is "generally the same text Claude receives". A request that Claude Code itself rejects by schema or validation fires neither event (H24); what Claude Code does with an `inputSchema` is open (OD-18 sub-question ⑤). A call stopped by a `PreToolUse` hook fires neither (H24, read).

### 3. (b) No hook after a call: alternative (iv)

- **Adopted: alternative (iv) of the task.** In these sessions **no `PostToolUse`, `PostToolUseFailure` or `PostToolBatch` hook is added**. For these sessions, PLAN P2-4's "PostToolUse 저널링" is carried by the tool layer: the two lines of the journaled step (ADR-0015 decision 5) and the files of the writing tools (decision 2). ADR-0015 Consequences already gave that reading of PLAN P2-4 for the two lines; this record extends it to the whole of what a call leaves in these sessions and closes the "beyond them" part for these sessions by adding nothing.
- **Not (i) — a hook that appends a further event to `events.ndjson`.** Weighed and **not adopted; left open** (Boundaries):
  - it needs a kind and a `data` payload no record defines (ADR-0006 decision 3), which is a data-plane schema change (CLAUDE.md A-13; the task's judgement) that this record may not choose;
  - it would be a second appender, in another process, beside the server's tool layer: `PostToolUse` "fires concurrently" for parallel calls (H23) and a sub-agent's call fires the same hooks (H26), while "the format assumes one appender at a time" and "Two concurrent writers can interleave bytes or remove each other's unfinished append" (ADR-0006 decision 10) — the torn-tail removal of decision 6, by the tool layer's append or by `run.commit` (Context), then removes the other writer's unfinished line. This is the window ADR-0015 decision 5 rejected for the end line ("the end line would be written by another process after the result has left the tool layer");
  - its line could not be relied on: a failure or timeout of the hook lets the call stand as it ran (H27), and `onFailure` only shows a line to Claude (H25, H27);
  - it would not see a call through the command-line front (ADR-0010 decision 6), so the log would hold the event for one front and not the other.
  If events beyond the step lines are wanted, **this record's reading** is that the tool function is their place, for the reasons ADR-0015 decision 5 gives for the step lines; that is a later record's, with the kind.
- **Not (ii) — a hook that verifies that a journaled call left its lines.** It would establish nothing the call does not already establish. After `PostToolUse` the end line is in the log by the order of decision 2; after `PostToolUseFailure` the model already receives the kind (`start_line_failed`, `end_line_failed` — ADR-0026 decision 3 — or `step_open` — ADR-0015 decision 2), as the `error` text (H24). A disagreement would be a defect of the tool layer that the hook could only report after the call (H25: it cannot block), at the cost of a process and a read of the log at every call, and with a second copy of the identity rule of ADR-0011 decision 3 read from `tool_input`, whose form for an MCP tool is not fixed (H23; ADR-0147 H10). That a journaled tool cannot go around its lines is required of the registry (ADR-0015 decision 5: "the registry offers no way to the step of a journaled tool that goes around the lookup and the two lines") and is the code's and its tests'.
- **Not (iii) — a hook that writes outside the data plane** (the turn's standard error or a log). Its stderr reaches Claude on exit 2 (H25), and with exit 0 Claude does not see it (H25); the loop does not read the session's standard error or output (`hilclaw/turn_loop.py`: "are not read here"); the session directory is removed after each turn (`hilclaw/turn_loop.py`, "A directory per turn"), so a file there is lost; a log elsewhere is neither the data plane (NFR-1) nor the decision log of FR-11. **This record's reading**: an operator's trace of calls is a runtime convenience, not P2-4's journaling, and nothing in the sources asks for it; it is left to a later record if wanted.
- **Not a `PostToolBatch` hook**: it has no matcher (H28), so it fires after every batch of every tool, and its one blocking effect stops the loop (H28), which nothing here asks for.
- **Not a `prompt` or `agent` hook** on these events: a model's judgement after each call, which is the concern of the proposal ("모델 행동이면 안 됨").

### 4. (c) The settings: unchanged

- **No hook is adopted, so (c) has no hook to describe.** The `hooks` member of the session's `.claude/settings.json` stays exactly as ADR-0148 decision 4 has it: "the two `PreToolUse` entries and this one `Stop` entry, and nothing else". The caller check, the budget check and the stop check, their programs, matchers, arguments, timeouts and `onFailure` settings are unchanged; no sentence of ADR-0146 to ADR-0148 decision 4 is revised; the loop passes nothing new.
- **No race is added**: nothing new appends to `events.ndjson` or writes the data checkout, so the appends of the tool layer (ADR-0006 decision 5; ADR-0011 decision 2's window) are as before.
