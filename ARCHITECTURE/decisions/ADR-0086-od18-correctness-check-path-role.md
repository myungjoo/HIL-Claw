## Context

- ADR-0083 decision 3 left a plain `OSError` of `build` without a row, and ADR-0084 decision 4 kept it so, for two reasons about what `build` states: "One class serves two rows" — `FileNotFoundError` and `IsADirectoryError` "come from the source test (S5) and from the output test (S3)", and the other classes of the path tests "from both" — and "Sources no row names" (`os.getcwd`, `os.urandom`, `time.monotonic`, the search for the compiler). The first thing both named that would let it be placed: "A code change of `clang_build.build` that tells, by class or by a member of the error, the source tests from the output tests, and both from the other lines before the start (P3 (b) to (e)). Then a record can weigh S5 and S3 for the first two." Task T-0259 (PR #163, `92d5432`) made that change and placed nothing in a row.
- **Terms of this record.** **The artefact path** is the `output` argument of `build`. The list of ADR-0060 decision 4 says "the output path (S3)" for it, as ADR-0083 and ADR-0084 read it; it is not the output path of ADR-0056 decision 3, the `output/` of the attempt, whose files are the sources.
- **Observations at `92d5432`** (`hilclaw/clang_build.py`; no code is bound):
  - **Q1. The docstring.** "Any `OSError` from testing a source path or the output path, including one that the test itself raises such as a `PermissionError`, is raised with the attribute `path_role` set to `"source"` or `"output"`; an `OSError` from anywhere else, such as forming the absolute path from the working directory, carries no `path_role`." The classes and messages of the path tests are unchanged.
  - **Q2. The source tests.** `_checked_sources` forms `Path(os.path.abspath(source))` outside a `try`; inside it calls `path.is_file()` and, when that is false, `path.is_dir()`, and raises `IsADirectoryError` when the second is true and `FileNotFoundError` otherwise; its `except OSError` sets `path_role = "source"` on the object and re-raises it with a bare `raise`. So a `FileNotFoundError` of a source also stands for an entry that exists and is neither a regular file nor a directory.
  - **Q3. The tests of the artefact path.** `build` forms `Path(os.path.abspath(output))` outside a `try`; inside it raises `NotADirectoryError` when the parent exists and is no directory, `FileNotFoundError` when it does not exist, and `IsADirectoryError` when the artefact path is a directory; its `except OSError` sets `path_role = "output"` and re-raises.
  - **Q4. No other error carries it.** `os.path.abspath` for the sources and the artefact path, `_resolve`, `secrets.token_hex`, `started = time.monotonic()` and every line after them stand outside both `try` blocks; the five classes, `ValueError`, `TypeError` and `CompilerNotFoundError` carry no `path_role` (T-0259's Result, and its tests). The source tests run before the tests of the artefact path, and both before `_resolve` and before `Popen` is called.
  - **Q5. When the test call itself raises** (cited, not established here): the tests raise any `OSError` but those whose `errno` is `ENOENT`, `ENOTDIR`, `EBADF` or `ELOOP` or whose `winerror` is 21, 123 or 1921 on 3.11, as on 3.12 and 3.13 by T-0246's Result, and none on 3.14 where the generic `os.path` functions apply (on Windows not read) (cited: ADR-0080 Context; ADR-0083 P3 (a)); the generic `exists` and `isdir` "return false for an `OSError`" (cited: ADR-0083 P3 (e)). T-0259's reviewer noted the same limit for 3.14. **So where the test does not raise, a refused or failed test reads as false: for a source and for the parent of the artefact path `build` then raises the `FileNotFoundError` of Q2 or Q3 with the same `path_role`; for `target.is_dir()` it raises nothing, and the build goes on** (Q3). What the compiler then meets at the artefact path is not established here.
- No owner comment on #5 speaks to ADR-0083, ADR-0084, ADR-0085, T-0259 or ⑱ (마) (checked on 2026-10-17; every comment since 2026-10-16 carries the driver tail).

## Decision

### 1. Scope and terms

- A call of `correctness.check` as ADR-0081 decision 1 has it. The six kinds, S1 to S10 and the keeper are as ADR-0079 decision 1 has them; a plain `OSError` of `build` as ADR-0083 decision 1 has it. **A path-test error** is a plain `OSError` of `build` whose `path_role` is `"source"` or `"output"`; **an unroled `OSError`** is one with no `path_role` (Q4). Whether the operation calls `build` itself or through `build_verification_executable`, which passes its errors on (cited: ADR-0060 Context), the object and its attribute are the same. **The mock** builds nothing and is unchanged.

### 2. The operation tells the path tests apart by `path_role`

- **From what `build` states alone**: an `OSError` that is none of the five classes, and `getattr(error, "path_role", None)`. `"source"` is a source test, `"output"` a test of the artefact path, and `None` no path test — one of the sources (b) to (e) of ADR-0083 P3 (Q1, Q4).
- **On which reading.** "What the operation observes decides the row" (cited: ADR-0060 decision 4). **This record reads what the operation observes as what `build` states of the error — its class and its documented members**, as ADR-0085 decision 2 read it for `returncode`. `path_role` is documented in the docstring (Q1). It reads no exception chain (cited for the stop: ADR-0081 decision 2), no message (as ADR-0083 alternatives (c) declined it), and, by this record's own choice, no `errno` and no private state.
- **"One class serves two rows"** (ADR-0083 decision 3) **no longer holds for a path-test error**: the role, not the class, says which test raised it. It still describes the classes, and it still holds for an unroled `OSError`, which can come in the classes of the path tests (a `FileNotFoundError` from `os.getcwd` — cited: ADR-0083 decision 3), but no longer as a reason: decision 6 rests on "Sources no row names".
- **The order of the tests.** The five classes are answered as ADR-0079 to ADR-0085 have them and never carry `path_role` (Q4); this record answers only a plain `OSError`.

### 3. `"source"` is S5, `build_input_missing`

- **The operation raises a path-test error with `path_role` `"source"` as S5, `build_input_missing`** — "A file of the compiled set is no longer a regular file when the build is called, or the verification program is missing from the installation", found "before the compiler is started" (cited: ADR-0060 decision 4; ADR-0056 decision 5).
- **For the `FileNotFoundError` and the `IsADirectoryError` `build` raises**: the source is missing, a directory, or another entry that is no regular file (Q2), each at the moment the build is called and before the compiler is started (Q4). That is the wording. Both halves of S5 are one kind, so the role need not tell a kernel file from the verification program; the message "may say which case of its row it was" (cited: ADR-0060 decision 5) where the operation knows it by its own step.
- **For an `OSError` the test call itself raises** (for example a `PermissionError` from a refused `stat` on 3.11; Q5), **this record reads "is no longer a regular file when the build is called" as covering a file the build's test could not establish as one**, and reads "the verification program is missing from the installation" the same way where the test of its source is the one that raised. Reasons: **the same answer on every Python version**, as ADR-0080 decision 3 gave a refused stat test of the artefact ("Where the test reads an error as false, … where it raises, it is S9 by this decision. … the version changes no row" — cited): where the test does not raise, the same refusal is the `FileNotFoundError` of the same role (Q5), which is S5 above; and the build stopped there, so the file reached no compiler. The file may still be a regular file; the reading rests on what the call could establish, not on what is there.
- **The cost, stated.** A file that exists and that the compiler might have read is answered as missing input, where the cause is the machine (a refused search of a directory, an I/O error); which `errno` a machine gives is not established here. A caller reads a tool failure in both answers: left open, the landed rules answer it `operation_answer_invalid` (cited: ADR-0045 decisions 4 and 5), a kind that says the backend's answer had neither form. The message may say "of which kind the error was" and shows "no text of an error" (cited: ADR-0060 decision 5).

### 4. `"output"` is S3, `build_directory_unusable`

- **The operation raises a path-test error with `path_role` `"output"` as S3, `build_directory_unusable`** — "The build directory cannot be made or written", found "before the build" (cited: ADR-0060 decision 4; ADR-0056 decision 5).
- **Why.** The executable "is written: in the build directory", "a directory the operation makes for that one call and that no other call uses" (cited: ADR-0056 decision 4), so the artefact path lies in it. **This record reads S3 as covering each case of Q3** as a build directory that cannot be written at the artefact path, found before the compiler is started (Q4):
  - **A missing directory** (`FileNotFoundError`): the directory the operation made is not there when the build is called.
  - **The artefact path is a directory** (`IsADirectoryError`): an entry the operation did not make holds the name, and `build` refuses to write there.
  - **An `OSError` the test call itself raises**: the call could not establish a place in the build directory it may write to, which this record reads as that directory not being writable at the artefact path. For a test of the parent, where the test does not raise, the same refusal is the `FileNotFoundError` above (Q5), so the answer does not depend on the Python version, as in decision 3. **For `target.is_dir()` it does**: where that test does not raise, the build goes on (Q5), and what follows is answered by what the operation then observes (cited: ADR-0060 decision 4, "What the operation observes decides the row") — for example S7, a broken result, if the compiler cannot write its temporary file and ends with a non-zero status. **The cost, stated**: for that one test, a refused search of the build directory is a tool failure on 3.11 to 3.13 and may be a result on 3.14; the reading rests on S3's wording alone, and how a compiler behaves there is not established here.
- **The `NotADirectoryError` of the artefact path** is S3 already (cited: ADR-0060 decision 4) and now carries `"output"` (Q3). **This record does not change that row.** That ADR-0060 decision 4 places a `NotADirectoryError` before the start by its class, so that one from an unread call of P3 (b) to (e), if one occurs, would meet the same row (ADR-0083 decision 3, "Unchanged"), is not revisited either.
- **The cost, stated.** ADR-0060 decision 4 dates S3 "before the build" and says "The row S3 holds for what the operation finds itself before the build"; here `build` finds it, as for the `NotADirectoryError` that decision already places. A directory removed or filled by another process is read as unusable. By this record's reading the cause may be the machine or a process an earlier call left — ADR-0056 decision 2 names such a survivor for the build directory of its own call ("A process that outlives its limit" — cited) — possibly one the attempt's own code started. A tool failure says that no outcome was established; the cause is not established here.

### 5. No log

- **Neither row has a log.** No compiler process was created (Q4), and "S3, S5, S6 and S4 found before the build start no compiler or none that ran, so they have no log" (cited: ADR-0078 decision 2); the operation hands nothing to the keeper. No rule is added.

### 6. An unroled `OSError` stays open

- **Except a `NotADirectoryError`**, if one of P3 (b) to (e) raises one: ADR-0060 decision 4 places it in S3 by its class, which this record's decision 4 does not revisit. The rest of this decision speaks of the other unroled errors.
- **"Sources no row names" still holds.** An unroled `OSError` comes from `os.getcwd` while forming an absolute path, `os.urandom`, `started = time.monotonic()` or the search for the compiler (ADR-0083 P3 (b) to (e); Q4), and **this record reads S3, S5 and S6 as ADR-0083 decision 3 read them: as covering none of them**. S3 names the build directory, and a working directory, random bytes and a clock are not it; S5 names a file that is no longer a regular file, and no file was tested; S6's "not found" is a search that ended without a find, not one that failed. A reading that takes them in would answer, say, a failed clock as a missing input. **"'Before the start' is several rows"** still holds as well.
- **What would let it be placed** (named, not written here): a step of the operation's own, as ADR-0060 decision 4 allows ("An operation places such an error by the step of its own at which it met it"), which for `os.getcwd` can only remove the call — absolute paths for the sources and the artefact path take it out of those two on POSIX, "not out of a relative found compiler" (cited: ADR-0083 decision 3) — and does not reach `os.urandom`, the clock or the search; or a record that adds the situation to the list of ADR-0056 decision 5. **That may need a new value of `error.kind`, a data-plane change that is the owner's (CLAUDE.md A-13); this record does not add one** and names the question in Consequences.
- **Until then**, an operation that lets it pass is answered `operation_answer_invalid` (cited: ADR-0045 decisions 4 and 5), with the cost ADR-0083 decision 3 stated for the sources before the start.

### 7. No data-plane change

- `path_role` is an attribute of a Python exception inside the tool function's process, read by the operation; it is no member of a file, a result, a request or a line, and the two answers use kinds already named (ADR-0060 decision 4). What a message of those kinds may say is as ADR-0060 decision 5 has it. No value of `condition` or `error.kind` is added, no kind is reserved, and no `schema_version` or layout version changes.

### 8. How far (마) is answered

- **Answered now, for `correctness.check` of the first case and of the mock**: a path-test error — S5 for `path_role` `"source"`, S3 for `"output"`, each with no log, an error the test call itself raises included (decisions 2 to 5); with it the entries "`FileNotFoundError` or `IsADirectoryError` for a source (S5) or for the output path (S3)" and "the other classes of the path tests" of ADR-0084 decision 5.
- **Open under (마)**: an unroled `OSError` of `build` — from `os.getcwd`, `os.urandom`, `time.monotonic` or the search for the compiler before the start (decision 6); the row of a `CompilerRunError` whose `timed_out` is false and whose `returncode` is `None` (cited: ADR-0085 decision 6); the `TypeError` of `clang_build.build`; whatever `clang_build.build` passes on from `subprocess` beyond the `OSError` its docstring names; and the `ValueError` or `TypeError` and the `OSError` for "a `cwd` that does not exist" of `local_run.run`.
