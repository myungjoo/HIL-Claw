## Decision

### 1. Scope and terms

- A call of `correctness.check`, the six kinds, S1 to S10 and the keeper, as ADR-0092 decision 1 has them; the operation reads the class (`isinstance`) and `getattr(error, "parameter", None)` (cited: ADR-0087 decision 2). **The artefact path** is the operation's own (cited: ADR-0060 decision 3). **U4** is now a pre-start `ValueError` of `build` with no `parameter` from after the check of `cwd` up to and including the start, outside V1's third step (V2). **The mock** builds nothing and is unchanged.

### 2. The temporary-name error is no row; the landed rules already say so

- **The operation lets it pass: no row.** A `ValueError` with `parameter` `"output"` is no row by ADR-0091 decision 2 and ADR-0092 decision 2, and a `TypeError` with `parameter` `"output"` by ADR-0087 decision 4, which applies ADR-0060 decision 4's "a `TypeError` for an argument that is no setting … is a defect of the operation's own code and is no row" (cited). Those rules place the error by its class and `parameter`, which is all the operation reads (decision 1), so **they already answer the temporary-name error, and this record only confirms that**. An operation that lets it pass is answered `operation_answer_invalid` (cited: ADR-0045 decisions 4 and 5); that is what the landed rules do with it, not an answer of this record.
- **Why the confirmation holds by meaning, not only by form.** The temporary name is formed from the artefact path alone, with the pid and a random part (V1, V2); the artefact path is the operation's own (ADR-0060 decision 3), in the directory the operation made for the call (cited: ADR-0056 decision 4). So a refusal of that name refuses something made by code — the path the operation's own code handed, and the pid and random part `build` adds itself — which is how ADR-0092 decision 2 and ADR-0089 decision 3 read a refused name and a refused `cwd`: a defect of code. No setting of the backend's — flags, compiler, time limits, environment (ADR-0060 decision 3) — enters the name, so S4 would name a setting that was not refused.
- **The operation cannot tell it from U3 or from the name error of ADR-0092**: as a `ValueError` it is one with `parameter` `"output"` as they are, and as a `TypeError` one with the same `parameter` as the `TypeError` of forming the absolute path (ADR-0087 decision 4); telling them apart would need the message or where it was raised, which the functions do not state (ADR-0092 decision 2). Any other row would move them too.
- **The cost, stated.** Which names `with_name` refuses, on which platform and Python version, was not read (V4 is T-0280's observation, not this record's). If a platform refuses a name the operation chose only because of how that platform reads it, a property of the machine is answered as a defect of code, as ADR-0092 decision 2 (ii) accepted for an encoding.

### 3. What is left of U4

- **Removed**: a `ValueError` from `with_name` (V1). U4 holds no error of V1's third step; the draws before it stay (below).
- **What stays, read from V2** — no claim is made beyond what is read and cited:
  - **The draws of the pid and the random part** (`os.getpid`, `secrets.token_hex(8)`), outside any step. Of `secrets.token_hex` only "Return a random text string, in hexadecimal" was read (cited: ADR-0092 J4); of `os.getpid` nothing was read. V3 shows that a `ValueError` from the token, if one arises, carries no `parameter`.
  - **The command**, in which ADR-0092 decision 3 read no `ValueError` (cited); this record adds nothing.
  - **The clock**, `time.monotonic`: no `ValueError` read and none established absent (cited: ADR-0092 decision 3).
  - **`subprocess.Popen`**, for the command, `cwd` and `env` `build` hands it, an `env` with no `items` method included: unread (cited: ADR-0060 decision 4; ADR-0091 decision 3).
- **It stays open, with the reason of ADR-0091 decision 3**: placing U4 in any row would read what `subprocess` raises into a row unread, and a `ValueError` from `Popen` may be a refused setting (S4 by its meaning) or not. Until it is placed, an operation that lets it pass is answered `operation_answer_invalid` (cited: ADR-0045 decisions 4 and 5), which is what the landed rules do. **The cost**, as there: a setting that only `subprocess` refuses with a `ValueError`, if one arises, gets no S4.
- **What would let it be placed** (named, not decided): a reading of what `os.getpid`, `secrets.token_hex(8)` and `time.monotonic` raise, and of what `subprocess.Popen` raises for what `build` hands it, in a later record; or a code change that makes `build` refuse an `env` with no `items` method, or another such value, in a named check before the start. Either is a later task's.

### 4. No log, and the message

- **No log.** The temporary-name error is raised before any process exists (V1, V3), so no compiler of that check ran; the file of ADR-0078 is absent, which says "that no compiler of that check ran or that its log did not reach the tool function" (cited: ADR-0078 decision 2).
- **The message** is that of `operation_answer_invalid`, which shows "of what was raised, neither its message nor its arguments nor where it was raised" (cited: ADR-0045 decision 6), so whatever the message of `with_name` holds of the name does not reach the log. No rule is added; the wording is the code's.

### 5. How far (마) is answered

- **Answered now, for `correctness.check` of the first case and of the mock**: the temporary-name error, `ValueError` or `TypeError` — no row, with no log (decisions 2 and 4), confirming ADR-0091 decision 2, ADR-0092 decision 2 and ADR-0087 decision 4 for it.
- **Narrowed**: U4, as ADR-0092 decision 6 left it, no longer holds `with_name`; it holds the draws of the pid and the random part, the command, the clock and `subprocess.Popen` (decision 3).
- **Still open under (마)**, as the sub-question ⑱ bullet of OpenDecisionProposals lists them on `main`, changed only for U4: the row of a `CompilerRunError` whose `timed_out` is false and whose `returncode` is `None`; an `OSError` without `path_role` before the start from `os.getcwd`, `os.urandom`, `time.monotonic` or the compiler lookup; an unnamed `TypeError` of `build` (binding the call, `subprocess.Popen` and later, and — named here because the list on `main` did not hold it — the draws of the pid and the random part, the command and the clock, if one arises there) and of `build_verification_executable` (binding the call); U4 as decision 3 reads it; whatever else `subprocess` passes on; and the `ValueError` or `TypeError` and the `OSError` for a missing `cwd` of `local_run.run`, which wait for its record.

## Consequences

- **Code** (code mode, D12 rules; names and modules are the code task's; **this record binds no code**): the operation of `cpu_standin` for `correctness.check`, when it is written, lets a `TypeError` or `ValueError` whose `parameter` is `"output"` pass whichever step of `build` raised it, as ADR-0092 Consequences already say; it needs no step of its own for the temporary-name error. A reading of the draws, the clock and `subprocess`, or a code change for what is left of U4 (decision 3), is a candidate follow-up, not required by this record.
- **Not edited and now less exact.**
  - ADR-0092 Status: "It narrows, and leaves open, the pre-start `ValueError` that carries no `parameter` (decision 3)", now narrower again; J3: "then, outside any step, the temporary name `target.with_name(…)`", which now runs in a step of `"output"` while the pid and token are drawn outside it (V1, V2); J4, read "for J3", now bears on that step; decision 1: "U4 is now a `ValueError` with no `parameter` from after the check of `cwd` up to and including the start (J3)", which no longer holds the temporary name; decision 3: "whether it holds another defect of the name is the unread part of `with_name` below", "The temporary name" and "So U4 now holds: a `ValueError` from `with_name` other than its documented case …", and, under "What would let it be placed", "a reading of `pathlib`'s `with_name` …", where `with_name` has left U4; decision 6: U4 "now holds … `with_name` beyond its documented case, the clock and `subprocess.Popen`"; Consequences: "A reading of `with_name` and `subprocess`"; Boundaries: "The row of U4 as decision 3 reads it", now narrower.
