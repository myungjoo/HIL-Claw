## Decision

A sentence is **cited** when a source is named with it. Every other sentence is **this record's own**.

### 1. Scope and terms

- **The sessions**: every `claude -p` turn session that the turn loop of ADR-0118 decision 3 starts for a run of ADR-0120 decision 1, with the command line of ADR-0139 decision 8. Inside one: **the main session** (the Round-Manager) and **the sub-agents** of the definition's `orchestration/agents/` — today `evaluator` and `coder-driver`. **Outside**: what ADR-0139 decision 1 puts outside (the interactive checkpoint session, the coder's own session in its container, the self-check's session) and every other run.
- **The caller check**: the check of decisions 2 to 6. **Holder list** of a caller: the `mcp__hilclaw__` tools it is meant to hold (decision 3).

### 2. (a) Whether and where: a `PreToolUse` command hook on every `hilclaw` tool

- **Every call of a `mcp__hilclaw__` tool in such a session, by the main session or by any sub-agent, passes the caller check before it runs.** The check refuses the call unless the tool is on the caller's holder list. It is a `PreToolUse` hook of the session's project settings whose matcher is a regular expression anchored to the prefix `mcp__hilclaw__` (H2; ADR-0010 F2) — the text of the matcher is the code slice's.
- **What a pass gives**: no decision. The hook exits 0 and prints nothing, so the call goes on to the permission flow of ADR-0139 — `dontAsk` with the exact pre-approved list (H3). **The hook never answers `"allow"`**: an allow skips the prompt (H4) and would let a hook widen what ADR-0139 lets run. So a call runs only when both the check and ADR-0139's list let it.
- **What a refusal gives**: exit status 2 with one line on standard error. The call is stopped before permission rules are evaluated, and the model reads the line as the denial (H3, H4).
- **Built-in tools are outside the check**: `Agent`, `Read`, `Grep` and `Glob`, the whole built-in set of ADR-0139 decision 4, are not matched. Reading is not restricted (cited: ADR-0128 decision 4; K2 "읽기 제한은 채택하지 않는다", as ADR-0139 cites it), a sub-agent cannot hold `Agent` (`turn_permissions` refuses it in a `tools` list), and delegation is limited to the definition's agents by `Agent(<name>)` (ADR-0139 decision 3).
- **Tools of another server are outside the check**: the session has the `hilclaw` server alone (`--strict-mcp-config`, ADR-0118 decision 6), the anchored matcher does not match another server's tools, and such a tool is not pre-approved (ADR-0139 decision 3). The documentation advises basing trust decisions on `mcp_server.source` "rather than on `name` or the `mcp__<server>__` tool-name prefix" (H2's page); with `--strict-mcp-config` no other server can bear the `hilclaw` name in these sessions, so this check relies on the prefix. Whether the program also reads `mcp_server` is the code slice's.
- **Why a hook and not the tool layer.** A call reaches the server as `tools/call` with a name and arguments (ADR-0010 F8), and "A front authenticates nobody" (cited: ADR-0010 decision 8). The tool layer cannot tell the caller unless the request said it, and a member the calling agent fills in is a claim by that agent, not a check of it. The hook input carries the caller from Claude Code itself (H1).
- **What it does not cover**: a call through the command-line front, which a typed-tool hook sees only as a Bash command (cited: ADR-0010 decision 6). No agent of these sessions has `Bash` (ADR-0139 decisions 3 and 4), so no such path exists today; sub-question ② stays open (Boundaries).

### 3. (b) The holder lists: the two sources of ADR-0139 decision 3, read by the same code

- **The main session's holder list is `ROUND_MANAGER_TOOLS`** of `hilclaw/turn_permissions.py`, the fixed list ADR-0139 decision 3 places in layer-2 code.
- **A sub-agent's holder list is the `mcp__hilclaw__` entries of the `tools` frontmatter of the agent file whose `name` equals its `agent_type`**, among the agent files of the session directory's `.claude/agents/`, read with the reader and the refusals that build the pre-approved list. Built-in entries of a `tools` list play no part (decision 2).
- **One list governs both**: the hook program takes both sources from the same module that builds `--allowedTools`, at each call, from the same files. No list is written into the hook settings or any other file, so the pre-approved list and the holder lists cannot drift apart within one version of the package. The hook program loads the package at each call, while the pre-approved list and the server are built at the turn's start (ADR-0118 decision 6), so a package replaced during a turn acts on the hook's next call; since a call needs both lists, such a drift can only refuse. **Two agent files with the same `name`** would make the pre-approved list the union of both while no single file says what that agent holds; so the shared reader refuses them, and the turn is refused before its session starts, as for the other refusals of ADR-0139 decision 3 (this record's addition to that list). A tool added to `ROUND_MANAGER_TOOLS` or to an agent's `tools` list is pre-approved and held at the next turn, with no change of this record or of the hook settings. **Where the reader's shared part lives, and its signature, is the code slice's.**
- **Telling the caller.** A call whose input carries **neither `agent_id` nor `agent_type`** is the main session's. **This is this record's reading of H1**: `agent_type` is present "when the session uses `--agent` or the hook fires inside a subagent", and a turn session uses no `--agent` (the command line of ADR-0139 decision 8; its Alternatives did not take `--agent`). A call whose input carries **both, `agent_type` a non-empty string**, is that sub-agent's (H1). Any other combination is a caller the check cannot tell (decision 6). That a main-session call carries neither field is item (lvii).
- **The session directory** is taken from `CLAUDE_PROJECT_DIR` in the hook's environment, "the project root where the session started" (H5); the input's `cwd` is not used. **This record's reading**: that root is the session directory, because the session starts there (cited: ADR-0118 decision 4) and no directory above it holds a `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md` or `.claude` other than the runtime user's own (cited: ADR-0118 decision 4; `hilclaw/turn_loop.py` refuses such a parent by its `MARKERS`). The documentation does not say what the project root is outside a repository; that it is the session directory is part of item (lvi). Were it not, every sub-agent call would be refused (decision 6), not let through.
- **Built-in agents.** A delegation to `general-purpose`, `Explore` or `Plan`, which ADR-0139 item (xxxviii) leaves open, would give an agent that inherits the whole pool (ADR-0139 P8). Its `agent_type` names no agent file, so the check refuses each of its `hilclaw` calls. A definition agent named like a built-in agent could not be told from it, so the shared reader also refuses an agent file named `general-purpose` (the reader's name form already excludes `Explore` and `Plan`), as one more refusal before the turn (this record's addition, with that of two files of one `name`).

### 4. (c) Delivery: the layer-2 code writes the session's `.claude/settings.json`

- **The hook settings are not kept as a file under `orchestration/`.** The hook program must be started with this machine's interpreter, as the server is (`sys.executable` in `hilclaw/turn_loop.py`), and a static file copied byte for byte by `LAYOUT` cannot name it. A bare name such as `python` found on `PATH` could be another interpreter, without this package.
- **Before each turn, after the definition is put, the turn loop's code writes the session directory's `.claude/settings.json`**, holding a `hooks` member with this one `PreToolUse` entry and nothing else. This is the way ADR-0118 decision 6 has the loop write the server configuration. ADR-0139 decision 8 holds unchanged: the file carries no `permissions` member. Because it holds nothing else, it sets no `env` member either, so the variable ADR-0141 decision 4 puts in the session's process environment is not overridden by it (ADR-0141 M6; its item (xli)); this record does not move that variable into the file.
- **The entry**: a `command` hook in exec form (H5), `command` the absolute path of `sys.executable` and `args` the interpreter options and a start text that puts the directory holding this package first on `sys.path` and runs the hook program, as the server entry does, so no shell parses an argument on any platform. It sets `"onFailure": "block"` (H3; decision 6) and a `timeout` well below the 600-second default; the value is the code slice's.
- **When the definition brings its own `settings.json`** (none does), the code refuses to start the turn with a fixed text rather than merge or overwrite it. A later record that needs static settings decides how the two combine. Whether `LAYOUT` keeps its `settings.json` key meanwhile, which can then no longer start a turn, is the code slice's.
- **Why the session reads it** (cited facts, not tried): the session starts in the session directory, whose `.claude/settings.json` is read with no parent fallback (R4); a `-p` session uses hooks of settings files in a folder never trusted (H6; ADR-0118 R10), so the trust rule that sets aside allow rules (ADR-0139 P7) does not touch it. That `--setting-sources project` leaves these hooks in force is not stated (H6) and is item (lvi), with ADR-0139 item (xl).
- **The program** is a new module of the package (layer 2: CLAUDE.md "세 층 모델" counts hook entry points there), in Python, so that it uses the reader of decision 3 itself. Its name and the start text are the code slice's.

### 5. What the hook program does

- It reads one JSON object from standard input. It finds the caller (decision 3) and the tool (`tool_name`), takes the caller's holder list from the session directory, and exits 0 with nothing printed when the tool is on it, or 2 with the line of decision 6 otherwise. It writes no file of its own, starts no process, calls no model and contacts no server.
- **Its whole body is guarded**: anything it raises ends in exit status 2 with the fixed line, so a fault of the program itself refuses rather than lets through (H3: exit 1 would be a non-blocking error). `onFailure` covers what happens before or outside that guard — an interpreter that does not start, an exit other than 0 or 2 (an import that fails before the guard, for example), or a timeout (H3).

### 6. (d) When it cannot tell, and what the caller is told

| The hook finds | It does |
|---|---|
| Standard input that is not UTF-8 JSON, or not one object; `hook_event_name` not `PreToolUse`; `tool_name` missing or not a string | Refuses |
| Neither `agent_id` nor `agent_type` | Main session: `ROUND_MANAGER_TOOLS` |
| Both, `agent_type` naming exactly one agent file of the session directory | That agent's holder list |
| Both, `agent_type` the `name` of two or more agent files (which the reader refuses before the turn, decision 3) | Refuses |
| Only one of the two fields, an empty or non-string `agent_type`, or an `agent_type` no agent file names | Refuses: a caller it cannot tell |
| A `mcp__hilclaw__` tool on no holder list (`blob_push`, `blob_fetch`, or any tool registered later and named by no list) | Refuses |
| A tool of another server or a built-in tool (the matcher sends none) | Refuses: the settings are not what this record writes |
| `CLAUDE_PROJECT_DIR` missing or no directory; an agent file unreadable or refused by the reader | Refuses, for every caller, the main session included: the reader's refusals are those that would have stopped the turn (ADR-0139 decision 3), so a definition in that state is not trusted for any list |
| An error of its own; a failure to start or a timeout | Refuses (decision 5; `onFailure`) |

- **The refused caller is told one fixed line**: that the caller check refused the call because the calling agent does not hold the tool, or could not be checked. It may name the tool when `tool_name` has the form `mcp__hilclaw__<name>`, and shows nothing else of the input or of any file. The wording is the code slice's.
- **A refusal is not a failure of the turn**: as with a `dontAsk` denial (ADR-0139 decision 2), the model reads it and goes on; what it then does is its definition's. The tool function never runs, so no start or end line is written (ADR-0015), and nothing is journaled (Boundaries).
- **This is the answer of this one check only.** The default-FAIL contract of OD-18 in general stays open (Boundaries).

## Consequences

- **Code slices for the planner** (code mode; each tested with fixture inputs, fixture agent files and a stub `claude` only, never a real one — D16; each within the D4 cap):
  1. **The hook program**: a new module of the package and its test file, per decisions 3, 5 and 6; it uses the reader of `hilclaw/turn_permissions.py`, which may gain a public function that gives the holder lists (the shared part of decision 3), and which gains the refusals of two agent files with the same `name` and of an agent file named `general-purpose` (decision 3). `turn_permissions`'s docstring "Not done here: … no hook" becomes less exact, and its "What is raised" list gains the new refusals; both are rewritten there.
  2. **The settings write**: after `put_definition`, the turn loop's code writes `.claude/settings.json` per decision 4, refusing a definition's own `settings.json`; tests check the written file and the refusal against a stub `claude`. The `turn_loop` docstring gains the file; `turn_definition`'s "no settings, hooks or permissions" stays true of the copy.
  - **The test-rule question** for slice 1, which this record does not decide: CLAUDE.md test rule ⑤ excludes tests of "hook 스크립트", while a hook entry point under `hilclaw/` is also a module of the layer-2 package, which rules ① to ④ cover. The planner of slice 1 settles which applies, or raises it.
- **Runtime acceptance items** (D16; nothing was tried, nothing is required of the development machine), numbered after the last on `main`, ADR-0145 (lv):
  - **(lvi)** In a session directory never trusted, a `-p` turn session started with the command line of ADR-0139 decision 8, `--setting-sources project` included, runs the `PreToolUse` hook of the `.claude/settings.json` the loop wrote, for every `mcp__hilclaw__` call of the main session and of each sub-agent, and for no built-in tool; `CLAUDE_PROJECT_DIR` in the hook's environment is the session directory; and under `--strict-mcp-config` every `mcp__hilclaw__` tool the session offers is a tool of the server the loop configured.
  - **(lvii)** The hook input of a main-session call carries neither `agent_id` nor `agent_type`; that of a custom sub-agent's call carries both, `agent_type` equal to its frontmatter `name`.
  - **(lviii)** Exit 2 stops the call, the model reads the line as the denial, and the session goes on without waiting; exit 0 with nothing printed leaves the call to `dontAsk` and the pre-approved list, so a held, pre-approved call runs without a prompt.
  - **(lix)** The Claude Code version in use honours `onFailure: "block"` (v2.1.295 or later, H3) and the exec form, so a hook that cannot start or times out blocks the call; on every platform the absolute path of `sys.executable` in `command` is spawned as written, with no `PATH` search (H5), and on Windows the start text reaches it as written.
  - **(lx)** On the runtime machine no managed setting (`allowManagedHooksOnly`, `disableAllHooks`) keeps the hook from running, and no installed mod approves a call the hook blocked (H4); that a `disableAllHooks` of the runtime user's own `settings.json` does not act is ADR-0139 item (xl).
- **Less exact, not edited** (found by reading the records of Required Reading and by a search of `ARCHITECTURE/decisions/` on 2026-10-22 for "until a hook", "a hook is P2-4's", "Only the prompt keeps", "tells callers apart", "calling agent" and "hook settings"; not claimed complete).
