### 2. The P2-14 reference forward pass

- **Inputs**: exactly what the executor gets (ADR-0166 decision 4) — the dimensions, `eps`, the five RoPE constants, the weights as bf16 patterns, the prompt, the given tokens and `lm_head_rows`. There is no binding and no dtype: the reference is of the bf16 pass, the only one built (ADR-0157 decision 5).
- **Widening**: every weight, the embedding table included, is widened as ADR-0163 decision 6 widens an operand (cited); both steps are exact, so the reference starts from the very values the kernels receive.
- **Precision: float64 throughout, no rounding between operations.** Every activation of the pass — each kind's output — stays float64; nothing is rounded to bf16 or binary32 at a kernel boundary. Reasons: O1 (3) asks for "a NumPy float64 implementation" of the model, and HQ-0066 (1)(a) (through ADR-0154 decision 3) defines the reference as the computation "넓혀 NumPy float64로" — of the operation, not of an implementation's storage; the bf16 input and output of each kernel (HQ-0065 (2)) is the executor's choice under test, and a reference that reproduced it would hide a fault in it; the per-kind references of ADR-0163 to ADR-0165 round nothing either. The bf16 rounding of the executor's activations is what the user's tolerance absorbs (O1 (2)). ADR-0166 Alternatives row 8 (b) rejected rounding between calls for a bit-exact test; with a tolerance it would only shrink the deviation the tolerance must cover, not decide anything.
- **`eps`**: the binary32 value of `model_binding.rmsnorm_eps(eps)`, the value every RMSNorm kernel receives (ADR-0158 decision 5; ADR-0163 decision 6 uses the passed binary32 value).
- **RoPE**: the binary32 table of `rope_table.build(head_dim=d, positions=S + G − 1, …)` that the executor receives (ADR-0166 decision 4), widened to float64, row t for position t — as ADR-0164 decision 9's reference takes the `freqs_cis` rows. The table is the host side's input, not a kernel's output (ADR-0161 decision 4), so the comparison measures the kernels and not the table's own rounding.
- **The operations** are ADR-0152 decision 2's in its order, each by the formula of its per-kind reference (cited above): the embedding rows of the fed tokens; per layer RMSNorm, the QKV product with the Q, K and V ranges in ADR-0166 decision 4's column order, the pair rotation of Q and K (pairs (2i, 2i + 1), ADR-0161 decision 5), SDPA with query head j reading KV head ⌊j / (H / H_kv)⌋, scores scaled by 1/√d and position t attending positions 0 … t (ADR-0162 decisions 6 and 15), the O product, the residual add, RMSNorm, the gate and up products, SwiGLU, the down product and the residual add; then the final RMSNorm and the lm_head product.
- **Teacher forcing in one causal pass.** The fed tokens are the prompt and the given tokens but the last — the S + G − 1 tokens the executor's passes take (ADR-0166 decision 7). The reference computes all S + G − 1 positions at once with the causal rule. At each position this is what the executor's prefill and decode passes compute there: the cache rows 0 … P − 1 a decode pass reads hold what the earlier passes of the same layer wrote (ADR-0162 decision 4, cited), the K and V of those positions, which the one pass computes from the same tokens. In float64 the two orders of evaluation differ by rounding only.
- **Validation**: before anything is computed, the arguments are checked by the whole-generation check of ADR-0166 decision 6 at `bf16` with no binding, as `model_forward_run.encode_input` does: its errors are raised, its invalid-input reasons raised as one error. A weight holding a NaN or infinity pattern is not refused (the check does not refuse it); its effect propagates into the reference and decision 3 fails the elements it reaches.

### 3. The teacher-forced comparison

- **Owner (O1 (2))**: element-wise, `rtol` and `atol` given by the user, no default.
- **The predicate** (cited, ADR-0163 decision 7): the reported pattern is widened as in decision 2; element (r, c) passes iff the output is finite and |out − ref| ≤ atol + rtol·|ref| in float64. Any NaN or infinity in the output fails.
- **A non-finite reference element fails**, whatever the output, and is counted apart. Reasons: no tolerance is defined around an infinity or a NaN; IEEE arithmetic would let an infinite reference pass every finite output whenever `rtol` > 0 (∞ ≤ ∞); and a logit that overflows or is undefined in float64 is not a run that matches a reference. It can arise only from the weights (a non-finite pattern, decision 2), so the separate count names the cause.
- **`rtol` and `atol`**: each an `int` or a `float`, finite and not negative, as ADR-0163's tolerance check requires; refused before anything else. No value is chosen here, Llama's included (O1 (2)).
- **The result**: whether every element passes; the number of failing elements; the number of non-finite output elements and of non-finite reference elements (each also failing); the number of failing elements of each row; and the row and column of the first failing element in row-major order. Row r of `"all"` is position r (it predicts the token at r + 1); row p of `"last"` is pass p, position S − 1 + p. No deviation or reference value is returned: the caller holds both arrays.

### 4. The rows it reads and the join with the executor

- **Both `lm_head_rows` values are accepted**; the reference computes exactly the rows the report holds, in the same order: S + G − 1 for `"all"`, positions S − 1 … S + G − 2 for `"last"`. "행마다" (O1 (2)) is read as every reported row. `"all"` checks every position of the teacher-forced sequence; `"last"` checks the rows a generation selects from (decision 5), so a generated run can be compared with the same function.
- **A pure function over a `ForwardReport`**, not a path through `model_forward_execute.execute`: the caller runs the executor, computes the reference from the same arguments and compares. `execute` and its `ForwardExecution` are unchanged. Reasons: the comparison builds and starts nothing, as the reference does not; keeping it out of `execute` keeps the tolerance out of the build-and-run path, and the P2-15 run on the runtime machine compares the same report with another reference (decision 5).
- **The report's token ids are not compared**: in the given-sequence mode they echo the input (ADR-0166 decision 7); a report whose logits have another shape than the reference's is refused.

### 5. The greedy generation mode (a later code slice)

- **The rule** (owner, O1 (1)): the next token is the argmax of the last bf16 logits row of a pass; among equal values the smallest token id. **Where**: in the forward program, between passes — after the `lm_head` call of pass k, the program selects from that pass's last logits row and feeds the selected token to pass k + 1. Reason: one process runs a generation's calls in order (ADR-0153 decisions 1 and 4), and the program holds the row; a host-side selection would need a process per pass or a dialogue over a pipe.
- **Comparing bf16 patterns**: by the values they encode (−0 equals +0; infinities order as values). **A NaN in the row stops the generation** as a run failure (ADR-0153 decision 5's "run failed"), naming the pass: the owner's rule is defined over values, and feeding a token chosen around a NaN would be a rule no one gave.
- **The mode**: the caller gives the prompt, no given tokens, and the generation length G; the program makes G passes, the prefill and G − 1 decode passes, and selects G tokens, the last from the last pass's row. The refusal of the generation mode (ADR-0166 decisions 6 and 7) is replaced by this mode in that slice; the given-sequence mode stays. **The report** then holds the prompt and the G selected tokens, and the logits rows as ADR-0166 decision 7 orders them. Its comparison is decision 3's, with the reference teacher-forced on the selected tokens (all but the last are fed), which is O1 (2)'s P2-14 metric.
- **The P2-15 check is named, not built here**: from the same prompt the executor's first N greedy tokens equal those of Hugging Face transformers under the same rule, and the teacher-forced logits meet the user's `rtol` and `atol` against its logits — both must hold (owner, O1 (2)). It needs real weights, a tokenizer and that package, which only the runtime machine has (O1 (3), D16); its implementation, the reference's configuration and its record are the runtime's (Boundaries).

### 6. Prompt, lengths and values

- The prompt, the given tokens, G, N, `rtol` and `atol` are the caller's, with no default and no Llama value chosen (O1 (2): "값은 사용자 지정, 기본값 없음", "N은 사용자 지정"). The cache stays sized by ADR-0166 decision 4's rule over the generation's own lengths; no longest sequence or capacity is chosen. The RoPE constants are the caller's; O2's 32 is a value of the real model a caller gives, not a default here.

### 7. The module of slice 1

- **`hilclaw/model_reference.py`** (Python: NumPy is already a runtime dependency, HQ-0004): `reference_logits` (decision 2, rows as decision 4), `compare` over a `ForwardReport` and float64 rows (decision 3), and the result tuple `LogitComparison`. It builds, starts, reads and writes nothing, keeps nothing between calls and gives no argument a default.
- **Its tests** (CLAUDE.md test rules): the reference on a synthetic model with two layers, H > H_kv, S ≥ 2 and G ≥ 3 under both `lm_head_rows` values equals an independent pass-by-pass float64 re-computation with an explicit cache; through `execute` with fixture kernels that compute each kind's real operation in binary32 and round to bf16, the executor's logits pass a tolerance the test derives from bf16 rounding, and fail it when a fixture swaps the RoPE cosine and sine or drops a cache row at the decode passes; the predicate's bound, non-finite outputs and references; and the refusals.

## Alternatives considered

| Point | Alternative | Why not |
|---|---|---|
| 2 | (b) Round each kind's float64 output to bf16 at the kernel boundaries | It reproduces the executor's storage instead of the model's operation, so a fault in that choice could not show; the tolerance absorbs the rounding (decision 2). |
| 2 | Round to binary32 at the boundaries | Neither the model nor the executor stores binary32 between kernels; it adds a precision no source gives. |
| 2 | Compute the RoPE angles in float64 from the constants | The comparison would then measure the host side's table rounding, which is no kernel's, and repeat `rope_table`'s frequency rule in a second implementation. |
| 2 | Use the caller's `eps` unrounded | The kernels receive the binary32 value (ADR-0158 decision 5); the difference would be a host-side rounding, as with the table. |
| 2 | Pass by pass with an explicit cache | The same values as one causal pass (decision 2) with more code; the test's independent re-computation is written that way. |
| 3 | Let a non-finite reference follow IEEE comparison | An infinite reference would pass any finite output with `rtol` > 0. |
| 3 | Refuse a non-finite reference as invalid input | It is known only after the reference is computed; counting it locates the cause and keeps one result form. |
| 3 | A default tolerance for the synthetic run | The owner gave none (O1 (2)). |
| 4 | Accept `"all"` only | `"last"` holds the rows a generation selects from; refusing it would need a second comparison for the generation mode. |
| 4 | Join the comparison into `execute` (a field of `ForwardExecution`) | It would put the tolerance and the reference into the build-and-run path and change a tuple tests pin; the P2-15 run needs the same report against another reference. |
| 5 | Select on the host side | A process per pass or a pipe dialogue, against ADR-0153 decision 1's one process per generation. |
| 5 | Skip NaN elements when selecting | A rule over NaN no source gives; the generation would continue from a fault. |
