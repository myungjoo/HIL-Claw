## Decision

A sentence is **cited** when a source is named with it. Every other sentence is **this record's own**.

### 1. Scope

- **The runs of ADR-0076 decision 1** (the hw_profile names `cpu_standin` or the mock; the op_signature is absent or covered by ADR-0041 decision 5) **whose `instance.json` is written by the start function of ADR-0115**: new runs only. A resumed, continued or branched run (①), and every other run, are outside; nothing here is required or allowed of them.
- **The question answered**: (a) who writes the first `STATE.json`; (b) its order against `instance.json`; (c) what a run directory that holds `instance.json` and no other file of the run means, and whether the turn loop takes it up. What the first file holds is ADR-0012's, and how it is written is ADR-0013's (`hilclaw.run_state_file.replace`); neither is restated or changed.

### 2. (a) The Round-Manager of the round-0 turn writes the first `STATE.json`

- **The first `STATE.json` of such a run is written by the Round-Manager of the run's round-0 turn session** (ADR-0118 decision 2), as the first write of that turn into the run. It holds `round` 0 and the start values of ADR-0012 decision 4 (cited: ADR-0012 decision 2).
- **Neither the start function of ADR-0115 nor the turn loop of ADR-0118 writes `STATE.json`.** The start writes `instance.json` (ADR-0115 decision 2) and, by this record, no other file of the run; this is the answer ADR-0115 decision 1 left to "a later record". The loop writes nothing into the run.
- **When.** The Round-Manager begins its turn by reading `STATE.json` (cited: #4 body §3c). If the run directory is fresh (decision 4) — `instance.json` under its final name (decision 3) and no other file of the tree — round 0 has not begun (cited: ADR-0012 decision 2), and it writes the first file **before anything else is written into the run**, and so before any journaled call for the run, which needs the file (cited: ADR-0019 decision 3; ADR-0030 decision 7). The bring-up work of round 0 comes after it (UC-1 steps 2 and 3). Calls that write nothing into the run are not ordered by this record; the self-check is one while it "writes no data-plane file" (cited: HQ-0006 answer; Boundaries).
- **The means is open, as for every other write of the file.** ADR-0012 decision 6 already has the Round-Manager write the end of each round. How the Round-Manager reaches `replace` — a tool of the registry, a command-line entry of the package, or another way — is not decided here (OD-23; OD-18), except that the first write is not the step of a journaled call, which a run without `STATE.json` cannot pass (cited: ADR-0019 decision 3; ADR-0030 decision 7). Otherwise it is the same open question as for the round ends.
- **Why the Round-Manager** (Alternatives):
  - It is the one writer of ADR-0004 and of W1 under either reading (Status), so no accepted record and no #4 agreement is changed.
  - It puts the first write inside the turn that does round 0, the first act of an instance after its start (FR-1). This is this record's weighing: no second writer is needed, and the state before round 0 is the one of decision 4 whatever writes the file.
  - Under every answer a death can leave `instance.json` without `STATE.json`: between the two writes of a start that wrote both (Alternatives (2)), or before the first write otherwise. Decision 4 has to give that directory a meaning anyway.

### 3. (b) `instance.json` comes first

- **In a run of decision 1, the first `STATE.json` is written only into a run directory whose `instance.json` is under its final name.** The start writes no file of the run before `instance.json` (decision 2).
- **How the order holds.** A Round-Manager writes the first file only when it finds `instance.json` under its final name (decision 2); a Round-Manager that finds neither file writes no `STATE.json`. The write of ADR-0013 may create a run directory (its decision 6), and within this scope it does not. What the turn reports then is not decided. This check alone makes the order hold. Beside it, and as this record's reading only: a start that returns an id as a run it started has passed the last step of ADR-0025, which fails on a taken name, so a loop given that id finds `instance.json` there. The moment of the start's report is left to the code task (cited: ADR-0111 decision 3), and a start that stops also reports an id (cited: ADR-0109 decision 3).
- **Grounds** (cited, not restated): the first bullet of ADR-0109 decision 5 — with `instance.json` first, a stop on a taken name leaves the other run "wholly unchanged"; ADR-0111 decision 5 — the hazard of "files before it" does not arise; ADR-0030 decisions 3 and 7 — no call passes ⓢ before `instance.json` is under its final name, and no journaled call can be what first writes `STATE.json`.
- **The question ADR-0109 decision 5 handed on** ("what a start does when a file it wrote before `instance.json` turns out to be in a directory whose `instance.json` it did not write") **does not arise in this scope**: the start writes no such file.
- **Not decided**: whether the writer of the first file also holds the run's layout stamp (reads `instance.json` as a valid version-1 file) before it writes (㉗ (가)); a check of existence is all this decision asks.

### 4. (c) `instance.json` and no other file: a run whose round 0 has not begun

- **A fresh run directory** is one of a run of decision 1 that holds `instance.json` under its final name and no other file of the tree: no `STATE.json`, `events.ndjson`, `artifacts.json` or `rounds/` (the run-level names of ADR-0004 decision 2, each at a known path, so telling it needs no listing). A leftover of either write (ADR-0013 decision 4; ADR-0025 decision 6) changes nothing in this.
- **A fresh run directory is a started run whose round 0 has not begun.** It is the state between the start and the first write of decision 2, and the state after a round-0 turn that died before that write. Both read like the first row of the ADR-0012 decision 3 table: "The round to run is 0".
- **The turn loop takes it up.** A loop started on a run whose directory is fresh starts the round-0 turn, and that turn writes the first file (decision 2). No member of the run can say that it is over, stopped or waiting, since there is no `STATE.json`. What else the loop's step-1 predicate weighs stays open (Boundaries). In particular, decision 4 says what a fresh directory means and that it is not a run that is over; what the loop does after a turn session that failed and left the directory fresh stays the open point of ADR-0118 decision 3 (OD-10, rest of OD-17, OD-19, OD-27).
- **A run whose id no caller kept** (cited: ADR-0111 decision 5) has a fresh directory as well. It is taken up only when a loop is started with its id. Nothing here lists `runs/` to find it, and finding it is not decided.
- **A run directory that holds no file of the tree**, or leftovers only, is not a run of this scope: the start had not put `instance.json` under its final name, so it returned no id as a run it started (decision 3). For a reader of `STATE.json` it is a missing file (cited: ADR-0013 decision 6). **A directory with `instance.json`, other files of the tree and no `STATE.json`**, or with any other file of the tree and no `instance.json`, is not produced by the order of decisions 2 and 3 (no journaled call can run before the first `STATE.json`); what it means, and what a Round-Manager does when it finds one, stay open.

### Walk-through

| Situation | What follows |
|---|---|
| The start function writes `instance.json` and returns the id; a person starts the loop on it | The loop starts the round-0 turn. Its Round-Manager finds the directory fresh, writes the first file (`round` 0) and then begins the bring-up work (decisions 2, 3) |
| The start returned, and no loop was started yet | A started run whose round 0 has not begun (decision 4) |
| The round-0 turn dies before its first write | The same state. The next turn is the round-0 turn again and writes the first file (decision 4) |
| The round-0 turn dies after its first write | The next turn finds `round` 0 and goes on with round 0 (cited: ADR-0012 decision 3) |
| The start dies after its write and before its caller kept the id | A run whose round 0 has not begun, and nothing names it (decision 4; ADR-0111 decision 5) |
| The start stops on a taken name | It wrote nothing under the name (at most a leftover — cited: ADR-0109 decision 3), and the other run is unchanged (decision 3; ADR-0109 decision 5) |
| A loop is started with an id whose directory has no `instance.json` | Its Round-Manager writes no `STATE.json` (decision 3). What it reports is not decided |
