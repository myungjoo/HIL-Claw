### 1. The values ADR-0054 left to the code task, as landed

Each is **cited** from the module named and **adopted here as this record's own provisional value**: provisional because no run on a runtime machine stands behind it (L2 below). A later record or task may change any of them without reopening ADR-0054.

- **The command** (`hilclaw/selfcheck.py`): `python -m hilclaw.selfcheck` — no argument, no option, nothing read from standard input. `check()` is the composition, public so that a later caller of the package gets the report as a value: `selfcheck_login.read` once; only when that says logged in, `selfcheck_session.run` once; then `selfcheck_report.build` over the two values and `selfcheck_report.system_facts()`. `main` writes `selfcheck_report.line` of the report to standard output, flushes it and returns the exit status. Step one runs in the working directory of the calling process (ADR-0054 line 70 names none).
- **The two time limits**: `LOGIN_TIMEOUT_S = 30` for step one and `SESSION_TIMEOUT_S = 300` for the session; fixed constants that no argument, option or environment variable changes (ADR-0054 lines 70 and 91 gave the values to the code). A limit that is too short costs a pass and never yields a false one: the outcome is then `login_unreadable` or `session_failed`.
- **The exit statuses** (`hilclaw/selfcheck_report.py`, `hilclaw/selfcheck.py`): 0 for `passed` and for nothing else; 10 `no_claude`, 11 `not_logged_in`, 12 `login_unreadable`, 13 `front_refused`, 14 `no_call`, 15 `session_failed` (the order of the outcome table); **20 (`EXIT_FAULT`) for a fault of the check itself and for a bad usage** — one value, told apart by standard error. A fault is any `Exception` of a step, of the report or of the data-root source (its `hilclaw.config.ConfigError` excepted, below), and a standard output that cannot be written, flushed or takes fewer bytes than the line; an `OSError` of making the check's directory or writing its configuration file is such a fault, not `session_failed` (`hilclaw/selfcheck_session.py`). Status 20 is not an eighth outcome and comes with no report: whatever standard output then holds is no report. The values avoided are 1 and 2 (the interpreter's), 3 and 4 (`python -m hilclaw`), 120, and 126 and above; if the interpreter's own flush at exit also fails, the status is 120. A bad usage is any argument, `--help` and the empty string included, refused before anything is started.
- **Standard error**: nothing when a report was written; otherwise one fixed line (nothing when standard error is missing or cannot be written; the status stays), `hilclaw.selfcheck: fault: <class>` (the name of the exception's class, never its text, which may name a path) or `hilclaw.selfcheck: usage: no argument is taken`.
- **A missing standard output is refused before step one**, so no session is spent for a report that cannot be written (status 20).
- **No data root configured** (`hilclaw.config.ConfigError` of the data-root source: no file, one that cannot be read, a missing value): the check goes on with an empty `keep_out`. The data root is only named to the session step, asked once just before the session and only when step two is entered; nothing in it is read or written. **What that leaves unchecked**: "outside both checkouts" (ADR-0054 line 87) is then checked only against the directory that holds the package (the source checkout when the package runs from one), and the report has no member that says so.
- **The report** (`hilclaw/selfcheck_report.py`): one compact ASCII JSON object and one LF. Top level `outcome`, `refused_a`, `refused_b` (which condition of `front_refused` held; both can; false for every other outcome), `instruction` (only for `not_logged_in`), and the groups `login` (`auth_method`, `exit_status`, `timed_out`), `system` (`os_name`, `os_release`, `python_version`), `session` (`started`, `init_read`, `result_read`, `exit_status`, `timed_out`, `wire_copy_read`, `tools`, `tools_dropped`, `token_tool_listed`, `fail_tool_listed`, `token_in_reply`, `fail_token_in_reply`, `directory_removed`) and `wire` (`initialize_seen`, `client_version`, `revision_asked`, `revision_answered`, `probe_seen`, `probe_before_initialize`, `probe_revision`, `probe_error`, `token_call_requested`, `token_call_answered`, `fail_call_requested`, `fail_call_answered`, `unforeseen_methods`, `unforeseen_dropped`). **Absent or null**: a group is left out when its source does not exist (`session` when no session step ran, `wire` when no readable wire copy exists); a member of a group that exists is always written and is `null` when its value is unknown; `instruction` is left out, never `null`. **The bound**: of the tool names only those beginning with `mcp__hilclaw__` are written (and the reader's own `other`); a client-supplied string (the version, the three revisions, such a tool name) is written only as 1 to 64 characters of ASCII letters, digits, `.`, `_`, `-` — a method name also `/` — else the word `other`; each list holds each distinct value once and at most 16, and its `..._dropped` member says that one was cut. **The report is the output of a process and not a data-plane schema** (ADR-0054 decision 7 stands): it carries no version and is no record of `STATE.json`, `instance.json` or `events.ndjson`.
- **The session** (`hilclaw/selfcheck_session.py`): `COMMAND`, one constant for every call — `claude -p <PROMPT> --mcp-config selfcheck.mcp.json --strict-mcp-config --setting-sources project --tools "" --permission-mode dontAsk --allowedTools mcp__hilclaw__selfcheck_token,mcp__hilclaw__selfcheck_fail --no-session-persistence --output-format stream-json --verbose`. The prompt is `PROMPT` of that module (not copied here; no token in it). The configuration file `selfcheck.mcp.json` is named to the session **by its file name alone**, against the session's working directory, so no path is in an argument; it holds the server entry under the member `mcpServers` and the name `hilclaw`. The wire copy is `selfcheck.wire`. The directory is made by `tempfile.mkdtemp` with the prefix `hilclaw-selfcheck-` under the system's temporary directory; its removal is tried four times within about two seconds.
- **The two tools and the stream names** keep the names ADR-0054 decision 5 gave as provisional (`selfcheck.token`, `selfcheck.fail`); the names read from the stream and their standing are those of `hilclaw/selfcheck_stream.py` (decision 6 below lists the ones not verified).

### 2. Where ADR-0054 and the code differ — each settled

Its content is at most what a kill leaves: the configuration file, the wire copy and the two tokens — no credential. The report says it: `session.directory_removed` is false. A fault of the check itself (status 20) whose removal also fails leaves it behind too, with no report, the removal having been tried before the fault is passed on; a killed check still leaves it with no report. Who removes a directory left behind is not decided (Boundaries). | cited (`selfcheck_session`, T-0165; `selfcheck_report`, T-0166); the sentence is own |

### 3. The wording questions of the outcome table

Each is **decided** here, and each decision equals what the landed code does (`hilclaw/selfcheck_outcome.py`, `hilclaw/selfcheck_stream.py`, `hilclaw/selfcheck_wire.py`). For every case the landed check can reach, all three are what ADR-0054's own words already say; this record confirms them and gives the reasons and the costs. For q2, `decide` alone reads ADR-0054 line 124 more narrowly in a case the landed check cannot reach; that reading is adopted here.

- **(q1) A -32602 answered by the front to a `tools/call` of a tool name it does not serve is an error of condition (a) of `front_refused`.** ADR-0054 line 124 already says so: condition (a) is any JSON-RPC error written by the front other than a -32601 to a method outside the four it serves, "so: an error answered to ... `tools/call`". This record confirms it (own): line 124 makes no exception for the code -32602, and a name the model chose reaches the server only if the client forwards it — ADR-0054 reads K5 as having `dontAsk` deny a call of an MCP tool outside `--allowedTools` (line 83, not verified) — so after a listing of exactly two tools a forwarded other name is the client's step, not the model's alone. **The cost**: if Claude Code forwards a name the model made up, a check whose front behaved correctly ends in `front_refused` and fails the bring-up. Whether Claude Code forwards such a call is runtime acceptance item (xv) (decision 6); if it does, this answer is revisited by a change of this record together with a code task.
- **(q2) An entry of `mcp_server_errors` undoes condition (b) of row 4 when it names `hilclaw`; an entry for another server alone does not** (cited: `decide` of `hilclaw/selfcheck_outcome.py`; adopted, own). ADR-0054 line 124 excludes "an entry in `mcp_server_errors` (a fault of the check's own configuration file)" without naming a server, while row 7 (line 127) speaks of a session that "named it" — the server — there; this record reads line 124 as row 7 does, an entry that names the check's server, and lists line 124 as less exact (decision 2). **In the check as landed the difference has no effect**: no page read says how an entry names its server (ADR-0054 K8), and under `--strict-mcp-config` the only configuration is the check's own file, which names one server, so the stream reader takes every entry to name `hilclaw` — it sets both `server_in_errors` and `any_config_error` whenever `mcp_server_errors` is present with any value but an empty array — and no such session reads as condition (b) or as `passed`. The case "another server alone" is reachable only with evidence built by hand.
- **(q3) A session with `hilclaw` connected that is also named in `mcp_server_errors`, with something of the model's part missing, is `no_call`.** This is ADR-0054's own order: "the first row whose condition holds, read from the top, is the outcome" (line 117); the condition of `no_call` (line 126) asks nothing of `mcp_server_errors`, and row 7 is "every other case", so its example ("or named it in `mcp_server_errors`") covers only sessions that no earlier row took (cited: ADR-0054's words; this record adds nothing). Such a session is never `passed`, which asks for no entry at all. The report does not say that an entry was present (decision 5).

### 4. The costs the code took to the safe side

Stated plainly (own; cited from `hilclaw/selfcheck_stream.py`, T-0164). None yields a false pass; each can turn a session that would have told something into `session_failed`. Which runtime acceptance item would show whether it bites is named.

- **Exactly one `system/init` event is read.** Two or more are an output the check cannot read: `init_read` is false, so neither `passed`, `no_call` nor condition (b) can hold. If a real session writes that event twice, **every** check ends in `session_failed` unless condition (a) holds — item (xii).
- **An omitted or mistyped `mcp_servers` member** gives the server the status `other`, not "not named": a client that drops the front and omits the member reads as `session_failed`, not `front_refused` (unless condition (a) holds) — items (v) and (xii).
- **The `result` message is told by its `type` member alone** (`result`), on the last line that is not blank; its `subtype` is not read, and one that another line follows is not it — item (xii).
- **`mcp_server_errors` present with any value but an empty array sets both error members** (decision 3, q2), so an entry for a server the check did not configure, should one ever appear, keeps the check from `passed` — item (v).

### 5. What the report does not carry beyond ADR-0054 decision 7

The report does not carry the error codes of condition (a), the server's status word, whether the wire copy was torn or held an unplaceable line, whether `mcp_server_errors` held an entry, whether `initialize` was answered with a result, whether a `tools/list` request came after it, was answered and listed both tools, or whether errors were dropped beyond 16, among others (cited: `hilclaw/selfcheck_report.py`). **This record decides that this is right for now** (own): decision 7 of ADR-0054 lists the members, and none of these is needed to read the outcome: each is a fact the outcome table uses, except the codes of the errors (the table counts errors and does not read their codes) and the dropped errors, and the report gives its effect (the outcome, `refused_a` / `refused_b`) but not the fact itself — a `session_failed` decided by a status word outside the list, an entry of `mcp_server_errors` or a torn copy does not say which. The client's own status word is never carried in any case (`selfcheck_stream` maps it to `connected`, a word of the list, `other` or none); the mapped word could be reported without carrying a string of the client, and is not. The cost is the one ADR-0054 line 139 accepts: a report says how far the session got and not why ("the user repeats the command by hand to read the reason"). A caller that needs one of them — P2-1 first — asks for it by a code task that adds a named member, bounded as decision 1 says; adding one is no change of a data-plane schema.

### 6. Runtime acceptance items added (D16)

Facts only a real, logged-in `claude` on a runtime machine can establish, continuing ADR-0054's list (i) to (viii); on each kind of machine of C-7. **None was tried, none is required of the development machine, and none is closed by a driver task**; ADR-0054's items stay with HQ-0016, and nothing here closes any of them.

- (ix) The configuration file wraps its server entries in the member `mcpServers`, and a stdio entry needs no member beyond `command`, `args`, `env`.
- (x) `--allowedTools` takes both MCP names as one argument joined by a comma.
- (xi) A configuration file named to `--mcp-config` by its file name alone is read against the session's working directory (observed once in T-0106 for one fixture; on no page).
- (xii) The stream names the check reads — `type` and `subtype` with `system` and `init` for the init event; `type` `result` for the result message; its member `result` for the final response text — and that a session writes exactly one `system/init` event and still writes `mcp_servers` when it drops a server. These are the concrete values of item (v).
- (xiii) A real session of the check ends within 300 s, and a real `claude auth status` within 30 s.
- (xiv) On Windows, where the `claude` found may be a command script, the empty argument of `--tools` and the comma of `--allowedTools` reach Claude Code as written.
- (xv) Whether Claude Code sends the server a `tools/call` of a name the server did not list (decision 3, q1).

### 7. Limits

- **L1 — Not code, nothing run.** Every statement about the code is read from the modules on `main`; every statement about what `claude` does is ADR-0054's K1 to K15 or an item of decision 6.
- **L2 — Provisional values stay provisional.** Decision 1 adopts what the code chose; it does not say that any value is right for a runtime machine, and no item of decision 6 or of HQ-0016 is said to hold.
- **L3 — No new value.** This record sets no bound, list cap or time limit the code does not already have.

## Consequences

- **Sentences of ADR-0054 that are now less exact** (none edited): line 93 ("only a check whose process is killed leaves it behind"); line 124 ("an entry in `mcp_server_errors` ... are **not** this outcome", read as an entry that names the check's server); line 130 ("The report names every such method") and line 137 ("as the interpreter states them"; "every unforeseen method name"); line 138 ("the length is the code task's"); line 139, read as a promise that the report holds no path (it is the reason no line is copied whole); line 140 ("The values are the code task's"); lines 70 and 91 ("the value is the code task's"); line 94 ("its text is the code task's"); line 187 ("no module, entry or value is named or decided here"). Each stays true of what ADR-0054 decided; decisions 1 and 2 give what now holds.
- **The owner's objection route.** If the owner reads ADR-0054 line 139 as a promise that the report holds no path and no token-shaped string, that is an objection to decision 2, and a narrower bound becomes a code task. If the owner reads -32602 to an unknown tool name as no refusal of the front, that is an objection to decision 3 (q1) and becomes a code task on `selfcheck_wire` / `selfcheck_outcome`.
- **Runtime acceptance items (ix) to (xv)** join ADR-0054's list; the driver raises them on issue #5 under DRIVER §8 (reason `runtime-acceptance`).
- **A-13 reading.** Document mode; no code, dependency, settings or schema file changes; no data-plane file, member or event is defined.
- **For P2-1.** The first caller meets: exit status 0, 10 to 15 or 20 (or 120 when the interpreter's own flush at exit fails, and whatever the system gives a process that is interrupted or killed); with 0 or 10 to 15, the report line on standard output; with 20, no report — whatever standard output holds (a part of a line, when the write or the flush itself failed) is no report — and one line on standard error unless it is missing or cannot be written; one session of plan usage per call when logged in; a wait of roughly 30 s plus 300 s plus the removal, with no bound stated here: a surviving child of a killed process can make a step outlast its limit (a known limit of `hilclaw/local_run.py`), and `system_facts()` and reading the configuration take time of their own; a directory of the check may be left behind, said by `session.directory_removed` or, after status 20, by nothing.
