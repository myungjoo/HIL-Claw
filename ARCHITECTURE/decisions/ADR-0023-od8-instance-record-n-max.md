## Context

- **Owner** (#5 B-4), under the heading "**First spec example (GEMM, MVP round 1)** — cost is controlled by instance parameters (FR-3), not by model choice": "Initial run caps: N = 1–2 candidates per round, budget 5–10 rounds, measurement repeats adaptive per OD-13 with an initial upper bound of 10. Expected HW time per round: tens of seconds on an 8-core laptop." Nothing else of the owner's speaks of this value.
- ADR-0007 made the bound a parameter of its policy: a measurement "stops at the first n with n ≥ `n_min` and CV < `cv_max` (converged), or at n = `n_max` (the upper bound)" (decision 4), and of the values of the policy `n_max` alone is "**per instance**, default 10, never below `n_min`", while `n_min` = 5 is a "constant of the policy" (decision 8, the table). It named no place: "`n_max` is the one value an instance may set … It is then part of what the instance was started with and is recorded with it (no field named; PLAN P1-8)"; the names of its table "are names of this record, not fields of any file"; "All values are initial values" (decision 10).
- ADR-0018 gave `instance.json` its frame, listed `n_max` among the members of later records (Boundaries) and said how the file grows: later records add members one at a time, and each such record "chooses between a member that may be absent from a valid file and a new version" (decision 2). ADR-0020 and ADR-0022 added `tolerance` and `source_commit` that way.
- The code takes the bound as an argument and reads it from no run: `hilclaw.harness.measurement.stopping_state(samples, *, n_max=N_MAX_DEFAULT)` with the constants `N_MIN = 5` and `N_MAX_DEFAULT = 10`, `hilclaw.harness.timing.run_timing(..., n_max=N_MAX_DEFAULT, ...)` and `driver_arguments(..., n_max, ...)`, and the `<n_max>` argument of the C driver program. `hilclaw/instance.py` defines `schema_version`, `hw_profile`, `tolerance` and `source_commit`; a top-level `n_max` of a content the module can read is handed back uninterpreted, whatever its JSON type, and the module imports nothing of the harness.
- Fixed and not re-decided: the owner's line; ADR-0007 decisions 1, 4, 8 and 10; ADR-0004 (the file is "What the instance was started with", written by "The start of the instance, once", and the tree enforces none of it — decision 10); the frame of the file and its version rule (ADR-0018 decision 2); the members `tolerance` and `source_commit`; that the outcome of a call does not depend on state kept from an earlier call (ADR-0010 decision 7).

## Decision

A sentence marked **owner** renders the line of #5 B-4 or its heading, both quoted in Context. A value is **cited** when another source is named with it. Every other value is **this record's own** choice — among them the name `n_max` as a member name, its place, the written form, the number 5 as the rule of version 1, that the member may be absent, that an absent member means "not stated" and never the default, that a present and invalid member makes the file invalid, and the list of limits.

### 1. Scope

This record fixes one thing of `runs/<run_id>/instance.json`: the member in which a run states the upper bound of repeats of one timing measurement. Nothing else of the file is fixed and nothing of any other file. **A file that holds what ADR-0018, ADR-0020, ADR-0022 and this record define is still not a complete instance record, and no run can be started from it alone** (ADR-0018 decision 1).

### 2. What the member states

- **The member states the `n_max` of ADR-0007 decision 4 for the run**: the largest number of samples one measurement may hold, a measurement being "one uninterrupted sequence of repeats of one built attempt at one execution point" (cited: ADR-0007 decision 1). The meaning is ADR-0007's; this record gives it a place and adds nothing to it.
- **What a reader of this record may conclude** from a file that states the member: that the run states this bound, and — only as far as a measurement of the run was in fact taken under the stated bound, which nothing checks (decision 6) — that the measurement holds no more samples than that.
- **What it may not conclude.** The member bounds the samples of **one** measurement. It is no bound on the number of measurements, of attempts, of candidates or of rounds, and no bound on the repeats of a run as a whole. **It is no budget member** — a reading of this record: it states no amount of time, of hardware quota or of tokens (OD-2, OD-19), and it is none of the four axes FR-3 lists today (loop iterations, tokens, wall-clock time, a target metric). FR-3 ends a run when an axis is used up; reaching this bound ends one measurement. **Owner**: the line stands under a heading that has cost "controlled by instance parameters (FR-3)". This record takes the run caps of that line for such parameters and reads the heading as saying that the bound is an instance parameter that controls cost — which the member is (decision 6) — and not as making it an axis of the budget vocabulary; the owner's line itself names "budget 5–10 rounds" beside the repeats and apart from them. The member says nothing of `n_min`, `cv_max` or any other constant of the policy, nothing of how many kernel calls a repeat times (ADR-0007 decision 2), and not that any measurement reached the bound, converged or was taken at all.
- **One value per run, and what that covers.** The inputs carry one value per instance (cited: ADR-0007 decision 8, "per instance") and name no execution point or backend with it. ADR-0007 applies its policy "now to the `cpu_standin` execution point"; for a simulator and a board "the same rules and values are **initial values only**" (decision 1), and "whether a deterministic simulator needs repeats at all" is open (its Boundaries; OD-13 sub-question ③). This record adds nothing to that: the member is the per-instance value of ADR-0007, wherever the policy of ADR-0007 applies. Whether a later policy for a simulator or a board uses this value, another or none is **not decided**, and no per-point or per-backend form is given; a record that gives a run more than one bound changes this member or adds one, and applies the version rule of ADR-0018 decision 2.

### 3. The member

- **The member is `n_max`**, a top-level member: an *integer* of ADR-0001 (0 to 2^53 − 1, the form ADR-0018 decision 2 uses for `schema_version`) that is **at least 5**.
- **Written form**: a JSON number in decimal digits without sign, fraction or exponent (the words of ADR-0012 decision 4 for a total). **`10.0` and `1e1` are no values**, though both denote ten: one spelling per value, and it agrees with the convention of `hilclaw/run_state.py` and `hilclaw/instance.py`, which take an integer member as exactly an `int` ("`true` and `1.0` are none"). `-0` and every negative number are no values either.
- **Nothing else is a value**: `true`, `false`, `null`, a string (`"10"` included), an array, an object, an integer below 5 and an integer above 2^53 − 1.
- **The name.** `n_max` is the name of ADR-0007, of the arguments of the harness and of the command line of the driver program, and ADR-0018 already lists the member under it; one name lets a value be followed from the file to the measurement without a mapping. ADR-0007's names "are names of this record, not fields of any file", so the member name is this record's choice. The cost: the name does not say what it bounds, and it stands near the N of FR-1, the number of candidates per round, which it does not bound (decision 6). No name is given here for N or for any other value.
- **Why a top-level integer and not a member of an object** that groups measurement parameters or run caps. No other member of such an object has a fixed form: every other value of the policy is a constant (cited: ADR-0007 decision 8), and N and the round budget wait for other decisions. The object would be shaped by members that do not exist. A later record that makes another value an instance parameter applies the version rule to its own member.
- **The lower bound is stated as the number 5.** It is cited: `n_min` = 5 and "never below `n_min`" (ADR-0007 decision 8). `n_min` is a constant of the harness source and an initial value (ADR-0007 decisions 8 and 10); the file is written once. **The rule of version 1 of this schema is the number, not a reference to the constant**: whether a file is valid is then a property of the file and of its `schema_version`, the same for every reader, and a file that was valid when the instance started does not become invalid — its `hw_profile` with it — because a constant of the source changed. What follows: **a change of `n_min` does not change this rule by itself.** If a later policy raises `n_min`, a file that states a bound from 5 to below the new `n_min` stays valid, and the policy refuses that bound when a measurement is attempted (`stopping_state` refuses an `n_max` below its `N_MIN` today); if it lowers `n_min`, a bound below 5 stays invalid in version 1. The record that changes `n_min` says what it does with this rule, and changing it changes the form of this member (ADR-0018 decision 2, "What raises the version").
- **No upper limit below the *integer* range.** No fixed input carries one: the owner's 10 is an "initial upper bound", which ADR-0007 took as the initial value and the default of a value an instance may set, and neither gives a ceiling for what an instance sets. **A valid value is not thereby one a measurement can be taken under**: the driver program of ADR-0009 allocates room for `n_max` samples before the first repeat and refuses what it cannot hold or allocate, and every repeat costs time (C-4, decision 6).
- **In version 1 a run states at most one bound**: the member is one integer.

### 4. A file without the member; the version; the default

- **The member may be absent from a valid file, and `schema_version` stays `1`** — the first of the two choices ADR-0018 decision 2 leaves to the record of a member ("A later record that defines a top-level member which may be absent and may be passed over does not raise it"). A version 1 reader may pass over the member: no fixed rule makes anything a reader of today does depend on it, and a reader that needs the bound is one that knows the member.
- **A member that is present must be valid.** A file whose `n_max` breaks decision 3 is **invalid** in the sense of ADR-0018 decision 2: a reader of this record reports it, uses no member of it — not its `hw_profile`, its `tolerance` or its `source_commit` either — and repairs nothing. This follows ADR-0020 decision 3 and ADR-0022 decision 5.
- **A valid file without the member states no bound.** A reader of this record that is asked for the bound of such a run finds that none is stated and **never substitutes a value — in particular not 10**, not `N_MAX_DEFAULT` or any other constant of the source the reader runs from, and not a value from another run.
- **How "default 10" reads with this.** ADR-0007 decision 8 gives the parameter a default and says in the same place that the value "is then part of what the instance was started with and is recorded with it". This record reads the two together: the default is the value **an instance has** when nothing sets another, and the value an instance has is what is recorded. So the default belongs to where an instance comes by its parameters, before the file is written, and **it is not a meaning of a file that is silent**. Whether the start of an instance writes the member when the user sets no bound, and where it takes 10 from, is the writer's and is not decided (sub-question ㉑). **Until something writes the file, "default 10" is** the constant `N_MAX_DEFAULT` of `hilclaw/harness/measurement.py` and the default of the argument `n_max` of `stopping_state` and `run_timing`: what a caller of those functions gets when it passes nothing. That is a convention of the harness functions for a call that names no bound; it is not the bound of any run, and by this record nothing turns it into one.
- **No path yields a bound the run did not state.** A reader of this record has the bound of a run only when the file of that run is valid, is of version 1 and holds the member. A missing file, a file that cannot be read, an invalid file, a file of another version and a valid file without the member each leave it without one. A later change of `N_MAX_DEFAULT` therefore changes what no file states.
- **What this record does not say**: whether a measurement of a run whose file states no bound may be taken at all. ADR-0007 decision 8 has the bound of an instance recorded; a bound that is applied and recorded nowhere is not what that sentence describes, and this record adds no rule to it (sub-question ㉑).
- **The cost**: validity does not show that a bound is stated. A file without the member and a file whose member name is misspelt look alike to a version 1 reader — both state none (decision 6).

### 5. How the bound of a run is read

- **The bound a run states is the one in this member of the file of that run**, `runs/<run_id>/instance.json` below the data root in use. A reader of this record reads the file as a whole, which must be valid (ADR-0018 decision 2), and **nothing is kept between calls** (cited: ADR-0010 decision 7; ADR-0018 decision 4): a later call reads the file again.
- **A value from elsewhere is not what the run states and does not stand in for it**: a member of a request, a value kept from an earlier call, a default of the source the reader runs from. Which members a request has is the contract of a tool (Boundaries); this record says only where the bound a run states is found.
- **How ADR-0009's "the caller's `n_max`" reads against this** — a reading; ADR-0009 is not edited. Its caller is the caller of the timing run, the Python side that passes arguments to the driver program; it is not the request of a tool, and ADR-0009 does not say where that caller has the value from beyond citing ADR-0007 decision 8. The per-instance value ADR-0007 decision 8 speaks of is, for a run, the one this member states; how it reaches that caller is not said here.
- **A measurement about no run** — the tests of the harness — reads no file; the harness functions keep taking the bound as an argument.
- **Today nothing reads or writes the member**: no tool, registry, backend, hook or module does, and `hilclaw/instance.py` passes it over. **Not said here**: which tool or component reads it, at which moment, and what a call answers when no bound is stated (Boundaries).

### 6. Limits

- **Whoever can write the file changes the bound of a run**, and with it the cost of each of its measurements. No access control exists and the tree does not enforce the single writer (cited: ADR-0004 decision 10); a file changed after the start is read as it is at that read (cited: ADR-0018 decision 6), so two measurements of one run can be taken under two bounds.
- **Nothing checks that a measurement was taken under the stated bound.** No result file records the bound a measurement was taken under (Boundaries); the "not converged" mark of ADR-0007 decision 4 says that a measurement reached its bound, and not which bound.
- **A misspelt name.** A top-level member that is not spelt `n_max` (`nmax`, `N_max`) is passed over (cited: ADR-0018 decision 2, the cost) and the file states no bound — never the default.
- **Two processes, two sources** (cited: ADR-0010 decision 7; ADR-0018 decision 6): a source older than the code of this record passes over the member and takes as valid a file whose `n_max` a newer source refuses; and two sources can hold two values of `N_MIN` or of `N_MAX_DEFAULT`. Neither changes what a file states (decisions 3 and 4), but a harness whose `N_MIN` is above a stated bound refuses that bound.
- **A large value is a cost this member does not cap** (C-4): a measurement that does not converge takes `n_max` repeats, and nothing here limits what a run may state below 2^53 − 1. Limiting the hardware time of a run is the budget (FR-3, OD-2), which this member is not.
- **The name is near N.** A reader that takes `n_max` for a bound of the candidates per round misreads it (decision 3).

### Walk-through

What a reader of this record finds when it is asked for the bound of repeats of the run `r1`.

| `runs/r1/instance.json` | What the reader finds |
|---|---|
| Valid, version 1, with `"n_max": 12` | The bound `r1` states: 12. Asked again in a later call, it reads the file again |
| Valid, version 1, without the member (or with `"nmax": 12`) | No bound is stated for `r1`. No value is substituted, 10 included. The `hw_profile`, the `tolerance` and the `source_commit` of the run can still be had |
| `"n_max": 4`, `0`, `-10`, `10.0`, `1e1`, `"10"`, `true`, `null`, `[10]` or `9007199254740992` | The file is invalid: no member of it is used, neither the bound nor the `hw_profile`, the `tolerance` or the `source_commit` |
| Missing, unreadable, or of another version | No bound can be had, as ADR-0018 has it for the `hw_profile` |
| `r1` states `"n_max": 12` and `runs/r2/instance.json`, below the same data root, states `"n_max": 5` | Asked for `r1` the reader finds 12, asked for `r2` it finds 5: each from the file of the run it is asked about, and nothing of one is used for the other |

## Alternatives considered

| Point | Alternative | Why not |
|---|---|---|
| 2 | A bound per execution point or per backend (an object keyed by point, or one member each) | No input carries more than one value per instance, and the values for a simulator and a board are not known (ADR-0007 decisions 1 and 10; OD-13 sub-question ③). |
| 3 | A member inside an object that groups measurement parameters or run caps | See decision 3: the object would be shaped by members that do not exist. |
| 3 | A descriptive name (one that names the repeats or the measurement) | A second name for the value ADR-0007, the harness and the driver program call `n_max`, to be mapped at every step; the cost of the short name is stated in decision 6. |
| 3 | Any JSON number whose value is an integer (`10.0`, `1e1`) | Two spellings of one value, and a rule about how a reader converts a number, where `schema_version` in the same file has none. |
| 3 | The lower bound by reference to the constant `n_min` of the source | The validity of a file written once would move with the source that reads it: two sources, two answers for one file of one version, and a run whose file was valid at its start could lose its `hw_profile` to a change of a constant. `hilclaw/instance.py` would have to import the harness. |
| 3 | No lower bound in the file; the policy refuses a low bound when a measurement is attempted | A bound ADR-0007 excludes for every instance would be a valid statement, found only at the first measurement. |
| 3 | An upper limit (10, the proposal's 30, or what the driver program can allocate) | No fixed input gives a ceiling for what an instance sets; what a machine can allocate is not a property of the file. |
| 4 | (a) An absent member means the default of ADR-0007 decision 8 | The bound of a run would be a constant of whichever source reads the file — nothing the run recorded. ADR-0007 traces constants through the source commit, and `source_commit` states the start only and may itself be absent (ADR-0022 decisions 5 and 6); a change of the constant would change the bound of a run whose file was never rewritten, and two sources would hold two bounds for one run. |
| 4 | (c) Required, with `schema_version` 2 | Every file and every reader of today would be of another version before a first run exists, and reading another version is OD-11 (ADR-0018 decision 2; ADR-0020 decision 3). |
| 4 | Required without raising the version | Against ADR-0018 decision 2, which makes a further required top-level member a new version. |
| 4 | A present and invalid member leaves the file valid and counts as "not stated" | Two notions of validity for one file (ADR-0020 decision 3, Alternatives), and a damaged statement of a cost bound would pass unreported. |
| 5 | Say that no request of a tool carries a bound | A rule for a contract that does not exist; this record says where the bound a run states is found, which is enough to keep another value from standing in for it. |

## Consequences

- **The code slice that can now be cut** (within the size cap, code mode): in `hilclaw/instance.py`, the validity of the member by decision 3 and a reader of the bound of a run beside `hw_profile_of`, `tolerance_of` and `source_commit_of`, with tests. The name and the return form of that reader and how "not stated" is told from a value are the code task's. The slice needs no import of the harness: the rule is the number 5, and the module's test that it imports neither NumPy nor the harness stays as it is. **Binding the reader to the timing run or to any tool is not part of that slice**, and neither is writing the file (ADR-0018 Consequences).
- **Sentences of the code that then change**: in the docstring of `hilclaw/instance.py`, "It defines no member besides the four (`schema_version`, `hw_profile`, `tolerance` and `source_commit`) and interprets no other", the order of the checks, and the description of `Instance.others`, in which an `n_max` member is handed back today. No case of `tests/test_instance.py` holds an `n_max` member today, so none asserts a content valid that this record makes invalid; the cases that compare a whole `Instance` (for example `test_members_not_defined_are_returned_as_parsed_and_not_interpreted` and `test_the_top_level_is_open`) change only if the slice adds a field to that tuple.
- **Not edited and now less exact** (follow-ups for the integrator): ADR-0007 decision 8 ("no field named; PLAN P1-8") and its Boundaries ("Fields and schemas of … `instance.json`"); the `n_max` row of the table of ADR-0009 ("the caller"); ADR-0018 Boundaries, which list `n_max` among the members of later records, and through that list the Boundaries of ADR-0020 and ADR-0022; the list of what makes `instance.json` invalid in ADR-0018 decisions 2 and 4 and in ADR-0019 decision 3, which an `n_max` that breaks this record joins; ADR-0020 decision 3 and ADR-0022 decision 5, where the members of an invalid file that are not used now have one more beside them. The OD-13 row of the register ("상한 10(#5 B-4, instance 파라미터)") and the ADR-0007 bullet of OpenDecisionProposals OD-13 ("instance가 바꿀 수 있는 유일한 값") stay exact and are not edited; they could name the member. No sentence of UsageCases became false: UC-1 step 1 does not list the bound among what the user gives.
- **A-13 reading**: document mode; no code, dependency, settings file or schema file changes. The record adds one member that may be absent to a file whose frame says how later records add members (ADR-0018 decision 2), along the D6 route as ADR-0020 and ADR-0022 did; by that frame's own rule the version stays `1`. **The set of valid version 1 files becomes narrower without a new version**: a file that holds an `n_max` breaking this record was valid before and is invalid now — the case ADR-0018 decision 6 named; no such file exists in a data plane, since nothing writes the file yet. No member, value list or validity rule of `hw_profile`, of `tolerance`, of `source_commit`, of the key records or of `STATE.json`, `spec.json`, `artifacts.json` or `events.ndjson` changes.

## Boundaries (not decided here)

- **Every other member of `instance.json`** (PLAN P1-8), none of which is named here, and no object that would enclose one: N per round and its bounds (OD-21, OD-29); the round budget and every budget member, their units and their enforcement (FR-3, OD-2, OD-19); the op_signature of the run; owner and project; any time member (OD-8 sub-question ⑨); the layout version stamp (ADR-0004 decision 9); and what waits for the owner — the objective (#5 A-4, OD-1), gates and the autonomy mode (#5 A-5, OD-3), the coder model and the token budget (#5 A-8), the model input (#5 B-5, OD-9), datasets (#5 B-8), tolerance vocabularies beyond the first case (#5 B-7).
- **Any other value of the measurement policy as an instance parameter**: `n_min`, `cv_max`, `trim`, `delta`, `confidence`, `resamples` and the seed stay constants (ADR-0007 decision 8; whether `delta` becomes an instance parameter is OD-1; OD-13 sub-question ④). **The rest of OD-13**: the values for a simulator and a board and whether a deterministic simulator needs repeats (sub-question ③); what a consumer does with a "not converged" measurement; the paired re-measurement; steady state; session hygiene; sub-questions ⑦ and ⑧.
- **The writer**: what writes `instance.json`, by which steps, from which input of the user it takes the bound, and whether it writes the default (OD-8 sub-questions ⑩ and ⑰, and ㉑ below; OD-23; UC-1).
- **Any tool's contract** (OD-18): which tool or component reads the member, the moment of a call, request and result members, any tool-failure kind.
