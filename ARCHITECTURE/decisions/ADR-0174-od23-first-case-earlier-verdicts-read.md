- **What exists** (code on `main`, as observation): `hilclaw.verdicts_file.parse` and `final_name` and the place `layout.verdict_record`; `verdicts.write` writes the file and reads no `verdicts.json` (its kinds for this file are `verdicts_exist` and `verdicts_not_written`, both of the write); `case.write` reads it and names its failures `verdicts_invalid`, `verdicts_unsupported` and `verdicts_unreadable`, a missing file being no failure there (`hilclaw/case_tool.py`); `hypotheses.read` is the per-round read of the selection's file. The selector holds `hypotheses_read`, `checks_read` and `cases_lookup`; `cases.lookup` leaves out the cases of the reader's own run (cited: ADR-0073 decision 1, as ADR-0173 decision 2 keeps it), so no tool gives the selector its own run's verdicts.

## Decision

A sentence is **cited** when a source is named with it. Every other sentence is **this record's own**.

### 1. Scope

- **How the selection of a round ≥ 1 of a run of ADR-0120 decision 1 takes the verdicts of the earlier rounds of its own run**, and whether it needs a read of measurements beyond them.
- **Outside**: round 0, which has no selection (cited: ADR-0059 decision 5); the cases of other runs, which `cases.lookup` gives (ADR-0173); everything under Boundaries.

### 2. (a) The tool `verdicts.read`

| Part | Content |
|---|---|
| Name (MCP name) | `verdicts.read` (`mcp__hilclaw__verdicts_read`); the name holds no `_` (ADR-0010 decision 4) |
| Request | Exactly `run_id` (ADR-0015 decision 4) and `round`, an *integer* of ADR-0001 decision 1 (at most 2^53 - 1) that is at least 1; both required; any other member, or one missing, is refused |
| Result | `{"record": …}`: the document of the file as one JSON object, its members as stored, unknown top-level members included |
| Checks, in order | ① the request, `round` 0 among its refusals (`invalid_request`); ② the data root (`no_data_root`); ③ the read and parse of the round's `eval/verdicts.json`: no file there (`verdicts_missing`), a place holding no regular file or bytes `verdicts_file.parse` refuses (`verdicts_invalid`), another `schema_version` (`verdicts_unsupported`), a read that fails otherwise (`verdicts_unreadable`); ④ the document's `run_id`, then its `round`, against the request's (`verdicts_invalid`) |

- **One round per call, not every earlier round at once.** A request of `run_id` alone would need the run's round from `STATE.json` or a listing of `rounds/`, and one failing file would fail the whole answer or need a carriage of per-round failures in the result; one call per round keeps the form of `hypotheses.read` (cited: ADR-0129 decision 3), reads one file and names its failure by kind. The cost is one call per earlier round.
- **Which rounds.** Round 0 is a refused request before the data root is asked (cited: ADR-0071 decision 6; as ADR-0129 decision 3 refuses it for `hypotheses.read`). **No `STATE.json` is read**, so any round ≥ 1 is admitted, the round being selected and later ones included; which rounds the selector asks for is decision 6. The round being selected has no verdicts while it is being selected, since evaluate comes after it in the round (cited: ADR-0172 decision 5, step 12), so a request for it normally answers `verdicts_missing`.
- **The whole valid document, not a part**, for the reason of ADR-0129 decision 3 (cited): choosing a part would make the tool decide what the selection needs, and the whole carries members later records add at the open top level (cited: ADR-0071 decision 2). It is the stored record, not a summary: a summary would be a second schema of the file.
- **Built on `hilclaw.verdicts_file`**: the bytes are parsed by `verdicts_file.parse` and no second parser. `verdicts.write` is not changed, and no public read is added to `hilclaw/verdicts_file.py`: no other tool's failures would be named through it, since `verdicts.write` reads no `verdicts.json` and `case.write` keeps its own read (Context).

### 3. (b) Its kinds, a missing file and its cost

- **Reused with their meanings**: `invalid_request` and `no_data_root` (cited: ADR-0015 decision 2); `verdicts_invalid`, `verdicts_unsupported` and `verdicts_unreadable` as `case.write` names the same failures of the same file (cited: ADR-0133 decision 3, `hilclaw/case_tool.py`), a file naming another run or round being `verdicts_invalid` there too. **No `run_file_*` kind is used**: `verdicts.json` is no run file of ADR-0019 decision 3 and is not read through `run_file_tools`. `verdicts_exist` and `verdicts_not_written` are kinds of a write and do not fit a read.
- **One new kind, `verdicts_missing`**: the round's file is not there, and the message says so when the data root is not an existing directory either. A search of `hilclaw/`, `tests/`, `orchestration/` and `ARCHITECTURE/` on 2026-10-26 found no use of the name. It is a name of the tool layer, **not a change of the data plane** and not reserved (as ADR-0132 decision 4 says of its kinds).
- **A missing file is a kind, not an empty result.** The absence "means that the tree holds no verdicts for that round and nothing more" (cited: ADR-0071 decision 2); an absence read as a value is what ADR-0072 Alternatives row 3 rejects (cited). A result `{"record": null}` would be a value the selector could read as a verdict of the round; a kind keeps the result always a stored record, as `hypotheses_missing` does for `hypotheses.read` (cited: ADR-0129 decision 3). `case.write` takes the absence as no failure because a round without verdicts is still promoted (cited: ADR-0133 decision 4); a read has nothing to build.
- **A number beyond the float range** in a top-level member no record defines cannot be returned: `bad_result`, as for `hypotheses.read` (cited: `hilclaw/hypotheses_tool.py`). It is the registry's kind, not this tool's.
- **Not journaled**: a read costs no limited resource and can be repeated (cited: the reasoning of ADR-0124 decision 3, as ADR-0129 decision 3 applies it). It appends no line, selects no backend, creates nothing and keeps nothing between calls. It joins `default_registry` in the source and in no other way (cited: #5 A-12 point 3).

### 4. (c) Measurements: no further read

- **The selector gets no read of `sim.run` or `board.run` results and no `timings.compare`.** What an earlier round measured reaches it in two typed forms already: each verdict's `comparison` entries, whose `difference` `verdicts.write` recomputed from the log (cited: ADR-0140 decisions 2 and 5), and the check results and standing of any attempt through `checks.read` (cited: ADR-0132 decision 3). The verdict records no sample, ratio, interval or magnitude (cited: ADR-0071 decision 3), and no landed rule weighs one (cited: ADR-0140 decision 4, "No parameter is added: not a margin beyond `delta`, not a magnitude"; OD-13, OD-1). A read of raw timing results would put before the selection a quantity that no record lets it weigh, and its use would be a comparison or a "better than" beside the evaluator's.
- **`timings.compare` stays the evaluator's**, for the reason ADR-0132 decision 3 gives (cited): "the comparison of two attempts is the evaluator's work (ADR-0140 decision 2), whose outcome reaches a later selection as a verdict; giving the selector the same comparison would let it judge a pair beside the evaluator". This record supplies the means by which that outcome reaches it.
- **The first-case N = 1 run has no sim measurement in a round ≥ 1** (cited: ADR-0172 decision 4, "and no `sim.run`"), so a `sim.run` read would have nothing to give these runs.
- **Left named**: a read of measurements for a selection, should a later record admit a magnitude or a selection rule that needs one (OD-13, OD-1); **profiles**, which `cpu_standin` does not provide (cited: ADR-0130); `eval.json` (OD-20).

### 5. (d) The holder

- **The technique-selector alone holds `verdicts.read`.** Its `tools` gain `mcp__hilclaw__verdicts_read`, the addition ADR-0132 decision 3 foresaw ("Later reads are added by the records that create them", cited). **No other agent file and not `ROUND_MANAGER_TOOLS` lists it**: the Round-Manager forms no hypothesis and earlier verdicts would enter its context, which ADR-0132 decision 2 rejected for the selection's inputs (cited); the evaluator judges its own round from its hypotheses, checks and comparisons (cited: ADR-0140 decision 6) and is given no earlier verdict here; the coder-driver and the experiment-runner hold no selection work (cited: ADR-0132 decision 2).
- **The caller check follows**: the entry is an exact `mcp__hilclaw__<name>`, so the derived pre-approval takes it with no change (cited: ADR-0139 decision 3), and the caller check lets it through for the selector and refuses it for the main session and every other sub-agent (cited: ADR-0146 decisions 2, 3 and 6).

### 6. (e) The selector's use

- **When**: in its work **before it sends the round's record** with `hypotheses.write`, since the hypotheses the verdicts inform are written once, with the record (cited: ADR-0059 decision 1). Its order against the `cases.lookup` call is free; both come before the record (ADR-0173 decision 5, cited). The `catalog.read` call and the choice of techniques stay after the record (cited: ADR-0171 decision 2).
- **Which rounds**: **once for each earlier round from 1 to the round before its own, in ascending order**; round 1 makes no call, since round 0 has no verdicts (cited: ADR-0071 decision 6). Every earlier round, not a chosen few, so that the input of FR-17 does not rest on a model's choice of what to open (the reason ADR-0073 decision 1 gives for the lookup, cited). **No bound is set** on the number of rounds read: the input grows by one file per round, as the cases do (cited: ADR-0173 decision 2, "The size of the result"); a selection rule for many rounds is left (Boundaries).
- **After `invalid_request`** the selector corrects its request and sends it again (its own error, as for `cases.lookup`, cited: ADR-0173 decision 4).
- **After `verdicts_missing`, `verdicts_invalid`, `verdicts_unsupported` or `bad_result`, that round gives no verdicts and the selection goes on** with the other rounds and the record. Reasons: the round has ended (decision 1 reads only earlier rounds), its file is written once and nothing repairs an invalid one (cited: ADR-0071 decisions 1 and 2), so a later turn would meet the same answer, and a stop would stop every later turn of the run for good; the absence says nothing more of the round (cited: ADR-0071 decision 2), and an invalid file's members are not used (cited: the same). Under the steps of ADR-0172 an ended round has its verdicts written (cited: its decision 6), so these kinds name a run or tree that left those steps.
- **After `no_data_root` or `verdicts_unreadable`, the selection writes no record**: it sends no `hypotheses.write` and no further request, reports the kind and ends — as after a failure of `cases.lookup` (cited: ADR-0173 decision 4). The Round-Manager's read then finds no record and comes to the stop (cited: ADR-0132 decision 6), and the next turn delegates the selection again. Reasons: these name a data root or a read that may be repaired before a later turn, and a record written without that round's verdicts would stay without them (cited: ADR-0059 decision 1).
- **When the round's record already exists** (a re-entered round, cited: ADR-0132 decision 6) the selector still reads the earlier verdicts first; its `hypotheses.write` then meets `hypotheses_exist` and nothing is replaced (cited: ADR-0132 decision 4).
- **What it does with them is its judgement**: the verdicts are input to the round's hypotheses (cited: FR-17) and among the records of earlier rounds it weighs when it chooses the techniques (cited: ADR-0171 decision 2, "the records of earlier rounds"). **An earlier verdict is a hint, not a target** (cited: FR-15, FR-18, read for a verdict as ADR-0173 decision 5 reads it for a case): a `refuted` verdict forbids no retry, and a `supported` one sets no target. **Nothing of the verdicts read is recorded**: `hypotheses.json` has no member for it, and a basis kind naming a verdict is OD-30's (Boundaries); adding either would be a data-plane change (A-13). The verdicts files themselves stay the record of what was there (cited: ADR-0071 decision 1, "a verdict that could be rewritten … would no longer be the one that round read").
- **Its fixed rules**: call `mcp__hilclaw__verdicts_read` once for each earlier round from 1 to the round before its own, in ascending order, before the record; on `invalid_request` correct the request and send it again; on `verdicts_missing`, `verdicts_invalid`, `verdicts_unsupported` or `bad_result` go on with the other rounds and the record; on any other kind send no record and no further request, report the kind and end. **Its report gains** one line per `verdicts_read` request, as every tool request has (cited: ADR-0132 decision 7), naming the round and the number of its verdicts or the failure kind. Its prohibition "Request no check, measurement, spec or coder call" (cited: ADR-0132 decision 7) is unchanged.

### Walk-through

| Situation | What follows |
|---|---|
| Round 1 | No `verdicts.read` call; the selection goes on as before |
| Round 3; rounds 1 and 2 ended with their verdicts written | Two calls, rounds 1 then 2; each returns the file whole; the selector forms round 3's hypotheses with them, then writes the record |
| Round 2 of a run whose round 1 is `refuted` | The selector may retry the hypothesis with another technique or form another; neither is forbidden (decision 6) |
| A call for round 1 answers `verdicts_invalid` (the file names another round) | Round 1 gives no verdicts; the selector reads round 2 and writes the record; its report names the kind for round 1 |
| A call answers `verdicts_unreadable` | No record; the report names the kind; step 7 answers `hypotheses_missing`; the stop; the next turn tries again |
| The selector asks for its own round | `verdicts_missing`, which says nothing more; the fixed rule asks for no such call |
| The Round-Manager or the evaluator calls `verdicts.read` | The caller check refuses it (cited: ADR-0146 decision 6) |

  - **(xc)** In a round ≥ 2 of a first-case run, the technique-selector calls `mcp__hilclaw__verdicts_read` once for each earlier round, in ascending order and before `mcp__hilclaw__hypotheses_write`, as decision 6 says; and the result for the largest verdicts file a first-case round writes reaches it whole, within any limit Claude Code puts on the result of an MCP tool call.

That the selector read every earlier round, and before the record, rests on its definition: `hypotheses.write` cannot tell, and no hook checks it. What the selector took from the verdicts is in its context and the transcript, in no file.
