## Decision

No sentence below renders a decision of the owner about a budget of wall-clock time; C-7 is cited as the row of Requirements it is. A value is **cited** when a source is named with it. Every other value is **this record's own** choice — among them the reading of the word "wall-clock", the unit, the name `wall_clock_budget_s`, its place, the written form, that the rule of validity starts at 1 and has no end below the *integer* range, that the member may be absent, that an absent member means "not stated" and never "unlimited", a default or zero, that a present and invalid member makes the file invalid, that the clock and the counting are left open, that no rule ties the member to `round_budget`, to `STATE.json`, to the spend view or to the log, and the list of limits.

### 1. Scope

This record fixes one thing of `runs/<run_id>/instance.json`: the member in which a run states its budget of wall-clock time. Nothing else of the file is fixed and nothing of any other file. **A file that holds what ADR-0018, ADR-0020, ADR-0022, ADR-0023, ADR-0024, ADR-0028, ADR-0031, ADR-0032 and this record define is still not a complete instance record, and no run can be started from it alone** (ADR-0018 decision 1).

### 2. What the member states

- **The member states the budget of wall-clock time (FR-3 ③) the instance was started with, as an amount of time.** That such a budget exists and that its value is given by the user at run time is cited (FR-3); this record gives it a place and adds nothing to it.
- **What the word "wall-clock" carries — this record's reading.** It names the kind of time: time as a clock shows it passing, as opposed to processor time, which adds up threads and processes (ADR-0009 decision 3 draws the same line for one timed interval: "elapsed time, not processor time"), and as opposed to an amount of use of hardware (OD-2). **This record reads no more into the word.** It names no clock and no moment from which the time runs, and this record does not take it to settle whether a stretch in which the instance waits, or in which no process of it runs, is part of the amount: no input applies the word to those cases, and each of them belongs to a decision that is open (below).
- **What a reader of this record may conclude** from a file that states the member: that the run states this amount as its budget of wall-clock time. No more.
- **What it may not conclude.** The member is no time of day and no deadline: it names no moment, and no file of a run states when the instance started (decision 6). It is no limit of one process, build, measurement, coder call or tool call — the `timeout_s` of `hilclaw/clang_build.py` and `hilclaw/local_run.py` and the time limit of a timing run (ADR-0009 decision 9) are none of it. It is no amount of hardware time (OD-2), no number of rounds (`round_budget`), no amount of tokens and no target metric (Boundaries). It does not say that the run took, takes or will take that long. That a stated budget used up ends the run is FR-3's; this record adds no rule that ends a run when a time reaches the amount, and nothing compares anything with it (decisions 5 and 6). A run may end earlier on another axis, on a target or on the user's word (FR-3; UC-2), and the member does not say which other axes the instance was given.
- **The clock, and what counts against the budget, are not decided here.** The inputs carry an amount of wall-clock time and no rule of counting. They do **not** carry, and this record does not decide: from which moment the time runs; whether the time counts in which the instance waits at a gate (FR-4), in which no process of it runs between two turns (UC-3), in which it is paused (the register row of OD-19 holds the pause at a rate limit as a proposal, "(제안)", after the "Design consequences" of #5 B-6; neither says whether paused time counts), and between the death of a process and the resume (NFR-1); how the time of a run that is continued or branched from is counted (sub-question ①); against which clock the time is read, and what holds when that clock is set or the run moves to another machine; and what compares the budget with what, at which moment. They are registered (sub-question ㉚ (i)). **The member has its meaning without them**: it records what the instance was started with (cited: ADR-0004), as FR-3 names the axis and S2 step 1 states "wall-clock 8h" without a clock or a rule of counting. The cost, plainly: until that rule exists, two readers can differ in whether a run has used up the stated amount, and this record gives neither of them the answer.
- **One value per run.** The file is written once (cited: ADR-0004 decision 4) and the member is one integer. How a continuation or a branch under a new budget (S3 step 3; FR-6) relates to a file that is written once is OD-8 sub-question ① and is not decided, as ADR-0032 decision 2 has it for the round budget.

### 3. The member

- **The member is `wall_clock_budget_s`**, a top-level member: an *integer* of ADR-0001 (0 to 2^53 − 1) that is **at least 1**. **It counts seconds.**
- **Written form**: that of ADR-0032 decision 3 — a JSON number in decimal digits without sign, fraction or exponent. **`28800.0` and `2.88e4` are no values**, though both denote 28800: one spelling per value.
- **Nothing else is a value**: `true`, `false`, `null`, a string (`"28800"`, `"8h"`, `"PT8H"` and `"unlimited"` included), an array, an object, a number with a fraction (`0.5`), `0`, `-0`, every negative number and an integer above 2^53 − 1.
- **The unit is the second** — this record's own choice; no input names a unit. Weighed: the hour, the minute, the second, a finer unit. An integer of hours states S2's "8h" and cannot state half an hour; an integer of minutes cannot state ninety seconds. No input gives a grain below which a budget may not be stated, so a coarser unit would fix one. Of the three the second is the one in which every amount written in whole hours, minutes and seconds is a whole number, each with one spelling. The range is no constraint in any of the three (2^53 − 1 seconds are about 2.8 × 10^8 years). **That the unit stops at the second is this record's choice as well**: a finer unit has the same property, and a second is itself a grain no input gives. The record stops there because no input asks for an amount below a second, because the package counts the time of one process in seconds (`duration_s`, `timeout_s`) and the `time` of a log line has that grain (ADR-0006 decision 3) — an agreement that **ties the member to neither** (decisions 2 and 5) —, and because each finer unit shortens what the *integer* range can state (2^53 − 1 nanoseconds are about 104 days). **What it cannot state: a fraction of a second.** In which unit the user gives the amount, and what converts it, is the writer's and is not decided (sub-question ㉚ (ii)).
- **The name** is this record's choice: "wall_clock" is FR-3's word for the axis, "budget" is FR-3's word, and `_s` is the unit. In `round_budget` the first word is the unit; "wall_clock" names a kind of time and no unit, and S2's example reads as 8, as 480 or as 28800 by the unit, so the name carries the unit for whoever reads the file without this record. Weighed against it:
  - `wall_clock_budget` — the unit would stand in this record only; `wall_clock_budget_seconds` — the same statement, longer, where the package's suffix is `_s`.
  - `time_budget`, `duration_s`, `timeout_s`, `deadline`, `max_wall_clock_s`: the first does not tell wall-clock time from hardware time (OD-2); the next two are the words of the package for the time of one process; a deadline is a moment; a `max_` names a limit that something keeps, and this member stops nothing (decision 6).
  - **A name shared with an axis of the spend view** (`budget_spent.totals`): no axis is named (cited: ADR-0011 decision 1), and whether an elapsed time is accounted through the log at all is open (cited: ADR-0011 decision 7). **`wall_clock_budget_s` is the name of a member of this file and nothing else**: this record names no axis of the spend view and does not say that time is, or is not, such an axis.
- **Why not another form.**
  - *A string in a duration notation* (ISO 8601: `"PT8H"`): one amount has several spellings (`"PT8H"`, `"PT480M"`, `"PT28800S"`), the notation holds days, months and years whose length depends on a calendar, a reader needs a parser of its own, and no file of the data plane holds such a form. The `time` of ADR-0006 is a moment and is fixed "for this file only"; this member is an amount, so sub-question ⑨ (the notation of times in other files) is not touched.
  - *An object of a value and a unit* (`{"value": 8, "unit": "h"}`): several spellings again, a vocabulary of units, and a comparison only after a conversion.
  - *A number with a fraction* (hours as `0.5`): two spellings of one value and a binary fraction where every integer member of this file is exact (`n_max`, `candidates_per_round`, `round_budget`).
- **Why a top-level member and not an object for the budget** with one member per axis. ADR-0032 decision 3 gave its reason — "no other member of such an object has a fixed form" — and named the cost. With this record one other axis has a form, so that reason now holds for tokens (#5 A-8), the target metric (#5 A-4, OD-1) and HW quota (OD-2) only. The reason that decides here is another: a budget object would either take `round_budget` in, which changes the form of a member ADR-0032 defined and raises `schema_version` (cited: ADR-0018 decision 2) — a change of that record, which this one may not make —, or stand beside it, which gives the budget of a run two places. **So the wall-clock part of sub-question ㉙ (iii) is answered: a member of its own beside `round_budget`.** **This record fixes no place and no name for any other axis and no rule that encloses them**, and two members side by side are no rule for a third: a later record states its axis in a member of its own or changes these, and applies the version rule. The cost: a later record that wants one object for all axes now moves two members.
- **The lower end is the number 1** — this record's own choice; no input states a lower end. A budget of no time is used up at the moment its clock begins to run, whichever clock that is: `0` would state no amount of time a run could use, and what a file that holds it would mean — a run that may not begin, or one that ends as its clock begins — hangs on the clock decision 2 leaves open. 1 is the smallest value of the form that states an amount of time. This is a choice of the same shape as that of ADR-0032 decision 3 for `round_budget`, and not the same argument: there the meaning of `0` hangs on whether round 0 counts; here a budget of one second may allow as little as a budget of none, and the rule does not claim otherwise (a valid value is not thereby one a run can be carried out with — last item). A record that settles the clock and finds that 0 must be a value changes the form of this member and applies the version rule.
- **No upper end below the *integer* range.** FR-3 has the value given by the user. S2's "8h" is the value of an example: it is no cap, no default and no typical value by this record. The file is written once; a number in its rule would turn a change of policy into a change of the form of this member. Whether the start of an instance checks a chosen value against any range is not decided (sub-question ㉙ (ii)).
- **A valid value is not thereby one a run can be carried out with**: the rule refuses neither an amount in which no round can be carried out nor one whose cost nobody would bear (for the latter, decision 6).

### 4. A file without the member; the version

- **The member may be absent from a valid file, and `schema_version` stays `1`** — the first of the two choices ADR-0018 decision 2 leaves to the record of a member ("A later record that defines a top-level member which may be absent and may be passed over does not raise it"), as ADR-0032 decision 4 chose for `round_budget`. A version 1 reader may pass over the member: no fixed rule makes anything a reader of today does depend on it, and a reader that needs the wall-clock budget of a run is one that knows the member. The inputs ask for it: the budget is optional at the start (UC-1 step 1, "(선택) budget"), FR-3 speaks of "복수 지정 시", and the instance of S1 step 2 is given "budget=20 라운드" and no amount of time.
- **A member that is present must be valid.** A file whose `wall_clock_budget_s` breaks decision 3 is **invalid** in the sense of ADR-0018 decision 2: a reader of this record reports it, uses no member of it — not its `hw_profile`, its `round_budget` or any other either — and repairs nothing. This follows ADR-0020 decision 3, ADR-0022 decision 5, ADR-0023 decision 4, ADR-0028 decision 4, ADR-0031 decision 5 and ADR-0032 decision 4.
- **A valid file without the member states no wall-clock budget.** A reader of this record that is asked for the wall-clock budget of such a run finds that none is stated. **"Not stated" is not "unlimited", not a default and not zero**: the reader **never substitutes a value** — not the 8 hours of S2, not a constant of the source the reader runs from, not a number derived from `round_budget` or from another member, not a difference of two `time` values of the log, not the time part of the `run_id`, and not a value from another run — and it does not conclude that the run may go on without end, nor that it may not begin.
- **No path yields a wall-clock budget the run did not state.** A reader of this record has the wall-clock budget of a run only when the file of that run is valid, is of version 1 and holds the member. A missing file, a file that cannot be read, an invalid file, a file of another version and a valid file without the member each leave it without one.
- **What this record does not say**: whether an instance may start with no budget axis at all, whether the start of an instance refuses to begin without one, and what ends a run whose file states none. That is sub-question ㉙ (ii), which this record leaves as it is. A valid file is "not thereby enough to start a run" (cited: ADR-0018 decision 2).
- **Why not a required member and version 2.** Against UC-1, which makes the budget optional, and S1 step 2, which starts an instance without an amount of time; and every file and every reader of today would be of another version before a first run exists, the record would have to say which layout version the new `schema_version` states (ADR-0024 decision 3), and reading another version is OD-11.
- **The cost**: validity does not show that a wall-clock budget is stated. A file without the member and a file whose member name is misspelt look alike to a version 1 reader — both state none (decision 6).

### 5. The member, `round_budget`, `STATE.json`, the spend view and the log; how it is read

- **This record adds no rule between the member and `round_budget`.** Each is valid by its own record; a file may state either, both or neither; no quotient or product of the two is a bound, and neither is derived from the other. That a run ends when any stated axis is used up is FR-3's ("any 소진 → 종료"); this record adds no rule of its own about a file that states both.
- **No rule between the member and `STATE.json`.** No file is invalid, and nothing is reported, because of the `round` a run is at. ADR-0012 defines no time member, and this record adds none.
- **No rule between the member and `budget_spent`.** `budget_spent.totals` "holds amounts accounted through the log only" (cited: ADR-0012 decision 4), and this record does not say that time is such an amount (decision 3). Nothing of ADR-0011 or ADR-0012 changes.
- **No rule between the member and the `time` of a line of `events.ndjson`, or the time part of a `run_id`.** No file is invalid, and nothing is reported, because the times of the lines of a run lie further apart than the stated amount. Those are readings of a clock at an append and at a build (cited: ADR-0006 decision 3; ADR-0027 decision 3); whether anything is counted from them is the clock of decision 2.
- **No rule that anything is stopped.** "The accounting stops nothing: reaching or passing a budget has no effect by this record (OD-19)" (cited: ADR-0011 decision 9), and neither has it by this one.
- **The wall-clock budget a run states is the one in this member of the file of that run**, `runs/<run_id>/instance.json` below the data root in use. A reader of this record reads the file as a whole, which must be valid (ADR-0018 decision 2), and **nothing is kept between calls** (cited: ADR-0010 decision 7; ADR-0018 decision 4): a later call reads the file again.
- **Today nothing reads or writes the member, nothing compares anything with a budget of a run, and nothing measures the time of a run**: no tool, registry, backend, hook or module does, and `hilclaw/instance.py` passes the member over. **Not said here**: which component reads it, at which moment, and what follows when no wall-clock budget is stated (Boundaries).

### 6. Limits

- **Whoever can write the file changes the wall-clock budget the run states.** No access control exists and the tree does not enforce the single writer (cited: ADR-0004 decision 10); a file changed after the start is read as it is at that read (cited: ADR-0018 decision 6).
- **The member stops nothing.** A run that goes on longer than the stated amount, by any clock, is not prevented, reported or made invalid by this record (decision 5).
- **No file of a run states when the instance started**, so nothing today could compare the member with a time counted from the start of the instance: the time part of a `run_id` is "no record of when the run started" (cited: ADR-0027 decision 3), the `time` of a line is the moment of an append, and no record defines a start time (sub-question ⑨; Boundaries).
- **A misspelt name.** A top-level member that is not spelt `wall_clock_budget_s` (`wall_clock_budget`, `wall_clock_s`, `wallclock_budget_s`, `time_budget`) is passed over (cited: ADR-0018 decision 2, the cost) and the file states no wall-clock budget — which is not "unlimited" (decision 4).
- **A unit read wrongly.** A writer that puts a number of hours or minutes into the member writes a valid file that states a far smaller budget; nothing in the file shows it beyond the `_s` of the name.
- **Two processes, two sources** (cited: ADR-0010 decision 7; ADR-0018 decision 6): a source older than the code of this record passes over the member and takes as valid a file whose `wall_clock_budget_s` a newer source refuses.
- **A large value is a cost this member does not cap**: a run that goes on costs coder calls under the one subscription of C-7 ② and hardware time (C-4). Nothing here limits what a run may state below 2^53 − 1.
- **A file written once cannot state a second budget** (decision 2). The name stands near `round_budget` and `budget_spent`; it is neither.

### Example

Neither is there because it is a default, and no reader supplies either for a file that lacks the member.**

### Walk-through

What a reader of this record finds when it is asked for the wall-clock budget of the run `r1`.

| `runs/r1/instance.json` | What the reader finds |
|---|---|
| Valid, version 1, with `"wall_clock_budget_s": 5400` | The wall-clock budget `r1` states: 5400 seconds. Asked again in a later call, it reads the file again |
| Valid, version 1, without the member | No wall-clock budget is stated for `r1`. No value is substituted, and the reader concludes neither that the run is unlimited nor that it may not begin. The other members of the run can still be had |
| `"wall_clock_budget_s": "5400"`, `"PT90M"`, `5400.0`, `5.4e3`, `1.5`, `-5400`, `0`, `null`, `true`, `[5400]` or `9007199254740992` | The file is invalid: no member of it is used, neither the wall-clock budget nor the `hw_profile` or any other |
| Valid, version 1, with `"wall_clock_budget": 5400` (or `"wall_clock_s": 5400`, `"time_budget": 5400`) | As the second row: the member of a nearby name is passed over, and no wall-clock budget is stated |
| Valid, version 1, with `"round_budget": 8` and `"wall_clock_budget_s": 5400` | The wall-clock budget `r1` states: 5400 seconds. The file states two axes; by this record nothing follows from the two numbers together, and neither bounds the other |
| `r1` states `"wall_clock_budget_s": 5400`, and by some clock more than 5400 seconds lie between two moments of the run (two `time` values of its log, for instance) | The wall-clock budget `r1` states: 5400 seconds. **By this record nothing follows**: no file is invalid, nothing is reported, and whether the budget is used up is not said (sub-question ㉚ (i)) |

## Alternatives considered

| Point | Alternative | Why not |
|---|---|---|
| 2 | The record states a clock (the time runs from the write of the file; waiting at a gate counts or does not) | No input carries one; it would decide part of OD-19 and bind what starts an instance and what pauses one, which no record has named (OD-23), and it would need a start time no file holds (sub-question ⑨). |
| 2 | No member until the clock is decided | The value the user gives at the start would be recorded nowhere, and the record of the clock would have nothing to count against; FR-3 and S2 state the axis without such a rule, as ADR-0032 found for rounds. |
| 2 | The member is a deadline: a moment in the notation of ADR-0006 | A moment fixes the start of the counting and that every stretch counts — the clock this record leaves open; FR-3 names an amount of time, and a time notation for this file is sub-question ⑨. |
| 3 | Hours, minutes, or a unit finer than the second | See decision 3. |
| 3 | A duration string; an object of a value and a unit; a number with a fraction | See decision 3. |
| 3 | An object `budget` with one member per axis | See decision 3: it moves `round_budget` or gives the budget two places. |
| 3 | `wall_clock_budget`, `wall_clock_budget_seconds`, `time_budget`, `duration_s`, `timeout_s`, `deadline`, `max_wall_clock_s`; the name of an axis of the spend view | See decision 3. |
| 3 | Validity carries a ceiling (the 8 hours of S2, a day) | An example of a scenario, not a rule; FR-3 has the value given by the user. |
| 3 | `0` is a value | It states no amount of time a run could use, and what it would mean hangs on the clock (decision 3). |
| 3 | A value for "unlimited" (`null`, `0`, a string) | A statement FR-3 does not have: an instance that gives no amount of time is the file without the member. |
| 4 | An absent member means "unlimited", or a default | Whether a run with no budget axis may run at all is not decided (decision 4); none of the documents read gives a default; a misspelt name would then read as an unlimited run. |
| 4 | Required, with `schema_version` 2; required without raising the version | See decision 4; the second is against ADR-0018 decision 2. |
| 4 | A present and invalid member leaves the file valid and counts as "not stated" | Two notions of validity for one file (ADR-0020 decision 3, Alternatives), and a damaged statement of a budget would pass unreported. |
| 5 | A rule between the two budget members (both required together; one derived from the other) | FR-3 has each axis given by the user ("복수 지정 시"), and UC-1 makes the budget optional; no input gives a rule that relates a number of rounds to an amount of wall-clock time (the "tens of seconds" of #5 B-4 is an expected hardware time per round on one host, and no rule). |
| 5 | A file is invalid, or a reader reports, when the `time` values of the log span more than the member | A rule across two files, a rule of counting (decision 2) and enforcement (OD-19); `time` "is used for neither the order, the identity nor an amount" (ADR-0011 decision 9). |

## Consequences

- **The code slice that can now be cut** (within the size cap, code mode): in `hilclaw/instance.py`, the validity of the member by decision 3 and a reader of the wall-clock budget of a run beside `round_budget_of`, with tests in `tests/test_instance.py`. The name and the return form of that reader and how "not stated" is told from a value are the code task's. **Binding the reader to a clock, to `STATE.json`, to the log, to a tool or to anything that ends a run is not part of that slice**, and neither is measuring the time of a run or writing the file. `hilclaw/instance_file.py` takes the validity of a content from `hilclaw.instance.parse`, so it refuses a content with an invalid member once the slice lands, without a change of its own.
- **Sentences of the code that then change**: in the docstring of `hilclaw/instance.py`, the list of the records in its first line and first paragraphs, the sentences that count the records ("the eight records", "the eight"), the order of the checks, and the descriptions of `Instance.others` in `parse` and of the records in `validate`; the sentence that the module makes `round_budget` "no amount of tokens, of time or of hardware quota" stays true and stands beside a member that is an amount of time, and the clause that follows it, "it names no other budget axis", changes. No case of `tests/test_instance.py` holds a top-level `wall_clock_budget_s` today, so none asserts a content valid that this record makes invalid; the assertion on `Instance._fields` and every case that builds an `Instance` positionally change only if the slice adds a field to that tuple.
- **Not edited and now less exact** (follow-ups for the integrator): ADR-0032 Context ("wall-clock time, for which no record fixes a unit or a clock" — the unit is fixed, the clock is not), decision 3 ("wall-clock time has no fixed unit") and Boundaries ("wall-clock time, its unit and its clock (a later record of OD-8 …)"), and its sub-question ㉙ (iii) as quoted there; the Boundaries of ADR-0012 ("Budgets: axes, units, who measures, enforcement"), ADR-0018 ("budget axes, units and caps"), ADR-0023, ADR-0028 and ADR-0031, which list "every budget member" among the members of later records; the lists of what makes `instance.json` invalid in ADR-0018 decisions 2 and 4 and in ADR-0019 decision 3, which a `wall_clock_budget_s` that breaks this record joins; ADR-0025 decision 2, where the members a valid content may lack now have one more. ADR-0011 and ADR-0027 stay exact. No sentence of UsageCases became false: the glossary and UC-1 step 1 could name the member.
- **A-13 reading**: document mode; no code, dependency, settings file or schema file changes. The record adds one member that may be absent to a file whose frame says how later records add members (ADR-0018 decision 2), along the D6 route as ADR-0020, ADR-0022, ADR-0023, ADR-0028, ADR-0031 and ADR-0032 did; by that frame's own rule the version stays `1`. **The set of valid version 1 files becomes narrower without a new version**: a file that holds a `wall_clock_budget_s` breaking this record was valid before and is invalid now — the case ADR-0018 decision 6 named; no such file exists in a data plane, since nothing starts an instance yet. No member, value list or validity rule of the members that exist, of the key records or of `STATE.json`, `spec.json`, `artifacts.json` or `events.ndjson` changes.

## Boundaries (not decided here)

- **The clock and the counting** (OD-19, OD-17, OD-18, OD-23): from when the time runs, what counts, against which clock, compared by what and when; what ends a run and what keeps the best; a pause at a rate limit and a resume. **Any time member of any file**: a start time of the instance, a time of an end, of a round or of a gate (OD-8 sub-question ⑨; the members of `STATE.json`). No proposal of OD-2, OD-17 or OD-19 is adopted or rejected.
- **Every other budget axis, and any rule that encloses them**: tokens and who counts them (#5 A-8 — owner; NFR-5); HW quota as an axis (OD-2); the target metric (#5 A-4 — owner; OD-1). No member is named for any of them. `round_budget` and sub-questions ㉙ (i) and (ii) stay as ADR-0032 left them.
- **Owner-only (DRIVER §9)**: gates on a budget and anything about gates (#5 A-5, OD-3); the token budget and the coder model (#5 A-8); the objective (#5 A-4). Notifications at the end of a run (FR-16, OD-27).
- **A new budget for a continuation or a branch** (OD-8 sub-question ①; S3 step 3; FR-6).
- **Every other member of `instance.json`** (PLAN P1-8), none of which is named here.
- **The writer and the start of an instance**: what writes `instance.json`, in which unit the user gives the amount and what converts it, what offers the user the choice, and whether the start refuses to begin without a budget (OD-8 sub-questions ⑩, ⑰, ㉕, ㉙ (ii) and ㉚ below; OD-23; UC-1).
- **Any tool's contract** (OD-18): no tool, moment of a call, request or result member or tool-failure kind is given here, and nothing HQ-0005 asks.
- **Any member of `STATE.json`**, any event kind, any result file; reading or migrating a file of another version (OD-11).
- **Sub-question this record raises** (registered under OD-8): ㉚ Two parts. (i) The clock of the wall-clock budget a run states: from which moment the time runs; whether the time counts in which the instance waits at a gate, in which no process of it runs between two turns, in which it is paused, and between the death of a process and the resume; how the time of a run that is continued or branched from is counted; against which clock the time is read, and what holds when that clock is set or the run moves to another machine; and what compares the budget with what, at which moment (with OD-19, OD-17, OD-18, OD-23, ① and ⑨). (ii) In which unit and notation the user gives the amount, what converts it to whole seconds, and what is done with an amount that is no whole number of seconds (with ⑰, ㉙ (ii), OD-23).
- Any change to a member that exists (`schema_version`, `hw_profile`, `tolerance`, `source_commit`, `n_max`, `candidates_per_round`, `op_signature`, `round_budget`), to `STATE.json`, to the spec schema, to another data-plane file; any change to ADR-0001 to ADR-0032, to `hilclaw/`, to tests, to CI, to `pyproject.toml`, to any settings file, or to the `HIL-Claw-data` repository; a JSON Schema file; any new external dependency.
