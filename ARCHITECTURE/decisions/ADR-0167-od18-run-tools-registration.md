## Decision

A sentence is **cited** when a record and its decision, or a requirement, is named with it; it then says what that source says and adds nothing. Every other sentence is **this record's own** - among them the choice to register now, the one default table, the readings of ADR-0142 and ADR-0147 in decision 5, and every weighing.

### 1. Scope and terms

- This record is about **the registry that `default_registry` builds** - the registry both fronts serve - and fixes four points for `sim.run` and `board.run` in it: whether they are registered now (decision 2); the backend table their tool functions are bound to (decision 3); their source of seeds and predicate "covered" (decision 4); their tool definitions and what follows (decision 5).
- The terms of ADR-0015, ADR-0016 (backend, operation, backend table, mock backend, script; the moments ① to ⑦) and ADR-0066 (default script) are used unchanged. **The default table**: the backend table bound to the tool functions of the HW tools in a registry that `default_registry` builds; ADR-0070 used the term for the table of `correctness.check`, and decision 3 makes the two one.
- **It says nothing of `profiler.collect`** (no contract; [ADR-0130](ADR-0130-od18-cpu-standin-profiler-collect.md) for `cpu_standin`), and the other tools of the registry are unchanged.

### 2. Both tools are registered now, before their `cpu_standin` operation exists

- **`sim.run` and `board.run` are registered in the registry that `default_registry` builds now, with the default table of decision 3.** They do not wait for the operation of `cpu_standin` for either tool.
- **The run tools' contract is complete enough for a registered tool; each item has a record** (all cited): the split, the point and the inputs (ADR-0061 decisions 2 to 6); the identity - journaled, `step` values, `execution` - and the empty `spend` (ADR-0062 decisions 2, 3 and 5); the result members (ADR-0063); the timing seed (ADR-0064); the form of an answer and the answer of neither form (ADR-0065); the mock's operation and default script (ADR-0066, with ADR-0108 decision 8); the answers of ④ and their order (ADR-0067); the backend kinds and a tool failure an operation raises (ADR-0068, ⑲ (나) but for the three pieces of its decision 8); the request, the schema and the descriptions (ADR-0106); the compiler's log (ADR-0108). The tool function that joins them exists (observation: `hilclaw/run_tool.py`). What is missing is an operation of one backend, not a part of the contract.
- **Three answers were weighed**, those of ADR-0070 decision 2.
  - **(a) Register now, with a default table whose one entry offering the tools is the mock** (decision 3). Layer 1 and the contract tests of P1-1 can call both tools through both fronts, which is why the mock exists: "layer 1 could never be run against it" was the reason against a mock only in tests (cited: ADR-0016 Alternatives), and the default script was chosen "so that the contract tests of P1-1 run the whole judging over the mock" (**owner**, HQ-0005 point 4, as ADR-0066 Status and decision 3 (a) quote it; a reason only). A call about a `cpu_standin` run is answered `no_backend` until the entry exists (decision 3).
  - **(b) Wait until the operation of `cpu_standin` for these tools exists.** It waits on the container's situations, the row of an error of two rows and the rest of ⑲ (라) (cited: ADR-0068 decision 8 and Consequences; ADR-0108 Consequences). Both tools would stay unreachable through either front for all of that time, for runs at the mock too, where none of it is needed.
  - **(c) Register now with a `cpu_standin` entry whose operation of these tools raises a tool failure** until the real one exists. No record names a kind for "not written yet"; a kind outside the eight backend kinds ends the call with `operation_failure_invalid` (cited: ADR-0068 decision 4), so the call would start a step and end the identity with a `failure` for a fault of registration - what ADR-0016 decision 2 placed before the start line to avoid (cited).
- **The choice is (a)**, for the reasons ADR-0070 decision 2 chose it for the check.
- **What need not be answered first** (each this record's own judgement, with the precedent where one applies).
  - **⑤, second half, and ①**: what Claude Code does with `inputSchema`, and whether the MCP server works in a live session, are runtime acceptance matters (cited: ADR-0077 decision 6); the other registered tools are served while they are open (observation), as ADR-0070 decision 2 found for the check.
  - **⑲, its open parts** (the isolated environment and its situations, the row of an error of two rows, the sorting of kinds for a comparison, the size bound of the log, the rest of (라); cited: OpenDecisionProposals OD-18 ⑲): each is a matter of a real operation or of its log; the mock builds and runs nothing and hands no log (cited: ADR-0066 decision 3; ADR-0108 decision 8). A later answer that reaches the request extends the list and the schemas, "and that is a change of this contract" (cited: ADR-0106 decision 2), of a registered tool from then on.
  - **⑳** (which execution counts, and what stops a further `execution`): it concerns what a caller does with end lines and is answered in part by a reader of them (cited: ADR-0140 for the first case); whether a registry holds the tools is not part of it, as ADR-0070 decision 2 found for ⑭.
  - **⑧** (fault injection in a live session): the default script injects none (cited: ADR-0066 decision 3); a test reaches the other outcomes with its own script (cited: ADR-0066 decision 5).
  - **The spend beyond the empty object** (OD-2, OD-19): a later record that names an axis changes the end line of a registered tool from then on, as ADR-0070 decision 2 said for the check.

### 3. One default table, whose mock offers the three HW tools

- **The default table holds exactly one entry, the mock backend under its reserved name, and that entry offers `correctness.check`, `sim.run` and `board.run`**: the first with the mock's operation bound to the default script of ADR-0044 (cited: ADR-0070 decision 3), the two others each with the mock's operation of that tool bound to the default script of ADR-0066 (decisions 3 and 6), which hands over no log (cited: ADR-0108 decision 8). "The mock of the default registry offers every HW tool of that registry" (cited: ADR-0016 decision 5 (d)); in this registry those are the three.
- **The check's table and the run tools' are one table.** "A name has one backend" (cited: ADR-0016 decision 2), and one registry has one mock: a caller that reaches the mock through one HW tool reaches the same backend through another. **Weighed against a table per tool** (the check's mock offering the check alone, the run tools' mock the two): each tool function would answer alike today, but the registry would hold two backends under one reserved name that offer different tools, against "a name has one backend", and the next HW tool would have to choose which table to join. **The choice is one table.** Whether the tool functions hold one table object or equal ones is the code task's.
- **It holds no `cpu_standin` entry**, since no operation of `cpu_standin` exists in the source for any of the three tools (cited for the check: ADR-0070 decision 3); when the entry is added is left to the record or task that adds such an operation (Boundaries). If it is added for another tool first, a call of a run tool about a `cpu_standin` run is `not_offered` by ADR-0016 decision 3 (cited), as ADR-0070 decision 3 says for the check. Today a call of either run tool about a run whose hw_profile names `cpu_standin` is answered in ④ with the reserved kind `no_backend` (cited: ADR-0016 decision 3), before any `op_signature_*`, `objective_*` or `n_max_not_stated` answer (cited for the order: ADR-0067 decision 5); no seed is drawn and no line is written, and "the same request can be repeated once the table has the entry" (cited: ADR-0016 Walk-through). **Weighed against a `cpu_standin` entry that offers nothing** (`not_offered`): rejected for the reasons of ADR-0070 decision 3 (cited), which hold for these tools as for the check.
- **A run whose hw_profile names another accelerator**, neither `cpu_standin` nor the mock, is answered `no_backend` in the same way. This follows from the frame and the table and answers nothing of #5 B-2, B-3 or B-7.
- **The table is built in the source**, with no option, environment variable or plugin that adds to it, and nobody names a backend (cited: ADR-0016 decisions 2 and 4).

### 4. The source of seeds and the predicate "covered"

- **The source of seeds of both run tools in the default registry is the random generator of the operating system**, the source ADR-0070 decision 4 chose for the check (cited), with the property of ADR-0021 decision 3 that ADR-0064 decision 2 takes for the timing seed (cited) and over the whole range of seeds the harness accepts for a timing run, 0 to 2^64 - 1 (cited: ADR-0064 decision 2). It is fixed in the source; no request, option or variable of the front process sets it. **Weighed against** a source of its own for the timing seed: no record asks for one, and the weighing of ADR-0070 decision 4 against a variable or a seeded generator applies unchanged (cited). **The choice is the same source.**
- **The predicate "covered" is the one of ADR-0041 decision 5**, as ADR-0067 decision 3 takes it for these tools (cited), fixed in the source.
- **A test binds its own** source of seeds, predicate, table or script by building a registry of its own from the same parts (cited for the manner: ADR-0070 decision 4).

### 5. The two definitions, and what follows

- **The definition of `sim.run` is**: the name `sim.run`; the tool function of decisions 3 and 4 for that tool, bound to the data-root source `default_registry` is given; the input schema of ADR-0106 decision 4; and a description that tells at least what ADR-0106 decision 5 requires for the sim point. **That of `board.run`** is the same for `board.run` and the board point. The texts and the module are the code task's (cited: ADR-0106 decision 5).
- **`default_registry` keeps its one parameter**, as ADR-0070 decision 5 chose (cited).
- **Both fronts then list `sim.run` and `board.run`** beside the tools they list today, as `mcp__hilclaw__sim_run` and `mcp__hilclaw__board_run` through the MCP front (cited for the names: ADR-0010 decision 4). **The check of ADR-0077 then covers both**, and this change brings one accepted request of each as data (cited: ADR-0077 decision 3; ADR-0106 decision 4).
- **The spend check of a first-case turn session lists both tools** (cited: ADR-0147 decision 2, "the slice that registers `board.run` or `sim.run` for these sessions also adds it to this check's list"). The reading that this registration is one "for these sessions" is this record's own: those sessions are given the package's MCP front (cited: [ADR-0118](ADR-0118-od18-round-process-boundary.md) decision 6), which serves the registry `default_registry` builds (observation: `hilclaw/mcp_front.py`).
- **How this reads ADR-0142 decision 7**: "Step 5 and the experiment-runner's definition land only together with the registration", "so no agent file names a tool the server lacks" (cited). The registration landing first leaves no agent naming a missing tool, so its reason holds; the stop after step 4 stays until step 5 and the experiment-runner land (PLAN P2 work), and the sentence "While `board.run` is not in `default_registry`" becomes less exact (Consequences). No tool of a first-case turn session is given to an agent by this record (cited for the list: [ADR-0139](ADR-0139-od18-first-case-turn-session-permissions.md)).

### 6. Limits

- **No timing run of a `cpu_standin` run through the default registry** until its operation exists; the round loop of FR-1 cannot be carried out at `cpu_standin` through these tools until then.
- **A timing run at the default mock is always completed and converged, with no figure** (cited: ADR-0066 decision 3); it times nothing. A test reaches the other outcomes with its own script.
- **Two processes, two tables**: an MCP server runs the table of the source it loaded at its start (cited: ADR-0016 Limits, as ADR-0070 decision 6 applies it).
- **What a live Claude Code session does with the tools** is not verified (① and ⑤).
