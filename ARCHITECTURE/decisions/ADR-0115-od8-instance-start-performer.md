## Decision

### 1. Scope, and how the answer holds while the rest stays open

- **The start of an instance of ADR-0076 decision 1**: the start that writes the `instance.json` of a new run. This is the scope of ADR-0111 decision 1.
- **Outside**: instances outside ADR-0076 decision 1 (another accelerator, a stated op_signature that ADR-0041 decision 5 does not cover, every case other than the first); a branch, a continuation or a resume (①); every other file of the run. Nothing here is required or allowed of them.
- **The question answered**: which layer, and which kind of component, performs that start. The answer holds while each of the following stays open, for the reason given with it:
  - **Who calls the start, and how the user's inputs reach it** (UC-1, OD-23). The caller may be a command-line front, a UI, the Round-Manager of PLAN P2-1, a CI, or a CI through a `claude -p` session as S2 step 1 has it. The function of decision 2 is the same for each. This record says what every caller goes through, not which caller there is.
  - **The form, the moment and the channel of the start's reports** (ADR-0076 decision 3, ADR-0109 decision 3, ADR-0111 decision 3). The function reports to its caller. How that report reaches whoever gave the values stays "the code task's and the UI's".
  - **⑩**: the order of the first files, and whether the start writes the first `STATE.json`. Decision 2 says only that the function performs the rules of the four records, and those records fix no order against `STATE.json`. If a later record lets the start write `STATE.json`, that record says whether the function does so.
  - **Where the start takes each value from** (ADR-0076 decision 2; ⑱, ⑳, ㉛; OD-9). Gathering the values is the caller's side (decision 2). If a later record gives the start another rule, that record says whether the function applies it or the caller supplies a value.
  - **The roster of agents and their allowlists** (rest of OD-23). The function is no agent and has no allowlist. Whether an agent calls it, and with which tools, is the roster's matter.
  - **⑰'s last part**: what a run directory with other files and no `instance.json` means. The function writes by ADR-0025 and leaves what ADR-0076 decision 3 and ADR-0109 decision 3 leave. It adds no file, so nothing here creates such a directory or gives it a meaning.

### 2. One deterministic function of the layer-2 package performs the start

**For the scope of decision 1, the start of an instance is one function of the layer-2 package `hilclaw/`.** The function:

- takes the values of the instance;
- applies ADR-0076 decisions 2 and 3, and ADR-0111 decision 2;
- builds the `run_id` by ADR-0027;
- writes `runs/<run_id>/instance.json` by the steps of ADR-0025;
- answers a taken name by ADR-0109 decisions 2 and 3;
- returns the id it built (ADR-0111 decision 3).

**Every way of starting such an instance calls that function. Nothing else writes the `instance.json` of such a start.** In particular, no agent composes and writes that file with its own file tools.

- **Deterministic** here means that the function makes no judgement and calls no model. Its outcome follows from its inputs together with three things that need not be inputs: the clock and the random source, which ADR-0027 decision 6 gives the id, and the state of the file system it writes into. Whether the function takes the time and the bits as arguments is the code task's (cited: ADR-0027 decision 6).
- **The order of its rules** is that of the records it applies. ADR-0076 decision 3 orders validity, then scope, then the filling-in of `n_max`, then the required set. ADR-0111 decision 2 inserts its look for a given id between the scope and `n_max`. The write comes only after all of these have passed, and the stop of ADR-0109 comes at its last step. When the id is built within the start is not fixed by those records and is not fixed here. Building an id creates nothing (cited: ADR-0027 decision 5), so the moment changes nothing on disk.
- **What the function takes, and what stays on the caller's side.** The function takes the values that the start writes. It may take them as a document, or in another form that the code task chooses. Gathering those values from whoever gives them is not in the function: asking a person, reading a command line, receiving them from an agent. Any judgement that gathering needs (for example reaching an op_signature from a model, OD-9) stays in layer 1 or with a person, and this record neither gives it to an agent nor takes it away. Where the start takes each value from stays open (decision 1). That includes whether the start takes the hw_profile record from a stored record (⑱), checks the source commit (⑳) or fills in owner and project (㉛). A later record that gives the start such a rule says whether the function applies it or its caller supplies the value.
- **Why one function** (Alternatives):
  - The rules of the four records are fixed rules without judgement. #4 condition 4 keeps such steps out of subagents, and #5 A-12 puts schema validation in layer 2.
  - In one function, those rules are code that tests check (CLAUDE.md D12), not text that a model follows.
  - The rules hold for every caller alike. A CI without an agent session can reach the function, and so can an agent.
  - ADR-0025's steps need operations that the package already has in code: a flush to stable storage, and a last step that cannot replace. No record says that an agent's file-writing tool gives those steps.
- **Where it belongs** is left to the code task: the module, the name, the signature, the binding of `accelerators` and `covers`, the way it is given its data root, and the form of its reports. **Its caller is not decided** (decision 1).

### 3. The function is no FR-10 tool

**This record does not make the start a tool.** The function is not entered in the registry of ADR-0010, has no MCP name and no tool name of the command-line front `python -m hilclaw <tool name>`, and its refusals and its stop are no tool-failure kinds. This record adds no event kind and no line of `events.ndjson`. Whether a start of an instance is logged as an event is sub-question ⑧ of OD-8 and stays open.

- **Why**:
  - The tools named so far are the HW experiment tools of FR-10 and the blob tools of C-3. The start is neither.
  - Making it a tool would add a tool and its failure kinds. It would also choose an agent as one of its callers, a choice that decision 1 leaves open.
- **What this leaves open**: a later record may decide that an agent calls the start and can reach the package only through the MCP front. That record then says how the agent reaches the function. If it makes the start a tool, it adds that tool under the records of OD-18. This record neither requires nor excludes that.
