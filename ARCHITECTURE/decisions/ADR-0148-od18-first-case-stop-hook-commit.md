# ADR-0148: The end commit of a first-case turn session, held by a `Stop` command hook — when the main session finishes its reply while `run.commit` would still commit something, the hook refuses that one stop with a fixed line that asks the Round-Manager to make the call "The end of a session" asks for, or to end at once where that call is not made; it never commits, refuses no stop that already continues a refused one, and lets the stop through whenever it cannot tell (part of OD-18, for the runs of ADR-0120 decision 1)

## Decision

A sentence is **cited** when a source is named with it. Every other sentence is **this record's own**. Below, **the definition's stop** is the step "The stop" of `orchestration/round-manager.md`, and **`Stop`** is the hook event.

### 1. Scope and terms

- **The sessions**: every `claude -p` turn session the turn loop starts for a run of ADR-0120 decision 1 (ADR-0146 decision 1), the main session only; nothing outside them.
- **The end commit**: the call of `run.commit` that ADR-0143 decision 2 has the Round-Manager make as its last act before every end of its session that follows a successful entry step 0.
- **A commit is owed**: `hilclaw.run_commit.commit_owed` answers true for the session's run (ADR-0143 decision 3).
- **The stop check**: the hook of decisions 3 to 5.

### 2. (a) Which ends a hook can hold, and which it must leave alone

| How the session ends | `Stop` fires (H13, H19, H20) | The end commit (ADR-0143 decision 2) | What the stop check does |
|---|---|---|---|
| The model finishes its reply at an end of entry steps 2 to 7, at the definition's stop, after a failed `round.end`, or after closing step 3 | Yes, read; item (lxiii) | Made before the end | Nothing, when the call was made and nothing was written after it (nothing owed); otherwise refuses this one stop |
| The model finishes its reply anywhere else (an end the definition does not name) | Yes, read | Owed by O1 ("such a turn's end"), not named by the prompt | The same |
| The model ends after a prompt with no valid run id | Yes, read | **Not made** (ADR-0123 decision 4) | May refuse once when a commit is owed (left by an earlier turn); its line then tells the model to end at once (decision 5) |
| The model ends after a failed `run.commit`, at entry step 0 or at an end | Yes, read | **Not made again** (ADR-0127 decision 5) | Lets the stop through when `commit_owed` cannot tell (decision 5); otherwise refuses once, and its line tells the model to end at once |
| An API error ends the turn: a rate limit, an authentication or billing error, and, by this record's reading, a usage limit that reaches the session as one of these | No: `StopFailure`, which cannot block (H19) | None: a dead turn (ADR-0143 decision 2) | Nothing. The next entry commits (O1) |
| SIGTERM, a crash, a kill the process cannot handle | No (H20; a crash and a kill: not stated, read) | None: a dead turn | Nothing. The next entry commits (O1) |
| A user interrupt, or SIGINT (for one, a Ctrl-C at the terminal of the entry, which reaches the session in the same process group) | No (H13: "Does not run if the stoppage occurred due to a user interrupt"; that SIGINT is such an interrupt is read, H20) | None: a dead turn | Nothing. The next entry commits (O1) |

- **What the hook adds**: a hold on every live end of the main session, in the one case the prompt alone holds today — a Round-Manager that ends with a commit owed, whether it skipped the call, wrote after it, or ended at a point the definition does not name. **What it does not add**: anything for a dead turn, which stays the next entry's (ADR-0143 decision 2), and anything for a sub-agent, which makes no commit (C2 of ADR-0127, W1).
- **The two ends without a call stay without one.** The stop check cannot see either: the `Stop` input carries neither the prompt nor the tool results (H14), and the transcript may lag (H14). So it does not try to tell them apart. It refuses at most once per end (decision 5), and its line repeats ADR-0143 decision 2's two exceptions, so that a Round-Manager at such an end ends at once without calling `run.commit`. **This is not a second rule**: the rule of which ends call and which do not stays ADR-0143 decision 2's, and the line only repeats it.

### 3. (b) Whether a hook, and in which form: a `Stop` command hook that refuses one stop while a commit is owed

- **Adopted: alternative (i) of the task** — a `Stop` command hook of the session's project settings. When the main session finishes its reply, a commit is owed and the stop does not already continue a refused one, it refuses the stop: exit 2 with one fixed line on standard error (H15). Otherwise it exits 0 and prints nothing, which lets the stop through.
- **Exit 2, not `decision: "block"` on standard output**: H15 gives both the same route. Exit 2 with a line on standard error and nothing on standard output is the form of the two existing hooks (ADR-0146 decision 5, ADR-0147 decision 3). Not `additionalContext`: it also continues the conversation (H15), so it gains nothing here.
- **It never commits.** The Round-Manager makes every commit, through `run.commit` only (C2 of ADR-0127, W1, both readings; ADR-0143 decision 2). The hook reads and refuses; the commit that follows a refusal is the Round-Manager's call, at the end where ADR-0143 decision 2 already puts it.
- **Why a hold below the prompt at all.** The end commit is the one call of a turn whose omission costs a record of the run's work when an unattended run is not started again (Context). The hold costs one process start per end of a session and, only where a commit is owed, one more reply of the model. Doing nothing leaves the call on the prompt alone, which the Context weighs as ADR-0146 did.
- **No `SubagentStop` entry.** No sub-agent commits (W1), so no sub-agent's end owes a call (H21).

### 4. (c) How the hook learns the run and the data root, what it reads, and how it is delivered

- **The run**: an argument of the hook entry. The command-line entry `hilclaw.turn_start` already holds the checked run id from which it builds the prompt (ADR-0123 decision 3). **`hilclaw.turn_loop.run` gains a required keyword-only parameter, the run id**, which it checks as `hilclaw.layout.check_run_id` does and writes as one more element of the `Stop` hook's exec-form `args`. The loop reads nothing by it and compares it with nothing; the prompt stays its caller's (ADR-0123 decision 3), and the entry passes the same value to both. **This revises ADR-0123 decision 3's "knows no run"** (Status). Not from the prompt: the loop does not parse its caller's prompt, whose wording is the entry's (ADR-0123 decision 3), and the hook does not see the prompt (H14). Not from the environment: the reasons ADR-0147 gives for its data root apply (it would change the session's environment of ADR-0141 decision 4, and every process of the session would carry it). Not by a listing of `runs/` (#4 §1).
- **The data root**: an argument of the hook entry, the same real absolute path the loop puts into the server entry's `env` and into the budget check's last argument (ADR-0147 decision 4, for the same reasons). A missing argument, or one that names no directory, is a root the hook cannot tell (decision 5).
- **What it reads**: `hilclaw.run_commit.commit_owed(data_root, run_id)`, once. **Unlike the two existing hooks, it starts processes**: `commit_owed` runs the machine's `git`, read-only, with a temporary index outside the repository (Context). It writes nothing into the data checkout, makes no commit, takes no lock of `git`, calls no model and contacts no server. It reads no field of the input besides `hook_event_name` and `stop_hook_active`, and never `transcript_path` or `last_assistant_message`.
- **The loop guard**: it refuses only when `stop_hook_active` is exactly `false`. A stop that comes while Claude Code "is already continuing as a result of a stop hook" (H14) is let through, whatever is owed. Read with H14, the hook refuses **at most once per end** that is not itself a continuation. If `stop_hook_active` turns `false` again after a tool call within the continuation (not stated, H14; item (lxiv)), a second refusal can follow only when a commit is still owed after that call; the line then tells the model to end at once (decision 5). The cap of H16 is a further bound only where no tool is called between refusals, and a runtime user can lift it (H16), so this record does not rely on it.
- **Delivery**: the turn loop writes one more member into the `hooks` member of the session's `.claude/settings.json`: `Stop`, an array of one entry with no `matcher` (H17), whose one hook is a `command` hook in the exec form of ADR-0146 decision 4 — `command` the absolute path of `sys.executable`, `args` the interpreter options, the start text of the program, the directory holding this package, the run id and the data root — with a `timeout` well below the 600-second default (H18). **It sets no `onFailure`**, which has no effect on `Stop` (H18). **This revises ADR-0146 decision 4 as revised by ADR-0147 decision 4** to: the two `PreToolUse` entries and this one `Stop` entry, and nothing else. The two `PreToolUse` entries, their programs, their tables, the rest of ADR-0146 decision 4 (no `permissions`, no `env`, a definition's own `settings.json` refused) and ADR-0147 decision 4 are unchanged.
- **The program** is a new module of the package (layer 2), in Python, so that it uses `commit_owed` and `check_run_id` themselves. Its whole body is guarded (decision 5). Its name, its start text and its line are the code slice's; so is the timeout, which bounds the reads of `git` on the runtime machine's data checkout (item (lxv)).

### 5. (d) What it does when it cannot tell, and what the model is told

| The hook finds | It does |
|---|---|
| Input that is not one UTF-8 JSON object; `hook_event_name` not `Stop` | Lets the stop through |
| `stop_hook_active` not exactly `false` (`true`, missing, or another type) | Lets the stop through (decision 4) |
| Arguments other than exactly a run id and a data root; a run id that `check_run_id` refuses; a data root that names no directory | Lets the stop through |
| `commit_owed` raises anything (`git` not run, no repository, a `commit_refused` state, a comparison that `git` fails) | Lets the stop through |
| `commit_owed` answers false | Lets the stop through |
| `commit_owed` answers true and `stop_hook_active` is `false` | **Refuses the stop**: exit 2, one fixed line on standard error |
| An error of its own (the guard: exit 0, nothing printed); a failure to start; a timeout | Lets the stop through (H18: a non-blocking error, and `onFailure` has no effect on `Stop`) |

- **Let through what it cannot tell — for this hook alone.** ADR-0146 decision 5 and ADR-0147 decision 5 refuse on fault; this hook does not, for three reasons of its own. (1) It could not be made to refuse on every fault: a hook that cannot start or times out lets the stop through whatever this record says (H18). (2) A refusal makes the model reply again and spends plan usage; where `commit_owed` cannot tell, `run.commit` would fail the same way (its kinds `no_repository`, `commit_refused`, `commit_not_made` come from the same checks — ADR-0127 decision 4, ADR-0143 decision 3), so the reply would gain nothing. (3) What a stop let through leaves uncommitted is held as a dead turn's is: by the next entry (O1). **The default-FAIL contract of OD-18 in general stays open.**
- **The cost of letting through** (stated plainly): a fault of the program, its interpreter, its arguments or `git` in the hook process leaves the end commit on the prompt alone, as before this record.
- **The model is told one fixed line**: that the stop was held because a commit of its run is owed; that it calls `mcp__hilclaw__run_commit` once, as "The end of a session" says, and then ends; and that if its prompt held no valid run id, or a call of `mcp__hilclaw__run_commit` has failed in this turn, it ends at once without calling it. The line shows no path, member or value. **The wording is the code slice's**, which keeps it from reading as a missing-file message (H18).
- **A refusal is not a failure of the turn and is not journaled**: nothing is written, the session goes on with the line, and the definition is unchanged; the call that follows passes the caller check (`run_commit` is the Round-Manager's, ADR-0146 decision 3) and is no spending call (ADR-0147 decision 2).

| Entry step 0 fails with `commit_not_made` (a stale `git` lock) | `commit_owed` true (it takes no lock): refused once; the line tells the model a failed call means end at once; it ends; through | Decisions 2, 5; ADR-0143 decision 2 |
| Entry step 0 fails with `commit_refused` (a tracked file missing) | `commit_owed` raises: through, no refusal | Decision 5 |
| The prompt holds no valid run id (a misread; the entry always builds a valid one) and an earlier turn died with work uncommitted | Refused once; the line tells the model to end at once; through | Decisions 2, 5 |
| A turn over a run that is over: entry step 4 calls `run_commit` and ends | Nothing owed: through | ADR-0143 decision 2 |
| A round ends: `round.end`, then `run_commit` (committed) | Nothing owed (that commit took the run directory and the round's case file; key record files alone owe nothing): through | ADR-0143 decision 3; ADR-0127 decision 4 |
| A round-3 turn's model writes `STATE.json` after the end call, against the prompt | Owed: refused once; the second call commits it | Decisions 3, 4; ADR-0143 decision 3 ("repeats without effect") |
| A turn after ADR-0121's own `"over"` write ends without the call; refused once, the model calls `run_commit` (committed) and ends | Step 1 then finds P2 with nothing owed: "run over", and no further turn for owed P2 is started (ADR-0143 decision 6), since nothing is left owed | Decisions 3, 4; ADR-0143 decision 6 |
| The turn ends on a rate limit | `StopFailure`, no `Stop`: no hold; the next entry commits | Decision 2; H19 |
| The hook's `git` hangs past the timeout | Cancelled: through | Decision 5; H18 |
| A sub-agent finishes its reply | No `SubagentStop` entry: nothing | Decision 3 |

## Alternatives considered

| Alternative | What it gives | Outcome |
|---|---|---|
| **(i)** A `Stop` command hook that refuses one stop while `commit_owed` is true, run id and data root as arguments, loop guard on `stop_hook_active`, let through what it cannot tell | A hold below the prompt on every live end; the Round-Manager stays the one committer; one process per end, one more reply only where a commit is owed | **Chosen** |
| **(ii)** A hook that makes the commit itself (on `Stop`, or as below) | Commits even when the model will not; but a second committer: against W1 (C2 of ADR-0127) under reading (i), "the manager is the one committer of every commit of a run", and the alternative ADR-0143 rejected as (c), "A second committer under reading (i)"; it would also put a write of the data repository into a hook process whose failure or timeout Claude Code ignores on `Stop` (H18) | Rejected |
| **(iii)** A `SessionEnd` hook | Fires also on SIGTERM (H20); but it has "no decision control" and "can't block", so it can only commit itself — alternative (ii) — within a budget of 1.5 seconds by default | Rejected |
| (iii) A `StopFailure` hook | Fires on API errors (H19); but its output and exit code are ignored, so again only (ii) | Rejected |
| (iii) A `SubagentStop` hook | Sub-agents make no commit (W1) | Not taken |
| **(iv)** Nothing beyond the prompt, the next entry and step 1 | No cost; the end commit rests on the prompt (item (xlvii)) and a skipped call waits for a next start that may not come | Rejected (decision 3) |
| (i) refusing on fault, as ADR-0146 and ADR-0147 decision 5 do | Not achievable for a hook that cannot start or times out (H18); a refusal where `commit_owed` cannot tell asks for a call that fails the same way, at the price of a reply | Not taken (decision 5) |
| (i) refusing every stop while owed, with no loop guard, relying on the cap of H16 | Up to eight replies per end, the count reset by each tool call, and the cap can be lifted (H16) | Rejected (decision 4) |
| (i) telling the two ends without a call apart by reading `transcript_path` | The transcript may lag the conversation (H14); a parse of a format the page does not fix | Not taken |
| (i) with `decision: "block"` on standard output, or `additionalContext` | The same route (H15); a different form from the two existing hooks | Not taken |
| The run id parsed from the prompt by the loop, or taken from the session's environment | Couples the loop to the entry's wording (ADR-0123 decision 3), or changes ADR-0141 decision 4's environment | Not taken (decision 4) |
| A `prompt` or `agent` `Stop` hook (the `/goal` form) | A model's judgement and a cost at every end | Rejected |

## Consequences

- **Code slices for the planner** (code mode; each tested with fixture inputs, a temporary git repository as data checkout and a stub `claude` only, never a real one — D16; each within the D4 cap):
  1. **The stop-check program**: a new module of the package and its test file, per decisions 4 and 5; it uses `hilclaw.run_commit.commit_owed` and `hilclaw.layout.check_run_id`, takes the run id and the data root from its arguments, and is tested against temporary git repositories in which a commit is owed, not owed, or cannot be told.
  2. **The `Stop` entry and the run id**: `hilclaw/turn_loop.py` gains the keyword parameter of decision 4 and writes the `Stop` entry beside the two `PreToolUse` entries; `hilclaw/turn_start.py` passes its run id; tests check the written file against a stub `claude`. The docstrings of both modules (`turn_loop`'s `run` and its "Decided by" list; `turn_start`'s account of the call of the loop) are rewritten there.
  - **The test-rule question** for slice 1, which this record does not decide: CLAUDE.md test rule ⑤ excludes tests of "hook 스크립트", while a hook entry point under `hilclaw/` is also a module of the layer-2 package, which rules ① to ④ cover. T-0403 and T-0406 read it as the latter, which their reviewers accepted as Info; the planner of slice 1 settles it again or raises it.
  - **No change of the definition is needed**: the line is self-contained, and "The end of a session" stays as it is.
- **Runtime acceptance items** (D16; nothing was tried, nothing is required of the development machine), numbered after ADR-0147's (lxii). ADR-0146 items (lvi), (lix) and (lx) apply to the `Stop` entry as written and are not repeated; **this record's reading** is that (lix)'s "the start text reaches it as written" covers the run id and the data root, which travel in the same `args`, as ADR-0147 read it for its data root.
  - **(lxiii)** In such a session, the `Stop` entry of the `.claude/settings.json` the loop wrote runs when the main session finishes its reply, before the `-p` process exits (H13), and not when a sub-agent finishes. Closed by the owner by hand, or by a runtime self-check whose `Stop` hook leaves a mark.
  - **(lxiv)** In a `-p` session, an exit 2 of that hook with one line on standard error makes the main session go on with the line as its instruction, and the process exits only after the model's next end (H15); the `Stop` that follows that continuation carries `stop_hook_active` `true`, also when the model called a tool in between (H14). Closed by the owner by hand, or by a runtime self-check whose `Stop` hook refuses once and records the `stop_hook_active` it then receives.
  - **(lxv)** On the runtime machine, the hook process finds the `git` that the server finds (H22; ADR-0127 item (xvi) for the server), and `commit_owed` on the data checkout finishes within the hook's timeout; a `Stop` hook that times out lets the stop through (H18, read). Closed by the owner by hand, or by a runtime self-check that runs the hook program on the data root with a test run.
  - **(lxvi)** A live Round-Manager told the line calls `mcp__hilclaw__run_commit` once and ends, and at the two ends without a call ends at once without calling it. A model's adherence, like item (xlvii); closed by the owner by hand.
- **Less exact, not edited** (found by reading the records of Required Reading and by a search of `ARCHITECTURE/decisions/`, `hilclaw/` and `orchestration/` on 2026-10-22 for "Stop", "Stop hook", "a hook does anything with commits", "knows no run", "one `PreToolUse`" and "nothing else"; not claimed complete). Each stays true outside these runs:
  - The sentences of ADR-0146, ADR-0147, ADR-0123 and ADR-0127 listed in Status.
  - ADR-0127 Boundaries, "**The Stop hook** that would enforce a commit, and every other hook"; ADR-0143 Boundaries, "**The Stop hook** that would enforce a commit at a turn's end"; ADR-0146 Boundaries, "the Stop hook that would enforce a commit (ADR-0127, ADR-0143 Boundaries)"; ADR-0147 Boundaries, "the `Stop` hook (ADR-0127, ADR-0143)"; ADR-0139 Boundaries, "a Stop hook" — for the end commit of these sessions.
  - ADR-0143 Consequences, item (xlvii), and `orchestration/round-manager.md` "The end of a session": the call is now also held by the stop check (once per end), not by the prompt alone.
  - In code, `hilclaw/turn_loop.py` (`run`'s parameters and the "Decided by" list, which names two hooks) and `hilclaw/turn_start.py` (the call of the loop, which passes no run id) (slice 2).
  - Not less exact: ADR-0143 decision 2 and its "Not called" bullet (the line repeats them); ADR-0143 "The cost, plainly" on a dead turn's work (a dead turn gets no `Stop`); `turn_start`'s "the prompt of every turn names the run by its id and nothing else hands over a place of the run" (the run id in the hook's arguments is no place, and the session is not given it).
- **UsageCases and StandardScenarios.** No sentence becomes false; no verdict changes (S0, S1, S2 rechecked; S2 step 3's "마지막 commit 지점" stays the last turn end committed, now held at a live end below the prompt as well).
- **A-13 reading.** Document mode. No code, test, setting, dependency or data-plane change.
- **The cost, plainly.** A Python process starts at every end of a turn session's main reply and runs `git` a few times on the data checkout — the first hook of these sessions that starts processes. Where a commit is owed, one more model reply follows, spending plan usage; at the two ends without a call that reply only ends the session. **What stays held only by the prompt**: the call itself — the hook asks once, and a model that ends again without it leaves the work for the next entry; that after a refusal the model calls `run_commit` once and, if that call fails, not again (the prompt's "do not call it again in this turn"); and every end the hook cannot read (a fault, a timeout, an unreadable run). **What stays held only by the next entry** (O1): every dead turn, an API error and a usage limit included (H19, H20), and every end the hook let through, until a next start that an unattended run may not get (ADR-0143 "The cost, plainly"). If a version of Claude Code does not run `Stop` in `-p` sessions, or does not set `stop_hook_active` as read, the hold is absent or may ask twice (items (lxiii), (lxiv)); the commits themselves are unchanged.

## Boundaries (not decided here)

- **Runs outside ADR-0120 decision 1**, and hooks of every other session: the interactive checkpoint session, the coder's own session in its container (HQ-0053), the self-check's session.
- **The rest of OD-18 and PLAN P2-4**: `PostToolUse` journaling, `SessionStart`, `PreCompact`, the kill switch, **default-FAIL in general**, the CLAUDE.md invariant list, the check of a request's `run_id` against the session's run, and sub-question ② (a shell and the command-line front).
- **Gates** and what a gate checks (OD-3, #5 A-5 — owner-only); a wait for the user or a gate as an end (OD-8 ㉝), which this hook treats like any end.
- **The retry** of a failed `run.commit` (OD-17; ADR-0143 Boundaries): the hook asks for no second call after a failed one.
- **The push**, the remote and the unpushed-commit count (#5 A-3; ADR-0127 decision 7).
- **Budget values and the usage-limit pause** (OD-19; ADR-0122 decision 6).
- **Sub-agent stops**: decided for these sessions (no `SubagentStop` entry, decision 3); a sub-agent that commits would need its own record.
- Any edit of an earlier record, of FR or NFR text, UsageCases, `hilclaw/`, `orchestration/`, tests, CI, `.claude/`, any settings file or the `HIL-Claw-data` repository; any new external dependency.
