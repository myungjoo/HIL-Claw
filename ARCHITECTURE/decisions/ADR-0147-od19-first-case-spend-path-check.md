## Decision

A sentence is **cited** when a source is named with it. Every other sentence is **this record's own**.

### 1. Scope and terms

- **The sessions**: the turn sessions of ADR-0146 decision 1 — every `claude -p` turn session the turn loop starts for a run of ADR-0120 decision 1 — and nothing outside them. **The budget**: the round budget alone (`round_budget`, ADR-0032; "over" by ADR-0121 decision 4).
- **The budget check**: the check of decisions 3 to 5. **A run at its round budget**: a run whose `STATE.json` holds no `run_status` and whose `instance.json` states a `round_budget` that its `round` is at or beyond — the state in which ADR-0121 decision 3 has the Round-Manager write `"over"` and begin no round.

### 2. (a) Which calls of such a session spend

| Call | What it consumes | Today (`52aa90c`) | After ADR-0141 slice (d) |
|---|---|---|---|
| `coder_run` (coder-driver) | Plan usage of a coder session and machine time of its container (cited: ADR-0126 decision 7, "A coder session spends plan usage") | Nothing: `no_container_runtime` before anything is created | Plan usage and machine time; the largest spend a tool call starts |
| `correctness_check` (evaluator) | Machine time: it builds and runs an attempt's verification (ADR-0021, [ADR-0056](ADR-0056-od18-correctness-check-verification-executable.md)); journaled, `spend` `{}` | The mock backend's script only | Unchanged by slice (d); more with a real backend (HQ-0021, HQ-0026) |
| `state_read`, `instance_read`, `run_fresh`, `hypotheses_read`, `checks_read`, `timings_compare` | A read of the run's files | Same | Same |
| `state_write`, `round_end`, `key_store`, `case_write`, `spec_write`, `verdicts_write` | A write of the run's files | Same | Same |
| `run_commit` | A commit in the data checkout | Same | Same |
| `Agent` (Round-Manager, built-in) | Plan usage of the sub-agent's model turns | Same | Same |
| The session's own model turns | Plan usage; no tool call carries it | Same | Same |

- **The spending tools** of this record are `coder.run` and `correctness.check`: the two that start work whose cost grows with what they run, beyond a read or a write of the run's files. `sim.run` and `board.run` would be such tools; they are not registered (HQ-0021, HQ-0026). [ADR-0142](ADR-0142-od23-first-case-round-zero-after-coder-call.md) decision 4 already gives `board_run` to a future `experiment-runner` of these sessions, which the caller check then admits with no change (ADR-0146 Walk-through); **so the slice that registers `board.run` or `sim.run` for these sessions also adds it to this check's list**, or the tool spends unchecked.
- **Plainly**: today the check guards almost no spend — `coder.run` creates nothing and `correctness.check` runs a mock. After slice (d) it guards the coder call. **The largest spend of a turn, the model turns of the session and its sub-agents, carries no tool call and is not on this path** (decision 3).

### 3. (b) Whether, and where: a second `PreToolUse` command hook on the spending tools

- **Every call of `mcp__hilclaw__coder_run` or `mcp__hilclaw__correctness_check` in such a session, by any caller, passes the budget check before it runs.** The check refuses the call when the run the request names is over, holds any `run_status`, is at its round budget, or cannot be read (decision 5); otherwise it gives no decision.
- **It is a `PreToolUse` command hook of the session's project settings**, a second entry beside the caller check's, whose matcher is the exact list of the two tool names (H11). A pass exits 0 and prints nothing; a refusal exits 2 with one line on standard error. **It never answers `"allow"`** and prints nothing on standard output, for the reasons of ADR-0146 decision 2 (H4 there), and so never returns `updatedInput` (H10).
- **Why these grounds, and no other moment.** `"over"` and an unknown value are ADR-0121 decision 2's: no round begins and no turn runs on that run. A run at its round budget is the state of ADR-0121 decision 3, in which the Round-Manager "begins no round"; the comparison is ADR-0121 decision 4's, `round` ≥ `round_budget`, with the same two numbers `round.end` uses. **No new rule of counting**: no amount of `budget_spent`, no open step, no time and no token count is read (no axis is accounted through the log, cited: ADR-0040 decision 6).
- **Why a hook and not the tool layer.** A check inside the tool functions holds for every caller and both fronts (ADR-0010 decision 6): a person, a test or a later record's re-verification calling `correctness.check` on a run that is over would be refused, which is a rule for all runs and outside this record's scope. In `correctness.check`, a journaled tool, it would add a failure kind to that tool's contract, near the lines of ADR-0011 decision 7 (avoided). In `coder.run` it would add a kind against ADR-0141 decision 2, "It adds nothing to the call's contract". The hook sees exactly the turn sessions, adds nothing to any contract, and sits beside the hook these sessions already run.
- **Why not nothing beyond today's holds.** Inside a turn, a spending call after `"over"` (written by `round.end` in the same turn, or met at entry step 4 and not obeyed), or after entry step 6's comparison was skipped, is stopped by nothing below the prompt; that is the hold ADR-0146 did not accept for its floor (Context). The cost of the check is one process start per spending call (Consequences).
- **What it does not cover**: `Agent` delegations and model turns (no run in the input, decision 4); a call through the command-line front (cited: ADR-0010 decision 6); every other tool, whose calls the prompt and step 1 of the loop hold as today.

### 4. (c) What the check reads and how it reaches it

- **The run**: the `run_id` member of `tool_input`, the request of the call (H10; cited: ADR-0015 decision 4 for the journaled `correctness.check`, ADR-0126 decision 3 for `coder.run`: both requests carry `run_id`). The check does not compare it with the session's run; that check stays open (ADR-0146 Boundaries). A request that names another run is checked against that run.
- **The data root**: the one the loop gives the server. The turn loop puts the same real absolute path it writes into the server entry's `env` (Context) as one more element of the hook's exec-form `args`, after the package directory, and the program reads the run below that path and nowhere else. **This record's choice**: an argument of the hook entry, not an `env` member of the settings (ADR-0146 decision 4 keeps "no `env`") and not `hilclaw.data_root_source.configured` in the hook process (Context: it can name another root). It is no member of a request, so ADR-0015 decision 3 ("The data root is never a member of a request") is untouched; the hook is no tool function and takes no data-root source. A missing argument, or one that names no directory, is a root it cannot tell (decision 5).
- **The files**: `runs/<run_id>/STATE.json`, and `instance.json` when `STATE.json` holds no `run_status`, each read once by the reader that `state.read` and `instance.read` use (`hilclaw.run_file_tools.read`, observation), so validity, version and the four `run_file_*` situations are the tool layer's. **The members**: `run_status` and `round` of `STATE.json`, `round_budget` of `instance.json`; no other member is interpreted, and an unknown top-level member is passed over (cited: ADR-0012 decision 2).
- **The comparison**: `round` ≥ `round_budget` refuses; `round` < `round_budget` gives no decision.
- **Delivery**: the turn loop writes this entry into the session's `.claude/settings.json` together with the caller check's, as a second element of the `PreToolUse` array, in the same exec form, with the data-root argument above, `"onFailure": "block"` and a `timeout` well below the default (H3, H5 of ADR-0146); the value is the code slice's. **This revises ADR-0146 decision 4's "this one `PreToolUse` entry and nothing else"** to these two entries and nothing else; the rest of that decision (no `permissions`, no `env`, a definition's own `settings.json` refused) holds. ADR-0146 decision 5, the caller check's program and its table are unchanged.
- **How the two hooks combine**: both match a spending call and run in parallel (H8); either one's exit 2 stops it (H9, read; item (lxii)); a call runs only when the caller check, the budget check and ADR-0139's pre-approved list all let it. Neither hook depends on the other's outcome or order.
- **The program** is a new module of the package (layer 2), in Python, so that it uses the tool layer's reader; it writes nothing, starts no process, calls no model and contacts no server. Its whole body is guarded as in ADR-0146 decision 5. Its name, start text, the constant holding the two tool names (from which the loop builds the matcher) and its line are the code slice's.

### 5. (d) When it cannot tell

| The hook finds | It does |
|---|---|
| Input that is not one UTF-8 JSON object; `hook_event_name` not `PreToolUse`; `tool_name` not one of the two spending tools | Refuses: the settings are not what this record writes |
| `tool_input` not an object; `run_id` missing, not a string, or not a run id (`hilclaw.layout.check_run_id`) | Refuses |
| The data-root argument missing, or naming no directory | Refuses |
| `STATE.json` missing, unreadable, invalid or of another version | Refuses |
| `run_status` present, `"over"` or any other value or type | Refuses (ADR-0121 decision 2) |
| No `run_status`; `instance.json` missing, unreadable, invalid or of another version | Refuses: whether a round budget is stated cannot be told (an invalid file is used for no member, cited: ADR-0032 decision 4) |
| No `run_status`; `instance.json` valid, version 1, stating no `round_budget` | No decision: the run states no round budget to be at, and what ends or stops such a run is OD-8 ㉙ (나) |
| No `run_status`; `round` ≥ `round_budget` | Refuses (ADR-0121 decisions 3, 4) |
| No `run_status`; `round` < `round_budget` | No decision |
| An error of its own; a failure to start or a timeout | Refuses (guard; `onFailure`) |

- **Refuse what it cannot tell.** A budget check that lets through what it cannot read rests on the prompt again in exactly the cases it cannot see. This answer is **for this check only**; the default-FAIL contract of OD-18 stays open.
- **Where this differs from the prompt** (`orchestration/round-manager.md`, observation): after a fresh run's first `STATE.json` (entry step 2) the turn goes to the round steps without reading `instance.json`, since the fresh test looks only for the file (ADR-0120 decision 4). So in round 0 of a fresh run whose `instance.json` is unreadable, invalid or of another version, the prompt delegates and the check refuses the spending calls; the turn comes to the stop with round 0 not ended. **This is this record's choice for a file it cannot read, not an answer to OD-8 ㉙ (나)**. In every other refused state, as the prompt finds the run at entry, the prompt itself ends the session before the round steps (entry steps 2 to 6). A file changed during the turn (cited: ADR-0032 decision 6) is checked as it is at the hook's read, so the check may also refuse a call that the prompt, having passed entry step 6, would make.
- **A run that states no round budget is let through**, round 0 of a fresh one included: refusing it would say that such a run may not spend, which ADR-0122 decision 4 leaves open ("It does not say that such a run is over, may not start or is invalid"). Its spending stays bounded as ADR-0122 decision 4 bounds its turns.
- **The refused caller is told one fixed line**: that the budget check refused the call because the run is over, at its round budget, or could not be checked. It may name the tool; it shows no member, path or value. The wording is the code slice's.
- **A refusal is not a failure of the turn and is not journaled**: as with the caller check (ADR-0146 decision 6), the tool function never runs, so `correctness.check` appends no start or end line; the model reads the line and goes on as its definition says.

  1. **The budget hook program**: a new module of the package and its test file, per decisions 4 and 5, with the constant of the two spending tools; it uses `hilclaw.run_file_tools.read` and `hilclaw.layout.check_run_id`, and takes the data root from its arguments.
  2. **The second settings entry**: `hilclaw/turn_loop.py` writes the two `PreToolUse` entries of decision 4, the second with the data-root argument; tests check the written file against a stub `claude`. The `turn_loop` docstring ("It holds one ``PreToolUse`` entry") is rewritten there.
  - **The test-rule question** for slice 1, which this record does not decide: CLAUDE.md test rule ⑤ excludes tests of "hook 스크립트", while a hook entry point under `hilclaw/` is also a module of the layer-2 package, which rules ① to ④ cover. T-0403 read it as the latter, which its reviewer accepted as Info; the planner of slice 1 settles it again or raises it.
- **Runtime acceptance items** (D16; nothing was tried, nothing is required of the development machine), numbered after ADR-0146's (lx). ADR-0146 items (lvi) and (lviii) to (lx) apply to the second entry as written and are not repeated.
  - **(lxi)** In such a session, the `tool_input` of a `PreToolUse` hook on `mcp__hilclaw__coder_run` or `mcp__hilclaw__correctness_check` is the arguments object the server then receives for that call, its `run_id` included (H10). Closed by the owner by hand, or by a runtime self-check that compares a hook's logged input with the server's request.
  - **(lxii)** Two `PreToolUse` entries of one `.claude/settings.json` that both match a call both run, also when their hooks have the same `command` and other `args` (H8: what makes two handlers "the same" is not stated), and the call is stopped when one exits 2 while the other exits 0 with nothing printed, whichever finishes first (H9). Closed by the owner by hand, or by a runtime self-check whose two hooks on one test tool each leave a mark.
  - **This record's reading** is that ADR-0146 item (lix), whose words are "the start text reaches it as written", is checked together with the data-root argument, which travels in the same `args`: on every platform that argument reaches the program as written. It is not counted as a new item.

- **UsageCases and StandardScenarios.** No sentence becomes false; no verdict changes (S0, S1, S2, S8 rechecked).
- **A-13 reading.** Document mode. No code, test, setting, dependency or data-plane change.
- **The cost, plainly.** A Python process starts before every spending call and reads two small files. A fault in the program, the interpreter, the data-root argument or the run's files refuses every spending call of the turn, so the round cannot go on until it is fixed. The check guards almost nothing today (decision 2) and the coder call once slice (d) lands. **What stays held only by the turn loop and the prompt**: the model turns of a session and its sub-agents and every `Agent` delegation, the largest spend of a turn; a call through the command-line front; and every check of the other axes. If a version of Claude Code sends a `tool_input` other than the arguments, every spending call is refused until this record is revisited (item (lxi)). Between the hook's read and the call, a parallel `round.end` of the same turn can write `"over"`; the call then runs once. A request that names another run that is not over passes this check; the `run_id` check stays open. A run that states no round budget is not held by this check at all (㉙ (나)), and round 0 of a fresh run whose `instance.json` cannot be read spends nothing through these two tools.
