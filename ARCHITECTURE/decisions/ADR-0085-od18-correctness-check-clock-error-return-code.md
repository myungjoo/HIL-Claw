## Context

- ADR-0084 decision 3 kept a failed clock read after a normal end open because "It is not told apart" from an error from closing the process after a read that ended, and because "The row would depend on a status that is not stated". The first thing it named that would let it be placed: "A code change of `clang_build.build` that states the return code it already holds (C2) for a failed clock read, and tells that source from the closing source … Then a record can weigh S7 for a non-zero status, with its log, by the value O1 gave." Task T-0257 (PR #162, `2124a33`) made that change and placed nothing in a row.
- **Observations at `2124a33`** (`hilclaw/clang_build.py`; no code is bound; `git diff 8782cf8 2124a33 -- hilclaw/` adds the member, binds `returncode = None` before the `try` and passes it, and edits two docstrings; the other changed lines only re-wrap the signature and the call):
  - **R1. The member.** `CompilerRunError` has the keyword-only member `returncode` beside `timed_out`, `log` and `removal_error`. The class docstring: "`returncode` is the return code of the compiler process when the error came from reading the clock after the process had ended by itself, the value `BuildResult.returncode` would have held: 0, a non-zero status, or a negative signal number on POSIX. It is `None` for every other source, including reading the clock after a kill for the time limit; `None` does not mean that the process did not end."
  - **R2. Where it comes from.** `build` binds `returncode = None` before the `try` around `_communicate`; `_communicate` returns `None` after a kill for the time limit and `process.poll()` otherwise, and every other source of the class — the first read, the kill after it, the kill for the time limit, the read or wait after that kill, closing the process — raises inside `_communicate`, before the assignment. Every `CompilerRunError` is raised with `returncode=returncode`. So `returncode` is not `None` exactly for a failed clock read after a normal end, as T-0257's Result has it ("The only source with a non-`None` `returncode` is an `OSError` from `duration_s = time.monotonic() - started` after `_communicate` returned from a normal end"), and then `timed_out` is false.
  - **R3. Its other members** are as ADR-0084 C3 has them: `timed_out` false and `log` "all of it" (docstring), as for the closing source, whose `returncode` is `None`.
  - **R4. The steps after the clock read** are as ADR-0084 C3 has them: the stat test and `os.replace` stand in the `else` of that `try` and do not run, and the `finally` removes the temporary file, the artefact a compiler that exited with 0 wrote in it included. The stat test runs only `if returncode == 0`, so for a non-zero status neither step would have run without the error either, and the `BuildResult` would have had `ok` false.
- No owner comment on #5 speaks to ADR-0084, T-0257 or ⑱ (마) (checked on 2026-10-17; every comment since 2026-10-16 carries the driver tail).

## Decision

### 1. Scope and terms

- A call of `correctness.check` as ADR-0081 decision 1 has it. The six kinds, S1 to S10 and the keeper are as ADR-0079 decision 1 has them; the time-limit branch and the other branch as ADR-0082 decision 1 has them; a failed clock read as ADR-0084 decision 1 has it. **A failed clock read after a normal end** is a `CompilerRunError` whose `returncode` is not `None` (R2). **The closing source** is an error from closing the process after a read that ended. **The mock** builds nothing and is unchanged.

### 2. The operation tells it apart by `returncode`

- **From what `build` states alone**: the class and its members `timed_out` and `returncode` (R1, R2). A `CompilerRunError` whose `returncode` is not `None` is a failed clock read after the compiler ended by itself, and no other source; its `timed_out` is false. The closing source, the first read and the kill after it have `returncode` `None` (R2).
- **On which reading.** "What the operation observes decides the row" (cited: ADR-0060 decision 4). **This record reads what the operation observes as what `build` states of the error — its class and its documented members** — as ADR-0082 decision 2 applied the class and `timed_out`, and ADR-0079 decision 3 the `returncode` of a carried build. It reads no exception chain, no private state and no text of the log (cited for the stop: ADR-0081 decision 2).
- **So both reasons of ADR-0084 decision 3 are gone for this source**: it is told apart from the closing source, and the status is stated. Its reading of "a compiler the call lost while it ran" as not covering it still holds and is kept: the compiler ended by itself and the call holds its status (R1).
- **The order of the tests.** `timed_out` true is answered by ADR-0082 decisions 2 and 3, as ADR-0084 decision 2 has it; its `returncode` is `None` (R1). This record answers only `timed_out` false with a `returncode`.

### 3. A non-zero `returncode` is S7, (B) `"build_exit_status"`

- **The operation answers a failed clock read after a normal end whose `returncode` is not 0 as S7**: it returns the form (B) `"build_exit_status"` (cited: ADR-0060 decision 4), and the tool function makes the broken result as for any S7 build. A negative `returncode` (a signal on POSIX) is S7 too, on the reading of ADR-0060 decision 4 ("That a compiler ended by a signal (a negative `returncode` on POSIX) is S7 is this record's reading"), which this record applies as it stands.
- **Why.** S7 is "The compiler ends with a non-zero status" (cited: ADR-0060 decision 4), and `build` states that it did (R1). O1 (**the owner's**: "One each: `build_exit_status` for S7 and `build_time_limit` for S8.") makes it a result. The error came after the end, from reading the clock; **this record reads S7 and O1 as reaching such a build**, as ADR-0082 decision 2 read S8 for a failure after the time limit: the experiment established that the compiler ended with a non-zero status, and a later failure to read the clock says nothing about the attempt.
- **The moment and `ok`.** S7 is dated "⑥, the build ended" (cited: ADR-0060 decision 4) and found when "the build ended; `ok` false" (cited: ADR-0056 decision 5). **This record reads both as ADR-0082 decision 2 read them for S8**: the end of the call of the build, which the call reached, and the build not having ended ok, which the error shows without a `BuildResult`. Here the reading costs nothing: with a non-zero status the `BuildResult` would have had `ok` false (R4).
- **What the answer loses.** Nothing: an answer of form (B) "holds the condition and nothing else: no status, no time and no byte of the log" (cited: ADR-0060 decision 4), so the duration the call failed to read is in no answer, and the artefact steps would not have run for this status (R4).
- **The `removal_error`** changes nothing, as ADR-0082 decision 2 has it for the time-limit branch.

### 4. Its log is handed over

- **The operation hands `log` to the keeper before it returns or raises, under the row of decision 3 or 5**, as for the log of any S7 or S9 build (cited: ADR-0078 decisions 2 and 6); a write that fails is answered as ADR-0078 decision 7 says. For S7, O2 (**the owner's**: "Kept, not returned: in a file of the attempt, never in the result or in `events.ndjson`") applies to it as ADR-0060 decision 5 applied it to S7 and S8. It is all the output (R3). **If `log` is `None`, the operation hands nothing over**, as ADR-0082 decision 3 has it; the docstring states no such case for this source.
- **Why apart from the closing source now.** ADR-0084 decision 3 did not decide the hand-over apart from the row because "by what `build` states it would be a rule for the closing source as well". The rule is now one for a `returncode` that is not `None` (decision 2), which the closing source does not have.
- **What it does to the cost ADR-0084 decision 3 stated**: the log of such a build is kept, as ADR-0078 decision 2 keeps "The log of every build whose compiler process was started and has ended — by itself, or killed for its time limit", and for a non-zero status as O2 says; and a build that S7 makes a result is no longer answered by a tool failure, against O1. The sentence a caller may rely on after a failed write, "its compiler ended" (cited: ADR-0078 decision 7), is exact for this source.

### 5. `returncode` 0 is S9, `build_output_missing`

- **The operation raises a failed clock read after a normal end whose `returncode` is 0 as S9, `build_output_missing`**, whether or not it also holds a `removal_error`, and hands its log over first (decision 4).
- **Why.** S9 is "Status 0 and no executable at the path, or it cannot be moved there" (cited: ADR-0060 decision 4). The compiler exited with 0 (R1) and nothing was moved to the output path (R4), which lies in the build directory the operation made for that call (cited: ADR-0056 decision 4), so no executable is at the path. **This record reads S9 as covering it on the reading ADR-0080 decision 3 gave `ArtefactNotCheckedError`**: "The compiler exited with 0 and nothing was moved to the output path … so no executable is at the path: the first case of that row's wording". There, too, the artefact was not tested to the end, nothing was moved, and the `finally` removed the temporary file. ADR-0056 decision 5's "(`ok` false)" is read as in decision 3: the build not having ended ok, which the error shows without a `BuildResult`.
- **On which reading of ADR-0084.** ADR-0084 decision 3 read S9 as not covering this case, as "the artefact was neither tested nor moved but removed with the temporary file", and named as one thing that would let it be placed "A record for status 0 with no artefact tested, which reads one row's wording to cover it". **This record is that record**: it reads S9's first case by the state at the output path when the call came back, as ADR-0080 decision 3 did, not by whether the artefact was tested.
- **Unlike a carried build.** ADR-0079 decision 3 answers a `TemporaryNotRemovedError` by its carried build, so `returncode` 0 is S9 only with `ok` false. This error carries no `ok`, and for status 0 whether the artefact was a regular file is not known (R4); this record places it by the output path, not by the build the call would have returned.
- **The message** may say which case of the row it was (cited: ADR-0060 decision 5); it shows no text of the error.
- **The cost, stated.** The compiler reported success and may have written a working executable, which the call removed untested (R4); the check that would have run it is answered by a tool failure, and a caller reads a missing output, which "may follow from what the attempt's source made" (cited: ADR-0060 decision 4), where here it followed from the machine's clock. ADR-0080 decision 3's answer for a refused stat test bears the same cost, though that record states none and its carried build reads S9 by itself. Left open, the landed rules would answer it `operation_answer_invalid` (cited: ADR-0045 decisions 4 and 5), a tool failure too, of a kind that says the backend's answer had neither form, and its log would not be kept. How often a machine's monotonic clock fails is not established here.
- **No new value of `error.kind`** is needed: the situation is a case of S9's wording.

### 6. How far (마) is answered

- **Answered now, for `correctness.check` of the first case and of the mock**: a failed clock read after a normal end — S7 with its log for a non-zero `returncode`, S9 with its log for `returncode` 0 (decisions 2 to 5).
- **Open under (마)**: the row of a `CompilerRunError` whose `timed_out` is false and whose `returncode` is `None` — the first read, the kill after it, and the closing source (ADR-0082 decision 4). The closing source is now told apart from the clock source by `returncode`, but this record does not place it: no status is stated for it (R1: "`None` does not mean that the process did not end"), so the second reason of ADR-0084 decision 3 still holds for it, and an error of the exit of `with process:` leaves the compiler's end unseen (cited: ADR-0081 decision 3). Also open: a plain `OSError` of `build` (ADR-0084 decision 4) and the other entries ADR-0084 decision 5 lists — the `TypeError` of `clang_build.build`, whatever `clang_build.build` passes on from `subprocess` beyond the `OSError` its docstring names, and the `ValueError` or `TypeError` and the `OSError` for "a `cwd` that does not exist" of `local_run.run`.

## Alternatives considered

| Point | Alternative | Why not |
|---|---|---|
| 2 | Tell the source by `log` not being `None` | The closing source has it too (R3; ADR-0082 L4). `returncode` is the member the docstring gives this source alone (R1). |
| 3 | **(a)** S7 for a non-zero `returncode` (chosen) | It answers what `build` states (R1) with the row O1 gives it; nothing of the answer is lost (decision 3). |
| 3 | **(b)** Leave every failed clock read after a normal end open | The two reasons of ADR-0084 decision 3 no longer hold (decision 2). Left open, the landed rules answer S7 by a tool failure, against O1, and its log is not kept, against O2. |
| 3 | **(c)** S7 only for a positive status; a signal left open | A negative `returncode` of a `BuildResult` is S7 by ADR-0060 decision 4; the same status after a failed clock read would get another answer by a step after the end. |
| 3 | **(d)** Read the status out of the log text, or from the exception chain | Not needed, and declined as ADR-0081 decision 2 declined the chain: it rests on what `build` does not state. |
| 4 | Hand the log over only for a non-zero status | ADR-0078 decision 2 keeps the log of S9 too, and of every build whose compiler ended by itself. |
| 5 | **(e)** S9 for `returncode` 0 (chosen) | Its first case holds at the output path when the call came back, on the reading ADR-0080 decision 3 gave the same state (decision 5). The cost: a working executable may have been removed untested. |
| 5 | **(f)** Leave `returncode` 0 open | The landed answer is a tool failure as well, `operation_answer_invalid`, which says the backend's answer had neither form, and the log is not kept against ADR-0078 decision 2. No stop of what `build` states remains. |
| 5 | **(g)** A new kind for "artefact lost after status 0" | A new value of `error.kind` is a data-plane change (CLAUDE.md A-13), and S9's wording covers the case (decision 5). |
| 5 | **(h)** Treat it as an ok build and start the executable | Nothing is at the output path (R4); the start would fail as S10 for a reason that is no fault of the executable. |
| 5 | **(i)** S7 for status 0 too | A compiler that exited with 0 would be answered as a compile or link failure, which O1 does not class (as ADR-0084 alternative (d) has it). |
| 6 | **(j)** Place the closing source now | Its `returncode` is `None` and its end is not seen (decision 6); its row would depend on a status `build` does not state. |

## Consequences

- **Code** (code mode, D12 rules; names and modules are the code task's; **this record binds no code**): the operation of `cpu_standin` for `correctness.check`, when it is written, applies ADR-0079 to ADR-0084 and this record. For a `CompilerRunError` whose `timed_out` is false and whose `returncode` is not `None`, it hands `log` to the keeper when it is not `None`, then returns (B) `"build_exit_status"` for a non-zero `returncode` and raises `build_output_missing` for 0; it leaves a `returncode` of `None` with `timed_out` false, and a plain `OSError`, to the landed rules. No change of `clang_build.build` is needed for this.
- **Not edited and now less exact.**
  - ADR-0081 decision 2: "no log and no return code reach the operation", and "S9 starts with "Status 0", at "the build ended", and no status is known", for a failed clock read after a normal end (R1).
  - ADR-0082 L5 ("Neither the members nor the docstrings say whether the compiler had ended when the error was raised"), since `returncode` now says it for one source; decision 4, "The row of a `CompilerRunError` whose `timed_out` is false stays open under (마)", which now holds only where `returncode` is `None` (decision 6); decision 4, "Whether an operation hands that log over is part of the open row", for a `returncode` that is not `None` (decision 4); and the alternatives row of point 4, "S7 needs a non-zero status and S9 starts with "Status 0" … and no status is stated", for that source; and decision 5's open entry "the row of the other branch (decision 4)", Consequences, Code, "it leaves the other branch to the landed rules", and Boundaries, "The row of the other branch of `CompilerRunError`, and whether its `log` is handed over", each of which now holds only where `returncode` is `None` (decision 6).
  - ADR-0083 decision 3, for the line after the end, which ADR-0084 already listed: "S7, S8 or S9 may hold for it, or the build may have ended ok, and nothing the class carries says which", since `returncode` now says which of S7 and S9, and a build that may have ended ok is answered S9 (decision 5); and "After the end, a build that S7 or S8 would make a result is answered by a tool failure, against O1", which no longer holds for a failed clock read after the end (decision 3; ADR-0084 decision 2); and decision 4's open entry "the row of a `CompilerRunError` whose `timed_out` is false (ADR-0082 decision 4)" and Boundaries' "among them the row of a `CompilerRunError` whose `timed_out` is false", now only where `returncode` is `None` (decision 6).
  - ADR-0084 Status ("It does **not** place a failed clock read after a normal end (decision 3)", and among its own design "that a failed clock read after a normal end stays in the open entry of ADR-0082 decision 4, on which reading and for which reason"); decision 3 as a whole — its title "stays open", its reasons "It is not told apart" and "The row would depend on a status that is not stated", "**this record reads S9 as not covering it** and reads no other row of S3 to S10 to do so", "**this record does not decide the hand-over apart from the row**" and its cost; decision 5's open entry "a failed clock read after a normal end included"; the walk-through rows "The compiler exits with 1; reading the monotonic clock fails" and "The compiler exits with 0; reading the monotonic clock fails" ("open under (마)"); alternative (c), "Each would need a row by a status the error does not state (C2): S7 for a non-zero status, none for status 0 (decision 3)", now that the status is stated and status 0 is S9 (decisions 2, 5); alternative (d)'s "and the closing source would get the same row", which `returncode` now rules out (decision 2); alternative (e)'s "and it would apply to the closing source too (decision 3)", which `returncode` now rules out (decisions 2, 4); alternative (g), "Leave it open (chosen)"; Consequences, Code, "leaves the other branch and a plain `OSError` to the landed rules", and "A code task may make `build` state the return code for a failed clock read and tell it from the closing source (decision 3)", which T-0257 did; its bullets on ADR-0083, "which this record reads otherwise for status 0 with the artefact removed untested (decision 3)", now that status 0 is S9 (decision 5), "for a `CompilerRunError` after a normal end it holds for S7 (decision 3)" and "now kept by the error and not handed over for a normal end (decision 3)", none of which holds after decisions 3 to 5; and Boundaries, "a failed clock read after a normal end included".
- **A-13 reading.** Nothing of the data plane is added or changed: no member, no value of `condition` or `error.kind`, no file, no version. Both answers use values already named (ADR-0060 decision 4).
- **Runtime acceptance items**: none. No `claude`, compiler or container is started or required; whether a real machine's monotonic clock fails after a build is the code tasks' observation.
