## Decision

A sentence marked **owner** quotes O1 or HQ-0005 point 4, as a reason only. A sentence is **cited** when a requirement or a record with its decision is named with it; it then says what that source says and adds nothing. ### 1. Scope and terms

- This record is about **the mock backend** and **a call of `sim.run` or `board.run` about one attempt of a run whose hw_profile names the mock** that reaches ⑥, the call of the operation (cited for the order: ADR-0062 decision 6). Such a run is in the scope of the run tools' contract: "The mock is this record's own scope" (cited: ADR-0061 decision 1), for the reason "so that the contract tests of P1-1 run the whole judging over the mock" (**owner**, HQ-0005 point 4, as ADR-0061 decision 1 quotes it).
- It fixes **three points and nothing else**: how the mock's operation of each tool asks its script (decision 2); what the default script answers for each tool (decision 3); and the rule by which it derives its report and its figure (decision 4). Decision 5 says what follows by citation and what is not decided.
- The terms of ADR-0009 (report, completed, broken), ADR-0016 (backend, operation, script, the moments ① to ⑦), ADR-0044 (the default script, a script of a test, the default mock), ADR-0052 (the figure), ADR-0063 (`outcome`, `ceiling`) and ADR-0065 (the timing parameters, (A), (B), an answer of neither form) are used unchanged. **`n_min`** and **`cv_max`** are the constants of ADR-0007 decision 8 (initial values 5 and 5 %, cited: ADR-0007 decision 4). This record fixes no name of code.

### 2. How the mock's operation of each tool asks its script

- **Cited, not re-decided.** "An operation of either tool is called with four things: the request, the hw_profile of the call, the timing parameters and the output path" (ADR-0065 decision 2). "For the mock, a script is asked with 'the called tool, the request, the hw_profile' ..., so the tool, and with it the point, reaches a script" (ADR-0065 decision 3, citing ADR-0016 decision 5 (c)). "The outcome of a mock call depends on its script and its call alone" (ADR-0016 decision 5 (e)).
- **What those sentences leave, decided here.**
  - **A script of either tool is asked with five things: the called tool, and the four things the operation was called with, as they are** — the request, the hw_profile, the timing parameters and the output path of that call, none derived, replaced or left out, and nothing added. The called tool is `sim.run` for the operation of `sim.run` and `board.run` for that of `board.run`. Of the point an operation is handed nothing: "Nothing is handed for it" (cited: ADR-0065 decision 3); so, this record's own inference, the called tool is the one statement of the point a script has.
  - **The script is asked exactly once for each call of the operation and at no other moment.** A call that does not reach ⑥ asks no script.
  - **The mock's operation does not look at what the script answers.** What the script returned is what the operation returns, and what it raised passes through unchanged. The form is established by the tool function: "The form is established before anything is judged" (cited: ADR-0065 decision 4).
- **Three choices were weighed for the things a script is asked with.** (a) The tool and the four things as they are — the shape ADR-0044 decision 2 gave the check, with the output path that [ADR-0056](ADR-0056-od18-correctness-check-verification-executable.md) decision 3 added there (cited for the manner). (b) The tool and the timing parameters alone — a script of a test then could not answer by `execution`, which "Fails first, then works" is written over (cited: ADR-0016 decision 5 (e)), or by `candidate`. (c) A point handed beside the tool — a second statement of what the called tool says (the reasoning of ADR-0065 decision 3 (b)). **The choice is (a).**
- **Two choices were weighed for the answer.** (a) Passed on unseen — a script is then all of what the operation does (ADR-0016 decision 5 (c)), and a script of a test can give an answer of neither form, so the tool function's answer of ADR-0065 decisions 6 and 7 can be exercised over the mock. (b) The operation checks the form — the form would be established at two places that can disagree, and the mock would itself have to answer an answer of neither form. **The choice is (a)**, as ADR-0044 decision 2 chose for the check and as `hilclaw/mock_backend.py` does today (observation).
- **What is fixed and what is the code task's.** Fixed: the five things, their being the operation's own as they are, once per call, the answer unseen. The code task's: names, positions and types by which they reach a script; whether one script callable serves every tool; how a mock backend is built so that its operations of these tools take four things (cited for "how the call is written": ADR-0016 decision 2).

### 3. What the default script answers for each tool

- **For every call of either tool, the default script answers with (A): the pair of the report of decision 4 and none as the figure.** By the judging of the tool function such an answer is a completed run, converged, with no figure (decision 4): a result with `outcome` `"converged"`, its `intervals_ns` and `resolution_ns`, no `memory_bytes`, the `ceiling` the run's file gives, and `shape`, `n_max` and `sample_form` as handed (cited for the members: ADR-0063 decisions 2 and 4 to 7).
- **The two tools are answered alike.** "Nothing but the execution point distinguishes the two operations" (**owner**, O1), and the default script stands for no point: the mock has "no hardware, no simulator, no other process" (cited: ADR-0016 decision 5 (a)). The two calls of one attempt therefore give two results of equal members when the run's file is the same at both reads; their end lines differ in `step` (cited for `step`: ADR-0062 decision 3). Each call reads the file in ④ — the dimensions and `n_max` (cited: ADR-0061 decision 3) and the `bound` (cited: ADR-0061 decision 6) — and "two measurements of one run can be taken under two bounds" (cited: ADR-0023 decision 6, as ADR-0063 decision 5 cites it); so, this record's own inference, `shape`, `n_max` and `ceiling` follow each read.
- **The answer depends on nothing the script is asked with**: not on the tool, not on any member of the request, not on the hw_profile, not on any of the six timing parameters (the seed among them) and not on the output path, which it does not read. It reads no clock, no random source, no counter and no file of its own (cited: ADR-0016 decision 5 (e)). It does read the constant `n_min` of the measurement policy of its own source commit (decision 4); this record reads that constant as part of "one script fixed in the source" (cited: ADR-0016 decision 5 (c)) and not as state or a file.
- **Five answers were weighed.**
  - **(a) (A), completed and converged, no figure.** A run at the default mock then has, for these tools, the ordinary path of a measured attempt, and the whole judging — the form, the zero-interval test, the replay, the verdict or *not stated* — runs on each answer (**owner**, HQ-0005 point 4).
  - **(b) An answer that depends on a member of the request** (a broken result at some `candidate`, a condition at some `execution`): in the default registry that is fault injection in a live session, OD-18 sub-question ⑧ (cited: ADR-0016 decision 5, "Not decided"). A script of a test can do it (decision 5).
  - **(c) Always (B), or always a tool failure.** (B) says a build or a run "failed first" (cited: ADR-0065 decision 4), and the mock builds and runs nothing; a tool failure needs a kind a backend may raise, which is ⑲ (나) (cited: ADR-0065 decision 9).
  - **(d) No answer for these tools.** "The mock of the default registry offers every HW tool of that registry" (cited: ADR-0016 decision 5 (d)).
  - **(e) (A) with a figure.** Weighed in decision 4.
- **The choice is (a).** A record that answers ⑧ may make the answer depend on more; it then amends this decision.
- **The default script never answers (B), never raises a tool failure and raises nothing else**: no answer of neither form comes from it (decision 4: every call has a report it can write).

### 4. The rule by which the default script derives its report and its figure

- **The form, cited.** In this order and with nothing else: "one `resolution_ns <integer>` line before the untimed call, one `interval_ns <integer>` line per repeat in the order taken, and a last line `stop converged` or `stop not_converged`", ASCII lines ending in LF (ADR-0009 decision 8). A run is completed when, besides the two conditions of the process, the output "is exactly of this form, and the replay of decision 7 agrees" (same decision); the replay requires "every proper prefix" to be `CONTINUE` and "the whole sequence" to give the reported state (ADR-0009 decision 7). The measurement stops "at the first n with n ≥ `n_min` and CV < `cv_max`" (ADR-0007 decision 4).
- **The report of the default script is exactly these lines**: `resolution_ns 1`; then `n_min` lines `interval_ns 1000000`; then `stop converged`.
- **Why it agrees with the replay.** Every proper prefix has fewer than `n_min` samples and is `CONTINUE`, whatever its spread (cited: ADR-0007 decision 4). The whole sequence holds `n_min` equal samples, in either sample form — equal intervals have equal reciprocals —, so their CV is 0, which is below `cv_max`; in the replay's floating-point arithmetic it is 0 for the integer samples of `interval` and within rounding of 0 for those of `reciprocal` (observation: `stopping_state`). The state is converged, as reported. The rule needs `n_max` ≥ `n_min`, which holds for every admitted value: `n_max` is "never below `n_min`" (cited: ADR-0007 decision 8), and today the bound of the member, "an integer of at least 5" (cited: ADR-0065 decision 2), equals `n_min` = 5. So `judge_report` finds it completed and converged for every admitted `n_max`, both sample forms and every value of `cv_max` above that rounding.
- **How the rule meets "never handed `n_min` or `cv_max`"** (cited: ADR-0065 decision 2). The operation is handed neither, and the rule needs no `cv_max`; it needs `n_min`, which it reads as the constant of its own source commit, as "The Python side passes `n_min` and `cv_max` from the constants of `measurement.py`" (cited: ADR-0009 decision 7) and as ADR-0061 decision 3 has the operation's code do (cited: "which the operation's code does, and the tool function replays with the same constants"). The script and the replay are then of one source commit, the premise of the form, which "is an interface between two parts of the harness that are always of the same source commit" (cited: ADR-0009 decision 8). **Three ways were weighed.**
  - **(i) `n_min` equal intervals, converged, `n_min` read from the source.** The fewest repeats the policy admits, agreeing with the replay for every handed value.
  - **(ii) A report that reads neither constant: `n_max` intervals alternating between 1 000 000 and 1 000 000 000 000, starting with the first, then `stop not_converged`.** Every prefix of two or more samples has a CV of about 0.87 or more in either sample form (this record's arithmetic: about 1.41 at two samples, about 0.87 at the lowest, three reciprocals), so the replay agrees for every `n_min` ≤ `n_max` and every `cv_max` below that, with `n_max` alone, which is handed. *For*: the script reads nothing beyond its call. *Against*: it rests on a bound of `cv_max` as (i) does, only on the other side; the default would be the less ordinary outcome, "usable and marked \"not converged\"" (cited: ADR-0007 decision 4), whose standing as a best or a baseline is open (OD-13 sub-question ②), so the converged path of the judging and of what follows it would never run over the default mock; and it would stand for a timing run of wild spread. (i) reads only the constant an operation of `cpu_standin` also reads (cited: ADR-0061 decision 3, above), so it reaches no further than such an operation. A script of a test can give (ii).
  - **(iii) A converged report that reads neither constant.** One exists only tuned to a narrow window around the value of `cv_max`: a converged report stops "at the first n with n ≥ `n_min` and CV < `cv_max`" (cited: ADR-0007 decision 4). Of equal samples, a report of c samples is `CONTINUE` for c < `n_min` and already converged at a proper prefix for c > `n_min`; of unequal samples, it must have a CV of at least `cv_max` at each proper prefix from `n_min` on and below `cv_max` at the whole, so the replay agrees only for a `cv_max` between the CV of the whole and the least CV of those prefixes, a narrow window that the values must be tuned to around today's 0.05 (this record's arithmetic: the `n_max` = 5 intervals 1 000 000, 1 095 000, 1 000 000, 1 095 000 and 1 047 500 have a CV of about 0.064 at two samples, above 0.051 at three and at four, and of about 0.045 at five, in either sample form, so the replay agrees for every `n_min` ≤ `n_max` and every `cv_max` from about 0.046 to about 0.051). It rests on the value of `cv_max`, not on a bound of it as (i) and (ii) do, and is not chosen.
- **The choice is (i).**
- **A rule fixed with this contract.** "A member a real backend would measure is derived from the call by a rule fixed with the tool's contract" (cited: ADR-0016 decision 5 (e)). This record reads a constant rule as such a rule — a function of the call that takes the same value for every call — and fixes it here.
- **The values.** `resolution_ns 1` is the value of the example of ADR-0009 decision 8 (cited). Each interval is 1 000 000 ns, one million times the resolution, so that it is no call near the clock resolution, the case OD-13 sub-question ⑧ leaves open. **Two other sources of the values were weighed.** (a) Derived from the seed — a value derived from the seed would reach `intervals_ns` in the log. The seed "is kept nowhere by the tool layer" (cited: ADR-0064 decision 5), and a path by which "a kernel can put a value it holds — the seed among them (decision 8) — into the log" is left open only as what a kernel can do (cited: ADR-0063 Limit 6); the default script stands for no kernel and has no reason to open it. (b) Derived from `m`, `k` and `n` — a cost model no record gives, and values without bound whose samples `stopping_state` refuses beyond the float range (observation: its `len * max` rule), so a large shape would turn the default into a replay failure. **Constants are chosen.**
- **The figure: none.** The figure is the maximum resident set "of the process of one timing run", read "for the ended process" (cited: ADR-0052 decisions 3 and 4); the mock has no process (cited: ADR-0016 decision 5 (a)), so no figure is obtained, as on a platform without a unit rule "there is no rule and therefore no figure" (cited: ADR-0052 decision 4). What follows: no result of the default mock has `memory_bytes`; today every result has `"ceiling": "not_stated"` (cited: ADR-0063 decision 7); once `memory_ceiling` is admitted, a run at the default mock that states a ceiling — its `bound` read in ④ (cited: ADR-0061 decision 6) — is *not judged*, and "**\"Not judged\" is never \"within\"**" (cited: ADR-0052 decision 5, as ADR-0063 decision 7 quotes it). **Against a figure** — say the bytes of the three operands, 4·(m·k + k·n + m·n): it is a number no process reported, smaller than any figure of ADR-0052 decision 3, which also holds the harness's share, and it would let the default mock call a ceiling *within* that no run judged. A script of a test returns a figure to reach *within* and *over*.
- **What the report and the figure stand for, and what not.** They stand for a timing run that completed at the fewest repeats with no spread and whose memory was not measured. They stand for no kernel, shape, point or clock, and they show no time of anything (Limits).
- **What is fixed and what is the code task's.** Fixed: the lines, their values and order, that `n_min` is read from the source commit's constant, and that the figure is none. The code task's: the spelling of the bytes beyond the form, and which code reads the constant.

### 5. What a script of a test can express, and what is not decided

- **By citation only.** A script must be able to express "everything a backend may return under the tool's contract" and, for a journaled tool, "the death of the process while the operation runs" (ADR-0016 decision 5 (d)); both tools are journaled (ADR-0062 decision 2), and "a script of the mock must express the death of the process during the operation only if it is" journaled (ADR-0062 Context). What an operation may return is (A), a pair of any byte string and a figure or none, and (B), one of four strings (ADR-0065 decision 4) — so a script of a test can give a report judged converged, not converged, `report_form`, `zero_interval` or `replay`, with a figure or none, and each condition of (B). By decision 2 it can also give an answer of neither form, which the tool function answers with `operation_answer_invalid` (ADR-0065 decision 7), and raise a request to end, which leaves the identity open (same decision).
- **The tool-failure kinds a backend may raise are not named** (⑲ (나); ADR-0065 decision 9). This record says of them only that the default script raises none.
- **Not decided by this record.** Fault injection in a live session (OD-18 sub-question ⑧). ⑲ (가) to (라). The spend (OD-2, OD-19). When the default registry comes to hold the mock with these operations: the binding is code, the contract is not whole, and `default_registry` binds no backend table today (observation). The input schema and the description. A target on another machine (#5 B-2), the simulator (#5 B-3), any rule of the frame (#5 A-4).

### 7. Limits

1. **A record, not code; nothing was built or run.**
2. **The default script proves nothing about any kernel or backend**: the judging over the mock "proves the tool function and not a kernel or a backend" (cited: ADR-0038 decision 8, as ADR-0044 cites it), and a result does not show which backend answered (cited: ADR-0063 Limit 7).
3. **No time is shown.** Its intervals are constants of this record; every attempt at the default mock has the same samples, and two measurements of equal samples are never called different (this record's reading of ADR-0007 decision 7: every replicate ratio is 1). So the default mock never shows an improvement or a regression, and what follows a comparison (OD-15, OD-29; OD-13 sub-questions ① and ②) is reached at the mock only by a script of a test.
4. **No memory is shown.** No result of the default mock has a figure, a stated ceiling there is *not judged*, and *within* and *over* are reached by a script of a test only (decision 4).
5. **The default script shares the constant `n_min` with the replay.** A defect of that constant or of the stopping rule is not seen by a call answered by it; a script of a test may count otherwise.
6. **For the default script nothing fails**: no broken result, no condition, no tool failure, no answer of neither form. How they are reached in a live session is ⑧.
7. **The script's answer is believed**: "The operation's answer is believed" (cited: ADR-0065 Limit 2), and by decision 2 the operation's answer is the script's: a script of a test that returns a report no process wrote is taken as it is.
8. The limits of ADR-0061 decision 8, ADR-0063 decision 11 and ADR-0065 decision 10 stand unchanged.
