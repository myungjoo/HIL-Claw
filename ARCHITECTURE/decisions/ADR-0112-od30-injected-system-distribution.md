## Decision

### 1. Scope, and what the rule is

- **Scope**: the rounds ≥ 1 of one run whose `instance.json` holds `injections` (ADR-0075 decision 2) — injection at instance start only. A run without `injections` holds only `system` entries (ADR-0075 decision 3), so nothing here changes it.
- **Terms**, read from files that exist: an input is **tested in round r** when an entry of round r's `hypotheses.json` names it by `injection`; a **system hypothesis** of a round is an entry of its `hypotheses.json` with `origin` `system` — including a variant of a written input (ADR-0075 decision 3) and one resting on a case (ADR-0073 decision 2), and excluding one derived from injected material, which is `injected` (ADR-0059 decision 3). A **written input** is an entry of `injections` of kind `hypothesis`.
- **The rules of decisions 2 and 3 are rules of conduct of the runtime's selection role** (the role that writes `hypotheses.json`, ADR-0059; 1층, PLAN P2-1 and P2-6). They are not rules of the validity of `hypotheses.json`, `verdicts.json`, `instance.json` or a case file: a file that breaks one stays valid by its records, and nothing refuses to write it. What enforces or checks them is not decided here (decision 6).
- **Where a round can record no system hypothesis** — the round-1 gap of ADR-0059 decision 3 (no attempt of round 0, no case, no material the runtime found itself) — the rule asks for none, since nothing can be recorded for it. Such a round may still test a hypothesis derived from injected material, whose `external` basis names that material (ADR-0075 decision 3), and then holds injected entries only.

### 2. Every round holds a system hypothesis — point (iv)

- **The selection of every round ≥ 1 tests at least one system hypothesis**, whatever the run injected.
- **Why**: it is the one answer that meets FR-17's "라운드마다 … 스스로 추가 가설을 세우는 일을 멈추지 않으며" and the addendum's "keeps forming additional hypotheses of its own" under both readings — per round and across the run — so no reading has to be chosen. A rule only across the run would choose the weaker reading. It is checkable from one round's `hypotheses.json` alone.
- **The cost, chosen**: with N = 1 a round that tests an injected hypothesis tests it on the one candidate that also tests the round's system hypothesis, so in a run of N = 1 (PLAN P2-5) every verdict of an injected hypothesis is one of a shared candidate, for which ADR-0071 decision 5 recommends the `cause` say that the effect is not attributed to it alone. Rounds that alternate between injected and system hypotheses would avoid it, and are what this rule excludes. The rule is also met by a narrower variant of a written input, which is the selection's own (`system`, ADR-0075 decision 3); whether such a variant was drawn "from the results it already has" is the conduct FR-17 binds as written, which the rule's check of `origin` does not see. The asymmetry, accepted: at N = 1 a system hypothesis can have the candidate to itself and an injected one cannot. The experiment, verification and verdict rule are the same for both (ADR-0071 decision 5 judges each hypothesis of a shared candidate alone); what differs is the company on the candidate, the price of meeting FR-17 under both readings.
- **What it does not say**: that the system hypothesis is new against earlier rounds — FR-17 binds that as written, and statements are *text* that no landed rule compares; nor how many system hypotheses a round holds beyond one (decision 5).

### 3. Coverage of written inputs — point (iii) (owner, HQ-0031)

- **Cited, the owner's answer** ([HQ-0031](https://github.com/myungjoo/HIL-Claw/issues/5#issuecomment-6255484182), 2026-10-24): each injected hypothesis is tested once during the run, and from round 1 every round tests at least one injected hypothesis not yet tested; one left untested to the end is not a fault but a shortfall the files show. The duty applies only to directly written hypotheses (entries of `injections` of kind `hypothesis`); deriving a hypothesis from material (`material`) is outside the duty and stays in OD-30.
- **Read against the files** (this record's reading, adding no rule): a written input is tested when an entry of some round's `hypotheses.json` names it by `injection` (decision 1). In every round ≥ 1 that begins with at least one written input that no earlier round has tested, the selection tests at least one such input; which one, how many and on which candidates are its judgement (decision 5). When every written input has been tested the pace asks nothing more. This record reads "한 번 시험" as at least once; a second test stays the selection's judgement (decision 5; ADR-0075 decision 3). Whether an input named only in a round that never reaches evaluate counts as tested follows that open item (Boundaries; NFR-1, OD-17).
- **Together with decision 2**: while a written input is untested, a round ≥ 1 tests at least one system hypothesis and at least one untested written input. At N = 1 both go on the one candidate (decision 4); with k written inputs and N = 1, rounds 1 to k each share their candidate, the cost decision 2 already takes. Where a round can record no system hypothesis (decision 1), the duty of this decision still holds. In that round-1 gap a written input too can be recorded only on an `external` basis naming injected material (cited: ADR-0075 decision 3, "no basis can be recorded" otherwise); with none, no entry can be recorded and the round cannot meet the pace. How the pace applies then is not decided here (Boundaries; OD-28).
- **A written input never tested** — because the budget ran out, the target was met (UC-1), or the run was stopped or died — is the shortfall the owner names, not a fault of the run or of a file: it stays recorded as the entry of `injections` that no `injection` of the run names (cited: ADR-0075 decision 4), which a reader of the run's files can list. This record reads "not a fault" as: nothing marks it further.
- **Material inputs**: outside the duty (owner's note). A hypothesis derived from material is `injected` and names the material entry by `injection` (ADR-0075 decision 3); it neither meets nor is required by the pace, and that no round derives one stays a valid state (cited: ADR-0075 decision 1). Who derives one and when, and whether it must then be tested, stay open (OD-30 residue; Boundaries).

### 4. Order and mixing — points (i) and (ii)

- **(i) No order between injected and system hypotheses is fixed.** Decision 2 puts a system hypothesis in every round, before, beside or after any injected one; the pace of decision 3 puts an untested written input in every round until none is left, beside the system hypothesis and not instead of it. Which untested written input a round takes is the selection's judgement, FR-15's "탐색 우선순위 힌트" being a hint to it; among written inputs no order is fixed; their order in `injections` carries no meaning (cited: ADR-0075 decision 1).
- **(ii) A round's candidates may test injected and system hypotheses together, and one candidate may test both** (valid by ADR-0059 decision 4). With N = 1 a round that tests an injected hypothesis must test it on the same candidate as its system hypothesis; with N ≥ 2 the recommendation of ADR-0059 decision 4 (one hypothesis per candidate where N allows) applies unchanged, and so does that of ADR-0071 decision 5 on the `cause` of a verdict whose comparisons all measure shared candidates. This record adds no rule of attribution.

### 5. Share beyond the minimum

- **No ratio is fixed.** How many injected and system hypotheses a round tests beyond decisions 2 and 3, whether an injected input is tested again, and which candidates test what, are the selection's judgement. It is recorded through what exists: `origin`, `injection`, `basis` and `tested_by` of each entry (ADR-0059, ADR-0075), and the identification of injected hypotheses in the decision log is that of ADR-0075 decision 4, unchanged (FR-11).

### 6. What would check or enforce the rule

- **Checkable from files**: decision 2 from one round's `hypotheses.json`; the pace of decision 3 by a reader holding the run's `instance.json` and its round files up to that round. Such a check would report a round that breaks a rule; it would refuse no file. The written inputs no round tested by the run's end are the shortfall of decision 3, listed by the same reader; that list reports no breach.
- **What enforces or checks the rules, when, and whether a breach stops a round** is OD-18 (with FR-17 "강제 수단 = OD-18"); which agent holds the selection role and receives the rule is OD-23. No hook, module, tool or prompt is named as binding, and that enforcement is not decided here.

### 7. How the answer holds while the open parts stay open

- **Injection at a gate or during a run (②, ③; owner)**: this record speaks of entries of `injections` in `instance.json` only. An input arriving otherwise is not in scope; the record that admits it says whether this record extends to it.
- **Who derives a hypothesis from material**: no rule here asks for a derivation (decision 3, owner's note); a hypothesis derived from material is `injected`, does not count as a system hypothesis (decision 1) and does not meet the pace of decision 3, whoever derives it.
- **The catalog boundary** (UC-5, OD-7, OD-24): decision 2 concerns which hypotheses a round tests, not what becomes a technique.
- **The verdict's comparison base**: decisions 2 and 3 read `origin` and `injection` in `hypotheses.json`, not verdicts, so it holds whatever base a verdict compares against.
- **Best-of-N beyond the MVP (OD-29)**: decisions 2 and 3 hold for every N ≥ 1, run in parallel or in order, whatever k is promoted.

### Example

A run injected `u1` and `u2`, both of kind `hypothesis`, and one material `u3`; N = 1. Round 1: candidate 1 tests a system hypothesis and `u1` (decisions 2 and 3; shared at N = 1, decision 4). Round 2: candidate 1 tests a system hypothesis and `u2`. Round 3: candidate 1 tests a system hypothesis only, since no written input is left untested. No round derives a hypothesis from `u3`, which is valid and outside the duty (decision 3). Had the budget ended after round 1, `u2` would be the shortfall the files show, not a fault. A round 2 testing a system hypothesis only would break the pace of decision 3; a round 2 testing `u2` alone would break decision 2. The Example of ADR-0075 (one written input `u1`; round 1, N = 2: `u1` on candidate 1, a system hypothesis on candidate 2) meets both.
